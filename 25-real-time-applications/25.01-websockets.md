## 25.1 WebSockets

### Client-Side API
```javascript
const ws = new WebSocket('wss://api.example.com/ws');

ws.onopen = () => console.log('Connected');
ws.onmessage = (event) => console.log('Message:', event.data);
ws.onerror = (error) => console.error('Error:', error);
ws.onclose = (event) => {
  console.log('Closed:', event.code, event.reason);
};

// Send
ws.send(JSON.stringify({ type: 'subscribe', channel: 'trades' }));

// Close gracefully
ws.close(1000, 'Normal closure');
```

### Server-Side (Node.js `ws`)
```javascript
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws, req) => {
  ws.isAlive = true;
  ws.on('pong', () => { ws.isAlive = true; });

  ws.on('message', (data) => {
    const message = JSON.parse(data);
    // route to subscribers
  });

  ws.on('close', () => {
    // cleanup subscriptions
  });
});

// Heartbeat: terminate dead connections
const interval = setInterval(() => {
  wss.clients.forEach((ws) => {
    if (!ws.isAlive) return ws.terminate();
    ws.isAlive = false;
    ws.ping();
  });
}, 30000);

wss.on('close', () => clearInterval(interval));
```

### Deeper Explanation: A Connection Is A Resource, Not A Function Call

Once a socket is open, both sides can push at any time, ordered within that connection. Everything hard about WebSockets follows from that: **you now own liveness, authentication over time, backpressure, and message protocol versioning** â€” none of which HTTP gave you for free.

Design decisions worth making explicitly:

- **Auth**: browsers cannot set headers on the upgrade, so use a cookie, a short-lived ticket in the query string, or an authenticated first message. Re-authenticate on reconnect.
- **Protocol**: a versioned envelope (`{ v, type, id, payload }`), a discriminated union on the server side, tolerant parsing on both ends. Unknown types must be ignored, never crash.
- **Liveness**: application-level ping/pong plus a server idle timeout. TCP can be half-open for minutes after a network change.
- **Backpressure**: check `bufferedAmount` before sending; drop or coalesce stale messages rather than queueing forever.
- **Scaling**: a message produced on node A must reach subscribers on node B, so you need sticky sessions or a pub/sub fan-out layer.

### Extended Example: Envelope, Heartbeat, and Backpressure Guard

```ts
type Envelope =
  | { v: 1; type: 'ping'; id: string }
  | { v: 1; type: 'pong'; id: string }
  | { v: 1; type: 'subscribe'; id: string; payload: { channel: string; since?: string } }
  | { v: 1; type: 'event'; id: string; payload: { channel: string; data: unknown; seq: number } };

export class Realtime {
  private ws?: WebSocket;
  private pending = new Map<string, (e: Extract<Envelope, { type: 'event' }>) => void>();
  private lastSeq = 0;

  constructor(private url: string, private onEvent: (e: Extract<Envelope, { type: 'event' }>) => void) {}

  private send(msg: Envelope) {
    const ws = this.ws;
    if (!ws || ws.readyState !== WebSocket.OPEN) return;
    if (ws.bufferedAmount > 1_000_000) return;   // never queue unboundedly
    ws.send(JSON.stringify(msg));
  }

  private startHeartbeat() {
    setInterval(() => this.send({ v: 1, type: 'ping', id: crypto.randomUUID() }), 25_000);
  }

  private onMessage(event: MessageEvent<string>) {
    const msg = JSON.parse(event.data) as Envelope;
    if (msg.type !== 'event') return;
    if (msg.payload.seq <= this.lastSeq) return;   // ignore duplicates after reconnect
    this.lastSeq = msg.payload.seq;
    this.onEvent(msg);
  }
}
```

### Additional Pitfalls
- **Reconnect without resync.** Messages sent while you were offline are lost; request `since: lastSeq` (or refetch) on reconnect.
- **Reconnect storms.** Exponential backoff with jitter, and stop retrying on 4xx auth failures until the token is refreshed.
- **Sending on every keystroke.** Coalesce and throttle; the socket is a shared resource.
- **No server-side idle timeout.** Half-open connections accumulate until the fleet runs out of sockets.
- **One socket per component.** Route everything through a single connection manager.

### Real-World Deal-Breakers
- **No heartbeat** → proxies and load balancers kill idle connections after 60-120 seconds.
- **No reconnection logic** → mobile network switches, laptop sleep/wake, and server deploys constantly break connections.
- **Unbounded send buffer** → a slow client causes memory exhaustion on the server. Enforce `maxBackpressure`.
- **No message size limit** → a malicious client sends a 100MB message and crashes the server.
- **`ws.send()` without checking `readyState`** → throws `InvalidStateError` if the socket is not open.
