### Example: Image Processing (Rust → WASM)
```rust
// Rust - image filter
#[wasm_bindgen]
pub fn apply_grayscale(pixels: &mut [u8]) {
    for chunk in pixels.chunks_exact_mut(4) {
        let r = chunk[0] as f32;
        let g = chunk[1] as f32;
        let b = chunk[2] as f32;
        let gray = (0.299 * r + 0.587 * g + 0.114 * b) as u8;
        chunk[0] = gray;
        chunk[1] = gray;
        chunk[2] = gray;
    }
}
```

```javascript
// JS - transfer pixel buffer, process in WASM, transfer back
const imageData = ctx.getImageData(0, 0, width, height);
const buffer = imageData.data.buffer;

// Transfer to worker → WASM → transfer back
worker.postMessage({ buffer, width, height }, [buffer]);

// In worker:
const pixels = new Uint8Array(buffer);
wasm.apply_grayscale(pixels); // zero-copy
self.postMessage({ buffer: pixels.buffer }, [pixels.buffer]);
```

### Deeper Explanation: Architecture For Heavy Compute

An app that genuinely computes (CAD, video editing, analytics, ML) needs an architecture, not a library:

1. **A job model.** Every heavy operation is a task with an id, progress, cancel, and result; the UI subscribes to tasks, never to raw buffers.
2. **Off-thread by default.** Workers (or a pool) run kernels; the main thread only marshals and renders.
3. **Bulk transfer.** Inputs and outputs cross the boundary as transferred `ArrayBuffer`s or shared memory, never as per-item calls.
4. **Progress and cancellation over latency.** Users tolerate seconds if they see progress and can stop; they do not tolerate a frozen tab.
5. **Streaming results.** For preview-class operations, push partial results so the first useful frame appears early (progressive image upscaling, chunked analysis).
6. **Fallbacks.** A JS path for small inputs and unsupported environments keeps the feature usable.

### Additional Pitfalls
- **Blocking the UI on the first result.** Show a skeleton and stream partial output.
- **No cancellation.** Long jobs hold memory and CPU; users will navigate away and leave them running.
- **Unbounded concurrency.** More workers than cores increases contention and memory pressure; cap at `hardwareConcurrency - 1`.
- **Ignoring thermal throttling.** Sustained mobile computation degrades; design for sustained throughput, not bursts.
- **Treating accuracy as free.** f32 kernels are faster and lossy; document the precision your product accepts.

### Real-World Deal-Breakers
- **Processing 4000×3000 images on the main thread** → 2+ seconds of frozen UI. Use a worker + WASM.
- **Copying large buffers instead of transferring** → 302ms vs 6.6ms for 32MB. Use Transferable Objects.
- **No progress reporting** → user stares at a frozen screen.
- **WASM without WebGPU for ML** → WebGPU compute shaders can be 10× faster for matrix operations.
