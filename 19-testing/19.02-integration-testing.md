### What Integration Tests Cover
Integration tests render a **tree of components** (not just one) with real context providers, real hooks, and mock the **network layer** - not the internal modules.

```tsx
// features/users/UserList.test.tsx
import { render, screen, waitFor } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { UserList } from './UserList';
import { server } from '@/test/msw/server';
import { http, HttpResponse } from 'msw';

function renderWithProviders(ui: React.ReactElement) {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false } },
  });
  return render(
    <QueryClientProvider client={queryClient}>{ui}</QueryClientProvider>
  );
}

describe('UserList', () => {
  it('renders users from the API', async () => {
    server.use(
      http.get('/api/users', () => {
        return HttpResponse.json([
          { id: 1, name: 'Alice' },
          { id: 2, name: 'Bob' },
        ]);
      })
    );

    renderWithProviders(<UserList />);

    expect(await screen.findByText('Alice')).toBeInTheDocument();
    expect(screen.getByText('Bob')).toBeInTheDocument();
  });

  it('shows error state when API fails', async () => {
    server.use(
      http.get('/api/users', () => {
        return HttpResponse.json({ message: 'Server error' }, { status: 500 });
      })
    );

    renderWithProviders(<UserList />);

    expect(await screen.findByText(/something went wrong/i)).toBeInTheDocument();
  });
});
```

### Real API Boundary Mocking (MSW)
Instead of mocking `fetch` or your API client, MSW **intercepts requests at the network level** - in Node.js via `setupServer` and in the browser via a Service Worker. This means your component uses the real `fetch`, the real API client, and the real parsing logic - only the response is mocked.

```typescript
// test/msw/server.ts
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

export const server = setupServer(...handlers);
```

```typescript
// test/setup.ts
import { beforeAll, afterEach, afterAll } from 'vitest';
import { server } from './msw/server';

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => server.resetHandlers()); // reset per-test overrides
afterAll(() => server.close());
```
**`onUnhandledRequest: 'error'`** is critical - it fails the test if a request isn't explicitly mocked, catching accidental real API calls.

### Deeper Explanation: Test At The Seam You Own

Integration tests are valuable because they exercise **your** composition â€” hook, query client, component tree, request shape â€” while replacing only the systems you do not control. The rule that keeps them honest: *mock at the network boundary, never inside your own app*. Mocking a module you also ship means you are testing the mock's fidelity, not your code.

Where the boundary sits determines the tool:

| Boundary you own | Replace with | Typical assertion |
|---|---|---|
| HTTP to a backend | **MSW** | Request body, URL, headers, retry count |
| Browser storage | `fake-indexeddb`, in-memory `localStorage` | Persisted shape, migration outcome |
| Time | an injected clock | Debounce, retry backoff, TTL expiry |
| Auth session | a context wrapper with a fake session | Redirect and gate behaviour |

The second integration-specific lesson is **cache hygiene**. Data-layer tests share a `QueryClient` between tests by accident far more often than by design, and a leaked cache turns a 200 ms test into a flaky one.

### Extended Example: Hook, MSW, And Asserting The Request Body

```typescript
import { renderHook, waitFor } from '@testing-library/react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { http, HttpResponse } from 'msw';
import { setupServer } from 'msw/node';

const server = setupServer();
beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => server.resetHandlers());
afterAll(() => server.close());

function wrapper({ children }: { children: React.ReactNode }) {
  const [client] = useState(() => new QueryClient({ defaultOptions: { queries: { retry: false } } }));
  return <QueryClientProvider client={client}>{children}</QueryClientProvider>;
}

it('creates a todo and returns the created entity', async () => {
  let seenBody: unknown;
  server.use(
    http.post('/api/todos', async ({ request }) => {
      seenBody = await request.json();
      return HttpResponse.json({ id: '1', ...(seenBody as object) }, { status: 201 });
    }),
  );

  const { result } = renderHook(() => useCreateTodo(), { wrapper });
  result.current.mutate({ title: 'ship it' });

  await waitFor(() => expect(result.current.isSuccess).toBe(true));
  expect(seenBody).toEqual({ title: 'ship it' });
  expect(result.current.data).toMatchObject({ id: '1' });
});
```

### Additional Pitfalls
- **A fresh `QueryClient` created inside the wrapper component body.** Each re-render silently resets the cache and the test either flickers or times out; create it once per test.
- **`onUnhandledRequest: 'warn'`.** The suite quietly makes real network calls (and hangs in CI); use `'error'`.
- **Asserting only the happy path.** Integration tests are the cheapest place to prove error and empty states â€” return a 500 and assert the error UI.
- **Sharing MSW overrides without `resetHandlers()`.** The override leaks into the next test and produces order-dependent failures.
- **Awaiting a fixed timeout.** Use `waitFor`/`findBy` so a slow machine does not fail the build.

### Real-World Deal-Breakers
- **Mocking `fetch` directly** → you're testing your mock, not your API layer. Use MSW.
- **No `onUnhandledRequest: 'error'`** → unmocked requests hit the real API (in CI, they fail silently or hang).
- **Forgetting `server.resetHandlers()`** → test-specific overrides leak into other tests.
- **Mocking internal modules** → integration tests should mock at the **network boundary**, not internal functions.
- **No `QueryClient` isolation** → shared cache between tests causes flaky results.
