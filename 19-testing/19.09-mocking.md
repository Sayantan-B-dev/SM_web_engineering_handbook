## 19.9 Mocking

### Subtopic Tree
- Why mock (isolation, speed, determinism)
- Test doubles: mocks, stubs, spies, fakes
- Function mocking (`vi.fn()`, `jest.fn()`)
- Module mocking (`vi.mock()`, `jest.mock()`)
- Network mocking (MSW)
- Time mocking (`vi.useFakeTimers()`)
- Environment mocking
- Mocking React hooks
- Anti-patterns (over-mocking)

### The Mocking Hierarchy

| Approach | Level | Best for |
|----------|-------|----------|
| **MSW** | Network | Integration tests, component tests |
| **Module mocking** | Import | Isolating a module's dependencies |
| **Function mocking** | Function | Spying on callbacks, testing side effects |
| **Fake timers** | Time | Testing debounce, intervals, timeouts |
| **Snapshot mocking** | Data | Testing large static data |

### MSW (Preferred for Network)
MSW works by intercepting requests at the **network level**. In Node.js, use `setupServer`; in the browser, use `setupWorker` (Service Worker).

```typescript
// test/msw/handlers.ts
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/users', () => {
    return HttpResponse.json([{ id: 1, name: 'Alice' }]);
  }),

  http.post('/api/users', async ({ request }) => {
    const newUser = await request.json();
    return HttpResponse.json({ id: 2, ...newUser }, { status: 201 });
  }),
];
```

```typescript
// test/msw/server.ts
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

export const server = setupServer(...handlers);
```

```typescript
// test/setup.ts
import { beforeAll, afterEach, afterAll } from 'vitest';
import { server } from './msw/server';

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => server.resetHandlers()); // reset per-test overrides
afterAll(() => server.close());
```
The three critical steps: enable interception before tests, reset handlers after each test, and close after all tests.

### Module Mocking (Use Sparingly)
```typescript
// ✅ Mock a module
vi.mock('@/lib/analytics', () => ({
  trackEvent: vi.fn(),
}));

// ✅ Spy without replacing
const spy = vi.spyOn(analytics, 'trackEvent');
```

### Hook Mocking
```typescript
const mockUseAuth = vi.fn();
vi.mock('@/features/auth', () => ({
  useAuth: () => mockUseAuth(),
}));

beforeEach(() => {
  mockUseAuth.mockReturnValue({ user: { name: 'Alice' }, logout: vi.fn() });
});
```

### Anti-Patterns
```typescript
// ❌ Mocking the module under test
vi.mock('./UserService');
import { UserService } from './UserService'; // this is now a mock

// ✅ Mock dependencies, test the real module
vi.mock('./api');
import { UserService } from './UserService'; // real implementation
```

---

### Deeper Explanation: A Mock Is A Claim About The Outside World

Every test double encodes an assumption â€” "the API returns 201 with this body", "the clock says January", "the user's plan is pro". A test fails for exactly two reasons: the code is wrong, or the assumption is stale. So the goal of mocking is not maximum isolation, it is **the smallest possible number of assumptions, each stated once and shared**.

That produces a preference order:

| Rank | Technique | Why |
|---|---|---|
| 1 | Real implementation (pure function, reducer) | No assumption to go stale |
| 2 | Injected dependency (`fetchImpl`, `now`, `storage`) | The assumption lives in the test, not in module magic |
| 3 | Network-level interception (**MSW**) | The same code path in dev, test, and Storybook |
| 4 | HTTP client stub (`nock`, `vi.spyOn(api, 'get')`) | Fast, but skips serialisation and interceptors |
| 5 | Module mock (`vi.mock`, `jest.mock`) | Broadest, most brittle, easiest to over-apply |

The tell that you are over-mocking: an internal refactor forces you to edit mocks. If a dependency must be mocked to test a unit, that dependency deserves to be injected.

### Extended Example: MSW With Latency, Error Mode, And Passthrough

```typescript
// tests/msw.ts
import { http, HttpResponse, delay } from 'msw';

export const handlers = [
  http.get('/api/user/:id', async ({ params }) => {
    await delay(10);
    if (params.id === 'missing') {
      return HttpResponse.json({ message: 'Not found' }, { status: 404 });
    }
    return HttpResponse.json({ id: params.id, name: 'Ada' });
  }),
];
```

```typescript
it('shows a retry affordance when the API fails once', async () => {
  let calls = 0;
  server.use(
    http.get('/api/user/:id', () => {
      calls += 1;
      return calls === 1
        ? HttpResponse.json({ message: 'boom' }, { status: 500 })
        : HttpResponse.json({ id: '1', name: 'Ada' });
    }),
  );

  render(<Profile id="1" />);
  await userEvent.click(await screen.findByRole('button', { name: /try again/i }));
  expect(await screen.findByText('Ada')).toBeInTheDocument();
});
```

### Additional Pitfalls
- **Mocking the module under test.** You assert your own stub and learn nothing; inject the collaborator instead.
- **`vi.mock` with a spy on everything.** Overrides hide signature drift â€” a renamed parameter passes your tests and fails in production.
- **Freezing time globally in a setup file.** Libraries that do `Date` maths internally (query staleness, chart scales) start behaving wrongly in unrelated tests; scope fake timers to the spec that needs them.
- **Stubbing `Math.random` with a constant.** IDs collide and React keys break in ways that mask real bugs; use a seeded sequence and reset it.
- **Leaked override handlers.** A forgotten 500 handler turns the next test red for the wrong reason.
- **Mocking `fetch` with a plain object.** You skip `.ok`, `.json()`, and streaming semantics your code depends on; return a real `Response`.

### Real-World Deal-Breakers
- **Mocking `fetch` directly** → you're testing your mock, not your API layer. Use MSW.
- **`onUnhandledRequest: 'error'` missing** → unmocked requests hit real APIs; CI flakiness.
- **No `server.resetHandlers()`** → test-specific mocks leak into other tests.
- **Over-mocking** → 10 mocks to test one function means the function is too coupled.
- **Mocking the module under test** → you're testing the mock, not the code.
- **Not clearing mocks between tests** → `vi.clearAllMocks()` in `afterEach`.
