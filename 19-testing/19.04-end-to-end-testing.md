### Playwright vs Cypress

| Feature | Playwright | Cypress |
|---------|-----------|---------|
| Browsers | Chromium, Firefox, WebKit | Chromium, Firefox (WebKit experimental) |
| Language | JS/TS, Python, Java, C# | JS/TS only |
| Architecture | Out-of-process, multi-tab | In-browser, single-tab |
| Auto-wait | Built-in | Built-in |
| Trace viewer | Excellent | Good |
| Component testing | Experimental CT | Stable component testing |
| Parallelism | Built-in sharding | Paid dashboard |
| 2026 trend | Dominant, top framework in surveys | Still widely used |

Playwright is a testing framework that lets you automate Chromium, Firefox, and WebKit with a single API. It provides true isolation for tests with a reliable mounting and mocking model.

### Basic E2E Test
```typescript
// e2e/checkout.spec.ts
import { test, expect } from '@playwright/test';

test('user can complete checkout', async ({ page }) => {
  await page.goto('/products');
  await page.getByRole('button', { name: 'Add to cart' }).first().click();
  await page.getByRole('link', { name: 'Cart' }).click();
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Email').fill('alice@example.com');
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByText('Order confirmed')).toBeVisible();
});
```

### Deeper Explanation: E2E Proves Wiring, Not Logic

An end-to-end test is the only test that exercises the real browser, the real server, real cookies, real redirects, and real serialisation. That makes it irreplaceable for *wiring* questions â€” does the session cookie survive the redirect, does the route actually stream, does a third-party script break hydration â€” and a poor tool for logic questions, which are slower, flakier, and less precise when tested here.

Two ideas keep E2E suites small and trustworthy:

- **Deterministic state, not deterministic clicking.** Seed the database (or a test-only API) to a known fixture and authenticate by injecting `storageState`, instead of driving onboarding and the login form in every spec.
- **Isolation by default.** Each Playwright test gets a fresh browser context â€” clean cookies, storage, and cache. Shared state fails in the worst way: green locally, red in CI, in a different order every run.

Also budget the suite: E2E belongs on the critical journeys (sign-up, checkout, the flow that loses money); everything else is cheaper one layer down.

### Extended Example: Seeded Session, Diagnostics, Web-First Assertions

```typescript
import { test, expect } from '@playwright/test';

test.use({ storageState: 'playwright/.auth/user.json' }); // logged in once in globalSetup

test('an invoice can be created and appears in the list', async ({ page, request }) => {
  const seeded = await request.post('/api/test-seed/invoices', {
    data: { customer: 'Ada Lovelace' },
  });
  expect(seeded.ok()).toBeTruthy();

  await page.goto('/invoices');
  await expect(page.getByRole('heading', { name: 'Invoices' })).toBeVisible();
  await page.getByRole('button', { name: 'New invoice' }).click();
  await page.getByLabel('Customer').fill('Ada Lovelace');
  await page.getByRole('button', { name: 'Create' }).click();

  // web-first assertion: retries until the row appears, no manual wait
  await expect(page.getByRole('cell', { name: 'Ada Lovelace' })).toBeVisible();
});
```

### Additional Pitfalls
- **`waitForTimeout(2000)`.** That is a sleep, not synchronisation. Locators already auto-wait; assert and let the assertion poll.
- **`waitUntil: 'networkidle'`.** Unreliable with polls, websockets, and analytics beacons; wait for a specific element instead.
- **`{ force: true }` to get past an overlay.** You just removed the simulation of the bug your users hit; fix or assert the overlay.
- **Data collisions under parallel workers.** Give every spec its own namespace (`user-${test.info().workerIndex}`) or a per-test seed.
- **No artifact on failure.** Without a trace, a red CI job gives you a screenshot of a spinner.
- **CSS-class selectors.** `.btn-primary` is a styling detail; `getByRole('button', { name: 'Save' })` is the contract.

### Real-World Deal-Breakers
- **Too many E2E tests** → slow CI, flaky tests, expensive to maintain. Reserve for critical journeys.
- **No test isolation** → tests share state; order matters. Each test must create its own data.
- **Hardcoded waits** (`page.waitForTimeout(2000)`) → flaky. Use Playwright's auto-waiting locators.
- **No trace on failure** → debugging CI failures is impossible. Enable traces on first retry.
- **Testing third-party integrations** → mock them; you don't control Stripe's uptime.
- **No parallelism** → a 30-minute E2E suite kills developer velocity. Use sharding.
