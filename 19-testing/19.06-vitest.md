### Why Vitest Over Jest
Vitest is built on Vite, inheriting its speed. Benchmarks show that Vitest runs tests **10 to 20 times faster than Jest in watch mode**, especially in modern TypeScript projects, leading to quicker TDD cycles. It offers compatibility with most of the Jest API, so in most projects it should be a drop-in replacement for Jest.

| Feature | Jest | Vitest |
|---------|------|--------|
| Speed (cold start, ~50 tests) | ~5s | ~1.5s |
| Watch-mode rerun | ~1s | <100ms (HMR-driven) |
| ESM support | Experimental | Native |
| Config | Separate config | Shares `vite.config.ts` |
| API | `describe`, `it`, `expect` | Same (Jest-compatible) |

### Setup
```bash
pnpm add -D vitest @vitejs/plugin-react jsdom @testing-library/react @testing-library/dom vite-tsconfig-paths
```

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';
import tsconfigPaths from 'vite-tsconfig-paths';

export default defineConfig({
  plugins: [react(), tsconfigPaths()],
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: ['./test/setup.ts'],
    coverage: {
      provider: 'v8',
      thresholds: { lines: 80, branches: 75 },
    },
  },
});
```

### Deeper Explanation: Vitest Is Vite In Test Mode

Vitest does not re-implement the build pipeline â€” it reuses your Vite config, so aliases, `define` constants, plugins, CSS handling, and TypeScript transforms behave in tests exactly as they do in development. That is why a Vite + Vitest project rarely needs mock plumbing: **there is no second module-resolution system to keep in sync**.

Two structural features are worth designing around:

- **Projects (formerly workspaces).** One repository, several test realities: `unit` (node env), `dom` (jsdom/happy-dom), `browser` (real Chromium through the Playwright provider). Split by glob and configure each environment once instead of scattering `// @vitest-environment` comments.
- **Browser mode.** For behaviour jsdom cannot model â€” CSS layout, `IntersectionObserver`, real pointer events, canvas â€” Vitest's browser mode runs the same specs in a real browser, which is often cheaper than escalating to full E2E.

### Extended Example: Projects, Setup Files, And Coverage Thresholds

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    projects: [
      {
        test: {
          name: 'unit',
          environment: 'node',
          include: ['src/lib/**/*.test.ts', 'src/**/*.node.test.ts'],
        },
      },
      {
        test: {
          name: 'dom',
          environment: 'jsdom',
          setupFiles: ['./tests/setup.ts'],
          include: ['src/**/*.test.tsx'],
          css: false, // skip CSS parsing unless a test asserts on styles
        },
      },
    ],
    coverage: { provider: 'v8', reporter: ['text', 'lcov'], thresholds: { lines: 75 } },
  },
});
```

```typescript
// tests/setup.ts
import '@testing-library/jest-dom/vitest';
import { afterEach, vi } from 'vitest';
import { cleanup } from '@testing-library/react';
import { resetHandlers } from './msw';

afterEach(() => {
  cleanup();
  resetHandlers();
  vi.clearAllMocks();
  vi.restoreAllMocks();
});
```

### Additional Pitfalls
- **`globals: true` without `"types": ["vitest/globals"]`.** Editors and `tsc` report `Cannot find name 'describe'` even though the tests run.
- **`environment: 'node'` for a component spec.** You get a confusing `document is not defined` from deep inside a dependency; set the environment per project.
- **ESM-only packages Vitest cannot transform.** Force inlining through `server.deps.inline` (or the deps optimiser) instead of downgrading the package.
- **`vi.useFakeTimers()` with `userEvent` or timer-based libraries.** Pass `advanceTimers`/`shouldAdvanceTime` or awaited interactions never settle.
- **Trusting `v8` coverage on transformed output.** Enable `coverage.all` and inspect the report for phantom uncovered branches before enforcing thresholds.
- **Using `--no-threads` to fix flakiness.** That hides shared-global leakage which will also break another machine in CI.

### Real-World Deal-Breakers
- **`globals: true` without types** → `describe`/`it` are undefined in TypeScript. Add `"types": ["vitest/globals"]` to `tsconfig.json`.
- **`environment: 'node'` for React** → `document` is undefined. Use `'jsdom'` or `'happy-dom'`.
- **No `setupFiles`** → `@testing-library/jest-dom` matchers (`toBeInTheDocument`) unavailable.
- **Assuming 100% Jest compatibility** → some Jest APIs (e.g., `jest.requireActual`) are shimmed but not identical. Check migration guide.
- **Not using Browser Mode for visual tests** → jsdom lacks layout engine; use Vitest Browser Mode or Playwright CT.
