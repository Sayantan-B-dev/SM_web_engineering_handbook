### Locators (Priority)
```typescript
// ✅ Priority order
page.getByRole('button', { name: 'Submit' });
page.getByLabel('Email');
page.getByText('Welcome back');
page.getByPlaceholder('Enter email');
page.getByTestId('submit-btn'); // last resort
```

### Auto-Waiting
Playwright automatically waits for elements to be actionable before interacting. No `waitForTimeout` needed.

```typescript
// ✅ Playwright waits for the button to be visible, enabled, and stable
await page.getByRole('button', { name: 'Submit' }).click();
```

### Deeper Explanation: Auto-Waiting, Locators, And One Source Of Truth

Playwright's core promise is that **every action and assertion is retried against live DOM state** until it succeeds or the timeout expires. That removes the two biggest sources of flake in older tools: the arbitrary sleep and the "element exists but is not actionable" error. Three consequences follow:

1. **Locators are lazy, not snapshots.** `page.getByRole('button', { name: 'Save' })` re-queries on every use; storing it in a variable is safe, converting it into an element handle is not.
2. **Assertions self-heal.** `expect(locator).toBeVisible()` polls. Exceptions such as `expect(await locator.count()).toBe(2)` need `expect.poll` or `toPass`.
3. **Choose one query strategy and stop there.** Role, label, and text queries exist so tests survive markup changes; test IDs are the escape hatch, not the default.

Beyond locators, three capabilities define a mature setup: **test isolation** (a fresh context per test), **reusable auth** (`storageState`), and **diagnostics on failure** (trace, video, screenshot, plus `--shard` for CI parallelism).

### Extended Example: Route Stubbing, Skeleton Assertions, And Retry-Safe Polling

```typescript
import { test, expect } from '@playwright/test';

test('shows a skeleton then the loaded profile', async ({ page }) => {
  await page.route('**/api/profile', async (route) => {
    await new Promise((r) => setTimeout(r, 300)); // simulate latency
    await route.fulfill({ json: { name: 'Ada', plan: 'pro' } });
  });

  await page.goto('/profile');
  await expect(page.getByTestId('profile-skeleton')).toBeVisible();
  await expect(page.getByRole('heading', { name: 'Ada' })).toBeVisible();
  await expect(page.getByTestId('profile-skeleton')).toBeHidden();
});

test('badge count converges without arbitrary waits', async ({ page }) => {
  await page.goto('/inbox');
  await expect.poll(() => page.getByTestId('badge').textContent()).toBe('3');
});
```

### Additional Pitfalls
- **Element handles (`page.$eval`, `elementHandle`).** They snapshot the DOM and reintroduce staleness; stay in locators end to end.
- **A global `beforeEach` that logs in through the UI.** It costs seconds per test and couples every spec to the login form; use `storageState`.
- **`test.describe.serial` to dodge data conflicts.** It hides the isolation bug and makes one failure cascade; namespace the test data instead.
- **Time and locale drift.** Freeze the clock in the app under test and pass an explicit locale whenever formatted output is asserted.
- **`expect(await locator.isVisible()).toBe(true)`.** `isVisible()` does not retry; the assertion form does. This one change removes most residual flake.
- **Running the whole suite on every push.** Shard in CI (`--shard=1/4`) and run the full matrix nightly.

### Real-World Deal-Breakers
- **`page.waitForTimeout(2000)`** → flaky and slow. Use auto-waiting locators.
- **CSS selectors (`.btn-primary`)** → break on style refactors. Use role/label/text.
- **No trace on failure** → debugging CI failures is impossible. Enable `trace: 'on-first-retry'`.
- **No test isolation** → tests share auth state; order matters. Use fixtures.
- **Not using `test.describe.configure({ mode: 'parallel' })`** → slow serial runs.
- **Hardcoded test data in tests** → shared state between tests. Use fixtures or factories.
