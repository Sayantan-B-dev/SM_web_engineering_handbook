### Essential SQL Patterns for React Developers

**Pagination with cursor (better than OFFSET)**
```sql
-- ❌ OFFSET pagination - slow for large offsets
SELECT * FROM posts ORDER BY created_at DESC LIMIT 20 OFFSET 10000;

-- ✅ Cursor pagination - constant time
SELECT * FROM posts
WHERE created_at < $1  -- last seen created_at
ORDER BY created_at DESC
LIMIT 20;
```

**UPSERT (INSERT ... ON CONFLICT)**
```sql
INSERT INTO users (id, email, name)
VALUES ($1, $2, $3)
ON CONFLICT (id) DO UPDATE SET
  email = EXCLUDED.email,
  name = EXCLUDED.name,
  updated_at = now()
RETURNING *;
```

**CTEs for complex queries**
```sql
WITH active_users AS (
  SELECT id, name FROM users WHERE last_login > now() - interval '30 days'
),
user_orders AS (
  SELECT user_id, COUNT(*) as order_count, SUM(total) as total_spent
  FROM orders
  WHERE created_at > now() - interval '90 days'
  GROUP BY user_id
)
SELECT u.name, o.order_count, o.total_spent
FROM active_users u
JOIN user_orders o ON o.user_id = u.id
ORDER BY o.total_spent DESC
LIMIT 10;
```

**Window functions**
```sql
SELECT
  name,
  department,
  salary,
  ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) as rank,
  LAG(salary) OVER (PARTITION BY department ORDER BY salary) as prev_salary
FROM employees;
```

**EXPLAIN ANALYZE - the single most important query tuning tool**
```sql
EXPLAIN ANALYZE
SELECT * FROM posts WHERE author_id = '...' ORDER BY created_at DESC LIMIT 20;
```
Look for: **Seq Scan** (missing index), **Nested Loop** with large row counts (missing index or bad join), **Sort** with high cost (missing index for ORDER BY).

### SQL Injection Prevention
```typescript
// ❌ NEVER - string concatenation
const result = await db.query(`SELECT * FROM users WHERE id = '${userId}'`);

// ✅ ALWAYS - parameterized queries
const result = await db.query('SELECT * FROM users WHERE id = $1', [userId]);

// ✅ With Prisma (parameterized by default)
const user = await prisma.user.findUnique({ where: { id: userId } });

// ✅ With Drizzle (parameterized by default)
const user = await db.select().from(users).where(eq(users.id, userId));
```

### Deeper Explanation: SQL Is The Debugging Tool And The Debug Target

Frontend engineers meet SQL in two roles: writing queries (often through an ORM) and diagnosing them (always through SQL). The skills that pay off immediately are reading `EXPLAIN ANALYZE`, understanding joins (inner/left/lateral), window functions for per-group calculations, CTEs for readability, and `RETURNING` for write-then-read in one round trip.

```sql
-- Cursor pagination that stays correct while rows change (no offset drift)
SELECT id, title, created_at
FROM issues
WHERE tenant_id = $1
  AND (created_at, id) < ($2, $3)          -- (cursor_created_at, cursor_id)
ORDER BY created_at DESC, id DESC
LIMIT 20;

-- Per-author last activity with a window function: no N+1 from the client
SELECT author_id, MAX(created_at) AS last_at,
       ROW_NUMBER() OVER (PARTITION BY author_id ORDER BY created_at DESC) AS rn
FROM comments
WHERE issue_id = $1
GROUP BY author_id, created_at;

-- Write and read in one round trip, safe under concurrency
INSERT INTO orders (id, user_id, total_cents)
VALUES ($1, $2, $3)
ON CONFLICT (id) DO NOTHING
RETURNING id, created_at;
```

### Additional Pitfalls
- **`OFFSET` for deep pagination.** It scans and discards; keyset pagination is O(log n) with the right index.
- **`N+1` queries from the server layer.** Batch with `IN (...)` or a join, and verify with query logging.
- **Implicit casts in `WHERE`.** They disable index usage; match types exactly.
- **`SELECT COUNT(*)` on hot paths.** Expensive at scale; use estimates or maintained counters.
- **Transactions held across awaits of external services.** Keep them short; do not span network calls.

### Real-World Deal-Breakers
- **String concatenation in SQL** → SQL injection. Always use parameterized queries.
- **OFFSET pagination for large datasets** → performance degrades linearly. Use cursor pagination.
- **No EXPLAIN ANALYZE** → you're guessing at query performance. Always check the plan.
- **SELECT *** → fetches columns you don't need. Specify columns explicitly.
- **N+1 queries** → each row triggers a separate query. Use JOINs or DataLoader.
