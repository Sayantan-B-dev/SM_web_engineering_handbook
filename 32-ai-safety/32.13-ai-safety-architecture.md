### The Layered Control Architecture
A layered control architecture for trustworthy AI agents organizes an agent-enabled process into **five layers**: channel, agent, action contract, platform enforcement, and human-in-the-loop approval. The architecture integrates hybrid reasoning, platform enforcement, and HITL approval.

### Safe-by-Design Governance
"Secure-IAppel" presents a comprehensive Safe-by-Design governance framework for deploying AI assistance in life-critical environments. It enforces **effective Human-in-the-Loop oversight through explicit validation hooks**.

### The Legitimacy Layer (Runtime Governance)
A runtime governance architecture for human oversight in AI-assisted critical decision systems. The architecture evaluates **four governance signals** (uncertainty, impact, and others) to determine whether human oversight is required.

### Meaningful Human Control (MHC)
As General-Purpose AI grows more capable of cross-domain reasoning and multi-agent coordination, an integrated delegation framework is needed for preserving **Meaningful Human Control** in GPAI-enabled human-machine teams.

### Deeper Explanation: Layers, Each With One Job

A defensible AI safety architecture is a chain of independent controls, so no single failure is fatal:

| Layer | Control | Failure it prevents |
|---|---|---|
| Identity | Separate agent principal, scoped per feature | Over-broad privilege |
| Input | Size limits, source allow-lists, sanitisation | Injection, resource exhaustion |
| Prompt structure | Labelled untrusted sections, schema-constrained output | Instruction confusion |
| Capability | Narrow tools, per-call server-side authz, rate limits | Escalation, abuse |
| Validation | Schema + semantic checks, fail closed | Malformed or unsafe actions |
| Approval | Human gate on consequential effects | Irreversible mistakes |
| Sandbox | Disposable environment, egress allow-list | Exfiltration, lateral movement |
| Observability | Prompt/tool/decision logs, evals, alerts | Undetected drift and incidents |

The design principle: **assume the model is compromised and design what it can reach.** That reframing converts a vague worry into a concrete permission and validation exercise.

### Additional Pitfalls
- **One control doing all the work.** A single "guardrail prompt" is not an architecture.
- **No ownership.** AI safety needs an owner and a review cadence like any security surface.
- **Static configuration.** Threats evolve; re-test injection and permission scenarios each release.
- **No incident response.** Define what happens when an agent misbehaves: kill switch, audit, user communication.
- **Compliance theatre.** Documented controls that are not exercised in tests are not controls.

### Real-World Deal-Breakers
- **No layered architecture** → safety depends on a single control. Use defense in depth.
- **No runtime governance** → oversight is static, not adaptive. Evaluate governance signals at runtime.
- **No action contract** → the agent's actions are not constrained by policy. Define the contract explicitly.
- **No platform enforcement** → the agent can bypass controls. Enforce at the platform layer.
