## 32.2 Indirect Prompt Injection (IPI)

### Subtopic Tree
- IPI as the default case in production
- Attack surface: retrieved documents, tool outputs, web pages, emails, invoices
- The low-privilege → high-privilege escalation path
- Mid-document placement and chunking
- Visual injections (images)
- RIPE-II benchmark (97% reach, 94% rank first)
- The "Framing Gap" - surface-level defenses fail

### Why IPI Is Now the Default
Indirect injection dominates production logs. The defensive model most enterprises inherited assumes the user is the potentially hostile party. Access controls, rate limits, and authentication are designed around user identity. **Indirect injection bypasses all of that**.

### The RIPE-II Benchmark (June 2026)
RIPE-II evaluates IPIs under a realistic content-poisoning threat model. It constructs **delimiter-free, position-aware poisoned corpora** across multiple domains and includes both textual and visual injections. Key findings:

- **Poisoned documents can reach the final model context in up to 97% of queries.**
- **They rank first in up to 94% of cases.**
- Retriever and reranker choices substantially shape RAG security exposure.
- **Cosine-based attack scoring can underreport semantic compromise by more than 5×** - lexical or embedding similarity alone is insufficient for evaluating IPI.

This means: **if an attacker can plant a document in your corpus, it will likely be retrieved and ranked first.** The question is not whether it will reach the model, but whether the model will act on it.

### The "Framing Gap" (August 2026)
A tool-using language agent that reads attacker-controlled web content and also holds a confidential value in its context faces an indirect prompt-injection risk. **Surface-level defenses fail** because the attack works through declarative context reframing and implicit file provenance trust.

### The Deeper Risk: Unauthorized Operational Attractors
Within the HibriMind ontology, the core risk of indirect prompt injection is not limited to malicious instructions embedded in external content. The deeper risk is **the conversion of external content into an unauthorized operational attractor capable of redefining the trajectory while appearing locally useful or coherent**. This is a **longitudinal risk** - memory contamination, relational drift, and internal recomposition over time.

### Deeper Explanation: The Attack Surface Is Everything You Ingest

Indirect injection is the realistic attack on AI features because the payload arrives through normal data: a web page you summarise, a support ticket you triage, an email you draft a reply to, a PDF you analyse, a commit message your agent reads, a React comment in a file. The attacker does not need access to your app â€” only to something it reads.

The structural defence is **capability limitation plus egress control**:

- The ingestion pipeline should never hand the model tools it does not need for that task.
- Anything the model proposes must pass a server-side policy check before touching the outside world (send, publish, transfer, delete).
- Content from untrusted sources should be summarised by a constrained call (structured output only) rather than fed into a tool-enabled loop.

### Additional Pitfalls
- **Tool-enabled agents reading untrusted content with write access.** The highest-risk configuration there is; keep ingestion and action in separate steps.
- **Trusting "internal" sources.** Wikis, tickets, and CI logs accept user input.
- **No provenance on retrieved chunks.** Without source attribution you cannot audit which document caused an action.
- **Assuming small content is safe.** A single line is enough to redirect a tool-using system.

### Real-World Deal-Breakers
- **No retrieval hardening** → poisoned documents reach the model context 97% of the time. Filter, validate, and provenance-tag retrieved content.
- **Trusting similarity scores** → cosine similarity underreports semantic compromise by 5×. Use a calibrated LLM-based judge for semantic override detection.
- **No mid-document placement defense** → attackers place payloads in the middle of documents, exploiting chunking and truncation.
- **Ignoring visual injections** → images can carry IPI payloads.
- **No provenance tracking** → you cannot distinguish "content the user typed" from "content the agent retrieved from an attacker-controlled source."
