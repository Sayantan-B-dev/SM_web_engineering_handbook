### Nginx Reverse Proxy (SPA + API)
```nginx
server {
  listen 443 ssl http2;
  server_name app.example.com;

  ssl_certificate /etc/ssl/cert.pem;
  ssl_certificate_key /etc/ssl/key.pem;

  # Static SPA
  location / {
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;
  }

  # API proxy
  location /api/ {
    proxy_pass http://backend:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Rate limiting
  limit_req zone=api burst=20 nodelay;
}
```

### Deeper Explanation: The Proxy Is Where Policies Live

A reverse proxy terminates connections and sits between the internet and your application, which makes it the natural home for cross-cutting policy: TLS, compression, caching, routing, rate limits, request/response header rewriting, and the security header set. Keeping that logic in the proxy rather than in the app means it applies to every deployment and can be changed without a code release.

Frontend-relevant jobs it does that are easy to forget:

- **Compression and caching policy** for static assets, so the app server is not asked for bytes that never change.
- **Path routing** â€” `/api/*` to the backend, everything else to the SPA, with the SPA fallback (`try_files ... /index.html`) so client routing works on deep links and refreshes.
- **Security headers** â€” CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` â€” set once, applied everywhere.
- **Rate limiting and request size limits** as the first line of defence against scraping and accidental loops.
- **Streaming-friendly settings**: disable response buffering so SSE and streamed SSR are delivered incrementally rather than held until completion.

### Extended Example: SPA Fallback, Streaming, And Headers In One Place

```nginx
server {
  listen 443 ssl http2;
  root /usr/share/nginx/html;

  add_header X-Content-Type-Options "nosniff" always;
  add_header Referrer-Policy "strict-origin-when-cross-origin" always;
  add_header Permissions-Policy "camera=(), microphone=(), geolocation=(self)" always;

  # SPA routes: never let a deep link 404 on refresh
  location / {
    try_files $uri $uri/ /index.html;
  }

  # SSE / streamed responses must not be buffered by the proxy
  location /api/stream {
    proxy_pass http://backend:3000;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;
}
```

### Additional Pitfalls
- **SPA fallback missing.** Users hit a 404 on refresh and blame the router; `try_files` belongs in the proxy config.
- **Lossy `X-Forwarded-*`.** Without `X-Forwarded-Proto`, the app thinks it is on HTTP and generates `http://` links or refuses to set `Secure` cookies.
- **Proxy buffering streaming responses.** SSE appears to "arrive all at once" after the stream ends; disable buffering on streaming paths.
- **Security headers left to the framework.** They then differ per route and disappear on error pages; set them at the edge.
- **No body-size limit.** A 2 GB upload request can exhaust memory before your app validates anything.

### Real-World Deal-Breakers
- **No `X-Forwarded-*` headers** → backend sees the proxy's IP, not the client's.
- **No rate limiting** → API abuse.
- **No SSL termination at proxy** → backend handles TLS, adding latency.
- **Still using ingress-nginx in 2026** → unsupported, security risk. Migrate to Gateway API.
