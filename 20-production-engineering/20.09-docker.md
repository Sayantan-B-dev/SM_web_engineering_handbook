### Multi-Stage Dockerfile (React + Vite)
```dockerfile
# Stage 1: Build
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production
FROM nginx:alpine AS runner
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### Next.js Standalone Dockerfile
```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
RUN addgroup -S app && adduser -S app -G app
COPY --from=builder --chown=app:app /app/.next/standalone ./
COPY --from=builder --chown=app:app /app/.next/static ./.next/static
COPY --from=builder --chown=app:app /app/public ./public
USER app
EXPOSE 3000
CMD ["node", "server.js"]
```

### Nginx SPA Config
```nginx
server {
  listen 80;
  location / {
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;  # SPA fallback
  }
  location /api/ {
    proxy_pass http://backend:4000;     # reverse proxy
  }
}
```

---

### Deeper Explanation: Layers, Cache, And Signals

A Docker image is a stack of immutable layers; each `RUN`, `COPY`, and `ADD` creates one. Build speed is therefore a function of **layer ordering**: copy the lockfile and install before copying source, and an edit to a component invalidates only the later layers. Image size is a function of layer *content*: multi-stage builds keep toolchains out of the runtime image entirely.

Two production details that frontend teams get wrong:

1. **Multi-stage for a static build.** The runtime image only needs a web server and the built assets; Node, the package manager, and node_modules never ship.
2. **Signal handling.** PID 1 receives `SIGTERM`; a shell-wrapped process may not forward it, so graceful shutdown hangs and the platform kills the container. Use `exec` form `CMD`, or an init like `tini`/`dumb-init`.

For a plain SPA, an Nginx or Caddy stage serving `dist/` is smaller, faster, and easier to secure than Node. For a Next.js server, use the standalone output mode so the runtime image contains only what is traced as used.

### Extended Example: Multi-Stage Build For A Vite SPA Plus Runtime Config

```dockerfile
# syntax=docker/dockerfile:1
FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile

FROM node:22-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ARG VITE_COMMIT_SHA
RUN pnpm build

FROM nginx:1.27-alpine AS runtime
COPY --from=build /app/dist /usr/share/nginx/html
COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf
# runtime config injected at start, so one image works in every environment
COPY deploy/entrypoint.sh /docker-entrypoint.d/40-runtime-config.sh
RUN chmod +x /docker-entrypoint.d/40-runtime-config.sh

USER nginx
EXPOSE 8080
HEALTHCHECK CMD wget -qO- http://127.0.0.1:8080/healthz || exit 1
STOPSIGNAL SIGTERM
```

### Additional Pitfalls
- **`COPY . .` before installing dependencies.** Every source edit busts the install layer and CI rebuilds `node_modules` from scratch.
- **No `.dockerignore`.** `.git`, `node_modules`, coverage output, and `.env` files inflate the context and can leak secrets into an image.
- **Running as root.** A container escape is much easier; create a non-root user and set `USER`.
- **A shell-form `CMD` that swallows signals.** Use `CMD ["node", "server.js"]`, not `CMD node server.js`.
- **Baking environment-specific values into the image.** Build once, configure at runtime, or you cannot promote the same artifact.

### Real-World Deal-Breakers
- **No multi-stage build** → 1GB image with all dev dependencies. Use multi-stage → ~50MB.
- **`COPY . .` before `npm ci`** → every code change invalidates the dependency cache. Copy package files first.
- **Running as root** → security vulnerability. Always create a non-root user.
- **No `.dockerignore`** → `node_modules` and `.env` copied into the image.
- **No health check endpoint** → orchestrators can't verify container readiness. Add `/api/health`.
- **No SPA fallback** → direct URL access 404s. Configure `try_files $uri /index.html`.
