## 20.20 Observability - Grafana Faro

### Subtopic Tree
- Grafana Faro Web SDK
- Instrumentation (errors, logs, traces, Web Vitals)
- Alloy Collector (telemetry pipeline)
- Loki (logs), Tempo (traces), Mimir (metrics)
- Grafana Cloud Frontend Observability
- Sourcemap deobfuscation
- PII filtering (`beforeSend`)
- Trace propagation (`propagateTraceHeaderCorsUrls`)
- React error boundaries
- `app.version` for release tracking

### Setup
```bash
npm install @grafana/faro-web-sdk @grafana/faro-react
```

```typescript
import { initializeFaro, getWebInstrumentations } from '@grafana/faro-web-sdk';
import { TracingInstrumentation } from '@grafana/faro-web-tracing';

initializeFaro({
  url: 'https://faro-collector.example.com',
  app: {
    name: 'my-app',
    version: process.env.NEXT_PUBLIC_APP_VERSION,
  },
  instrumentations: [
    ...getWebInstrumentations(),
    new TracingInstrumentation(),
  ],
  beforeSend: (item) => {
    // PII filtering
    if (item.meta?.user?.email) item.meta.user.email = '[REDACTED]';
    return item;
  },
});
```

### Critical Configuration Checklist
> "Check that you have these configured: `beforeSend` PII filtering (URLs and console output may contain tokens), `propagateTraceHeaderCorsUrls` (without this, browser traces never connect to backend spans), `paused on localhost`, `app.version` (filter errors by deploy), Error boundary (catches React errors)."

### Real-World Deal-Breakers
- **No `beforeSend` PII filter** → user emails, tokens, and FNRs logged to observability stores.
- **No `propagateTraceHeaderCorsUrls`** → browser traces never connect to backend; you have two disconnected halves.
- **No `app.version`** → errors can't be filtered by deploy; you can't tell if a new deploy caused a spike.
- **No sourcemap upload** → stack traces are minified and useless.
- **No error boundary** → React rendering errors are silently lost.
