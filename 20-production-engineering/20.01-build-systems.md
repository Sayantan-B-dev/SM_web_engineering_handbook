### The 2026 Build Tool Landscape

| Tool | Type | Best for | Key trait |
|------|------|----------|-----------|
| **Vite** | Dev (esbuild) + Prod (Rollup/Rolldown) | Any framework | Fastest dev server start, flexible |
| **Turbopack** | Rust-based full-stack | Next.js 15+ | 2.4× faster dev start, HMR < 100ms |
| **Rspack** | Rust-based Webpack drop-in | Webpack migration | Webpack compatibility with Rust speed |
| **Rolldown** | Rust-based Rollup | Vite production builds | 4.4× faster than Turbopack |
| **esbuild** | Go-based | Maximum speed | Fastest raw build tool |

**Benchmark (33-route app):** Vite 8 + Rolldown: **1.67s** production build. Turbopack (Next.js 16): **7.38s**.

### Tree Shaking - The Four Conditions
Tree shaking only works when **all four** are met:

1. **ES Module syntax** - `import`/`export`, not `require`/`module.exports`.
2. **No side effects declared** - `"sideEffects": false` in `package.json` or precise list.
3. **Production mode build** - physical removal happens in minification.
4. **Named imports** - `import { debounce }` not `import _ from 'lodash'`.

```typescript
// ❌ Breaks tree shaking
import _ from 'lodash';
import * as utils from './utils';

// ✅ Tree-shakeable
import { debounce } from 'lodash-es';
import { formatDate } from './utils';
```

### Deeper Explanation: Bundlers Solve A Graph Problem, Runtimes Consume The Output

A build system does four separate jobs, and conflating them is why build configs become unmaintainable: **resolve** the module graph (aliases, workspace packages, conditions), **transform** each module (TS â†’ JS, JSX â†’ JS, CSS modules), **optimise** the graph (tree shaking, minification, code splitting, compression), and **emit** assets with a manifest that maps logical names to hashed filenames.

The modern frontier is not "which bundler is fastest" but which layer runs the transform. In 2026:

| Layer | Examples | Trade-off |
|---|---|---|
| Native bundler in Go/Rust | Turbopack, Rspack, esbuild, Rolldown | 10-100x faster cold start, smaller plugin ecosystem |
| JS bundler with persistent cache | Vite 6+, webpack 5 with filesystem cache | Richest plugins, watch-mode churn |
| Native dev server, bundler on demand | Vite dev, Next dev | Instant HMR, production build stays the cost centre |

Practical rule: measure the *cold CI build*, not local HMR. Reducing a 6-minute CI build to 90 seconds is worth more engineer-hours per week than shaving HMR by 200 ms.

### Extended Example: Bundle Budget As A Build Failure

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  build: {
    target: 'es2022',
    sourcemap: true,               // upload to the error monitor, do not ship publicly
    manifest: true,                // stable asset names for the CDN and SSR
    rollupOptions: {
      output: {
        manualChunks(id) {
          if (id.includes('node_modules/react')) return 'react';
          if (id.includes('node_modules/@tanstack')) return 'data';
          return undefined;        // let Rollup decide the rest
        },
      },
    },
  },
  plugins: [visualizer({ filename: 'stats.html', gzipSize: true })],
});
```

### Additional Pitfalls
- **Optimising the wrong build.** Local dev speed is a comfort metric; CI cold build time and shipped bytes are business metrics.
- **Shipping public sourcemaps.** They expose your source to anyone; upload them to the error monitor and keep them private.
- **`manualChunks` by folder.** Package-based chunking beats path-based chunking, or one big shared vendor chunk defeats caching granularity.
- **Rebuilding assets on every deploy without content hashes.** `app.js` behind a CDN cache means users get yesterday's code with today's HTML.
- **Ignoring the lockfile in CI.** `npm install` instead of `npm ci` lets dependency drift into a deploy.

### Real-World Deal-Breakers
- **CommonJS dependencies** → cannot be tree-shaken; entire module ships. Use ESM alternatives (`lodash-es` not `lodash`).
- **No `sideEffects: false`** → bundler conservatively includes everything.
- **Dev/prod mismatch** → Vite's esbuild dev vs Rollup prod can produce different output. Turbopack avoids this by using the same module graph for both.
- **No bundle analysis** → a single bad import adds 500KB silently.
- **No build caching in CI** → rebuilding everything on every push. Use Turborepo remote cache or GitHub Actions cache.
