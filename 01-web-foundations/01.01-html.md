## 1.1 HTML

### Syntax & Core Concepts
Every HTML element follows the pattern: `<tag attribute="value">content</tag>`. Attributes belong in the opening tag and consist of a name and value. Tags should be written in lowercase for consistency and readability.

```html
<!-- Anatomy of an element -->
<a href="https://example.com" target="_blank" rel="noopener">Visit Site</a>
<!-- tag  attribute  value                                    content -->
```

### Real-World Examples & Tricks
- **`<picture>` for art direction**: Serve different crops for mobile vs desktop.
```html
<picture>
  <source media="(min-width: 800px)" srcset="hero-wide.avif" type="image/avif">
  <source media="(min-width: 400px)" srcset="hero-square.avif" type="image/avif">
  <img src="hero-fallback.jpg" alt="Team collaborating" loading="lazy">
</picture>
```
- **`loading="lazy"`** on images and iframes defers offscreen loading, directly improving LCP.
- **`data-*` attributes** for JS hooks without polluting classes: `document.querySelector('[data-user-id="42"]')`.
- **`<template>`** for inert DOM that's cloned via JS — zero initial render cost.
- **`<dialog>`** for native modals with built-in focus trapping, ESC-to-close, and backdrop.

### Real-World Deal-Breakers
- **Missing `alt` on images** → fails WCAG 1.1.1, breaks screen reader users, hurts SEO.
- **Multiple `<h1>` tags** → confuses search engines. Use one H1, then H2 → H3 in order.
- **Div soup** (`<div class="header">` instead of `<header>`) → loses all semantic meaning for AT and crawlers.
- **Unclosed tags** → browser auto-corrects unpredictably; your DOM tree may not match your intent.
- **No `lang` attribute on `<html>`** → screen readers may pronounce content in the wrong language.
