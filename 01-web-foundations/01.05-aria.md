## 1.5 ARIA

### Subtopic Tree
- Roles (`role="button"`, `role="dialog"`, `role="navigation"`)
- States (`aria-expanded`, `aria-checked`, `aria-disabled`, `aria-hidden`)
- Properties (`aria-label`, `aria-labelledby`, `aria-describedby`, `aria-controls`)
- Live regions (`aria-live="polite"`, `aria-live="assertive"`, `role="alert"`)
- Landmark roles vs native landmarks
- ARIA authoring practices (APG)
- When NOT to use ARIA

### The Three Categories
WAI-ARIA divides semantics into **roles** (what an element is), **states** (dynamic conditions like expanded/collapsed), and **properties** (supplemental descriptive information like labels and relationships).

### Syntax Examples
```html
<!-- Role + State + Property -->
<button role="switch"
        aria-checked="true"
        aria-label="Dark mode">
</button>

<!-- Custom tablist (no native HTML equivalent) -->
<div role="tablist" aria-label="Settings tabs">
  <button role="tab" aria-selected="true" aria-controls="panel-1" id="tab-1">
    General
  </button>
  <button role="tab" aria-selected="false" aria-controls="panel-2" id="tab-2">
    Security
  </button>
</div>
<div role="tabpanel" id="panel-1" aria-labelledby="tab-1">...</div>

<!-- Live region for search results -->
<div aria-live="polite" aria-atomic="true">
  <!-- Updated dynamically with result count -->
</div>
```

### The First Rule of ARIA
**Don't use ARIA if native HTML can do the job.** Prefer native elements and attributes whenever they provide necessary semantics and keyboard behavior. Using ARIA incorrectly produces more accessibility errors than not using it at all.

### Real-World Tricks
- **`aria-expanded`** on accordion triggers → screen readers announce "collapsed" or "expanded".
- **`aria-hidden="true"`** on decorative icons → removes from accessibility tree. **Never** put it on focusable elements.
- **`aria-label` vs `aria-labelledby`**: `label` for short strings; `labelledby` to reference visible text by ID (preferred for i18n).
- **`role="status"`** → implicit `aria-live="polite"`, perfect for status messages.
- **`aria-controls`** → programmatically associate a control with the element it affects.

### Real-World Deal-Breakers
- **`role="button"` on a `<div>`** → must add `tabindex="0"`, keyboard handlers for Enter and Space, and `aria-pressed` if toggleable. Just use `<button>`.
- **`aria-hidden="true"` on a focusable element** → element is focusable but invisible to AT — a serious violation.
- **Overriding native semantics** → `<h2 role="button">` confuses AT. Don't do it unless you have an extremely specific reason.
- **ARIA changes announcements, not behavior** → `role="dialog"` doesn't trap focus or close on ESC; you must implement that.
- **Missing required ARIA attributes** → e.g., `role="checkbox"` without `aria-checked` is invalid.
