## 1.2 Semantic HTML

### Subtopic Tree
- Structural elements: `<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`
- Content elements: `<article>`, `<section>`, `<figure>`, `<figcaption>`, `<time>`, `<address>`
- Interactive: `<button>` vs `<a>`, `<details>`/`<summary>`
- Document outline algorithm (deprecated but conceptual)
- Landmark roles (implicit ARIA from semantics)
- When NOT to use semantic elements

### Syntax & Examples
Semantic HTML uses tags that describe **what the content is**, not how it looks.

```html
<!-- ❌ Non-semantic -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="content">...</div>

<!-- ✅ Semantic -->
<header>
  <nav aria-label="Main navigation">...</nav>
</header>
<main>
  <article>
    <h1>Article Title</h1>
    <section aria-labelledby="comments-heading">
      <h2 id="comments-heading">Comments</h2>
    </section>
  </article>
  <aside>Related links</aside>
</main>
<footer>© 2026</footer>
```

### Real-World Tricks
- **`<article>` vs `<section>`**: Use `<article>` if content could stand alone in an RSS feed. Use `<section>` for thematic grouping that needs a heading.
- **`<button>` vs `<a>`**: `<a>` for navigation to a URL; `<button>` for actions (submit, toggle, open modal). Using `<div role="button">` is an anti-pattern.
- **`<time datetime="2026-09-10">`**: Machine-readable dates improve event scraping and accessibility.

### Real-World Deal-Breakers
- **Using `<section>` for everything** → if it doesn't have a heading, it's probably a `<div>`.
- **`<article>` nested in another `<article>`** when the inner content isn't independently distributable → confuses content extraction.
- **Putting `<main>` inside `<article>`** → `<main>` must be unique per page and not nested in article/section/aside.
- **`<nav>` for every link list** → only major navigation blocks. Footer links don't need `<nav>` unless it's a substantial navigation set.
