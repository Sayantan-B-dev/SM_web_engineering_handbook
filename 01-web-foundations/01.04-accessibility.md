## 1.4 Accessibility

### Subtopic Tree
- WCAG principles (POUR: Perceivable, Operable, Understandable, Robust)

### The POUR Framework
WCAG guidelines are organized into four principles: **Perceivable** (content can be perceived via multiple senses), **Operable** (navigation via keyboard, mouse, assistive tech), **Understandable** (clear, logical content), and **Robust** (works across browsers and AT). Level AA is the widely accepted legal and practical standard.

### Key Implementation Areas
- **Semantic HTML** → provides free accessibility (landmarks, roles, keyboard behavior).
- **ARIA attributes** → enhance dynamic content and complex widgets.
- **Color contrast** → 4.5:1 for normal text, 3:1 for large text and UI components.
- **Keyboard navigation** → all interactive elements reachable and operable via keyboard; visible focus indicators.
- **Accessible forms** → proper labels, error identification, logical tab order.
- **Text alternatives** → alt text, transcripts, captions.

### Real-World Testing Tools
- **Screen readers**: NVDA (Windows), VoiceOver (macOS/iOS), JAWS (Windows).
- **Automated**: axe DevTools, Lighthouse, WAVE, Pa11y.
- **Manual**: Tab through the entire page; verify focus visibility; zoom to 200%; navigate with screen reader only.

### Real-World Deal-Breakers
- **`outline: none` on focus** → keyboard users lose track of position. Use `:focus-visible` to style without removing.
- **Color as sole information carrier** → "red means error" fails for colorblind users. Add icons/text.
- **Carousel auto-play without pause** → violates WCAG 2.2.2 (Pause, Stop, Hide).
- **Custom components without keyboard support** → e.g., a `<div>` dropdown that only responds to mouse clicks.
- **Placeholder-only labels** → disappears on typing; not announced as a label by AT.
