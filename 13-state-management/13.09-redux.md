### Core Concepts
```javascript
// Actions
const increment = () => ({ type: 'counter/increment' });

// Reducer
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case 'counter/increment':
      return { value: state.value + 1 };
    default:
      return state;
  }
}

// Store
const store = createStore(counterReducer);

// Usage with hooks
function Counter() {
  const count = useSelector(state => state.counter.value);
  const dispatch = useDispatch();
  return <button onClick={() => dispatch(increment())}>{count}</button>;
}
```

### When Redux Fits
- **Large, complex app state** with many interacting pieces.
- **Time-travel debugging** is valuable (undo/redo).
- **Middleware-heavy** workflows (analytics, logging, sagas).
- **Team familiarity** - Redux is well-known.
- **Server state is separate** - use React Query for server, Redux for client.

### Real-World Deal-Breakers
- **Redux for server state** → use React Query.
- **Redux for local UI state** → use `useState`.
- **Plain Redux without Toolkit** → too much boilerplate. Use Redux Toolkit.
- **Over-normalizing** → stores become complex entity graphs; often overkill.
- **`useSelector` returning new objects** → re-renders on every state change.
