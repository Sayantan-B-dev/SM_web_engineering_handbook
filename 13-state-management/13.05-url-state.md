## 13.5 URL State

### Subtopic Tree
- Definition: state encoded in the URL
- Query params, path params, hash
- Shareable, bookmarkable, back-button-friendly
- Search filters, pagination, tabs
- Tools: `useSearchParams`, `nuqs`, TanStack Router

### When to Use URL State
- **Search queries** (`?q=react`)
- **Filters** (`?category=books&sort=price`)
- **Pagination** (`?page=2`)
- **Tabs** (`?tab=settings`)
- **Modal state** (`?modal=login`)
- **Any state users might want to share or bookmark**

### Example
```jsx
'use client';
import { useSearchParams, useRouter } from 'next/navigation';

function SearchPage() {
  const searchParams = useSearchParams();
  const router = useRouter();
  const query = searchParams.get('q') ?? '';

  function handleChange(e) {
    const params = new URLSearchParams(searchParams);
    params.set('q', e.target.value);
    router.replace(`/search?${params}`);
  }

  return <input value={query} onChange={handleChange} />;
}
```

### `nuqs` (Type-Safe URL State)
```tsx
import { useQueryState } from 'nuqs';

function SearchPage() {
  const [query, setQuery] = useQueryState('q', { defaultValue: '' });
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}
```

### Real-World Deal-Breakers
- **Filters in `useState` instead of URL** → users can't share filtered views, back button breaks.
- **URL state without defaults** → `?page=undefined` errors. Always provide defaults.
- **Too much state in URL** → ugly URLs, hard to reason about.
- **Replacing instead of pushing history** → back button behaves unexpectedly.
