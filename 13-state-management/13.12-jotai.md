## 13.12 Jotai

### Subtopic Tree
- Atomic state model
- Atoms (primitive + derived)
- `useAtom`, `useAtomValue`, `useSetAtom`
- No providers needed (or optional)
- Bottom-up composition
- Async atoms
- Integration with Suspense

### Basic Atoms
```typescript
import { atom, useAtom } from 'jotai';

const countAtom = atom(0);

function Counter() {
  const [count, setCount] = useAtom(countAtom);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

### Derived Atoms
```typescript
const firstNameAtom = atom('');
const lastNameAtom = atom('');
const fullNameAtom = atom((get) => `${get(firstNameAtom)} ${get(lastNameAtom)}`);

function Display() {
  const [fullName] = useAtom(fullNameAtom);
  return <p>{fullName}</p>;
}
```

### Async Atoms
```typescript
const userAtom = atom(async () => {
  const res = await fetch('/api/user');
  return res.json();
});

function User() {
  const [user] = useAtom(userAtom); // throws Promise for Suspense
  return <p>{user.name}</p>;
}
```

### Real-World Deal-Breakers
- **Too many small atoms** → hard to track.
- **Assuming atoms replace server state** → Jotai is for client state; use React Query for server.
- **Overusing derived atoms for cheap computations** → recomputes unnecessarily.
