## 13.2 Derived State

### Subtopic Tree
- Definition: computed from other state/props
- Anti-pattern: storing derived in state
- Compute during render
- `useMemo` for expensive derivations
- Sync issues with stored derived state
- React Compiler's role

### The Rule
**If you can compute it from existing state/props, don't store it.**

```jsx
// ❌ Storing derived state - sync bugs
function NameForm() {
  const [first, setFirst] = useState('');
  const [last, setLast] = useState('');
  const [full, setFull] = useState('');

  useEffect(() => {
    setFull(`${first} ${last}`);
  }, [first, last]);
}

// ✅ Compute during render
function NameForm() {
  const [first, setFirst] = useState('');
  const [last, setLast] = useState('');
  const full = `${first} ${last}`; // always in sync, no extra render
}
```

### Expensive Derivations
```jsx
const sorted = useMemo(() => [...items].sort(cmp), [items]);
```

Use `useMemo` only when the computation is measurably expensive. React Compiler auto-memoizes most of these.

### Real-World Deal-Breakers
- **Duplicate state for "convenience"** → sync bugs, stale UI.
- **`useEffect` to sync two states** → extra render, potential flicker.
- **Filtering in state instead of render** → stale filter when source changes.
- **Memoizing trivial derived values** → overhead without benefit.
