## 13.3 Global State

### Subtopic Tree

### When You Actually Need Global State
Very few things are genuinely global:
- **Theme** (dark/light)
- **Locale** (i18n)
- **Auth user** (current user)
- **Cart** (e-commerce)
- **Feature flags**
- **Toast/notification queue**

**Everything else is usually local, server, or URL state.**

### Anti-Pattern: Globalizing Local State
```jsx
// ❌ Modal state in Redux
dispatch(openModal());

// ✅ Local state
const [open, setOpen] = useState(false);
```

### Real-World Deal-Breakers
- **Global state for everything** → hard to track, breaks modularity, causes unnecessary re-renders.
- **Global state for server data** → duplicate caches, stale data. Use React Query / SWR.
- **Multiple global stores** → conflicts, unclear ownership.
- **Global state without devtools** → debugging becomes guesswork.
