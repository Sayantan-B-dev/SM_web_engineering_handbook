### What Cache State Is
A client-side copy of data that lives on the server. It's not authoritative - the server is. It's a performance optimization.

### Cache Lifecycle
```jsx
useQuery({
  queryKey: ['user', id],
  queryFn: fetchUser,
  staleTime: 60_000,      // consider fresh for 1 minute
  gcTime: 5 * 60_000,     // keep in memory for 5 minutes after last use
  refetchOnWindowFocus: true,
  refetchOnMount: true,
});
```

### Optimistic Updates
```jsx
const mutation = useMutation({
  mutationFn: updateTodo,
  onMutate: async (newTodo) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] });
    const previous = queryClient.getQueryData(['todos']);
    queryClient.setQueryData(['todos'], old => [...old, newTodo]);
    return { previous };
  },
  onError: (err, newTodo, context) => {
    queryClient.setQueryData(['todos'], context.previous);
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] });
  },
});
```

### Real-World Deal-Breakers
- **Treating cache as source of truth** → cache can be stale; server is truth.
- **No `staleTime`** → refetches on every mount, wasting bandwidth.
- **No cache invalidation after mutation** → UI shows stale data.
- **Optimistic updates without rollback** → broken UI on error.
