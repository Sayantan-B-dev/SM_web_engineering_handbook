### What a Speaker Directory Is
A speaker directory is a **searchable index of community members who have spoken at React Kolkata events**. It answers: **"Who has spoken before, on what topic, and who wants to speak next?"**

The directory is both a **visibility mechanism** (speakers get credit for their talks) and a **planning tool** (organizers can find speakers for upcoming events).

```text
Speaker Directory Data Model:
─────────────────────────────────
member_id: uuid
talks: Talk[]
  - title: string
  - event: string (June 2026 Online Meetup)
  - date: timestamp
  - recording_url: string
  - slide_url: string
  - talk_type: enum (lightning, full, workshop)
  - topic_tags: string[] (React Query, Observability, Scaling)
availability: enum (open_to_speaking, open_to_mentoring_speakers, not_available)
preferred_formats: enum[] (lightning, full, workshop, panel)
```

### Speaker Pipeline: From Lightning Talk to Full Talk
```
Community member
  → Lightning talk (5 min)
    → Full talk (20-30 min)
      → Conference talk (React Nexus, React India)
        → Mentor for new speakers
```

The speaker directory makes this pipeline **visible and navigable**. A first-time speaker can see who has walked the path before them and who is available to mentor.

---

### Deeper Explanation: Speakers Need Evidence, Organisers Need Reliability

A speaker directory serves two audiences: organisers looking for someone on a topic with a track record, and speakers wanting visibility. The fields that make it useful are those that predict a good talk: topics (bounded tags), talk history with links to recordings or slides, past venues, language(s), and willingness (in person / remote / emergency backup).

```ts
type Speaker = {
  id: string;
  name: string;
  topics: string[];                       // e.g. 'react', 'testing', 'accessibility'
  talks: Array<{ title: string; event: string; year: number; videoUrl?: string; slidesUrl?: string }>;
  formats: Array<'lightning' | 'talk' | 'workshop'>;
  languages: string[];
  travel: { inPerson: boolean; remote: boolean; emergencyBackup: boolean };
  contact: { preferredChannel: 'email' | 'dm'; value: string };   // never public
};
```

The organiser workflow this enables: filter by topic and availability, contact through the platform (keeping emails private), and record an outcome (booked / declined) so the same request is not repeated.

### Additional Pitfalls
- **No evidence of speaking quality.** Topic lists alone are weak signals; require at least one link.
- **Contact details exposed publicly.** Spam risk; keep contact behind the platform.
- **No availability state.** Organisers waste time asking speakers who are unavailable.
- **Free-text topics.** Filtering breaks; use the shared vocabulary from other modules.
- **Stale talk history.** Encourage updates after each event and show recency.

### Real-World Deal-Breakers
- **No speaker directory** → the same speakers speak at every meetup because organizers don't know who else is available.
- **No talk history** → speakers don't get credit for past talks. Their contribution is invisible.
- **No recording archive** → talks happen and disappear. No one can watch them later.
- **No speaker mentorship** → first-time speakers have no path. They don't know who to ask for help.
