### What a Mentor Directory Is
A mentor directory is a **searchable index of community members who have volunteered to mentor others**. It answers: **"Who can help me with X?"**

React Kolkata's mentorship model already exists in Project Parbon, where top 3 finalists receive **1 month of mentorship from GSoC contributors and industry leaders**. The directory extends this model to the entire community, not just Project Parbon finalists.

### Mentorship Formats

| Format | Description | Best for |
|--------|-------------|----------|
| **1:1 mentoring** | Regular one-on-one sessions | Career guidance, deep technical growth |
| **Group mentoring** | Mentor works with a small group | Learning from peers' questions |
| **Project-based** | Mentor guides a specific project | Project Parbon, open source contribution |
| **Code review** | Mentor reviews code and provides feedback | Skill refinement, best practices |

### Mentor Matching
```text
Mentee input:
  - Goal: "I want to contribute to open source"
  - Current skill: "Intermediate React, no open source experience"
  - Time commitment: "2 hours per week"

Matching logic:
  - Find mentors with expertise: "open source"
  - Filter by availability: "open to mentoring"
  - Match time commitment: "2 hours per week"
  - Return top 3 matches with mutual opt-in
```

---

### Deeper Explanation: Mentorship Matching Is About Scope, Not Prestige

A mentor directory works when it captures what mentors will actually do: which topics they will help with (career, code review, system design, interviews), how much time (30 minutes fortnightly), the format (async chat, calls), the level of mentee (absolute beginner to mid-level), and how many slots are open. A directory without capacity information produces frustrated mentees.

```ts
type Mentor = {
  id: string;
  topics: Array<'frontend' | 'career' | 'interviews' | 'system-design' | 'open-source'>;
  capacity: { slotsOpen: number; cadence: 'weekly' | 'fortnightly' | 'monthly'; minutes: number };
  format: Array<'async' | 'call'>;
  menteeLevel: Array<'beginner' | 'intermediate'>;
  languages: string[];
  status: 'accepting' | 'paused';
};
```

### Additional Pitfalls
- **No capacity or status.** Requests arrive indefinitely; mentors burn out and disappear.
- **No expectations written down.** Both sides assume different commitments and drift apart.
- **Matching only on topic.** Time zone, language, and cadence matter as much.
- **No feedback loop.** Remove or pause inactive mentors after a period of no activity.
- **Request spam.** Rate-limit requests per mentee and require a short application note.

### Real-World Deal-Breakers
- **No mentor directory** → mentorship only happens through informal networks. New members don't know who to ask.
- **No matching** → mentees are matched randomly. Neither party gets value.
- **No mentor capacity limits** → mentors burn out from too many mentees.
- **No feedback loop** → no one knows if the mentorship is working.
