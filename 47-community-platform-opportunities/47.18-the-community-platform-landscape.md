### The Core Mental Model
A community platform is not a website. It is **persistent infrastructure for a community's most valuable assets: its people, their contributions, and the connections between them**. Meetups happen monthly. Platform value accrues daily.

The 2026 reality: React Kolkata has a LinkedIn page with **11,064 followers**, a WhatsApp community, a GitHub repository with **22 stars and 45 forks**, and a Luma event calendar. Each of these is a fragment. **The platform opportunity is integration** - one identity, one profile, one place where a developer's entire React Kolkata journey lives.

### Deeper Explanation: Platforms Are Products With A Trust Problem

A community platform (directories, archives, matchmaking, newsletters) is a product whose value is entirely derived from participation: an empty directory is worse than none. That produces three engineering requirements that differ from normal product work: **low friction to contribute** (a profile, a talk, a project entry), **visible value for contributing** (discovery, introductions, recognition), and **trustworthy curation** (verified identity, moderation, and clear data policies).

The technical consequences follow: authentication that respects privacy, profile data that is user-owned and exportable, search that works without a huge corpus, and moderation/reporting paths from day one. Build the smallest loop that produces value (a single directory with a working "find a mentor" flow) before adding more modules.

### Additional Pitfalls
- **Building modules before the loop works.** Ten half-empty features lose to one populated one.
- **No moderation or verification.** Spam and impersonation destroy trust fast.
- **Data that cannot be exported.** Contributors are contributing their own information; give it back.
- **No privacy model.** Public profiles need granular visibility controls.
- **No reason to return.** Without new content or a notification loop, participation decays.

### Real-World Deal-Breakers
- **Treating the platform as a website** → it becomes a brochure, not infrastructure. The value is in the **data model**: who contributed what, who mentored whom, who spoke when.
- **Building everything from scratch** → React Kolkata already uses Luma, WhatsApp, and GitHub. The platform integrates, not replaces.
- **No contribution graph** → a developer's React Kolkata history is invisible. They can't prove they spoke, mentored, or contributed.
- **Ignoring the contributor-to-maintainer pipeline** → GitHub's Octoverse report names a widening **"contributor-to-maintainer gap,"** worsened by **"AI slop"** - low-quality, auto-generated pull requests that consume maintainer time without adding real value. The platform must surface **verified** contributions, not AI-generated noise.
