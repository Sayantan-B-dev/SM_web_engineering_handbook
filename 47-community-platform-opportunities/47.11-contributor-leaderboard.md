## 47.11 Contributor Leaderboard

### Subtopic Tree
- Definition: ranked list of community members by contribution
- Contribution types (talks, mentoring, open source, event organization)
- Point system (different contributions have different weights)
- Seasonal leaderboards (quarterly, annual)
- Recognition (top contributors get badges, goodies)
- Integration with community badges
- The AI slop problem: verified contributions only

### What a Contributor Leaderboard Is
A contributor leaderboard is a **ranked list of community members by contribution**. It answers: **"Who is contributing the most to this community?"**

The leaderboard is a **motivation mechanism**. It makes contribution visible and rewards the people who make the community work.

### Point System

| Contribution | Points |
|-------------|--------|
| Lightning talk | 10 |
| Full talk | 25 |
| Workshop facilitator | 30 |
| Mentoring (per session) | 15 |
| Open source PR merged | 20 |
| Event organization | 50 |
| Project Parbon submission | 15 |
| Project Parbon finalist | 30 |
| Project Parbon winner | 50 |

### Seasonal Leaderboards
- **Quarterly leaderboard** - top 10 contributors each quarter
- **Annual leaderboard** - top 3 contributors of the year
- **All-time leaderboard** - the community's most consistent contributors

### The AI Slop Problem
The leaderboard must only count **verified contributions**. AI-generated PRs, spam issues, and low-effort contributions must be filtered out. A contribution is verified when:
- A talk has a recording or slide deck
- A mentoring session is confirmed by both parties
- A PR is merged by a maintainer
- A Project Parbon submission passes the evaluation phase

---

### Deeper Explanation: Recognition Mechanics Are Fragile

A leaderboard can motivate a minority and demotivate the majority; its design determines which. Contributions that count should be broad (answers, talks, reviews, docs, mentoring, event help) rather than only code, and the metric should reward consistency rather than volume to avoid incentivising spam or gatekeeping.

Safer alternatives to a ranked list: monthly cohorts ("contributors this month"), milestone badges, and per-area highlights. If you do rank, keep it to a short window (a season), make the rules public, and never let rank confer privileges.

### Additional Pitfalls
- **Code-only metrics.** They erase the work that keeps communities running.
- **Permanent all-time rankings.** Early joiners dominate forever and newcomers see no path.
- **Gameable counters.** Posting many low-value comments wins; weight by impact or use curation.
- **Rank as status.** It creates hierarchies and politics; keep recognition distinct from authority.
- **No explanation.** Unexplained scores feel arbitrary and generate disputes.

### Real-World Deal-Breakers
- **No leaderboard** → contribution is invisible. There's no incentive to contribute beyond altruism.
- **Unverified contributions** → AI slop inflates the leaderboard. The ranking becomes meaningless.
- **No seasonal reset** → early contributors dominate forever. New contributors can't compete.
- **No recognition** → the leaderboard exists but no one sees it. Recognition drives participation.
