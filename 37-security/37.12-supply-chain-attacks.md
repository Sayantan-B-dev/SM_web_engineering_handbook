## Supply Chain Attacks

### Subtopic Tree
- Attack surfaces: npm packages, postinstall scripts, CI actions, build tooling, CDNs
- Typosquatting and dependency confusion
- Compromised maintainer accounts and malicious releases
- Postinstall script execution
- Lockfile integrity and `integrity` hashes
- Provenance and attestation (SLSA, npm provenance)
- Pinning CI actions by SHA
- Build reproducibility and least-privilege CI tokens

### The Mental Model
A supply-chain attack means someone else's compromise becomes your incident â€” malicious code that reaches production through a dependency, an action, or a build step. Most incidents share one enabling factor: **code from an untrusted source was executed with your privileges** (a postinstall script, a CI action with a write token, a CDN-hosted script).

```yaml
# Harden the pipeline: least privilege, pinned actions, no lifecycle scripts by default
permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4            # pin to a full SHA in security-critical repos
      # ignore install scripts unless a package is explicitly allow-listed
      - run: pnpm install --frozen-lockfile --ignore-scripts
      - run: pnpm rebuild esbuild sharp      # rebuild only what genuinely needs native binaries
```

### Real-World Deal-Breakers
- **`--ignore-scripts` never enabled.** Every dependency's postinstall runs with your build credentials.
- **CI actions pinned by tag.** Tags are mutable; a compromised action version reaches your secrets.
- **`write-all` tokens.** Least privilege per job, and never expose secrets to fork PRs (`pull_request_target`).
- **No lockfile integrity checks.** A tampered registry response can slip in a different artifact.
- **New dependencies added without review.** Most supply-chain entries arrive via an unreviewed `pnpm add`.
- **No provenance or signature verification.** Where available, verify attestations in CI (npm provenance, Sigstore).
- **Self-hosted third-party scripts in the page.** A CDN compromise is a browser-side supply-chain attack; self-host or pin with SRI.
