### The Mental Model
CORS is a browser enforcement mechanism that decides whether JavaScript on origin A may **read** a response from origin B. The server still receives the request regardless (for simple requests), so CORS is not access control: it protects users from a hostile page reading their data, while actual authorisation protects the API from *everyone*.

```ts
// Server-side CORS with an explicit allow-list and correct preflight handling
const ALLOWED = new Set(['https://app.example.com', 'https://preview.example.com']);

function cors(req: Request, res: Response) {
  const origin = req.headers.get('origin');
  if (origin && ALLOWED.has(origin)) {
    res.setHeader('Access-Control-Allow-Origin', origin);       // echo, never '*', when credentials are used
    res.setHeader('Access-Control-Allow-Credentials', 'true');
    res.setHeader('Vary', 'Origin');                            // critical for caches
    res.setHeader('Access-Control-Allow-Methods', 'GET,POST,PATCH,DELETE,OPTIONS');
    res.setHeader('Access-Control-Allow-Headers', 'content-type,authorization,x-request-id');
    res.setHeader('Access-Control-Max-Age', '600');             // cache the preflight
  }
  if (req.method === 'OPTIONS') return res.status(204).end();
}
```

### Preflight In One Sentence
If a request is "non-simple" (custom headers, methods other than GET/HEAD/POST, or a JSON content type with a custom header), the browser first sends `OPTIONS`; the response must explicitly permit the method and headers, otherwise the real request is never sent.

### Real-World Deal-Breakers
- **`Access-Control-Allow-Origin: *` with credentials.** Browsers refuse it; loosening it further (reflecting any origin) is equivalent to no protection.
- **Missing `Vary: Origin`.** A CDN caches one origin's response and serves it to another, producing bizarre intermittent failures.
- **Preflight not cached.** Every API call costs two round trips; set `Access-Control-Max-Age`.
- **Confusing CORS with auth.** `curl` ignores CORS entirely; API authorisation is separate and mandatory.
- **Wildcard methods/headers.** Permissive configuration enlarges the surface; allow only what the client sends.
- **CORS handled per route.** It must apply consistently, including on error responses, or the browser hides your error messages.
