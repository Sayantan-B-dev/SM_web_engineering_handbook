## Secret Exposure

### Subtopic Tree
- Where secrets leak: bundles, sourcemaps, logs, error reports, git history, screenshots
- Build-time inlining and `NEXT_PUBLIC_`/`VITE_` prefixes
- Environment variable hygiene and per-environment keys

- Rotation as the only reliable remediation
- Least privilege and short-lived credentials
- OIDC federation instead of static cloud keys
- Client-side "publishable" keys and their limits

### The Mental Model
Two rules cover most of the discipline: **anything shipped to a browser is public**, and **anything committed is permanent**. So secrets belong on the server, fetched at execution time, scoped narrowly, and rotated on a schedule rather than only after an incident.

```ts
// WRONG: inlined into the client bundle, readable by anyone
const key = import.meta.env.VITE_STRIPE_SECRET_KEY;

// RIGHT: the browser never sees a secret; the server mints a scoped, short-lived capability
// POST /api/checkout-session
export async function POST() {
  const session = await stripe.checkout.sessions.create({
    line_items: await cartItems(),
    mode: 'payment',
    success_url: `${origin}/done`,
  });
  return Response.json({ url: session.url });   // only the session URL crosses the boundary
}
```

### Real-World Deal-Breakers
- **Secrets with client prefixes.** `NEXT_PUBLIC_`/`VITE_` values are inlined at build time; prefixes document exposure, they do not prevent it.
- **Committed `.env` files and hard-coded fallbacks.** `process.env.KEY || 'sk_live_...'` ends up in history forever.
- **Secrets in sourcemaps or error payloads.** Error monitors receive request headers and bodies; scrub before send.
- **One key for all environments.** A staging leak reaches production data; issue per-environment credentials.
- **Rotation only after detection.** Any secret that might have leaked should be rotated immediately â€” history rewrites do not un-leak it.
- **Static cloud keys in CI.** Use OIDC federation to obtain short-lived credentials instead.
- **Publishable keys treated as secrets.** They are public by design; their protection comes from server-side scoping and rate limits.
