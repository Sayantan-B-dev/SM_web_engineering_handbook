### OAuth 2.1 Changes
As of OAuth 2.1 (current draft `draft-ietf-oauth-v2-1-15`, March 2026): **PKCE is mandatory for every client**, the implicit grant is removed, the resource-owner-password-credentials grant is removed, and the authorization server MUST reject any `redirect_uri` that doesn't exactly match a registered URI.

### The BFF Pattern (2026 Recommendation)
For browser apps, the IETF's Browser-Based Apps BCP ranks architectures by safety: **BFF (Backend-For-Frontend) > token-mediating backend > pure SPA OAuth client**. The pure-SPA pattern is "vulnerable to all attack scenarios" and should only be used when no backend is available.

The prevailing 2026 guidance for browser SPAs is to keep tokens in **HttpOnly, Secure, SameSite cookies** - often via a lightweight backend-for-frontend that holds the tokens server-side and exposes only a session cookie to the browser. That removes tokens from JavaScript's reach entirely.

### Authorization Code Flow + PKCE
```typescript
// Generate the PKCE pair (Web Crypto)
const verifier = base64url(crypto.getRandomValues(new Uint8Array(32)));
const challenge = base64url(
  await crypto.subtle.digest('SHA-256', new TextEncoder().encode(verifier))
);

// Store verifier in sessionStorage (temporary, cleared after exchange)
sessionStorage.setItem('pkce_verifier', verifier);

// Redirect to authorization endpoint
const params = new URLSearchParams({
  response_type: 'code',
  client_id: CLIENT_ID,
  redirect_uri: 'https://myapp.com/callback',
  scope: 'openid profile email',
  state: generateState(), // CSRF protection
  code_challenge: challenge,
  code_challenge_method: 'S256',
});
window.location.href = `https://auth.example.com/authorize?${params}`;
```
An intercepted authorization code is useless without the verifier.

### `state` vs `nonce`
- **`state`** - prevents CSRF on the callback. Validate that the returned `state` matches what you sent.
- **`nonce`** - prevents ID token replay. Include it in the authentication request and verify it in the ID token.

### Token Storage Decision Matrix

| Storage | XSS Risk | CSRF Risk | 2026 Recommendation |
|---------|----------|-----------|---------------------|
| `localStorage` | **High** - readable by any JS | None | Avoid for tokens |
| `sessionStorage` | **High** - readable by any JS | None | Avoid for tokens |
| `HttpOnly` cookie | **None** - not readable by JS | Requires CSRF defense | **Recommended** (with SameSite + CSRF tokens) |
| BFF (server-side) | **None** - tokens never reach browser | Session cookie CSRF | **Best** - IETF recommended |

### Deeper Explanation: The Flow Choice Determines Your Attack Surface

OAuth is an authorisation framework with several flows; only one is appropriate for browser apps:

| Flow | Status | Use |
|---|---|---|
| Authorization Code + **PKCE** | Recommended (OAuth 2.1) | All browser and mobile apps |
| Client Credentials | Recommended | Server-to-server |
| Implicit | Deprecated | Never |
| Password (ROPC) | Deprecated | Never for third parties |

For a SPA the safe pattern is BFF-style: the browser talks to your own backend, which holds tokens and performs the code exchange, so refresh tokens never reach JavaScript. If tokens must be in the browser, use short-lived access tokens in memory, no refresh token in storage, and a silent re-auth via a same-site cookie or an iframe to your own backend.

### Additional Pitfalls
- **Implicit flow with tokens in the URL fragment.** Leaks via history, referrers, and extensions.
- **No PKCE.** Authorisation-code interception becomes viable.
- **`state` missing or unvalidated.** CSRF on the callback; also validate `nonce` for OIDC.
- **Wildcard redirect URIs.** Open redirect and token theft; exact-match URI allow-lists only.
- **Refresh tokens in `localStorage`.** Long-lived credential in a JavaScript-readable store.
- **Scopes granted broadly "for later".** Request least privilege per feature.

### Real-World Deal-Breakers
- **Implicit flow** → removed in OAuth 2.1. Never use it.
- **No PKCE** → mandatory in OAuth 2.1. An intercepted authorization code is usable without PKCE.
- **Wildcard redirect URIs** → authorization server MUST reject non-exact matches.
- **Tokens in localStorage** → one XSS and the attacker exfiltrates the token instantly.
- **No `state` validation** → CSRF on the OAuth callback. Always validate `state`.
- **No `nonce` validation** → ID token replay. Always validate `nonce`.
- **Pure SPA OAuth** → "vulnerable to all attack scenarios." Use BFF when a backend is available.
