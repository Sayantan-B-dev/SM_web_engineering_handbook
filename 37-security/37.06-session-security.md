## 37.9 Session Security

### Subtopic Tree
- Session ID generation (cryptographically random)
- Session fixation prevention (regenerate on login)
- Session expiry (idle timeout, absolute timeout)
- Session revocation (logout, password change)
- Concurrent session limits
- Session storage (Redis, database)

### Session Fixation Prevention
```typescript
app.post('/login', async (req, res) => {
  const user = await authenticate(req.body.email, req.body.password);

  // Regenerate session ID after login
  req.session.regenerate((err) => {
    if (err) return res.status(500).json({ error: 'Session error' });
    req.session.userId = user.id;
    res.json({ success: true });
  });
});
```

### Session Expiry
```typescript
app.use(session({
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
    maxAge: 7 * 24 * 60 * 60 * 1000, // absolute: 7 days
  },
  rolling: true, // idle timeout: reset on activity
}));
```

### Deeper Explanation: The Session Lifecycle Is The Security Model

A session has a lifecycle (create â†’ use â†’ elevate â†’ idle â†’ expire â†’ revoke) and each stage needs an explicit decision:

- **Create**: cryptographically random id (â‰¥128 bits), stored server-side, bound to a session record with user, tenant, IP/user-agent fingerprints (as signals, not as sole gates), and creation time.
- **Use**: httpOnly `__Host-` cookie, HTTPS-only, `SameSite=Lax`, with the session lookup cached but authoritative.
- **Elevate**: re-authenticate (or step-up MFA) before sensitive actions; rotate the session id at that moment.
- **Idle/absolute timeouts**: short idle window (30 min for sensitive apps) plus an absolute maximum (12 h) so a stolen session cannot live forever.
- **Revoke**: on logout, password change, permission change, and anomaly detection â€” server-side, immediately effective.
- **List and manage**: users should see active sessions and be able to end them.

### Additional Pitfalls
- **Session ids in URLs or logs.** They leak through referrers, proxies, and analytics.
- **No rotation on privilege change.** Session fixation remains possible.
- **Idle timeout only.** Stolen sessions stay valid indefinitely with activity.
- **No concurrent-session policy.** Decide whether multiple devices are allowed and enforce it.
- **Trusting client-provided user ids.** Identity comes from the server-side session record only.

### Real-World Deal-Breakers
- **Session ID not regenerated on login** → session fixation attack. Always regenerate after authentication.
- **No session expiry** → sessions live forever. Use both idle timeout and absolute timeout.
- **No session revocation on password change** → stolen sessions remain valid after password change. Revoke all sessions on password change.
- **Predictable session IDs** → `Math.random()` is not cryptographically secure. Use `crypto.randomUUID()` or a session library.
