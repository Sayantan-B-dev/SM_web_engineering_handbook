### The Mental Model
Browser ML trades **server compute for user compute**. The upsides are structural â€” data never leaves the device (privacy and compliance), inference happens with zero network latency and no per-call cost, and the feature works offline. The downsides are equally structural â€” model size is bounded by download size, memory is bounded by the tab, and throughput is bounded by the device, which on a mid-tier phone can be 10-50Ã- slower than a laptop.

So the decision is a fit question, not a capability question: run locally when the model is small, the input is sensitive, the feature must work offline, and a fixed cost per user is preferable to per-call billing. Keep it server-side when you need frontier quality, long context, or consistent latency for every user.

```ts
// Transformers.js in a worker â€” the realistic shape of a browser-ML feature
import { pipeline, env } from '@huggingface/transformers';

env.backends.onnx.wasm.numThreads = navigator.hardwareConcurrency;   // worker only
env.allowLocalModels = false;

const classifier = await pipeline('text-classification', 'Xenova/distilbert-base-uncased-finetuned-sst-2-english', {
  dtype: 'q8',            // quantised weights: ~4x smaller, small accuracy cost
  device: 'webgpu',       // falls back to wasm automatically in recent builds
  progress_callback: (p) => self.postMessage({ type: 'progress', p }),
});

self.onmessage = async ({ data }) => {
  const [result] = await classifier(data.text);
  self.postMessage({ type: 'result', id: data.id, result });
};
```

### Real-World Deal-Breakers
- **Shipping a multi-hundred-megabyte model.** Users on mobile data pay for it in seconds and megabytes; load on demand, never on first paint.
- **Assuming a GPU.** Many devices have no WebGPU (or a blocklisted adapter); always have a WASM path.
- **Running inference on the main thread.** It freezes the UI for seconds; use a worker.
- **Ignoring memory limits.** Model weights plus activations can exceed a mobile tab's budget and the browser kills the page.
- **No progress or cancel.** First-load downloads need progress, resumability, and a cancel.
- **Re-downloading the model every visit.** Cache it (Cache API/IndexedDB) and check a version hash before refetching.
