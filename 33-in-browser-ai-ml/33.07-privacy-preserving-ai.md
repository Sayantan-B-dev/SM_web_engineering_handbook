## 33.7 Privacy-Preserving AI

### Subtopic Tree
- Architectural privacy: the design itself makes data upload impossible rather than relying on policy promises
- Client-side inference: no data ever leaves the user's machine
- Use cases: healthcare predictions, search assistance, ad preferences, website relevance classification
- Mozilla + Mistral partnership: Firefox Smart Window with zero data retention
- Federated learning in the browser (AdFL)
- Differential privacy for local model parameters

---

### Deeper Explanation: Local Inference Is A Compliance Strategy

Running inference on-device removes an entire class of data-flow questions: personal data never leaves the user's machine, no processor agreement is needed for that processing, and there is no prompt retention to audit. That makes browser AI attractive for exactly the features that are hardest to ship server-side: health notes, financial documents, private messages, photos, and anything under GDPR/HIPAA scrutiny.

To keep the property, be strict about the boundary: no telemetry containing input text, no model that phones home with prompts, no "anonymous" analytics that carries the payload, and no fallback that silently sends data to a server. If you do need a server path for quality reasons, make the choice explicit and consented per feature.

### Additional Pitfalls
- **Telemetry that leaks the input.** The most common way local inference stops being private.
- **Silent server fallback.** Users believe their data stayed local; a fallback breaks that promise.
- **Model downloads from an untrusted CDN.** Weights are executable artifacts; pin and verify.
- **Assuming local means compliant.** Consent, retention of outputs you store, and device-sharing still apply.
- **No explanation in the UI.** Users cannot benefit from a privacy property they cannot see.

### Real-World Deal-Breakers
- **Policy-based privacy is not enough** → architectural privacy (no data leaves the device) is the only guarantee that cannot be broken by policy changes or server breaches.
- **No local-first design** → if the app requires a server round-trip, user data is exposed. Use client-side inference.
- **Ignoring zero-retention promises** → Firefox Smart Window and Mistral commit to zero data retention, but this is a policy promise, not an architectural guarantee.
