## 33.6 AI Performance

### Subtopic Tree
- Dispatch overhead: dominant at batch size 1
- Kernel fusion: the effective optimization for WebGPU LLM inference at batch size 1
- Cold-start: 1-5s shader compilation for WebGPU
- Real-world LLM inference: Phi-3-mini token latency drops from ~320ms to ~85ms when switching from WebGL to WebGPU on M2
- Largest model successfully run in browser via WebGPU: 20GB of Q5_K_XL weights loaded into 31.5GB of available WebGPU memory on a consumer iGPU, 23 tokens/second decode speed

---

### Deeper Explanation: The Four Numbers To Measure

Browser AI performance is four measurements, and optimising without them is guessing:

| Metric | Why it matters | Typical target |
|---|---|---|
| Model load (cold / warm) | First-use experience | < 3 s warm, cached after |
| Time to first token / result | Perceived latency | < 500 ms for interactive use |
| Steady-state throughput | Feasibility at scale | Device-dependent; measure p50/p95 |
| Memory + battery | Stability on mobile | Stay under tab limits; avoid sustained GPU |

Techniques that reliably help: run in a worker with SIMD/threads, use the GPU when available, batch inputs, keep tensors on-device across calls, cache embeddings and predictions, and debounce streaming inputs (do not run inference per keystroke).

Also instrument the *product*: how often the feature is used, how often it falls back to the server, and how long users wait. Those numbers decide whether local inference is a win.

### Additional Pitfalls
- **Benchmarking cold only.** Warm numbers reflect what users experience after the first visit â€” or the reverse if caching is broken.
- **Ignoring the main thread cost.** Even a worker-based pipeline costs main-thread time for messaging and rendering.
- **No fallback path measurement.** If 40% of sessions fall back to the server, the local model is not paying for itself.
- **Assuming p50 is enough.** Low-end devices are the p95 that decides whether the feature is usable.

### Real-World Deal-Breakers
- **Dispatch overhead dominates** → at batch size 1, per-operation overhead dominates regardless of kernel quality. Reduce dispatch count through kernel fusion.
- **Cold-start latency** → WebGPU shader compilation adds 1-5 seconds on first run.
- **Memory constraints** → the largest model run in a browser used 20GB of weights, requiring 31.5GB of available WebGPU memory. This is not available on most devices.
