## 33.2 WebNN API

### Subtopic Tree
- W3C Candidate Recommendation (March 2026)
- Platform-independent API for executing neural network models
- Access to specialised NPUs on mobile devices
- Chrome 146 promoted WebNN to an **origin trial** (February 2026)
- DirectML backend deprecated during Microsoft Build 2025; WebNN will leverage Windows ML to access OpenVINO and other execution providers
- Browser support: Chrome 127+ and Edge 127+ (full); Chrome <127 requires flag; Firefox and Safari not supported

---

### Deeper Explanation: The NPU Path

WebNN exposes a graph API that the browser maps onto hardware accelerators (NPU, GPU, or CPU) with a shared buffer model between JS and the device. Its promise is efficiency: NPU inference uses far less power than WebGPU, which matters for sustained features on laptops and phones.

The reality in 2026 is fragmented support, so the pragmatic approach is to treat it as an optional acceleration path: build the graph once in your runtime abstraction, request an `MLContext` with a preferred device type, and fall back to WebGPU then WASM. Runtimes (ONNX Runtime Web, Transformers.js) increasingly select WebNN automatically when present, which means most teams should enable it via configuration rather than writing graphs by hand.

### Additional Pitfalls
- **Treating WebNN as the baseline.** Feature-detect and fall back; support is Chromium-first and device-dependent.
- **Hand-writing graphs.** Runtimes generate better graphs and manage the fallback ladder.
- **Assuming NPU availability.** `ml.getContext('npu')` can fail even on capable hardware if drivers or the OS disagree.
- **Ignoring buffer copies.** Moving tensors between JS and the device costs; keep data on-device across steps.

### Real-World Deal-Breakers
- **Assuming WebNN is production-ready** → it's a W3C Candidate Recommendation and an origin trial in Chrome 146. Not stable for production.
- **Ignoring NPU limitations** → NPU access is mobile-focused; desktop NPU support is not guaranteed.
- **No WebGPU/WebGL fallback** → WebNN is not universally supported; always provide fallbacks.
