### Deeper Explanation: The Browser As A Model Provider

The built-in AI APIs turn the browser into a zero-download model provider: summarisation, translation, language detection, and prompting, all backed by an on-device model the browser manages. That changes the economics of small features â€” no model hosting, no API key, no download from your CDN, and privacy by construction.

The constraints are equally important: availability is limited to certain browsers and versions, capability is modest compared with frontier models (short context, weaker reasoning), download of the underlying model can be prompted but not guaranteed, and output is not deterministic. So the right fit is *soft* features â€” summarise this page, rewrite this text, detect the language, translate a paragraph â€” inside a capability-detected layer with a graceful fallback.

```ts
// Capability detection plus a session, with a server fallback
type Availability = 'available' | 'downloadable' | 'downloading' | 'unavailable';

async function summarise(text: string): Promise<string> {
  const api = (globalThis as any).ai?.summarizer;
  const availability: Availability = api ? await api.availability() : 'unavailable';

  if (availability === 'downloadable') await api.create({ monitor: (m) => console.log(m.loaded) });
  if (availability === 'unavailable') return serverSummarise(text);   // explicit, not silent

  const session = await api.create({ type: 'key-points', format: 'markdown', length: 'short' });
  return session.summarize(text);
}
```

### Additional Pitfalls
- **Assuming availability.** Feature-detect and provide a server path; never let the feature simply vanish.
- **Trusting output as fact.** Summaries can invent details; keep the user able to see the source.
- **Ignoring download UX.** A first-use model download needs a progress affordance and a fallback.
- **Bundling the API expectation into the main bundle.** Load the feature lazily so unsupported browsers pay nothing.
- **No privacy note.** The selling point is local processing; tell the user, and never silently send the text to a server.

### Real-World Deal-Breakers
- **Assuming universal availability** → Prompt API is Chrome Canary/Dev only. Not production-ready for cross-browser apps.
- **No fallback** → if the Prompt API is unavailable, the app breaks. Use WebLLM or WASM fallback.
