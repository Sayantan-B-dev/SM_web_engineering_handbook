## 33.4 Model Loading

### Subtopic Tree
- Model formats: ONNX, GGUF, TFLite, MediaPipe
- Quantization: INT8, Q4F16, Q5_K_XL
- q4f16 optimized for WebGPU; q8-compatible quantized weights for WASM path
- Cache API and Origin Private File System for model caching
- External data for models >2GB (protobuf file size limit)
- Bundler configuration: Webpack/Vite need explicit instructions to treat `.onnx` files as static assets

### Deeper Explanation: Delivery Is Half The Engineering

Model loading has three phases and each has a different tactic:

1. **Download** â€” tens to hundreds of MB. Serve from a CDN with immutable caching, use `Content-Encoding: br`, show progress with `fetch` streaming (`response.body` reader) so users see movement, and support cancel/retry.
2. **Cache** â€” persist the weights so the second visit is instant: Cache API for `Response`s, IndexedDB for blobs, or the Origin Private File System for large files. Verify integrity with a version/hash so a model update actually refreshes.
3. **Instantiate** â€” compile/instantiate (WASM) or build pipelines (WebGPU). Do it in a worker, reuse the session across inferences, and keep the session alive as long as the feature is in use.

Quantisation belongs here too: `q4`/`q8` weights are 2-8Ã- smaller with modest quality loss, which often decides whether a model is shippable on mobile at all. Ship a small model first, then upgrade in the background if the device supports it.

### Additional Pitfalls
- **Blocking first render on a model.** Load lazily behind user intent, or after idle time.
- **No versioning.** A cached model from a previous release keeps producing old predictions; key the cache by model revision.
- **Ignoring the storage quota.** Multi-hundred-MB caches hit eviction; request persistence and handle `QuotaExceededError`.
- **Re-instantiating per call.** Compilation and pipeline setup cost seconds; keep one session per worker.
- **No offline story.** If the model is cached but the app requires the network, the offline promise is broken.

### Real-World Deal-Breakers
- **Naive bundling** → Webpack or Vite attempts to process `.onnx` files through standard loaders, producing a grotesquely oversized bundle or erroring out.
- **No quantization** → unquantized models are 4× larger and slower. Use INT8 or Q4F16 quantization.
- **No cache strategy** → 10-15 second gap between user action and first result if nothing is cached.
- **Ignoring external data** → models >2GB require external data files; ONNX Runtime Web needs explicit configuration.
