## 33.3 Client-Side Inference

### Subtopic Tree
- Model loading and caching (Cache API, Origin Private File System)
- ONNX Runtime Web: WASM (CPU with SIMD) + WebGPU (GPU) + WebGL (legacy) + WebNN
- Transformers.js v4: WebGPU runtime rewritten in C++, 4× speedup for BERT models, supports 20-billion parameter models at 60 tokens per second
- WebLLM: high-performance in-browser LLM inference engine
- LiteRT.js: Google's high-performance Web AI inference on WebGPU, upcoming WebNN, fallback to WASM for CPU
- ONNX Runtime Web platform restrictions: max ArrayBuffer in Chrome ~2GB; WASM memory limit 4GB; protobuf file limit 2GB

---

### Deeper Explanation: The Latency Budget Changes The Product

Client inference has a different shape from server inference: **no network hop, but a variable device**. That changes the design:

- **First run is slow, subsequent runs are fast.** Model load (tens of MB, seconds) is a one-time cost; cache aggressively and show progress.
- **Throughput is unpredictable.** The same model runs at 100 tokens/s on a laptop and 3 tokens/s on a low-end phone â€” design UI that tolerates both (streamed output, progress, cancellation).
- **Batching beats per-item calls.** One embedding call for 32 items is far faster than 32 calls; the boundary cost dominates.
- **Warm-up matters.** The first inference includes kernel compilation and memory allocation; run a dummy input after load.

Measure with `performance.mark` around load, first inference, and steady-state inference, on a throttled profile, and treat the numbers as product requirements.

### Additional Pitfalls
- **Measuring on a developer machine only.** Real devices are 10-50Ã- slower; throttle to 4Ã- CPU to approximate.
- **Assuming the model stays loaded.** Browsers evict; treat the loaded state as a cache with a cold path.
- **Blocking on load.** Awaiting a 60 MB model before rendering the page is a UX regression; load lazily behind the feature.
- **No quality fallback.** Quantised local models are marginally worse; decide how visible that is to users.

### Real-World Deal-Breakers
- **Large model loading** → a quantized all-MiniLM-L6-v2 is ~23MB; unquantized larger architectures can exceed 100MB. On Fast 3G, download alone can take 8-12 seconds.
- **No caching** → every page refresh reloads the model. Use Cache API or OPFS.
- **Main-thread contention** → ONNX Runtime's WASM execution runs on the main thread by default, competing with React's reconciliation and paint cycles. Peak memory allocation for a sentence-embedding model can reach 150-300MB.
- **Ignoring WebAssembly memory limits** → WASM has a 4GB memory limit due to 32-bit addressing; ONNX Runtime Web cannot run models larger than 4GB.
