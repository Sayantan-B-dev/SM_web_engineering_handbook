### The Pipeline

```text
client -> resumable upload -> object storage (raw, private)
                                    |
                              [ transcoding queue ]
                                    |
                          workers (ffmpeg/sharp/vips)
                                    |
                       variants -> object storage (public/CDN)
                                    |
                        metadata -> database (duration, dims, status)
```

Ingest is asynchronous by necessity: transcoding a 4K video takes minutes and cannot happen in a request handler. Model it as a job with explicit states (`uploading`, `queued`, `processing`, `ready`, `failed`) so the UI can be honest about progress.

### Image Variants

```typescript
import sharp from 'sharp';

export const IMAGE_VARIANTS = [
  { name: 'thumb',   width: 320,  format: 'webp', quality: 72 },
  { name: 'card',    width: 768,  format: 'avif', quality: 55 },
  { name: 'hero',    width: 1600, format: 'avif', quality: 50 },
] as const;

export async function processImage(src: Buffer) {
  const meta = await sharp(src).metadata();

  // Strip EXIF (GPS!) and normalise orientation before anything else
  const base = sharp(src).rotate().withMetadata({ exif: {} });

  return Promise.all(
    IMAGE_VARIANTS.map(async (v) => ({
      name: v.name,
      width: v.width,
      body: await base.clone().resize({ width: v.width, withoutEnlargement: true })[v.format]({ quality: v.quality }).toBuffer(),
    })),
  );
}
```

EXIF contains GPS coordinates. Uploading a phone photo with untouched EXIF publishes the user's home address. `.rotate()` applies orientation first, then strip metadata.

### Video Ladder

```text
1080p  5.0 Mbps  h264   (compatibility)
 720p  2.8 Mbps  h264
 480p  1.4 Mbps  h264
 360p  0.7 Mbps  h264
 720p  1.8 Mbps  h265/AV1  (efficiency, where supported)

Segment into 4-6s chunks -> HLS playlist (.m3u8) + segments (.ts/.m4s)
```

Adaptive streaming needs segments, not a single file: the player switches quality per segment based on measured throughput, so a mobile user on a train keeps watching at 360p rather than buffering at 1080p.

### Resumable Uploads

```text
1. Client asks for an upload session           -> uploadId
2. Client sends 5-8 MB chunks with an offset    -> each chunk acknowledged
3. On network failure, retry from the last ack   -> no restart from zero
4. On completion, server verifies size + hash    -> then enqueues transcoding
```

### Entitlement And Delivery

```typescript
// Signed, expiring URL: the only way to serve private media through a CDN
const url = await signUrl({
  key: `videos/${videoId}/720p/index.m3u8`,
  expiresIn: 3600,
  ip: hashedClientIp,          // optional binding to reduce link sharing
});
```

Access control must be enforced on the *segments*, not just the manifest. An unprotected segment directory means anyone can fetch the video even if the player refuses to start.

### Deeper Explanation: Media Is An Infrastructure Project

Text is cheap: store it in a row, serve it in a response. One image is three encodes and a cache. One video is a ladder of encodes, a segmentation job, a manifest, a player and an egress bill.

The professional reflex when a feature involves user media is to budget for compute time, storage growth and egress *before* writing the upload handler - because the egress bill is the part that surprises everyone, and the transcoding queue is the part that takes an order of magnitude longer than expected.

### Additional Pitfalls

- **Transcoding in a request handler.** Worker timeouts kill the job mid-encode and leave no record.
- **Forgetting EXIF stripping.** GPS coordinates published with every user photo.
- **One output resolution.** Every device downloads a 1600px image to render a 320px thumbnail.
- **No moderation queue.** Harmful content is hosted and served under your domain, with legal exposure.
- **Unbounded upload size.** One 20 GB upload fills the disk and blocks the queue for everyone.

### Real-World Deal-Breakers
- **Egress unbounded and uncached** - the media bill exceeds revenue.
- **No signed URLs on private media** - any file is public to anyone who knows the path.
- **No content validation beyond the extension** - malformed media exploits the decoder or the CDN cache.
- **Transcoding without idempotency** - a retried job duplicates variants and stores them forever.
- **No retention policy for raw uploads** - you pay for source files you will never fetch again.
