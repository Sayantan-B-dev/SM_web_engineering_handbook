### What `gcTime` Does
`gcTime` is the time in milliseconds that **unused/inactive cache data remains in memory**. When a query's cache becomes unused or inactive, it's garbage collected after this duration. Default is 5 minutes.

```tsx
useQuery({
  queryKey: ['user', id],
  queryFn: fetchUser,
  gcTime: 10 * 60 * 1000, // keep in memory for 10 minutes after last use
});
```

### Inactive vs Active
A query is **active** when at least one mounted component is using it. When the last component unmounts, the query becomes **inactive** and the `gcTime` timer starts.

### Real-World Deal-Breakers
- **`gcTime` too short for navigation-heavy apps** → data garbage collected between route transitions; full refetch on back-navigation. Increase `gcTime` for frequently-visited routes.
- **`gcTime` too long for large datasets** → memory bloat, especially on mobile. Tune per query.
- **Setting `gcTime: 0`** → data removed immediately after last component unmounts; no cache benefit.
- **Confusing `gcTime` with `staleTime`** → `gcTime` only applies to **inactive** queries; `staleTime` applies to **active** queries.
