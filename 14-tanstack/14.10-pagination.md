## 14.10 Pagination

### Subtopic Tree
- Standard pagination with `useQuery` + `keepPreviousData`
- `placeholderData: keepPreviousData`

- Prefetching next page
- `useInfiniteQuery` for infinite scroll
- Cursor-based vs offset-based

### Standard Pagination
```tsx
function PaginatedTodos() {
  const [page, setPage] = useState(1);

  const { data, isPlaceholderData } = useQuery({
    queryKey: ['todos', page],
    queryFn: () => fetchTodos(page),
    placeholderData: keepPreviousData, // show previous page while next loads
  });

  // Prefetch next page
  useEffect(() => {
    if (!isPlaceholderData && data?.hasMore) {
      queryClient.prefetchQuery({
        queryKey: ['todos', page + 1],
        queryFn: () => fetchTodos(page + 1),
      });
    }
  }, [data, page, queryClient]);

  return (
    <>
      <TodoList todos={data?.items} />
      <button onClick={() => setPage(p => p - 1)} disabled={page === 1}>Prev</button>
      <button onClick={() => setPage(p => p + 1)} disabled={isPlaceholderData || !data?.hasMore}>Next</button>
    </>
  );
}
```

`placeholderData: keepPreviousData` keeps the previous page's data visible while the next page loads, preventing a flash of empty state. Prefetching the next page makes pagination feel instant.

### Real-World Deal-Breakers
- **No `keepPreviousData`** → page flashes empty on every page change.
- **No prefetching** → each page change shows a loading spinner.
- **Page number not in query key** → all pages share the same cache entry.
- **Cursor-based pagination with offset key** → stale results when data shifts. Use the cursor value in the key.
