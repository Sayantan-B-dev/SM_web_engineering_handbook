## 14.4 Query Keys

### Subtopic Tree
- Must be an array at the top level
- Simple vs complex keys
- Hierarchical organization
- Deterministic hashing
- Key factories
- Including variables in keys
- Prefix matching for invalidation
- `exact` option

### Key Structure
Query keys must be an **array at the top level**. They can be as simple as `['todos']` or as complex as `['todos', { status: 'done', page: 1 }]`. Keys are **hashed deterministically** - object key order doesn't matter.

```tsx
// Simple
useQuery({ queryKey: ['todos'], queryFn: fetchAllTodos });

// With variables
useQuery({ queryKey: ['todo', todoId], queryFn: () => fetchTodoById(todoId) });

// With filters
useQuery({
  queryKey: ['todos', { status: 'done', page: 1 }],
  queryFn: () => fetchTodos({ status: 'done', page: 1 }),
});
```

### Key Factory Pattern
```tsx
// queryKeys.ts
export const todoKeys = {
  all: ['todos'] as const,
  lists: () => [...todoKeys.all, 'list'] as const,
  list: (filters: string) => [...todoKeys.lists(), { filters }] as const,
  details: () => [...todoKeys.all, 'detail'] as const,
  detail: (id: string) => [...todoKeys.details(), id] as const,
};

// Usage
useQuery({ queryKey: todoKeys.detail(id), queryFn: () => fetchTodo(id) });

// Invalidate all todo queries (prefix match)
queryClient.invalidateQueries({ queryKey: todoKeys.all });
```

### Prefix Matching
`invalidateQueries` uses **prefix matching by default**. `invalidateQueries({ queryKey: ['posts'] })` invalidates all queries that start with `['posts', ...]`. Use `exact: true` to match only the exact key.

### Real-World Deal-Breakers
- **Non-array keys** → runtime error. Keys must be arrays.
- **Keys without variables** → `['todo']` for different todo IDs returns the same cached data for all IDs. Always include the variable.
- **Inconsistent key structure** → `['user', id]` in one place and `['users', id]` in another; invalidation won't match.
- **Object in key with different reference every render** → TanStack Query hashes deterministically, so `{ a: 1 }` and `{ a: 1 }` match. But large objects in keys are slow to hash.
