## 14.12 Prefetching

### Subtopic Tree
- `queryClient.prefetchQuery`
- `queryClient.prefetchInfiniteQuery`
- `usePrefetchQuery` (render-time prefetch)
- `usePrefetchInfiniteQuery`
- Prefetch on hover
- Prefetch in route loaders (TanStack Router integration)
- Server-side prefetch + hydration
- `staleTime` on prefetched queries

### Event-Based Prefetching
```tsx
const queryClient = useQueryClient();

function UserLink({ id }) {
  const prefetch = () => {
    queryClient.prefetchQuery({
      queryKey: ['user', id],
      queryFn: () => fetchUser(id),
      staleTime: 60_000, // don't refetch immediately
    });
  };

  return <Link to={`/users/${id}`} onMouseEnter={prefetch}>User {id}</Link>;
}
```

### Render-Time Prefetching
```tsx
import { usePrefetchQuery } from '@tanstack/react-query';

function Parent() {
  // Fires a prefetch during render - no return value
  usePrefetchQuery({
    queryKey: ['user', id],
    queryFn: () => fetchUser(id),
  });
  return <Child id={id} />;
}
```

### Prefetch in Route Loaders (TanStack Router)
```tsx
export const Route = createFileRoute('/users/$userId')({
  loader: ({ context: { queryClient }, params: { userId } }) => {
    return queryClient.ensureQueryData(userOptions(userId));
  },
  component: UserPage,
});
```
The loader runs before the route renders, so the component gets data instantly from cache.

### Real-World Deal-Breakers
- **Prefetching with default `staleTime: 0`** → prefetched data is immediately stale; the actual render refetches anyway. Set a `staleTime` on the prefetch.
- **Prefetching too aggressively** → wasted bandwidth for data the user never views.
- **No `staleTime` on prefetched queries** → prefetch provides no benefit; the real query refetches immediately.
- **Prefetching on every hover** → repeated prefetches for the same key. TanStack Query deduplicates, but the network call may still fire if data is stale.
