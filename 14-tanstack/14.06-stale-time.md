## 14.6 Stale Time

### Subtopic Tree
- Definition: how long data is trusted without refetch
- Default: `0` (stale immediately)
- Setting per-query or globally
- Interaction with `gcTime`
- `Infinity` for truly static data
- `staleTime` and prefetching
- Background refetch triggers (mount, focus, reconnect, interval)

### What `staleTime` Does
`staleTime` is how long **you trust cached data without checking**. Default is `0` - data is stale immediately, so every mount triggers a background refetch.

```tsx
useQuery({
  queryKey: ['user', id],
  queryFn: fetchUser,
  staleTime: 5 * 60 * 1000, // fresh for 5 minutes
});
```

### Global Default
```tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000, // 1 minute for all queries
    },
  },
});
```

### `Infinity`
```tsx
staleTime: Infinity // never stale - only refetch on explicit invalidation
```
Use for truly static data (country list, config).

### Real-World Deal-Breakers
- **Default `staleTime: 0`** → every mount refetches, even for data that rarely changes. Set `staleTime` deliberately.
- **`staleTime` for data that changes frequently** → users see stale data. Use shorter `staleTime` + background refetch.
- **`staleTime: Infinity` for mutable data** → data never refetches; users see old data until manual invalidation.
- **Confusing `staleTime` with `gcTime`** → `staleTime` = trust duration; `gcTime` = memory retention after inactivity.
