## 14.5 Query Cache

### Subtopic Tree
- `QueryClient` cache
- In-memory, per-browser-tab
- `staleTime` vs `gcTime`

- `queryClient.getQueryData` / `setQueryData`

- `queryClient.cancelQueries`

- Server-side hydration (`HydrationBoundary`)

### Cache Lifecycle
1. **Fresh** - within `staleTime`, served from cache without refetch.
2. **Stale** - after `staleTime`, refetched in background on mount/focus.
3. **Inactive** - no components using the query. Kept in memory for `gcTime`.
4. **Garbage collected** - after `gcTime` expires.

### `queryClient.setQueryData`
```tsx
queryClient.setQueryData(['user', id], newUser); // overwrite cache
```

### Cache Persistence
```tsx
import { PersistQueryClientProvider } from '@tanstack/react-query-persist-client';
import { createSyncStoragePersister } from '@tanstack/query-sync-storage-persister';

const persister = createSyncStoragePersister({ storage: localStorage });

<PersistQueryClientProvider client={queryClient} persistOptions={{ persister }}>
  <App />
</PersistQueryClientProvider>
```

### Real-World Deal-Breakers
- **`gcTime` less than `staleTime`** → data garbage collected before it's stale. `gcTime` should always be **greater than or equal to** `staleTime`.
- **No cache persistence** → full refetch on every page reload. Use `PersistQueryClientProvider` for critical data.
- **`removeQueries` instead of `invalidateQueries`** → removes cache entirely; next mount fetches fresh with no stale data shown.
- **Assuming cache is shared across tabs** → cache is per-tab; use `BroadcastChannel` or persistence for cross-tab.
