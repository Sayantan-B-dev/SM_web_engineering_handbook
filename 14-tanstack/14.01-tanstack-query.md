### What TanStack Query Is
TanStack Query (formerly React Query) is a **server state management library** - not a general state manager. It handles caching, background refetching, deduplication, stale-while-revalidate, pagination, and mutations. It does **not** replace Redux or Zustand; it replaces the `useEffect` + `useState` + fetch pattern.

```tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient();

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <Router />
    </QueryClientProvider>
  );
}
```

### v5 Breaking Changes
v5 unified every hook on a **single object argument** - no more positional overloads.

```tsx
// ❌ v4
useQuery(key, fn, options)

// ✅ v5
useQuery({ queryKey, queryFn, ...options })
```

Callbacks on `useQuery` (`onSuccess`, `onError`, `onSettled`) have been **removed** - use `useEffect` or `queryClient` callbacks instead. `useQuery` no longer has a `remove` method. `isLoading` → `isPending`; `cacheTime` → `gcTime`.

### v5 Suspense-First
v5 made Suspense a first-class citizen with dedicated hooks where `data` is **never typed as `undefined`**:

```tsx
// data: T (not T | undefined)
const { data } = useSuspenseQuery({ queryKey: ['user', id], queryFn: fetchUser });

// Also available:
useSuspenseInfiniteQuery()
useSuspenseQueries()
```

### Real-World Deal-Breakers
- **Using TanStack Query for client state** → it's for server state. Use Zustand/Jotai for client-only state.
- **Not installing DevTools in dev** → debugging cache and query states becomes guesswork.
- **Assuming `isLoading` is still the flag** → v5 uses `isPending` for the initial load state.
- **Callbacks on `useQuery`** → removed in v5. Use `useEffect` or `queryClient` callbacks.
