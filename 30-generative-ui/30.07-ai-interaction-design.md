## 30.9 AI Interaction Design Principles

### Subtopic Tree
- Intent-based access (replacing hierarchical navigation)

### The Shift from Navigation to Intention
Research on generative UI identifies three paradigm shifts:

1. **Weakening of rigid hierarchical navigation** → intent-based access
2. **Redefinition of the user's role** → from operator to collaborator
3. **Emergence of generative "Liquid UI"** → interface modules rendered on demand

### Nine-Guideline Framework
A synthesis of research yields a nine-guideline framework that specifies how to design proposal-first intervention, explicit and editable intent representation, explainable AI, trust in automation, and recoverability/undo.

### Key Principles

| Principle | What it means |
|-----------|--------------|
| **Proposal-first intervention** | The AI proposes a UI; the user approves or edits |
| **Editable intent** | The user can see and modify what the AI understood |
| **Explainable AI** | The AI explains why it chose this UI |
| **Trust calibration** | Confidence indicators; the user knows when to trust |
| **Recoverability/undo** | The user can undo the AI's changes |
| **Direct manipulation** | The user can directly manipulate generated components |
| **Minimal cognitive load** | The UI doesn't overwhelm; it adapts |

### Deeper Explanation: Progressive Disclosure Of Uncertainty

The interaction design problem in AI features is keeping the user oriented while the system works on something probabilistic. The pattern that works â€” in assistants, copilots, and generated UI alike â€” is progressive disclosure of *both* progress and uncertainty:

- **Show intent early, detail late.** "Looking at Q3 revenue by region" appears before the chart exists.
- **Make states visually distinct.** Thinking, streaming, complete, and failed must not look alike; confidence should be visible in the content itself (sources, caveats, ranges).
- **Keep the human's controls constant.** Stop, edit, retry, and refine must stay in the same place across states.
- **Never block the whole page.** Generated content lives inside its own region so the rest of the app stays usable.
- **Treat latency as a design material.** Under 200 ms: no affordance. 1-3 s: skeleton plus status. Over 3 s: background run with notification and a way to continue elsewhere.

### Additional Pitfalls
- **An identical spinner for every duration.** Users cannot tell a 300 ms call from a 40 s agent.
- **Optimistic confidence.** Presenting a possibly-wrong answer with no hedging or sources erodes trust the first time it is wrong.
- **Disappearing controls.** Hiding stop/retry during different states forces users to wait out a bad answer.
- **Blocking the page on generation.** One long generation should never freeze unrelated work.
- **No keyboard story.** Assistants are used with keyboards; shortcuts for send, stop, and accept are expected.

### Real-World Deal-Breakers
- **No proposal-first** → the AI generates a UI without approval. Always propose, then execute.
- **No editable intent** → the user can't correct the AI's misunderstanding.
- **No undo** → the user can't recover from a bad generation.
- **No explainability** → the user doesn't know why the AI chose this layout.
