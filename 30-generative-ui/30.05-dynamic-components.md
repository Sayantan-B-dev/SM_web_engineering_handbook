## Dynamic Components

### Subtopic Tree
- Rendering model-selected components from a registry
- Static imports vs lazy loading by key
- Prop coercion and defensive defaults
- Error boundaries per generated node
- Suspense and progressive rendering
- Memoisation and stable identity for generated trees
- Testing generated output deterministically

### The Mental Model
Dynamic components mean the *choice* of component is data, not code: `{ type: 'Metric', props }` becomes `<Metric {...props} />` through a lookup table. The registry must be explicit â€” a map from a bounded set of keys to real components â€” because both safety and bundle control depend on it. Never resolve components by evaluating strings or importing by arbitrary path.

```tsx
// registry.ts â€” the single allow-list; adding a component is a deliberate, reviewable change
import { lazy } from 'react';

export const registry = {
  Metric: lazy(() => import('./widgets/Metric')),
  Table: lazy(() => import('./widgets/Table')),
  Chart: lazy(() => import('./widgets/Chart')),
  Form: lazy(() => import('./widgets/Form')),
  Callout: lazy(() => import('./widgets/Callout')),
} as const;

export type WidgetKey = keyof typeof registry;

export function Widget({ widget, props }: { widget: WidgetKey; props: Record<string, unknown> }) {
  const Component = registry[widget];
  return (
    <ErrorBoundary fallback={<Callout tone="error">Could not render this section.</Callout>}>
      <Suspense fallback={<Skeleton />}>
        <Component {...props} />
      </Suspense>
    </ErrorBoundary>
  );
}
```

### Real-World Deal-Breakers
- **Resolving components from arbitrary strings.** `import(/* @vite-ignore */ name)` is a code-execution surface and a bundle nightmare.
- **No error boundary per node.** One bad widget takes down the whole generated page.
- **Unstable keys.** Generated trees re-render wholesale if list keys are indices of a changing array.
- **Spreading unvalidated props.** `{...props}` lets the model reach any prop, including callbacks-shaped holes; pick and coerce explicitly.
- **Lazy-loading everything.** For a handful of common widgets, static imports are faster; reserve `lazy` for the heavy ones.
- **No deterministic tests.** Snapshot a fixed tree for each widget key with realistic props so regressions are visible.
