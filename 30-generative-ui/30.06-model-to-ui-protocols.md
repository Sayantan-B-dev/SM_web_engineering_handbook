## Model-to-UI Protocols

### Subtopic Tree
- Why a protocol beats ad-hoc JSON per feature
- Envelope design: version, type, id, payload, status
- Streaming framing: events, deltas, terminal states
- Tool-call lifecycle events (`call`, `delta`, `result`)
- UI events and client actions (`client_action`)
- Resumability and sequence numbers
- Error, retry and cancellation semantics
- Interop between protocols (AG-UI, A2UI, json-render, MCP)

### The Mental Model
A model-to-UI protocol is an **event stream with typed frames**: the same shape whether the model is writing text, calling a tool, or asking the UI to update. Defining it once means every feature (chat, canvas, canvas-in-a-chat, agent run) reuses the same client, the same persistence, and the same debugging tools â€” instead of each feature inventing its own SSE format.

```ts
// A deliberately small, versioned protocol. Every frame carries an id for resumption.
export type Frame =
  | { v: 1; type: 'message.start'; id: string; runId: string }
  | { v: 1; type: 'message.delta'; id: string; text: string; seq: number }
  | { v: 1; type: 'tool.call'; id: string; callId: string; name: string; argsPartial: string; seq: number }
  | { v: 1; type: 'tool.result'; callId: string; ok: boolean; output: unknown; seq: number }
  | { v: 1; type: 'ui.render'; node: AssistantReply; seq: number }
  | { v: 1; type: 'client.action'; name: 'focus' | 'scroll' | 'highlight'; target: string }
  | { v: 1; type: 'message.end'; id: string; reason: 'stop' | 'length' | 'cancelled' | 'error'; usage?: { in: number; out: number } };
```

```ts
// Client reducer: the whole UI state machine, testable without a network
export function reduce(state: ChatState, frame: Frame): ChatState {
  switch (frame.type) {
    case 'message.delta':
      return state.seq >= frame.seq ? state : { ...state, seq: frame.seq, draft: state.draft + frame.text };
    case 'ui.render':
      return { ...state, widgets: [...state.widgets, frame.node] };
    case 'message.end':
      return { ...state, status: frame.reason === 'error' ? 'error' : 'complete' };
    default:
      return state;
  }
}
```

### Real-World Deal-Breakers
- **Per-feature JSON shapes.** Every new feature re-implements streaming, cancellation, and persistence.
- **No sequence numbers.** Reconnects duplicate or drop content with no way to detect it.
- **No terminal frame.** The UI cannot distinguish "still generating" from "finished silently".
- **Mixing presentation and transport concerns.** Protocols carry data and events; styling decisions belong to the renderer.
- **Ignoring usage accounting.** Token usage per frame is how you price and rate-limit the feature.
- **Protocol versioning ignored.** A deployed client and a new server must negotiate or degrade, not crash.
