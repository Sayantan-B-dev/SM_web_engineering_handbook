## 30.4 Streaming JSON → React Server Components

### Subtopic Tree
- The streaming architecture: token stream → JSON parser → Zod validation → RSC tree
- Incremental JSON stream parser (brace-depth counting)
- Recursive discriminated `UINode` Zod schema
- Validation at the stream boundary (`safeParse`)
- Component registry (schema variant → React component)
- `useTransition` + progressive `setNodes` batching
- Layout shift prevention (`contain: layout`, dimension-matched skeletons)
- No proprietary library lock-in

### The Data Flow
The data flow is linear: **LLM token stream → incremental JSON parser → Zod validation → component registry → React tree**.

```
LLM tokens: { "type": "Card", "props": { "title": "Weather" }, "children": [...]
     ↓
Incremental JSON parser (brace-depth counting)
     ↓
Zod validation (safeParse)
     ↓
Component registry (Card → <Card />)
     ↓
React Server Component tree
```

### The Incremental JSON Parser
The parser uses the Web Streams `TransformStream` API with **brace-depth counting**. It buffers incoming chunks and emits complete JSON objects as soon as the brace depth returns to zero.

```typescript
class IncrementalJSONParser {
  private buffer = '';
  private depth = 0;

  push(chunk: string): object[] {
    this.buffer += chunk;
    const objects: object[] = [];
    let start = 0;

    for (let i = 0; i < this.buffer.length; i++) {
      if (this.buffer[i] === '{') this.depth++;
      if (this.buffer[i] === '}') {
        this.depth--;
        if (this.depth === 0) {
          try {
            objects.push(JSON.parse(this.buffer.slice(start, i + 1)));
          } catch { /* incomplete */ }
          start = i + 1;
        }
      }
    }
    this.buffer = this.buffer.slice(start);
    return objects;
  }
}
```

### The Zod Contract
A recursive, discriminated `UINode` Zod schema is the contract between LLM output and React rendering:

```typescript
const UINodeSchema: z.ZodType<UINode> = z.lazy(() =>
  z.discriminatedUnion('type', [
    z.object({ type: z.literal('Text'), props: z.object({ value: z.string() }) }),
    z.object({ type: z.literal('Button'), props: z.object({ label: z.string(), action: z.string() }) }),
    z.object({
      type: z.literal('Card'),
      props: z.object({ title: z.string() }),
      children: z.array(UINodeSchema),
    }),
  ])
);
```

### Layout Shift Prevention
Prevent layout shifts with CSS `contain: layout` and dimension-matched skeleton placeholders. The streaming container should reserve space using `min-height` and `aspect-ratio` so content below doesn't jump.

---

### Deeper Explanation: Stream Structure, Not Just Text

Streaming a *structure* means the UI can render progressively: a heading appears while the data for the chart is still arriving. The technique is incremental JSON over a stream: partial nodes render as skeletons, then hydrate as their fields complete. Two approaches dominate:

- **Partial JSON parsing** on the client â€” parse what is complete, keep the rest buffered. Libraries like `partial-json`/`best-effort-json-parser` make this practical; each parsed increment updates the tree.
- **Server-driven serialisation** â€” the server streams React Server Components (or a payload that maps to them) as it resolves async data, so Suspense boundaries fill in out of order.

The UI contract is what keeps it from feeling janky: **fixed-size skeletons matched to the final layout**, per-node error boundaries, and a stable identity per node so late data updates in place rather than remounting.

### Additional Pitfalls
- **Parsing on every chunk with a full parse.** Cost grows; parse incrementally and only the incomplete tail.
- **Replacing the tree on each update.** Keys must be stable or every increment remounts components and loses focus.
- **Skeletons with the wrong height.** Progressive rendering becomes measurable layout shift.
- **No terminal event.** The client cannot tell "structure finished" from "stream stalled".
- **Unbounded node counts.** A model can emit hundreds of nodes; cap and paginate.

### Real-World Deal-Breakers
- **No incremental parser** → you wait for the full JSON before rendering anything.
- **No Zod validation at the boundary** → malformed JSON crashes the renderer.
- **No component registry** → JSON types don't map to React components.
- **No layout shift prevention** → content reflows as it streams in. Reserve space.
