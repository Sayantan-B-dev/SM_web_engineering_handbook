### What json-render Is
Vercel has open sourced json-render, a framework it describes as "Generative UI," allowing AI models to generate structured user interfaces from natural language prompts. The project is released under the Apache 2.0 license and has accumulated over 13,000 stars and 200 releases since its January 2026 launch.

The core idea: developers define a **catalog of permitted components and actions using Zod schemas**, and an LLM generates a JSON specification constrained to that catalog. The framework then renders the output progressively as the model streams its response.

```typescript
import { defineCatalog } from "@json-render/core";
import { schema } from "@json-render/react/schema";
import { z } from "zod";

const catalog = defineCatalog(schema, {
  components: {
    Card: {
      description: "A card container with optional title and padding",
      props: z.object({
        title: z.string().optional(),
        padding: z.enum(["sm", "md", "lg"]).optional(),
      }),
    },
    TextInput: {
      description: "A text input field with optional label and placeholder",
      props: z.object({
        label: z.string().optional(),
        placeholder: z.string().optional(),
        type: z.enum(["text", "email", "password", "number", "textarea"]).optional(),
      }),
    },
    Button: {
      description: "A clickable button with label and style variants",
      props: z.object({ label: z.string(), variant: z.enum(["primary", "secondary"]) }),
    },
  },
});
```
Each component has a Zod schema for its props and a description that the AI reads to understand when to use it. The catalog is the **guardrail**: the agent can arrange and combine your components freely, but cannot step outside the set you approve.

### Multi-Framework Support
The renderer supports React, Vue, Svelte, Solid, React Native, and more. It ships with 36 pre-built shadcn/ui components for teams that want a head start, alongside packages for PDF generation, HTML email, video via Remotion, OG image rendering, and 3D scenes through React Three Fiber.

### Deeper Explanation: JSON In, Components Out

`json-render`-style approaches formalise the declarative level: the model emits a JSON document describing a tree of registered components and props, and a renderer walks it. The value is that everything hard (safety, styling, accessibility, layout) stays in your code while everything variable (composition, labels, data selection) becomes model output.

Implementation essentials:

- **A registry with typed props** (Zod/TypeBox) â€” the same schema used to validate before render and to advertise the shape to the model.
- **Strict decoding** where available, plus validation and one repair attempt.
- **Per-node error boundaries** and skeletons sized to the real layout.
- **A closed vocabulary**: no raw HTML, no style strings, no URLs.

### Additional Pitfalls
- **A schema with too many optional fields.** Models fill optional fields inconsistently; prefer required, small prop sets.
- **Rendering before validation.** A single bad node should degrade, not crash the tree.
- **Treating the JSON as trusted state.** Store it only after validation, and version it for later replay.
- **One component doing everything.** Small, single-purpose components are easier for both the model and the design system.

### Real-World Deal-Breakers
- **No catalog** → the AI can generate arbitrary components. Always define a constrained catalog.
- **No Zod schemas** → props are `any`; runtime errors from bad shapes.
- **No streaming** → the UI appears all at once after the model finishes. Stream progressively.
- **Assuming React only** → json-render supports 5+ frameworks. Use the right renderer for your stack.
