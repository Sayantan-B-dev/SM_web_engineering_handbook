## 2.2 Cascade

### Subtopic Tree
- Origin & importance (user agent < user < author < author !important < user !important < user agent !important)
- Specificity
- Source order
- Inheritance
- `!important`
- Cascade layers (`@layer`)
- `revert`, `revert-layer`, `initial`, `unset`, `inherit`

### How the Cascade Works
When multiple rules match an element, the browser resolves conflicts by checking, in order:

1. **Origin & importance** — where the CSS came from and whether `!important` is used.
2. **Specificity** — how specific the selector is.
3. **Source order** — later rules win when specificity is equal.

```css
/* Origin order (low → high) */
/* 1. User-agent styles (browser defaults) */
/* 2. User styles (browser settings) */
/* 3. Author styles (your CSS) */
/* 4. Author !important */
/* 5. User !important */
/* 6. User-agent !important */
```

### Cascade Layers (Modern)
`@layer` gives you explicit control over the cascade, independent of specificity. Layers declared later win, regardless of selector specificity.

```css
/* Declare layer order */
@layer reset, base, components, utilities;

/* Reset layer — lowest priority */
@layer reset {
  * { margin: 0; padding: 0; }
}

/* Components layer */
@layer components {
  .card { padding: 1rem; }
  .card .title { font-size: 1.5rem; }  /* high specificity but still lower than utilities */
}

/* Utilities layer — highest priority */
@layer utilities {
  .text-lg { font-size: 2rem !important; }  /* wins over .card .title */
}
```

**Real-world trick**: Use `@layer` to tame third-party CSS. Put vendor styles in an early layer, your components in a later layer, and utilities in the last layer. This eliminates `!important` wars.

### Inheritance
Some properties inherit by default (color, font-family, font-size, line-height, letter-spacing, text-align, visibility, cursor). Others don't (margin, padding, border, background, width, height, display, position).

```css
/* Force inheritance */
.child { color: inherit; }

/* Force initial value */
.child { margin: initial; }  /* margin: 0 */

/* Revert to user-agent value */
.button { all: revert; }

/* Unset: inherit if inheritable, initial if not */
.element { color: unset; }
```

**Real-world trick**: Use `inherit` on form elements to make them inherit page typography:

```css
input, button, select, textarea {
  font: inherit;
  color: inherit;
}
```

### `!important` — When (Almost Never) to Use
`!important` overrides all other declarations except user-agent and user `!important` rules. It breaks the cascade and makes debugging nightmarish.

**Legitimate uses:**
- Utility classes (`.hidden { display: none !important; }`)
- Overriding inline styles from third-party scripts you don't control
- Print stylesheets

**Real-world deal-breaker**: Using `!important` to patch specificity issues creates a cascade of `!important` everywhere. Fix specificity instead. Use `@layer` for architecture-level control.
