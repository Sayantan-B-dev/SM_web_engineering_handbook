## 2.7 Container Queries

### Subtopic Tree
- `container-type` (`normal`, `size`, `inline-size`)
- `container-name`
- `@container` rule
- Container query units (`cqw`, `cqh`, `cqi`, `cqb`, `cqmin`, `cqmax`)
- Style queries (`@container style()`)
- Fallback strategies

### Why Container Queries Matter
Media queries respond to **viewport** size. Container queries respond to the **parent container's** size. This enables truly reusable components that adapt to wherever they're placed — sidebar, main content, modal, etc.

```css
/* Define a container */
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

/* Component adapts to its container, not viewport */
.card {
  display: flex;
  flex-direction: column;
}

/* When container is wider than 400px, switch to horizontal */
@container card (min-width: 400px) {
  .card {
    flex-direction: row;
    align-items: center;
  }
}

/* When container is wider than 600px, show more detail */
@container card (min-width: 600px) {
  .card .description {
    display: block;
  }
}
```

### Container Query Units

| Unit | Relative to |
|------|------------|
| `cqw` | Container width |
| `cqh` | Container height |
| `cqi` | Container inline size |
| `cqb` | Container block size |
| `cqmin` | Smaller of cqi/cqb |
| `cqmax` | Larger of cqi/cqb |

```css
.card-title {
  font-size: clamp(1rem, 4cqi, 2rem);  /* scales with container width */
}
```

### Style Queries (Experimental)
```css
/* Query a container's custom property value */
@container style(--theme: dark) {
  .card { background: #222; color: #fff; }
}
```

### Real-World Pattern: Reusable Card
```css
/* Card works in sidebar (narrow) and main content (wide) */
.card-container {
  container-type: inline-size;
}

.card { padding: 1rem; }

@container (min-width: 300px) {
  .card { display: flex; gap: 1rem; }
  .card img { width: 100px; }
}

@container (min-width: 500px) {
  .card { padding: 2rem; }
  .card img { width: 200px; }
}
```

### Real-World Deal-Breakers
- **`container-type: size` requires explicit height** → if the container has no defined height, `size` queries fail. Use `inline-size` for width-based queries.
- **Containment side effects** → `container-type: inline-size` applies `contain: layout inline-size`, which can affect `position: fixed` descendants.
- **No container query support** → provide fallback with media queries or `@supports`.
- **Over-nesting containers** → each container adds containment; too many can hurt performance.
