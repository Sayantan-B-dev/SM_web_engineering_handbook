### BEM (Block Element Modifier)
```css
/* Block: standalone component */
.card { }

/* Element: part of a block (double underscore) */
.card__title { }
.card__image { }
.card__body { }

/* Modifier: variation (double dash) */
.card--featured { }
.card--compact { }
.card__title--large { }
```
```html
<div class="card card--featured">
  <img class="card__image" src="..." alt="...">
  <h2 class="card__title card__title--large">Title</h2>
  <div class="card__body">...</div>
</div>
```

**Pros**: Flat specificity, self-documenting, no nesting. **Cons**: Verbose class names, manual discipline required.

### Utility-First (Tailwind)
```html
<div class="flex items-center gap-4 rounded-lg bg-white p-4 shadow-md">
  <img class="h-12 w-12 rounded-full" src="..." alt="...">
  <div>
    <h2 class="text-lg font-semibold text-gray-900">Title</h2>
    <p class="text-sm text-gray-500">Description</p>
  </div>
</div>
```

**Pros**: No naming, no unused CSS, consistent spacing. **Cons**: Verbose HTML, learning curve, can look messy.

### CSS Modules
```css
/* Button.module.css */
.button { background: blue; }
.primary { composes: button; background: green; }
```
```jsx
import styles from './Button.module.css';
<button className={styles.primary}>Click</button>
```

**Pros**: Local scoping by default, works with any preprocessor. **Cons**: Requires build tooling, no dynamic theming without CSS variables.

### ITCSS (Inverted Triangle)
```
1. Settings    — variables, config
2. Tools       — mixins, functions
3. Generic     — reset, box-sizing
4. Elements    — bare HTML element styles
5. Objects     — layout patterns (no cosmetics)
6. Components  — UI components
7. Utilities   — helpers, overrides
```

**Real-world trick**: Combine ITCSS with `@layer` for explicit cascade control without specificity wars.

### CSS-in-JS (styled-components, Emotion)
```jsx
import styled from 'styled-components';

const Button = styled.button`
  background: ${props => props.primary ? '#3b82f6' : 'white'};
  color: ${props => props.primary ? 'white' : '#3b82f6'};
  padding: 0.5rem 1rem;
  border-radius: 6px;
`;

<Button primary>Click</Button>
```

**Pros**: Dynamic styles, co-located with components, scoped. **Cons**: Runtime overhead, larger bundles, SSR complexity. Modern trend is moving away from runtime CSS-in-JS toward zero-runtime solutions (Vanilla Extract, Linaria, Tailwind).

### Architecture Decision Guide

| Approach | Best For | Avoid When |
|----------|----------|-----------|
| BEM | Large teams, long-lived projects | Small projects, utility-heavy |
| Utility-first | Rapid prototyping, design systems | Highly custom designs |
| CSS Modules | Component-based apps, React | Global theming needs |
| CSS-in-JS | Dynamic theming, co-location | Performance-critical, SSR |
| Cascade layers | Any project needing cascade control | Very old browser support |

### Real-World Deal-Breakers
- **No naming convention** → `.red-text`, `.big-box`, `.left-thing` become unmaintainable.
- **Deep nesting** (Sass) → `.page .content .card .title .link` creates specificity nightmares.
- **Global namespace collisions** → generic names like `.title`, `.container`, `.button` conflict across components.
- **No design tokens** → hardcoded colors and spacing diverge across the codebase; rebranding becomes impossible.
- **Mixing paradigms** → BEM + utility + CSS-in-JS in one codebase confuses everyone. Pick one primary approach.
