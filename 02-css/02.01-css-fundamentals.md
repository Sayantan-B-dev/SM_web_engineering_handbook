- Colors: named, hex, rgb(), hsl(), oklch(), color-mix()

- Stacking context & z-index

### Syntax
A CSS rule consists of a selector and a declaration block. Each declaration is a property-value pair ending with a semicolon.

```css
/* selector { property: value; } */
.card {
  padding: 1rem;
  border-radius: 8px;
  background: #fff;
}

/* Multiple selectors */
h1, h2, h3 {
  font-family: 'Inter', sans-serif;
  line-height: 1.2;
}

/* Combinators */
.parent > .child { }        /* direct child */
.parent .descendant { }     /* any descendant */
h2 + p { }                  /* adjacent sibling */
h2 ~ p { }                  /* general sibling */
```

### Box Model (Critical)
Every element is a box with four layers: content, padding, border, and margin. The `box-sizing` property determines how width and height are calculated. With `content-box` (the default), `width` applies only to the content area, and padding and border are added on top. With `border-box`, `width` includes content, padding, and border — making layout math far more predictable.

```css
/* Universal border-box — best practice */
*, *::before, *::after {
  box-sizing: border-box;
}
```

**Real-world deal-breaker**: Without `border-box`, a `width: 100%` element with `padding: 20px` overflows its parent, causing horizontal scrollbars and broken layouts.

### Units — When to Use What

| Unit | Relative to | Best For |
|------|------------|----------|
| `px` | Absolute (CSS pixels) | Borders, small fixed values |
| `rem` | Root font-size (usually 16px) | Font sizes, spacing, layout |
| `em` | Parent font-size | Component-internal scaling (padding on buttons) |
| `%` | Parent dimension | Widths, fluid layouts |
| `vw`/`vh` | Viewport width/height | Full-screen sections (use `dvh` for mobile) |
| `dvh` | Dynamic viewport height | Mobile-safe full-height layouts |
| `svh`/`lvh` | Small/large viewport height | Fixed UI (headers/footers) that shouldn't jump |
| `ch` | Width of "0" character | Form input sizing, prose width |
| `fr` | Grid free space | Grid tracks |
| `vmin`/`vmax` | Smaller/larger viewport dimension | Responsive scaling |

```css
/* rem for typography, em for component padding */
.button {
  font-size: 1rem;        /* scales with root */
  padding: 0.75em 1.5em;  /* scales with button's font-size */
}

/* ch for readable prose */
.prose { max-width: 65ch; }

/* dvh for mobile-safe full height */
.hero { min-height: 100dvh; }

/* svh for fixed header that doesn't jump on scroll */
.toolbar { height: 100svh; position: fixed; }
```

**Trick**: `dvh` accounts for mobile browser chrome (URL bar) that appears/disappears. `100vh` on mobile causes content to be hidden behind the browser UI. Use `100dvh` for hero sections and `100svh` for fixed elements.

### Positioning Cheat Sheet

| Value | Behavior | Common Use |
|-------|----------|-----------|
| `static` | Default; ignores top/left/z-index | Normal flow |
| `relative` | Offsets from normal position; keeps space | Positioning context for children |
| `absolute` | Removed from flow; positioned relative to nearest positioned ancestor | Overlays, dropdowns, modals |
| `fixed` | Removed from flow; positioned relative to viewport | Sticky headers, floating buttons |
| `sticky` | Hybrid: relative until threshold, then fixed | Table headers, sidebar nav |

```css
/* Sticky header */
.header {
  position: sticky;
  top: 0;
  z-index: 100;
}

/* Modal overlay */
.modal-overlay {
  position: fixed;
  inset: 0;             /* shorthand for top:0; right:0; bottom:0; left:0 */
  background: rgb(0 0 0 / 0.5);
  display: grid;
  place-items: center;
}

/* Dropdown anchored to button */
.dropdown {
  position: relative;
}
.dropdown-menu {
  position: absolute;
  top: 100%;
  left: 0;
  z-index: 10;
}
```

### Stacking Context & z-index
`z-index` only works on positioned elements (or flex/grid children). A stacking context is created by: `position` + `z-index`, `opacity < 1`, `transform`, `filter`, `will-change`, `isolation: isolate`, `contain: layout/paint`, and more.

```css
/* Force a stacking context to contain children's z-index */
.card {
  isolation: isolate;  /* prevents child z-index from escaping */
}
```

**Real-world deal-breaker**: Setting `z-index: 9999` without creating a stacking context does nothing. A child's `z-index: 9999` cannot escape its parent's stacking context. If a modal is trapped behind a header, check whether a parent has `transform` or `opacity` creating an unexpected stacking context.

### Display Types

```css
/* Block: full width, new line */
div { display: block; }

/* Inline: flows with text, no width/height */
span { display: inline; }

/* Inline-block: flows with text but accepts width/height */
button { display: inline-block; }

/* Flex: one-dimensional layout */
.nav { display: flex; gap: 1rem; }

/* Grid: two-dimensional layout */
.layout { display: grid; grid-template-columns: 1fr 2fr; }

/* Contents: element's box disappears, children participate in parent layout */
.wrapper { display: contents; }

/* None: removed from layout and accessibility tree */
.hidden { display: none; }
```

**Trick**: `display: contents` is useful for semantic wrappers (like `<article>`) that shouldn't interfere with flex/grid layout. **But** it removes the element from the accessibility tree in some browsers — test with screen readers.

**Real-world deal-breaker**: `display: none` removes from accessibility tree (invisible to screen readers). `visibility: hidden` keeps it in the tree (screen readers may still see it). `opacity: 0` keeps it fully in the tree and interactive. Choose the right one for the situation.

### Overflow

```css
.container {
  overflow: hidden;      /* clip content, no scroll */
  overflow: auto;        /* scroll only when needed */
  overflow: scroll;      /* always show scrollbar */
  overflow: clip;        /* like hidden but no programmatic scroll */
  overflow-x: auto;      /* horizontal scroll only */
  overflow: visible;     /* default; content escapes */
}
```

**Real-world trick**: `overflow: auto` on a flex child prevents it from overflowing the container — flex items have `min-width: auto` by default, which can cause overflow. Set `min-width: 0` on flex children to allow shrinking.
