## Type-Safe Forms

### Subtopic Tree
- Deriving the form type from the schema (`z.infer`)
- RHF generics: `useForm<TFieldValues, TContext, TTransformedValues>`
- Input type vs output type (coercion, defaults, transforms)
- Typed field paths (`Path<T>`, `FieldPath<T>`)
- Typed `register`, `setValue`, `getValues`, `useFieldArray`
- Typed errors (`FieldErrors<T>`)
- Typed Server Action input
- No `as` casts, no duplicated interfaces

### One Type, Derived
```typescript
const schema = z.object({
  email: z.string().email(),
  age: z.coerce.number().int(), // input is a string, output is a number
});

type FormInput  = z.input<typeof schema>;  // { email: string; age: string }
type FormOutput = z.output<typeof schema>; // { email: string; age: number }
```

### Wiring It Into `useForm`
```tsx
const form = useForm<FormInput, unknown, FormOutput>({
  resolver: zodResolver(schema),
  defaultValues: { email: '', age: '' },
});

// handleSubmit receives the parsed output type
const onSubmit = form.handleSubmit((output) => {
  output.age; // number - coerced, validated, typed
});
```
`useForm` takes `TFieldValues` (what the inputs actually hold), an optional `TContext`, and `TTransformedValues` (what the resolver returns). Naming both ends is what makes coercion and transforms type-safe instead of a cast.

### Typed Paths and Errors
```tsx
import type { Path, FieldErrors } from 'react-hook-form';

function TextField({
  name,
  errors,
}: {
  name: Path<FormInput>;
  errors: FieldErrors<FormInput>;
}) {
  const { register } = useFormContext<FormInput>();
  return <input {...register(name)} aria-invalid={!!errors[name]} />;
}
```
A typo in a field name is now a compile error, and `errors[name]?.message` is typed without `any`.

### Typed Server Boundary
```typescript
'use server';
export async function createUser(input: z.input<typeof schema>) {
  const data = schema.parse(input); // narrowed to z.output
  // data.age is a number here
}
```
Use the schema's **input** type for what the caller is allowed to send, and its **output** type for what the handler works with after parsing.

### Real-World Deal-Breakers
- **Declaring the form interface by hand** → it silently drifts from the schema; derive it with `z.infer`.
- **`as FormData` / `as any` at the boundary** → an assertion, not a proof; parse instead.
- **Using the output type for `defaultValues`** → coerced fields hold a `number` in the type but an empty `<input>` holds a `string`.
- **Untyped field names (`name: string`)** → a renamed field breaks at runtime instead of at build time.
- **Casting the resolver's result** → if you need a cast, the input/output generics are wired wrong.
