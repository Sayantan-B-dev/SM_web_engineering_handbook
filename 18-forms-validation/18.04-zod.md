## 18.4 Zod

### Subtopic Tree
- Schema definition (`z.object`, `z.string`, `z.number`)
- Type inference (`z.infer`)
- `.parse()` vs `.safeParse()`
- Primitives and coercion (`z.coerce`)
- String validations (`.email()`, `.min()`, `.max()`, `.regex()`)
- Object composition (`.extend()`, `.merge()`, `.pick()`, `.omit()`)
- Arrays and tuples
- Unions and discriminated unions
- `.refine()` for cross-field validation
- `.transform()` for data manipulation
- `.pipe()` for chaining
- Error handling and custom messages
- `zodResolver` integration with RHF
- Zod v4 features: `z.uuid()`, `z.xor()`, `z.fromJSONSchema()`, `exactOptional()`

### Why Zod
Zod is a **TypeScript-first schema validation library with static type inference**. One schema works on both client and server with full TypeScript inference via `z.infer`.

### Core Patterns
```typescript
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  age: z.coerce.number().int().positive(), // coerce string → number
  role: z.enum(['admin', 'user', 'guest']).default('user'),
});

type FormData = z.infer<typeof schema>;
```

### `parse` vs `safeParse`
```typescript
// parse - throws on failure
const data = schema.parse(input);

// safeParse - returns result object (preferred for forms)
const result = schema.safeParse(input);
if (result.success) {
  result.data; // typed
} else {
  result.error.issues; // validation errors
}
```

### Cross-Field Validation (`.refine()`)
```typescript
z.object({
  password: z.string(),
  confirm: z.string(),
}).refine((data) => data.password === data.confirm, {
  message: "Passwords don't match",
  path: ['confirm'], // CRITICAL: Error appears on this field
});
```
The `path` option is **critical** - without it, the error won't map to the correct field in RHF.

### Zod v4 Features
```typescript
// Exact optional - can omit field, but NOT undefined
z.string().exactOptional()

// Exclusive union - exactly one must match
z.xor([z.string(), z.number()])

// Import from JSON Schema
z.fromJSONSchema({
  type: "object",
  properties: { name: { type: "string" } }
})

// Preferred UUID syntax (v4)
z.uuid() // instead of z.string().uuid()
```


### Server-Side Validation (CRITICAL)
```typescript
// SAME schema on server
const data = schema.parse(await req.json());
```
**Never skip server-side validation.** Client validation is for UX; server validation is for security.

### Real-World Deal-Breakers
- **No `path` in `.refine()`** → error doesn't appear on the correct field.
- **Using `.parse()` in forms** → throws on failure; use `.safeParse()` to handle errors gracefully.
- **Not coercing form inputs** → form inputs are always strings. `z.coerce.number()` is required for numeric fields.
- **Client-only validation** → trivially bypassed; always validate server-side.
- **Zod v3 patterns in v4** → `z.string().uuid()` is now `z.uuid()`. Check the migration guide.
