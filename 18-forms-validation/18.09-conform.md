## 18.3 Conform

### Subtopic Tree
- Built for Server Actions and progressive enhancement
- Native `FormData` submission
- `parseWithZod`
- Server-returned field errors
- Works without JavaScript
- Remix actions integration
- `useForm` hook
- `getInputProps`
- `getTextareaProps`
- `getSelectProps`

### The Core Differentiator
Conform is the best fit when your form is really a **Next.js or Remix server workflow**: progressive enhancement, native `FormData`, and server-returned field errors are the core design rather than an integration afterthought.

**Best for:** Next.js App Router forms built around Server Actions, Remix action forms, heavy file-upload forms (native `FormData` keeps files in the browser/server submission format).

### Basic Usage (Next.js Server Action)
```tsx
'use client';
import { useForm } from '@conform-to/react';
import { parseWithZod } from '@conform-to/zod';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

export function LoginForm({ action }) {
  const [form, fields] = useForm({
    onValidate({ formData }) {
      return parseWithZod(formData, { schema });
    },
    shouldValidate: 'onBlur',
    shouldRevalidate: 'onInput',
  });

  return (
    <form id={form.id} action={action} onSubmit={form.onSubmit} noValidate>
      <input {...getInputProps(fields.email, { type: 'email' })} />
      {fields.email.errors && <span>{fields.email.errors}</span>}
      <input {...getInputProps(fields.password, { type: 'password' })} />
      {fields.password.errors && <span>{fields.password.errors}</span>}
      <button>Login</button>
    </form>
  );
}
```

### Progressive Enhancement
Conform works **without JavaScript enabled** because it uses native form submission and `FormData`. The server validates and returns errors that Conform maps back to fields.

### Real-World Deal-Breakers
- **Only makes sense with Server Actions** → if you're building a client-heavy SPA, RHF or TanStack Form are better fits.
- **Smaller ecosystem** → 300K downloads/week vs RHF's 12M. Fewer examples, fewer integrations.
- **Framework coupling** → designed for Next.js/Remix action patterns; less useful in pure Vite SPAs.
