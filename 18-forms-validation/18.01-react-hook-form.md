## 18.1 React Hook Form

### Subtopic Tree
- `useForm` hook
- `register` for uncontrolled inputs
- `Controller` for controlled/third-party inputs
- `handleSubmit`
- `formState` (`errors`, `isSubmitting`, `isDirty`, `touchedFields`)
- `watch` vs `useWatch`
- `setValue` / `getValues`
- `setError` / `clearErrors`
- `useFieldArray`
- `useFormContext` + `FormProvider`
- `resolver` (Zod, Yup, etc.)
- Validation modes (`onSubmit`, `onBlur`, `onChange`, `onTouched`, `all`)
- `shouldUnregister` for multi-step forms
- `<FieldArray />` component (v7.81+)
- v8 beta status (not production)

### The Core Insight
React Hook Form uses **uncontrolled inputs by default**. React doesn't manage input state, so there are **no re-renders per keystroke**. Only form submission and validation trigger re-renders, making RHF significantly more performant than controlled-input approaches.

**Current stable: 7.85 (August 2026).** v8 is in beta (8.0.0-beta.3) and not stable.

### Quick Start
```bash
npm install react-hook-form@7.85.0 zod@4.3.5 @hookform/resolvers@5.9.0
```

```typescript
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

// zodResolver infers types - no need for z.infer<typeof schema>
const form = useForm({
  resolver: zodResolver(schema),
  defaultValues: { email: '', password: '' }, // REQUIRED to prevent uncontrolled warnings
});

const onSubmit = form.handleSubmit((value) => {
  console.log(value);
});

<form onSubmit={onSubmit}>
  <input {...form.register('email')} />
  {form.formState.errors.email && (
    <span role="alert">{form.formState.errors.email.message}</span>
  )}
</form>
```
`defaultValues` is **required** to prevent uncontrolled warnings.

### `register` vs `Controller`

| | `register` | `Controller` |
|--|-----------|-------------|
| Use for | Standard HTML inputs | Third-party components (React Select, date pickers, MUI) |
| Performance | Uncontrolled - best | Controlled - re-renders |
| Syntax | `<input {...register('email')} />` | `<Controller name="x" control={form.control} render={({ field }) => <CustomSelect {...field} />} />` |

**Rule:** Use `register` for native inputs; reserve `Controller` for controlled and third-party inputs while keeping native inputs uncontrolled for performance.

### Validation Modes

| Mode | When validation runs | Best for |
|------|---------------------|----------|
| `onSubmit` (default) | On submit only | Best performance |
| `onBlur` | When field loses focus | Good balance |
| `onChange` | On every keystroke | Live feedback, more re-renders |
| `onTouched` | On blur, then on change | Best UX |
| `all` | On blur + change | Maximum feedback |

```typescript
const form = useForm({
  mode: 'onBlur',
  reValidateMode: 'onChange',
});
```


### `watch` vs `useWatch`
- **`watch`** - subscribes at the form level; triggers re-render of the entire component.
- **`useWatch`** - subscribes at the field level; only re-renders the component that uses it.

```typescript
// ❌ Re-renders entire form on every change
const value = watch('email');

// ✅ Only re-renders the component using useWatch
const email = useWatch({ control: form.control, name: 'email' });
```

### `useFieldArray` - Dynamic Lists
```typescript
import { useFieldArray } from 'react-hook-form';

const { fields, append, remove, move, insert } = useFieldArray({
  control: form.control,
  name: 'items',
});

{fields.map((field, index) => (
  <div key={field.id}> {/* ALWAYS use field.id, NEVER index */}
    <input {...register(`items.${index}.name`)} />
    <button onClick={() => remove(index)}>Remove</button>
  </div>
))}
<button onClick={() => append({ name: '' })}>Add</button>
```
**Critical:** Use `field.id` as key in field arrays, **never** the index. `useFieldArray` is a custom hook for working with field arrays (dynamic forms) with optimized performance.

### `FormProvider` + `useFormContext`
```typescript
// Parent
<FormProvider {...form}>
  <FormFields />
</FormProvider>

// Deeply nested child - no prop drilling
function FormFields() {
  const { register, formState: { errors } } = useFormContext();
  return <input {...register('name')} />;
}
```
**Performance warning:** `useFormContext` with deeply nested fields can affect performance because `FormProvider` triggers a re-render whenever form state updates. Use `React.memo` to prevent unnecessary re-renders.

### Multi-Step Forms
```typescript
const form = useForm({
  shouldUnregister: true, // remove field data when unmounted
  mode: 'onTouched',
});
```
`shouldUnregister: true` removes field data when unmounted - essential for multi-step wizards where each step is a separate component.

### Real-World Deal-Breakers
- **Missing `defaultValues`** → uncontrolled warnings, form state is `undefined`.
- **Using `Controller` for every input** → unnecessary re-renders. Use `register` for native inputs.
- **Using index as key in `useFieldArray`** → field state jumps between items on reorder. Use `field.id`.
- **`useFormContext` in deeply nested forms without `React.memo`** → full-form re-renders on every change.
- **@hookform/resolvers version mismatch** → resolvers 5.x requires RHF 7.55.0+. Pair RHF 7.85 with resolvers 5.9.x.
- **Reaching for v8 in production** → v8 is beta. Stay on 7.85.
- **Not spreading `{...field}` in `Controller`** → the field doesn't work. `{...field}` is mandatory.
