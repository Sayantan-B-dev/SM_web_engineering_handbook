## 18.8 Accessibility

### Subtopic Tree
- Error messages with `role="alert"`
- `aria-invalid` on invalid fields
- `aria-describedby` linking errors to fields
- Labels (`htmlFor` + `id`)
- Focus management on submit errors
- Screen reader testing
- `aria-live` for dynamic errors

### Accessible Form Field
```tsx
function TextField({ label, name, register, errors }) {
  const error = errors[name];
  const id = `field-${name}`;
  const errorId = `${id}-error`;

  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input
        id={id}
        {...register(name)}
        aria-invalid={!!error}
        aria-describedby={error ? errorId : undefined}
      />
      {error && (
        <span id={errorId} role="alert">
          {error.message}
        </span>
      )}
    </div>
  );
}
```

### Real-World Deal-Breakers
- **Error messages without `role="alert"`** → screen readers don't announce errors.
- **No `aria-invalid`** → screen readers don't know the field is in an error state.
- **No `aria-describedby`** → error message isn't associated with the field.
- **No focus management** → on submit, focus should move to the first invalid field.
