## 18.7 Multi-Step Forms & Wizards

### Subtopic Tree
- State preservation across steps
- Per-step validation
- `shouldUnregister` in RHF
- Conditional steps
- Progress indicators
- Server Actions per step
- URL state for step tracking

### Pattern (RHF)
```tsx
function Wizard() {
  const [step, setStep] = useState(0);
  const form = useForm({
    mode: 'onTouched',
    shouldUnregister: true, // remove fields when step unmounts
  });

  const steps = [
    { component: <PersonalInfo form={form} />, schema: personalSchema },
    { component: <AddressInfo form={form} />, schema: addressSchema },
    { component: <Review form={form} />, schema: reviewSchema },
  ];

  async function next() {
    const valid = await form.trigger(); // validate current fields
    if (valid) setStep(s => s + 1);
  }

  return (
    <FormProvider {...form}>
      {steps[step].component}
      <button onClick={next}>Next</button>
    </FormProvider>
  );
}
```
`shouldUnregister: true` removes field data when a step unmounts - essential for multi-step wizards.

### Real-World Deal-Breakers
- **No `shouldUnregister`** → old step data persists, causing validation errors on hidden fields.
- **Validating entire form per step** → use `form.trigger()` to validate only current step.
- **No URL state for step** → users can't bookmark or share a step. Put step in URL (`?step=2`).
