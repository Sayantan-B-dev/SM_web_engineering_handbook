### Syntax
```typescript
interface User {
  id: number;
  name: string;
  email?: string;          // optional
  readonly createdAt: Date; // can't reassign after creation
  greet(): string;          // method
  update(data: Partial<User>): void;
}

const user: User = {
  id: 1,
  name: 'Alice',
  createdAt: new Date(),
  greet() { return `Hi, ${this.name}`; },
  update(data) { Object.assign(this, data); },
};

user.createdAt = new Date(); // ❌ Error: readonly
user.email = 'a@b.com';      // ✅ optional
```

### Index Signatures
```typescript
interface Dictionary {
  [key: string]: number;
}

const scores: Dictionary = {
  math: 95,
  science: 88,
};
// scores.english = 'A'; // ❌ Error: string not assignable to number

// Mixed: known + index signature
interface Config {
  name: string;
  [key: string]: string | number; // must include `name`'s type
}
```

### Extending Interfaces
```typescript
interface Animal {
  name: string;
}

interface Dog extends Animal {
  breed: string;
}

interface ServiceDog extends Dog {
  task: string;
}

// Multiple inheritance
interface Employee {
  company: string;
}

interface Manager extends Employee, Animal {
  reports: number;
}
```

### Declaration Merging (Unique to Interfaces)
```typescript
interface Window {
  myCustomProperty: string;
}

// Later in another file — merges with the above
interface Window {
  anotherProperty: number;
}

// Result: Window has both properties
window.myCustomProperty = 'hello';
```

### Interface vs Type Alias

| Feature | Interface | Type Alias |
|---------|-----------|------------|
| Object shapes | ✅ | ✅ |
| Union types | ❌ | ✅ |
| Intersection | via `extends` | via `&` |
| Declaration merging | ✅ | ❌ |
| Computed properties | ❌ | ✅ |
| Mapped types | ❌ | ✅ |
| Conditional types | ❌ | ✅ |
| Performance | Better (cached) | Slower for complex |
| Error messages | Better | Sometimes worse |

```typescript
// ✅ Interface for object shapes (public APIs, extensible)
interface User {
  name: string;
}

// ✅ Type for unions, mapped, conditional, computed
type Status = 'active' | 'inactive';
type Nullable<T> = T | null;
type Keys = keyof User;
```

**Real-world trick**: Use interfaces for public APIs and object shapes (better error messages, extensible). Use types for unions, utilities, and complex type operations.

### Real-World Deal-Breakers
- **Over-using declaration merging** → two files define the same interface with different shapes → confusing errors.
- **Index signature too broad** → `[key: string]: any` loses all type safety.
- **Readonly is shallow** → `readonly` prevents reassignment but nested properties remain mutable:
```typescript
interface Config {
  readonly db: { host: string };
}
const c: Config = { db: { host: 'localhost' } };
c.db = {};          // ❌ Error
c.db.host = 'x';    // ✅ Allowed! readonly is shallow
```
- **Extending interfaces with conflicting types** → `interface A { x: string }` + `interface B extends A { x: number }` → error.
- **Empty interfaces** → `interface Foo {}` accepts anything; use `type Foo = Record<string, never>` for "no properties".
