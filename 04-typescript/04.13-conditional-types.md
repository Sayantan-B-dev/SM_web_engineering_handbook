## 4.13 Conditional Types

### Subtopic Tree
- `T extends U ? X : Y`
- Distributive conditional types
- `infer` keyword
- Nested conditionals
- Recursive conditional types
- Non-distributive conditionals (`[T] extends [U]`)
- `never` handling

### Syntax
```typescript
type IsString<T> = T extends string ? true : false;

type A = IsString<'hello'>;  // true
type B = IsString<42>;       // false
type C = IsString<string>;   // true
```

### `infer` — Extract Types
```typescript
// Extract return type
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

// Extract array element type
type ElementType<T> = T extends (infer U)[] ? U : never;
type Num = ElementType<number[]>; // number

// Extract Promise value
type UnwrapPromise<T> = T extends Promise<infer U> ? U : never;
type Str = UnwrapPromise<Promise<string>>; // string

// Extract function parameters
type FirstParam<T> = T extends (first: infer F, ...rest: any[]) => any ? F : never;
type P = FirstParam<(name: string, age: number) => void>; // string
```

### Distributive Conditional Types
```typescript
// When T is a naked type parameter, conditional distributes over unions
type ToArray<T> = T extends any ? T[] : never;
type Result = ToArray<string | number>;
// Distributes: string[] | number[]

// Prevent distribution by wrapping in tuple
type ToArrayNonDist<T> = [T] extends [any] ? T[] : never;
type Result2 = ToArrayNonDist<string | number>;
// (string | number)[]
```

### Real-World Conditional Types

```typescript
// Extract non-nullable
type NonNull<T> = T extends null | undefined ? never : T;

// String or number check
type IsStringOrNumber<T> = T extends string | number ? true : false;

// Function type check
type IsFunction<T> = T extends (...args: any[]) => any ? true : false;

// Deep unwrap
type DeepUnwrap<T> = T extends Promise<infer U>
  ? DeepUnwrap<U>
  : T extends object
    ? { [K in keyof T]: DeepUnwrap<T[K]> }
    : T;

// Extract union members matching a type
type ExtractByType<T, U> = T extends U ? T : never;
type Numbers = ExtractByType<string | number | boolean, number>; // number

// Conditional based on array
type Flatten<T> = T extends Array<infer U> ? U : T;
type F1 = Flatten<string[]>;  // string
type F2 = Flatten<number>;    // number
```

### Recursive Conditional Types
```typescript
// Deep flatten
type DeepFlatten<T> = T extends Array<infer U> ? DeepFlatten<U> : T;
type Flat = DeepFlatten<number[][][]>; // number

// Path to nested property
type Path<T, K extends keyof T = keyof T> = K extends string
  ? T[K] extends object
    ? `${K}` | `${K}.${Path<T[K]>}`
    : `${K}`
  : never;

interface Config {
  db: { host: string; port: number };
  api: { url: string };
}

type ConfigPath = Path<Config>;
// 'db' | 'db.host' | 'db.port' | 'api' | 'api.url'
```

### Real-World Deal-Breakers
- **Forgetting distribution** → `T extends string ? ...` distributes over unions; sometimes you want `[T] extends [string]`.
- **`never` in distributive types** → `never extends string ? true : false` → `never` (distributes over empty union).
- **Infinite recursion** → recursive conditional types without a base case → "excessively deep" error.
- **`infer` in multiple positions** → `T extends (infer U)[] | infer U ? ...` — TS may not infer as expected.
- **Complex conditionals slow the compiler** → deeply nested conditionals cause IDE lag; simplify when possible.
