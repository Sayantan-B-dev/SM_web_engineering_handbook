## 4.10 `unknown` vs `any`

### Subtopic Tree
- `any` — opt out of type checking
- `unknown` — type-safe top type
- When to use each
- Narrowing `unknown`
- `any` propagation
- `noImplicitAny`
- `unknown` in catch blocks
- Type-safe parsing

### `any` — Dangerous
```typescript
let value: any = 'hello';
value.toFixed(2);       // ✅ no error (but crashes at runtime!)
value.nonexistent.foo;  // ✅ no error (crashes)
value();                // ✅ no error (crashes)

// any propagates — infects everything it touches
const result = value.map(x => x.foo); // result is any
```

### `unknown` — Safe
```typescript
let value: unknown = 'hello';
value.toFixed(2);  // ❌ Error: Object is of type 'unknown'

// Must narrow before use
if (typeof value === 'string') {
  value.toUpperCase(); // ✅ narrowed to string
}

if (typeof value === 'number') {
  value.toFixed(2); // ✅ narrowed to number
}
```

### Comparison

| Feature | `any` | `unknown` |
|---------|-------|-----------|
| Assignable to anything | ✅ | ❌ |
| Anything assignable to it | ✅ | ✅ |
| Can access properties | ✅ | ❌ (must narrow) |
| Can call | ✅ | ❌ (must narrow) |
| Type safety | None | Full |
| Use case | Migration, escape hatch | Safe top type |

### Real-World Patterns

```typescript
// ✅ unknown for external data
async function fetchData(url: string): Promise<unknown> {
  const res = await fetch(url);
  return res.json();
}

const data = await fetchData('/api/user');
// data is unknown — must validate before use

// Type-safe parsing with validation
function parseUser(data: unknown): User {
  if (
    typeof data !== 'object' || data === null ||
    !('name' in data) || typeof data.name !== 'string' ||
    !('email' in data) || typeof data.email !== 'string'
  ) {
    throw new Error('Invalid user data');
  }
  return { name: data.name, email: data.email };
}

// ✅ catch blocks: error is unknown (with useUnknownInCatchVariables)
try {
  await riskyOperation();
} catch (err: unknown) {
  if (err instanceof Error) {
    console.error(err.message);
  } else {
    console.error('Unknown error:', String(err));
  }
}
```

### Real-World Deal-Breakers
- **`any` in function signatures** → `function process(data: any)` — the whole function loses type safety.
- **`any` spreads silently** → `const x: any = ...; const y = x.foo.bar.baz;` — no errors, runtime crashes.
- **`as any` to silence errors** → hides real bugs. Prefer `as unknown as T` only when you're absolutely sure.
- **`unknown` in catch without narrowing** → `catch (err) { err.message }` → error. Always narrow.
- **`noImplicitAny` off** → implicit `any` everywhere; enable `strict: true` in tsconfig.

**Real-world trick**: Set `"strict": true` in `tsconfig.json` — this enables `noImplicitAny`, `strictNullChecks`, `strictFunctionTypes`, and more. Never disable it.
