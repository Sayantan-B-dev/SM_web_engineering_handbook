## 4.6 Intersections

### Subtopic Tree
- Intersection syntax (`&`)
- Combining object types
- Intersection with unions
- Conflict resolution
- Practical uses (mixins, composition)
- `never` from conflicting intersections

### Syntax
```typescript
type Person = { name: string; age: number };
type Employee = { company: string; role: string };

type StaffMember = Person & Employee;
// { name: string; age: number; company: string; role: string }

const staff: StaffMember = {
  name: 'Alice',
  age: 30,
  company: 'Acme',
  role: 'Engineer',
};
```

### Composition Pattern
```typescript
// Mixin-style composition
type Timestamped = { createdAt: Date; updatedAt: Date };
type Identifiable = { id: string };
type SoftDeletable = { deletedAt: Date | null };

type Entity = Identifiable & Timestamped & SoftDeletable;

type User = Entity & {
  name: string;
  email: string;
};

type Post = Entity & {
  title: string;
  body: string;
  authorId: string;
};
```

### Intersection with Unions (Distributive)
```typescript
type A = { a: string } | { b: number };
type B = { c: boolean };

type C = A & B;
// Distributes to:
// ({ a: string } & { c: boolean }) | ({ b: number } & { c: boolean })
// = { a: string; c: boolean } | { b: number; c: boolean }
```

### Conflicting Intersections → `never`
```typescript
type Impossible = { x: string } & { x: number };
// x: string & number = never
// The entire type becomes unusable

const bad: Impossible = { x: 'hello' }; // ❌ Error
```

### Real-World Deal-Breakers
- **Conflicting properties** → intersection of incompatible types produces `never`.
- **Intersection of primitives** → `string & number` = `never`.
- **Intersection doesn't merge methods** → two interfaces with same method name but different signatures → overload (confusing).
- **Prefer `extends` for interfaces** → `interface C extends A, B` gives better errors than `type C = A & B`.
