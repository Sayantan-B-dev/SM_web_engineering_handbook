## 4.11 Function Typing

### Subtopic Tree
- Function declarations
- Function expressions
- Arrow functions
- Optional parameters
- Default parameters
- Rest parameters
- Function overloads
- `this` typing
- Callback typing
- Generic functions
- Async functions
- Void return type

### Syntax
```typescript
// Function declaration
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Function type alias
type MathOp = (a: number, b: number) => number;
const divide: MathOp = (a, b) => a / b;

// Optional and default parameters
function greet(name: string, greeting: string = 'Hello', punctuation?: string): string {
  return `${greeting}, ${name}${punctuation ?? ''}`;
}
greet('Alice');                    // "Hello, Alice"
greet('Alice', 'Hi');              // "Hi, Alice"
greet('Alice', 'Hi', '!');         // "Hi, Alice!"

// Rest parameters
function sum(...numbers: number[]): number {
  return numbers.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // 10
```

### Function Overloads
```typescript
// Overload signatures
function createElement(tag: 'div'): HTMLDivElement;
function createElement(tag: 'span'): HTMLSpanElement;
function createElement(tag: 'input'): HTMLInputElement;
// Implementation signature (not visible to callers)
function createElement(tag: string): HTMLElement {
  return document.createElement(tag);
}

const div = createElement('div');     // HTMLDivElement
const span = createElement('span');   // HTMLSpanElement
// createElement('p');                // ❌ Error: no overload matches 'p'

// More practical: different return types based on input
function parse(input: string): string[];
function parse(input: number): number[];
function parse(input: string | number): string[] | number[] {
  if (typeof input === 'string') return input.split('');
  return [input];
}
```

### `this` Typing
```typescript
function handleClick(this: HTMLButtonElement, event: MouseEvent) {
  this.disabled = true;
}

button.addEventListener('click', handleClick);

// Explicit this for object methods
interface Counter {
  count: number;
  increment(this: Counter): void;
}

const counter: Counter = {
  count: 0,
  increment() { this.count++; },
};
```

### Callback Typing
```typescript
type Callback<T> = (error: Error | null, data?: T) => void;

function fetchData<T>(url: string, callback: Callback<T>): void {
  // ...
}

fetchData<User>('/api/user', (err, data) => {
  if (err) return console.error(err);
  console.log(data?.name); // data is User | undefined
});

// Event handler typing
const handleChange: React.ChangeEventHandler<HTMLInputElement> = (e) => {
  console.log(e.target.value);
};
```

### Async Function Typing
```typescript
async function fetchUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

// Async arrow
const fetchPost = async (id: string): Promise<Post> => {
  const res = await fetch(`/api/posts/${id}`);
  return res.json();
};

// void vs Promise<void>
function fireAndForget(): void {
  doSomethingAsync(); // returns Promise<void> but ignored
}

async function waitForIt(): Promise<void> {
  await doSomethingAsync();
}
```

### Real-World Deal-Breakers
- **Overload implementation signature must be compatible** → implementation signature isn't visible to callers but must accept all overload args.
- **`void` return type doesn't mean "no return"** → it means "return value is ignored". `(): void => 42` is valid.
- **Callback `this`** → regular callbacks lose `this`; use arrow functions or `.bind()`.
- **Optional parameters before required** → `function fn(a?: string, b: string)` → error. Optional params must come last (or use `undefined`).
- **Default parameter type inference** → `function fn(x = 10)` infers `x: number`; explicit annotation can narrow it.
- **Function type assignability** → `(a: number) => void` is assignable to `(a: number) => void`, but parameter bivariance can surprise.
