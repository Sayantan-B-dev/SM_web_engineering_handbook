## 4.1 Types

### Subtopic Tree
- Primitive types: `string`, `number`, `boolean`, `bigint`, `symbol`, `null`, `undefined`
- Special types: `any`, `unknown`, `never`, `void`, `object`
- Literal types
- Array types
- Tuple types
- Enum types
- Union & intersection types
- Type inference vs annotation
- Type assertions
- `as const`
- Template literal types

### Syntax & Core Concepts
TypeScript adds a **static type system** on top of JavaScript. Types are erased at compile time — they exist only during development.

```typescript
// Primitives
let name: string = 'Alice';
let age: number = 30;
let isActive: boolean = true;
let big: bigint = 100n;
let id: symbol = Symbol('id');
let nothing: null = null;
let notSet: undefined = undefined;

// Arrays
let numbers: number[] = [1, 2, 3];
let names: Array<string> = ['Alice', 'Bob']; // equivalent

// Tuples — fixed length, fixed types per position
let point: [number, number] = [10, 20];
let entry: [string, number] = ['age', 30];
let rgb: [red: number, green: number, blue: number] = [255, 0, 0]; // named

// Literal types — exact values
let direction: 'north' | 'south' | 'east' | 'west';
direction = 'north'; // ✅
direction = 'up';    // ❌ Error

// Type inference — TS figures it out
let inferred = 'hello'; // type: string
const literal = 'hello'; // type: 'hello' (const → literal type)
```

### `as const` — Const Assertions
```typescript
// Without as const — widened types
const config = {
  url: 'https://api.example.com',
  method: 'GET', // type: string
};
// config.method = 'POST'; // ✅ allowed (string)

// With as const — narrowest types, readonly
const config2 = {
  url: 'https://api.example.com',
  method: 'GET',
} as const;
// config2.method = 'POST'; // ❌ Error: readonly
// type: { readonly url: "https://api.example.com"; readonly method: "GET" }

// Array as const → readonly tuple
const colors = ['red', 'green', 'blue'] as const;
// type: readonly ["red", "green", "blue"]
type Color = typeof colors[number]; // 'red' | 'green' | 'blue'
```

### Template Literal Types
```typescript
type EventName = 'click' | 'focus' | 'blur';
type Handler = `on${Capitalize<EventName>}`;
// type: 'onClick' | 'onFocus' | 'onBlur'

type CSSUnit = `${number}${'px' | 'rem' | 'em' | '%'}`;
const width: CSSUnit = '100px'; // ✅
const bad: CSSUnit = '100pt';   // ❌

type Route = `/api/${string}`;
const endpoint: Route = '/api/users'; // ✅
```

### Enums (Use Sparingly)
```typescript
// Numeric enum (avoid — has quirks)
enum Direction {
  Up,    // 0
  Down,  // 1
  Left,  // 2
  Right, // 3
}

// String enum (preferred over numeric)
enum Status {
  Active = 'ACTIVE',
  Inactive = 'INACTIVE',
}

// Const enum (inlined at compile time, but has issues with isolatedModules)
const enum Color {
  Red = 'RED',
  Blue = 'BLUE',
}

// ✅ Modern alternative: union of literals + as const object
const Status = {
  Active: 'ACTIVE',
  Inactive: 'INACTIVE',
} as const;
type Status = typeof Status[keyof typeof Status]; // 'ACTIVE' | 'INACTIVE'
```

**Real-world trick**: Prefer `as const` objects over enums. Enums generate runtime code, have confusing reverse mappings (numeric), and don't tree-shake well.

### Real-World Deal-Breakers
- **Using `any` everywhere** → defeats the purpose of TypeScript; no type safety.
- **Numeric enums** → `Direction[0]` returns `'Up'` (reverse mapping), which is rarely what you want.
- **Type assertion (`as`) to silence errors** → hides real bugs. Use type guards instead.
- **`object` type** → means "any non-primitive"; use `Record<string, unknown>` or a specific interface.
- **`null` vs `undefined`** → with `strictNullChecks`, they're distinct. Use `undefined` for optional values, `null` for intentional absence.
