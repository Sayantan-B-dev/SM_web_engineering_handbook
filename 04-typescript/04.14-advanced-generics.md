## 4.14 Advanced Generics

### Subtopic Tree
- Constrained generics (`extends`)
- Default type parameters
- Generic constraints with `keyof`
- Generic inference from arguments
- Variadic tuple types
- Higher-order generics
- Generic classes with static members
- Phantom types (branded types)
- `const` type parameters (TS 5.0+)

### Constrained Generics
```typescript
// Constraint: T must have a `length` property
function logLength<T extends { length: number }>(item: T): T {
  console.log(item.length);
  return item;
}

// Constraint: K must be a key of T
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

// Constraint: T must be constructable
function createInstance<T extends new (...args: any[]) => any>(
  Ctor: T,
  ...args: ConstructorParameters<T>
): InstanceType<T> {
  return new Ctor(...args);
}
```

### Default Type Parameters
```typescript
interface ApiResponse<T = unknown, E = Error> {
  data?: T;
  error?: E;
}

// Can use without type args
const res: ApiResponse = { data: 'anything' };
const userRes: ApiResponse<User> = { data: user };
```

### Variadic Tuple Types
```typescript
// Prepend to tuple
type Prepend<T extends any[], U> = [U, ...T];
type WithString = Prepend<[number, boolean], string>; // [string, number, boolean]

// Append
type Append<T extends any[], U> = [...T, U];
type WithNumber = Append<[string, boolean], number>; // [string, boolean, number]

// Practical: typed curry
type Curry<T extends any[], R> =
  T extends [infer First, ...infer Rest]
    ? (arg: First) => Curry<Rest, R>
    : R;

function curry<T extends any[], R>(
  fn: (...args: T) => R
): Curry<T, R> {
  return function curried(...args: any[]): any {
    if (args.length >= fn.length) return fn(...args as T);
    return (...next: any[]) => curried(...args, ...next);
  } as Curry<T, R>;
}

const add = (a: number, b: number, c: number) => a + b + c;
const curriedAdd = curry(add);
curriedAdd(1)(2)(3); // 6 — fully typed
```

### `const` Type Parameters (TS 5.0+)
```typescript
// Without const — T inferred as string[]
function tuple<T extends readonly unknown[]>(...args: T): T {
  return args;
}
const t1 = tuple('a', 'b', 'c'); // string[]

// With const — T inferred as readonly ['a', 'b', 'c']
function tuple2<const T extends readonly unknown[]>(...args: T): T {
  return args;
}
const t2 = tuple2('a', 'b', 'c'); // readonly ['a', 'b', 'c']
```

### Branded / Phantom Types
```typescript
// Nominal typing via branding
type Brand<T, B> = T & { readonly __brand: B };

type UserId = Brand<string, 'UserId'>;
type PostId = Brand<string, 'PostId'>;
type USD = Brand<number, 'USD'>;
type EUR = Brand<number, 'EUR'>;

function getUser(id: UserId) { /* ... */ }

const userId = 'abc' as UserId;
getUser(userId);  // ✅
// getUser('abc'); // ❌ string not assignable to UserId

// Currency safety
function addUSD(a: USD, b: USD): USD {
  return (a + b) as USD;
}
// addUSD(usd, eur); // ❌ Error
```

### Higher-Order Generics (Type-Level Functions)
```typescript
// A type that takes a type and returns a type
type Mapper<T> = {
  map<U>(fn: (value: T) => U): Mapper<U>;
  value(): T;
};

function createMapper<T>(value: T): Mapper<T> {
  return {
    map<U>(fn: (value: T) => U): Mapper<U> {
      return createMapper(fn(value));
    },
    value: () => value,
  };
}

const result = createMapper(5)
  .map(n => n * 2)
  .map(n => `Result: ${n}`)
  .value(); // 'Result: 10'
```

### Real-World Deal-Breakers
- **Over-constraining** → `T extends string` when you meant "any type" limits reuse.
- **Generic inference failure** → complex generics infer `unknown` or `{}`; provide explicit type arguments.
- **Too many type parameters** → APIs with 4+ generics are hard to use; consider splitting.
- **Branded types require casting** → `'abc' as UserId` is unchecked. Validate at runtime in the constructor/parser.
- **Variadic tuples with optional elements** → complexity grows quickly; test thoroughly.
- **`const` type parameters on mutable arrays** → may produce `readonly` types that conflict with mutable expectations.
