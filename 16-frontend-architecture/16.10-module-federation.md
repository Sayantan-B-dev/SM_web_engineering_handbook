## 16.10 Module Federation

### Subtopic Tree
- Webpack 5 feature

- Federation in Next.js (`@module-federation/nextjs-mf`)

### Key Concepts
- **Host** - the app that consumes remotes.
- **Remote** - an independently deployed app that exposes modules.
- **`remoteEntry.js`** - a manifest describing the remote's exposed modules.
- **Shared** - dependencies that must be singletons (React, React DOM, state stores).

### Shared Dependencies
```javascript
shared: {
  react: {
    singleton: true,          // only one instance across host + remotes
    requiredVersion: '^19.0.0',
    eager: false,             // lazy load
  },
  'react-dom': { singleton: true, requiredVersion: '^19.0.0' },
  zustand: { singleton: true }, // shared state store
}
```

**`singleton: true` is critical for React.** Two React copies = broken hooks.

### Dynamic Remotes
```javascript
// Load remote URL at runtime (from config API)
const remoteUrl = await fetch('/api/remotes').then(r => r.json());
const Checkout = React.lazy(() => import(`${remoteUrl.checkout}/Cart`));
```

### Real-World Deal-Breakers
- **No `singleton: true` on React** → hooks break.
- **Version mismatches** → `requiredVersion` conflicts cause runtime errors or silent fallback.
- **Remote down** → host crashes unless you wrap in error boundaries with fallbacks.
- **No type sharing** → host and remote drift on shared types; runtime errors.
- **No caching strategy for `remoteEntry.js`** → every page load fetches the manifest.
