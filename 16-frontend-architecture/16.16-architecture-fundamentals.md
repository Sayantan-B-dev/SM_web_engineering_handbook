### Core Mental Model
Architecture is **the set of decisions that are expensive to reverse**. Folder structure is not architecture. Naming conventions are not architecture. Architecture is: "Should this be a monolith or micro-frontends?", "Where does state live?", "What's the boundary between teams?", "How does data flow?"

```text
Decisions cheap to change:     filenames, CSS approach, test framework
Decisions expensive to change: monolith vs micro-frontends, state ownership,
                               deployment topology, team boundaries
```

### Conway's Law
> "Any organization that designs a system will produce a design whose structure is a copy of the organization's communication structure." - Melvin Conway, 1967

If you have 3 teams, you'll get 3 modules. If you want a modular architecture but have one giant team, you'll get a monolith. **Inverse Conway Maneuver**: restructure teams to get the architecture you want.

### Real-World Deal-Breakers
- **Copying architecture from a FAANG blog** → their constraints aren't yours. A 500-person company needs micro-frontends; a 5-person startup needs a monorepo.
- **No architectural drivers written down** → every decision becomes a debate. Document: scale targets, team size, deployment cadence, compliance requirements.
- **Architecture by accident** → you don't choose; it emerges from thousands of small decisions. Choose deliberately.
