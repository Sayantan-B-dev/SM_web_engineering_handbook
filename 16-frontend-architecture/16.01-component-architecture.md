### Atomic Design (Brad Frost)
```text
Atoms:        Button, Input, Label, Icon
Molecules:    SearchField (Input + Button), FormField (Label + Input + Error)
Organisms:    Header, ProductCard, CommentThread
Templates:    Layouts with slots (no real data)
Pages:        Templates + real data
```

**Caveat**: Atomic Design is a **mental model**, not a folder structure. Teams that literally create `atoms/`, `molecules/`, `organisms/` folders often regret it - the categories blur as components grow.

### Presentational vs Container (Still Useful, Renamed)
```jsx
// ✅ Modern equivalent: hook + pure component
function useUser(id) {
  // data logic
  return { user, loading, error };
}

function UserCard({ user }) {  // pure, testable, no data logic
  return <div>{user.name}</div>;
}

function UserCardContainer({ id }) {
  const { user, loading } = useUser(id);
  if (loading) return <Skeleton />;
  return <UserCard user={user} />;
}
```

### Compound Components
```jsx
<Select value={value} onChange={setValue}>
  <Select.Trigger>Choose...</Select.Trigger>
  <Select.Options>
    <Select.Option value="a">Option A</Select.Option>
    <Select.Option value="b">Option B</Select.Option>
  </Select.Options>
</Select>
```
Parent and children share implicit state via Context. Consumers get full layout control.

### Component API Design Principles
1. **Simple API for common cases; escape hatches for complex.**
2. **Sensible defaults.**
3. **Composition over configuration.**
4. **Consistency with HTML/native semantics.**
5. **Accessible by default.**

```jsx
// ❌ Boolean prop explosion
<Button primary secondary danger loading disabled rounded outlined />
// 2^7 = 128 combinations

// ✅ Variant enums
<Button variant="primary" size="lg" loading />
// 5 variants × 3 sizes × 2 states = 30 well-defined combos
```

### Real-World Deal-Breakers
- **Boolean prop explosion** → 15 boolean props on a Button. Use enums/variants.
- **Components > 300 lines** → split into subcomponents.
- **No testable pure components** → testing requires mocking APIs and providers. Extract a pure component.
- **Copy-paste components** → two Card components with 90% overlap. Consolidate or compose.
- **No component ownership** → everyone edits everything; no one feels responsible.
