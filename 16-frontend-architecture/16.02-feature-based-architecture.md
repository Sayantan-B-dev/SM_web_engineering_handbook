## 16.2 Feature-Based Architecture

### Subtopic Tree
- Feature folders (vertical slices) vs type folders (horizontal slices)
- Feature boundaries
- Public API per feature (`index.ts` barrel)
- Feature ownership
- Cross-feature imports (what's allowed)
- Shared modules (`shared/`, `common/`, `lib/`)
- Feature flags
- Feature deletion

### Feature Folders vs Type Folders

```text
❌ Type-based (horizontal)              ✅ Feature-based (vertical)
src/                                    src/
├── components/                         ├── features/
│   ├── UserCard.tsx                    │   ├── auth/
│   ├── PostCard.tsx                    │   │   ├── components/
│   └── CommentCard.tsx                 │   │   ├── hooks/
├── hooks/                              │   │   ├── api/
│   ├── useUser.ts                      │   │   ├── types.ts
│   ├── usePosts.ts                     │   │   └── index.ts
│   └── useComments.ts                  │   └── posts/
├── api/                                │       ├── components/
│   ├── user.ts                         │       ├── hooks/
│   ├── posts.ts                        │       ├── api/
│   └── comments.ts                     │       └── index.ts
└── types/                              ├── shared/
    ├── user.ts                         │   ├── components/
    ├── post.ts                         │   ├── hooks/
    └── comment.ts                      │   └── utils/
                                        └── app/
```

### Public API per Feature
```typescript
// features/auth/index.ts - the ONLY public surface
export { LoginForm } from './components/LoginForm';
export { useAuth } from './hooks/useAuth';
export type { User, AuthState } from './types';

// ✅ Other features import from the public API
import { useAuth, LoginForm } from '@/features/auth';

// ❌ Reaching into internals - forbidden
import { useAuth } from '@/features/auth/hooks/useAuth';
```

**Enforce with ESLint:**
```json
{
  "rules": {
    "no-restricted-imports": ["error", {
      "patterns": ["@/features/*/components/*", "@/features/*/hooks/*"]
    }]
  }
}
```

### Cross-Feature Imports
**Rule:** Features can import from `shared/`, but **features cannot import from other features** - or only via a documented, approved boundary.

```text
✅ features/auth  → shared/utils
✅ features/posts → shared/components
❌ features/posts → features/auth/components/LoginForm
✅ features/posts → features/auth (public API only, if allowed)
```

If two features need each other, extract the shared logic into a third module.

### Feature Deletion
A well-designed feature can be **deleted by removing its folder and its route**. If deleting a feature requires touching 20 files across the codebase, the boundary is broken.

### Real-World Deal-Breakers
- **Type-based folders at scale** → `components/` grows to 200 files; nobody knows what depends on what.
- **No public API per feature** → every import path is possible; refactoring breaks everything.
- **Cross-feature imports everywhere** → features become entangled; you have a monolith with extra folders.
- **Feature with 500 files** → the boundary is too coarse; split into sub-features.
