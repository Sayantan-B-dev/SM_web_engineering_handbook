## 16.3 Modular Frontend

### Subtopic Tree

### Layered Architecture
```text
┌─────────────────────────────────┐
│  UI Layer (React components)    │  ← depends on application
├─────────────────────────────────┤
│  Application Layer (use cases)  │  ← depends on domain
├─────────────────────────────────┤
│  Domain Layer (business logic)  │  ← depends on nothing
├─────────────────────────────────┤
│  Infrastructure (APIs, storage) │  ← implements domain interfaces
└─────────────────────────────────┘
```

**Dependency rule:** Dependencies point **inward**. The domain layer knows nothing about React, HTTP, or the database.

```typescript
// domain/user.ts - pure business logic
export class User {
  constructor(public id: string, public email: string) {}
  canPost(): boolean { return this.email.endsWith('@company.com'); }
}

// application/createPost.ts - use case
export function createPost(user: User, post: Post, repo: PostRepository) {
  if (!user.canPost()) throw new Error('Not allowed');
  return repo.save(post);
}

// infrastructure/PostApiRepository.ts - adapter
export class PostApiRepository implements PostRepository {
  async save(post: Post) { await fetch('/api/posts', { ... }); }
}

// ui/NewPostForm.tsx - UI
function NewPostForm() {
  const { user } = useAuth();
  const repo = usePostRepository();
  return <form onSubmit={() => createPost(user, post, repo)}>...</form>;
}
```

### Hexagonal Architecture (Ports & Adapters)
- **Ports** = interfaces defined by the domain (`PostRepository`).
- **Adapters** = implementations (`PostApiRepository`, `PostLocalStorageRepository`, `PostMockRepository`).

The domain doesn't know if it's talking to an API, IndexedDB, or a test mock.

### Real-World Deal-Breakers
- **Circular dependencies** → module A imports B, B imports A. Breaks tree-shaking, causes `undefined` at runtime. Enforce with `madge` or `dependency-cruiser`.
- **UI logic in the domain layer** → `User` class imports React. Domain should have zero framework dependencies.
- **No interfaces between layers** → swapping the API client requires changing every call site.
- **Layers without boundaries** → "layered" architecture where everything imports everything.
