### Design Tokens - Three Tiers
```css
/* Tier 1: Primitive tokens (raw values) */
--color-blue-500: #3b82f6;
--color-gray-100: #f3f4f6;
--space-4: 16px;

/* Tier 2: Semantic tokens (purpose) */
--color-primary: var(--color-blue-500);
--color-background: var(--color-gray-100);
--space-button-padding: var(--space-4);

/* Tier 3: Component tokens (specific) */
--button-primary-bg: var(--color-primary);
--button-primary-padding: var(--space-button-padding);
```

**Why three tiers?** Changing the brand color means editing one primitive token. Changing "primary" usage means editing one semantic token. Apps consume component tokens.

### Figma ↔ Code Sync
Tools like **Tokens Studio** export Figma variables to CSS/JSON. Changes to design tokens flow to code automatically. Without this, designers and developers diverge.

### Real-World Deal-Breakers
- **Component library without a design system** → 15 shades of blue, 8 spacing values. Inconsistency everywhere.
- **Tokens defined only in Figma** → engineers hardcode hex values. Design system is aspirational, not real.
- **No contribution model** → 3 designers and 20 engineers fight over every component change.
- **No deprecation strategy** → old components never removed; library grows forever.
- **Design system as a gatekeeper** → slow approvals kill adoption. Teams fork components.
