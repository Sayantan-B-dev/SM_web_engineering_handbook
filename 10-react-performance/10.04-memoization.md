### The Three Memoization Tools

```jsx
// React.memo - component-level shallow compare
const Child = React.memo(function Child({ data, onUpdate }) { ... });

// useMemo - cache a computed value
const filtered = useMemo(
  () => items.filter(i => i.name.includes(query)),
  [items, query]
);

// useCallback - stable function reference
const handleClick = useCallback(() => setCount(c => c + 1), []);
```

### The Memoization Tax
Every `useMemo`/`useCallback` asks React to: store previous inputs and result, compare current inputs shallowly on every render, and decide whether to reuse. That comparison **is not free** - it's memory + CPU on every render.

```jsx
// ❌ Over-memoization - string concat is trivially fast
function UserProfile({ user }) {
  const displayName = useMemo(
    () => `${user.firstName} ${user.lastName}`,
    [user.firstName, user.lastName]
  );
  const handleClick = useCallback(() => console.log('clicked'), []);
}
// The comparison overhead exceeds the saved work.
```

### When Memoization Actually Helps
1. **Expensive computation** - sorting, filtering, or transforming large datasets.
2. **Referential stability for downstream memo** - passing a stable object/function to a `React.memo` child.
3. **Effect dependency stability** - a value used in a `useEffect` dep array that must not change.

```jsx
// ✅ Good useMemo - expensive stats
const statistics = useMemo(() => {
  return {
    mean: dataset.reduce((a, b) => a + b, 0) / dataset.length,
    median: [...dataset].sort((a, b) => a - b)[Math.floor(dataset.length / 2)],
    standardDeviation: calculateStdDev(dataset),
  };
}, [dataset]);
```

### Shallow Equality Trap
`React.memo` uses `Object.is` for each prop. Passing a new object literal (`style={{...}}`), a new array (`items={[...]}`), or an inline function (`onClick={() => {}}`) **defeats memoization completely** - the new reference fails the comparison.

```jsx
// ❌ Memo useless - new object/function every render
<MemoChild style={{ color: 'red' }} onClick={() => handle()} />

// ✅ Stable references
const style = useMemo(() => ({ color: 'red' }), []);
const handleClick = useCallback(() => handle(), []);
<MemoChild style={style} onClick={handleClick} />
```

### React Compiler Era
React Compiler (React 19+) can automatically apply memoization at build time, making most manual `useMemo`/`useCallback`/`React.memo` unnecessary. The compiler analyzes reactive scopes and inserts cache boundaries more granularly than manual memoization. However, manual memoization is still needed when:
- Referential stability is required for correctness (effect deps, third-party libs).
- The compiler bailed out on that component (Rules of React violation).
- You need memoization the compiler can't prove safe.

### Real-World Deal-Breakers
- **Memoizing everything "to be safe"** → makes the app slower due to comparison overhead.
- **`React.memo` with inline props** → memo never fires; pure waste.
- **`useMemo` with unstable deps** (object/array literal) → recomputes every render.
- **Using `useMemo` for side effects** → `useMemo` must be pure; use `useEffect`.
- **Removing all manual memo after enabling compiler without validating** → the compiler may bail out on some components, leaving them unmemoized.
