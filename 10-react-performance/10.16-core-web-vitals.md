## 10.16 Core Web Vitals

### Subtopic Tree
- LCP (Largest Contentful Paint) - loading
- INP (Interaction to Next Paint) - interactivity
- CLS (Cumulative Layout Shift) - visual stability
- TTFB (Time to First Byte) - server response
- Measuring with `web-vitals` library
- Field data (CrUX) vs lab data (Lighthouse)
- React-specific optimizations for each metric

### The Three Metrics

| Metric | Good | Needs Improvement | Poor |
|--------|------|-------------------|------|
| **LCP** | ≤ 2.5s | 2.5-4.0s | > 4.0s |
| **INP** | ≤ 200ms | 200-500ms | > 500ms |
| **CLS** | ≤ 0.1 | 0.1-0.25 | > 0.25 |
| **TTFB** | < 600ms | 600-1000ms | > 1000ms |

### Measuring in React
```javascript
import { onLCP, onINP, onCLS } from 'web-vitals';

onLCP((metric) => sendToAnalytics('LCP', metric.value));
onINP((metric) => sendToAnalytics('INP', metric.value));
onCLS((metric) => sendToAnalytics('CLS', metric.value));
```
Use the `web-vitals` library - it matches Chrome's field measurement.

### React Optimizations for LCP
- Preload the LCP image (`fetchpriority="high"`, no lazy loading).
- Preload critical fonts.
- Eliminate render-blocking resources.
- Avoid client-side rendering for above-the-fold content (use SSR/SSG).
- Optimize server TTFB.

### React Optimizations for INP
- Break up long tasks with `startTransition` / `useDeferredValue`.
- Use `useTransition` for non-urgent updates.
- Virtualize long lists.
- Offload heavy work to Web Workers.
- Keep event handlers fast.

### React Optimizations for CLS
- Always set `width` and `height` on images.
- Reserve space for dynamic content (skeletons matching final layout).
- Use `font-display: swap` + `size-adjust` for fonts.
- Avoid inserting content above existing content.

### Real-World Deal-Breakers
- **Client-side rendering above the fold** → LCP is delayed until JS loads + renders; use SSR/SSG.
- **Lazy-loading the hero image** → hurts LCP directly.
- **No `width`/`height` on images** → CLS spikes.
- **Blocking the main thread with long tasks** → INP suffers.
- **Measuring only with Lighthouse** → lab data ≠ field data; use CrUX or `web-vitals` for real users.
