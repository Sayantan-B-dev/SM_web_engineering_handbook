## 10.11 Network Performance

### Subtopic Tree
- HTTP/2 / HTTP/3 multiplexing
- CDN for static assets
- Compression (gzip, Brotli)

- Service worker caching
- Network waterfall analysis
- TTFB optimization

### Key Techniques

**Compression:**
Enable Brotli (better than gzip) on your CDN/server. A typical JS bundle compresses 70-80%.

**Cache headers:**
```
Cache-Control: public, max-age=31536000, immutable
```
For hashed assets (e.g., `main.a1b2c3.js`), cache forever. For HTML, cache briefly.

**Resource hints:**
```html
<link rel="preconnect" href="https://cdn.example.com" />
<link rel="dns-prefetch" href="https://analytics.example.com" />
<link rel="preload" as="font" type="font/woff2" href="/fonts/Inter.woff2" crossorigin />
```
`preconnect` establishes the TCP/TLS connection early; `dns-prefetch` resolves DNS; `preload` fetches critical resources with high priority.

**CDN:**
Serve static assets from a CDN edge close to the user. Reduces TTFB and improves LCP.

### Network Waterfall
Open Chrome DevTools → Network tab. Look for:
- **Serial requests** - request A blocks request B. Parallelize.
- **Large uncompressed responses** - check `Content-Encoding`.
- **Slow TTFB** - server or CDN issue.
- **Render-blocking resources** - CSS/JS in `<head>` without `defer`/`async`.

### Real-World Deal-Breakers
- **No compression** → 3-4× larger downloads.
- **No cache headers on hashed assets** → users re-download unchanged files.
- **`preconnect` to too many origins** → browser opens many sockets; only preconnect to critical origins.
- **No CDN** → users far from origin get slow TTFB.
- **`preload` for non-critical resources** → wastes bandwidth; only preload LCP assets and critical fonts.
