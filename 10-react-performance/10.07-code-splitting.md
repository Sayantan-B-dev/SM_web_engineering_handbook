### How It Works
Code splitting divides your JS bundle into smaller chunks that load on demand. The standard approach uses dynamic `import()` to create split points; bundlers like Webpack and Vite generate separate chunks automatically.

```javascript
// Static import - bundled into main chunk
import { heavyFeature } from './heavy-feature';

// Dynamic import - separate chunk, loaded on demand
button.addEventListener('click', async () => {
  const { heavyFeature } = await import('./heavy-feature');
  heavyFeature();
});
```

### Webpack Magic Comments
```javascript
// Named chunk → readable filename
const module = await import(/* webpackChunkName: "analytics" */ './analytics');

// Prefetch → download during browser idle time
const module = await import(
  /* webpackPrefetch: true */
  /* webpackChunkName: "settings" */
  './Settings'
);

// Preload → download with high priority alongside parent chunk
const module = await import(
  /* webpackPreload: true */
  /* webpackChunkName: "critical" */
  './CriticalFeature'
);
```
Named chunks produce readable filenames; prefetch downloads chunks during idle; preload hints the browser to fetch immediately.

### Vendor Chunk Splitting
```javascript
// vite.config.js
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
          charts: ['recharts', 'd3'],
        },
      },
    },
  },
});
```
Separating vendor code means app updates don't invalidate the vendor chunk → better caching.

### Measuring
```bash
# Webpack
npx webpack --profile --json > stats.json
npx webpack-bundle-analyzer stats.json

# Vite
npx vite build --mode production
# Check dist/ for multiple .js files
```
The bundle analyzer shows which chunks are large and whether splitting is working.

### Real-World Deal-Breakers
- **Barrel files (`index.ts` re-exports)** → can pull the entire library into the main chunk, defeating tree shaking and splitting.
- **`manualChunks` too aggressive** → too many tiny chunks = more HTTP requests and worse performance.
- **No `sideEffects: false` in `package.json`** → bundler assumes all modules have side effects → can't tree-shake.
- **Splitting a chunk that's always used** → extra request with no benefit.
- **Ignoring chunk size warnings** → a single chunk > 250KB (gzipped) is a red flag.
