## 10.14 CPU Bottlenecks

### Subtopic Tree
- Long tasks (>50ms) blocking the main thread
- Expensive render computations
- Large lists without virtualization
- Synchronous JSON parsing
- Heavy effects on mount
- Breaking up work with time slicing / `startTransition`
- Web Workers for off-main-thread work
- Profiling with Chrome Performance panel

### How to Identify
In Chrome Performance panel, look for **long tasks** (red triangles) and **long flame chart entries**. If typing lags or scrolling jitters, it's CPU-bound.

### Common CPU Bottlenecks in React

**1. Expensive render computation:**
```jsx
// ❌ Filtering/sorting a large list on every render
const sorted = [...items].sort(compare);

// ✅ Memoize (or use React Compiler)
const sorted = useMemo(() => [...items].sort(compare), [items]);
```

**2. Large lists without virtualization:**
Rendering 10,000 DOM nodes is slow. Virtualize:
```jsx
import { FixedSizeList } from 'react-window';
<FixedSizeList height={600} itemCount={10000} itemSize={35} width="100%">
  {({ index, style }) => <div style={style}>{items[index]}</div>}
</FixedSizeList>
```
Only visible rows are rendered.

**3. Long tasks in event handlers:**
```jsx
// ❌ 500ms synchronous work blocks the UI
function handleClick() {
  const result = expensiveCalculation(largeDataset);
  setResult(result);
}

// ✅ Break into chunks with time slicing
import { startTransition } from 'react';
function handleClick() {
  startTransition(() => {
    const result = expensiveCalculation(largeDataset);
    setResult(result);
  });
}
```

**4. Heavy effects:**
```jsx
// ❌ Blocks mount
useEffect(() => {
  parseHugeJSON(hugeString); // 200ms
}, []);

// ✅ Offload to Web Worker
useEffect(() => {
  const worker = new Worker('./parser.worker.js');
  worker.postMessage(hugeString);
  worker.onmessage = (e) => setData(e.data);
  return () => worker.terminate();
}, []);
```

### Real-World Deal-Breakers
- **Rendering 10,000 list items** → main thread blocked for seconds; always virtualize large lists.
- **Synchronous JSON.parse on huge payloads** → blocks the thread; parse in a Worker or stream.
- **No `startTransition` for expensive state updates** → input becomes laggy.
- **Heavy work in render body** → runs on every re-render; memoize or move to effects/workers.
- **Assuming React can fix algorithmic complexity** → O(n²) logic is still O(n²) with React.
