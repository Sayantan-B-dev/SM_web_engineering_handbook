### Tools

| Tool | For |
|------|-----|
| `webpack-bundle-analyzer` | Webpack - treemap of chunks |
| `rollup-plugin-visualizer` | Vite/Rollup - sunburst/treemap |
| `source-map-explorer` | Any source-map-based build |
| `treeshake-check` | CLI - detects tree-shaking issues in Vite/Webpack/Rollup/esbuild |

```bash
# Vite
npm install -D rollup-plugin-visualizer
```

```javascript
// vite.config.js
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [react(), visualizer({ gzipSize: true, brotliSize: true })],
});
```
The visualizer opens an interactive treemap showing exactly which packages dominate your bundle.

### What to Look For
- **Large vendor chunks** - is a single library (moment, lodash, MUI icons) bloating the bundle?
- **Duplicate packages** - two versions of React or a library pulled in transitively.
- **App code in vendor chunk** - misconfigured `manualChunks`.
- **Unused code** - imports you thought were tree-shaken but aren't.
- **Gzip vs raw** - a 1MB raw file may gzip to 200KB; focus on gzipped size.

### CI Bundle Budget
```json
// package.json
{
  "scripts": {
    "check-bundle": "bundlesize"
  },
  "bundlesize": [
    { "path": "./dist/main.*.js", "maxSize": "150 kB" },
    { "path": "./dist/vendor.*.js", "maxSize": "200 kB" }
  ]
}
```
Fails CI if the bundle exceeds the budget - prevents silent regressions.

### Real-World Deal-Breakers
- **Never analyzing the bundle** → you don't know what's shipping; a single bad import can add 500KB.
- **Optimizing raw size instead of gzipped** → misplaces effort; gzipped size is what users download.
- **Ignoring duplicates** → two copies of a library (e.g., `lodash` + `lodash-es`) double the cost.
- **No bundle budget in CI** → every PR slowly grows the bundle; no one notices until it's 2MB.
