### React DevTools Profiler
The Profiler tab in React DevTools records a session while you interact with the app, then shows a flamegraph of which components rendered, how long they took, and why. Wide bars = slow components; tall stacks = deep trees; frequent re-renders = wasted work.

**Workflow:**
1. Open React DevTools → Profiler tab.
2. Click record (●).
3. Interact with the app.
4. Stop (■) and analyze the flamegraph.

Click any component to see the exact reason it rendered: **props changed**, **hook changed**, **state changed**, or **parent rendered**.

### `<Profiler>` Component
Wrap any subtree to measure it programmatically:

```jsx
import { Profiler } from 'react';

function onRenderCallback(
  id,              // component name
  phase,           // "mount" | "update"
  actualDuration,  // time spent rendering this update
  baseDuration,    // estimated time without memoization
  startTime,       // when React began rendering
  commitTime,      // when React committed
) {
  if (actualDuration > 100) {
    // ship to Sentry / DataDog / analytics
    reportSlowRender({ id, phase, actualDuration });
  }
}

<Profiler id="Dashboard" onRender={onRenderCallback}>
  <Dashboard />
</Profiler>
```

`baseDuration` is gold: it estimates how long the subtree would take **without any memoization**. Compare it to `actualDuration` to know whether your memoization is paying off.

### Nested Profilers
Wrap each section separately to isolate slow areas:

```jsx
<Profiler id="Header" onRender={onRenderCallback}><Header /></Profiler>
<Profiler id="Sidebar" onRender={onRenderCallback}><Sidebar /></Profiler>
<Profiler id="Content" onRender={onRenderCallback}><Content /></Profiler>
```

### Production Profiling
Profiling adds overhead and is disabled in production by default. To profile in production, you need a **special profiling build** of React (`react-dom/profiling`).

### Why Did You Render (Community Tool)
For pinpointing *why* a component re-rendered:

```bash
npm install @welldone-software/why-did-you-render
```

```javascript
// wdyr.js
import React from 'react';
if (process.env.NODE_ENV === 'development') {
  const whyDidYouRender = require('@welldone-software/why-did-you-render');
  whyDidYouRender(React, { trackAllPureComponents: true });
}
```

### Real-World Deal-Breakers
- **Profiling with default dev build** → overhead skews numbers; use the profiling build for accurate results.
- **Profiling "in production" without the profiling build** → no data; profiling is opt-in.
- **Sending every render to analytics** → `onRender` fires often; filter for slow renders only (`actualDuration > 100`).
- **Wrapping the whole app in one Profiler** → you see total time but not *which* part is slow. Use nested Profilers.
- **Trusting `baseDuration` as ground truth** → it's an estimate; use it comparatively, not absolutely.
