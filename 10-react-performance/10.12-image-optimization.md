### The LCP Image Rule
The Largest Contentful Paint element is often a hero image. It must load as fast as possible:
- **Don't lazy-load it** - `loading="eager"` (or omit `loading`).
- **Add `fetchpriority="high"`** - hints the browser to prioritize it.
- **Preload it** - `<link rel="preload" as="image" href="/hero.webp" fetchpriority="high" />`.

### Responsive Images
```jsx
<img
  src="image-800.jpg"
  srcSet="image-400.jpg 400w, image-800.jpg 800w, image-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, (max-width: 1200px) 50vw, 800px"
  width="800"
  height="600"
  loading="lazy"
  alt="Description"
/>
```
`srcSet` provides width variants; `sizes` tells the browser how wide the image will render; the browser picks the best variant. `width` and `height` reserve space → no CLS.

### Modern Formats
```html
<picture>
  <source srcset="image.avif" type="image/avif" />
  <source srcset="image.webp" type="image/webp" />
  <img src="image.jpg" width="800" height="600" alt="..." />
</picture>
```
AVIF compresses 50% better than WebP; WebP is 30% better than JPEG. Serve AVIF with WebP/JPEG fallback.

### Framework Helpers
- **Next.js `<Image>`** - automatic format negotiation, lazy loading, width/height enforcement, blur placeholder.
- **React `@page-speed/img`** - computes pixel-perfect `src`, DPR-aware `srcset`, `sizes` on the client.

### Real-World Deal-Breakers
- **Lazy-loading the LCP image** → directly hurts LCP; keep it eager + `fetchpriority="high"`.
- **No `width`/`height`** → CLS when the image loads and pushes content down.
- **Serving 2MB JPEGs** → modern formats + CDN resizing cut this by 80%+.
- **`srcSet` without `sizes`** → browser picks wrong variant; may download a 1200px image for a 300px slot.
- **No CDN for images** → large images served from origin are slow globally.
