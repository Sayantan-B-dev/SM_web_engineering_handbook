### How It Works
Bundlers analyze `import`/`export` statements, build a dependency graph, and eliminate exports that aren't imported anywhere.

```typescript
// utils.ts
export const add = (a, b) => a + b;
export const subtract = (a, b) => a - b;
export const heavyFunction = () => { /* 50KB of code */ };

// main.ts - only `add` is used
import { add } from './utils';
console.log(add(2, 3));
// Result: only `add` is bundled; heavyFunction is eliminated
```

### The Two Big Tree-Shaking Killers

**1. Side-effect imports:**
```javascript
// ❌ Prevents tree shaking of the entire module
import 'some-library';
import { specificFunction } from 'some-library';

// ✅ Only import what you need
import { specificFunction } from 'some-library';
```

**2. Barrel files (re-export everything):**
```typescript
// ❌ components/index.ts
export * from './Button';
export * from './Input';
export * from './Modal'; // 200KB heavy component

// main.ts - imports Button, but barrel may pull Modal too
import { Button } from './components';

// ✅ Direct imports
import { Button } from './components/Button';
```
Barrel files can prevent tree shaking because the bundler can't always prove the re-exports are side-effect-free.

### `sideEffects` in `package.json`
```json
{
  "name": "my-lib",
  "sideEffects": false
}
```
Tells the bundler: "if an export isn't used, it's safe to remove, even if the module has top-level code." For apps with CSS:
```json
{
  "sideEffects": ["*.css", "*.scss"]
}
```

### Verifying
Use `webpack-bundle-analyzer` or `rollup-plugin-visualizer`. If a library you only partially use appears at full size, tree shaking failed - check for barrel files, CommonJS, or missing `sideEffects: false`.

### Real-World Deal-Breakers
- **CommonJS modules** → cannot be tree-shaken; always bundled in full. Use ESM or `lodash-es` instead of `lodash`.
- **Namespace imports (`import * as X`)** → often defeats tree shaking; use named imports.
- **`sideEffects` missing from package.json** → bundler conservatively includes everything.
- **Barrel files** → the #1 cause of "why is this 500KB library in my bundle?"
- **Default exports from libraries** → named exports tree-shake more reliably.
