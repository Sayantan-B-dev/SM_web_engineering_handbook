## 10.2 React DevTools

### Subtopic Tree

### What Each Tab Does
- **Components tab** - inspect the tree, select a component, view/override props and state, see its hooks.
- **Profiler tab** - record renders, analyze timing, see render causes.

### The Most Important Toggles
1. **"Highlight updates when components render"** - flashes borders on re-rendering components. Instantly shows wasted renders.
2. **"Record why each component rendered while profiling"** - adds reasons (props/hooks/state/parent) to the flamegraph.

These two settings turn the Profiler from "something is slow" into "this exact component re-rendered because this exact prop changed".

### "Memo ✨" Badge (React Compiler)
With React Compiler enabled, optimized components get a "Memo ✨" badge. If a component you expected to be optimized has no badge, the compiler skipped it - usually due to a Rules of React violation.

### Performance Tracks (React 19.2+)
React 19.2 introduced **Performance Tracks** in DevTools - a new profiling view that shows the relationship between React's internal work and the browser's own Performance panel tracks. It helps diagnose "did React cause this paint, or the browser?".

### Real-World Deal-Breakers
- **Never enabling "why did this render"** → you see slowness but not cause; you guess instead of fixing.
- **Using DevTools on a production build** → component names are minified; keep a source map or use a development build to diagnose.
- **Assuming "Highlight updates" is definitive** → it highlights renders, not DOM changes. A render may produce no DOM changes.
- **No badge ≠ broken** → "Memo ✨" only appears on components the compiler actually optimized.
