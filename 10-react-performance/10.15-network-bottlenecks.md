## 10.15 Network Bottlenecks

### Subtopic Tree
- Large bundle size (main chunk)
- Serial request waterfalls
- Slow TTFB / server response
- Uncached API responses
- Excessive API calls (fetch on every keystroke)
- Missing compression
- No CDN
- Render-blocking resources

### How to Identify
In Chrome Network panel, look for:
- **Large transferred sizes** (bundle > 250KB gzip).
- **Waterfalls** - request B starts after A finishes.
- **Slow TTFB** - server takes > 600ms to first byte.
- **Render-blocking CSS/JS** - blocking first paint.

### Common Bottlenecks

**1. Large bundle:**
```javascript
// ❌ Imports entire library
import _ from 'lodash';

// ✅ Named import from ESM version
import { debounce } from 'lodash-es';
```

**2. Fetch on every keystroke:**
```jsx
// ❌ Fires an API call on every keystroke
useEffect(() => {
  fetch(`/api/search?q=${query}`);
}, [query]);

// ✅ Debounce
const debouncedQuery = useDebounce(query, 300);
useEffect(() => {
  if (debouncedQuery) fetch(`/api/search?q=${debouncedQuery}`);
}, [debouncedQuery]);
```

**3. Serial requests:**
```jsx
// ❌ Sequential - 3 round trips
const user = await fetchUser(id);
const posts = await fetchPosts(user.id);
const comments = await fetchComments(posts[0].id);

// ✅ Parallel where possible
const [user, posts] = await Promise.all([fetchUser(id), fetchPosts(id)]);
```

**4. No caching:**
Use React Query / SWR to cache API responses and avoid refetching on every mount.

### Real-World Deal-Breakers
- **Fetching on every keystroke** → high CPU + network usage; debounce.
- **No HTTP caching for API responses** → refetches on every navigation; use stale-while-revalidate.
- **Large uncompressed responses** → enable Brotli/gzip on the server/CDN.
- **Blocking the bundle with non-critical JS** → defer analytics, chat widgets, etc.
- **No CDN for static assets** → global users experience high TTFB.
