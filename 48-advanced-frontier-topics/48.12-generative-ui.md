## 48.12 Generative UI

### Subtopic Tree
- Vercel's json-render (open sourced January 2026)
- Streaming JSON → React Server Components
- Incremental JSON stream parser with brace-depth counting
- Recursive, discriminated `UINode` Zod schema as the contract
- @assistant-ui/react-generative-ui: streaming props, `$status` prop
- CopilotKit: render agent work as live React components

### The Architecture
The data flow is linear: **LLM token stream → incremental JSON parser → Zod validation → component registry → React tree**. The architecture uses an **incremental JSON stream parser** with brace-depth counting, a **recursive discriminated `UINode` Zod schema** as the contract between LLM output and React rendering, and **hydration into type-safe React Server Component trees** in Next.js.

### Streaming Props
By default a component renders only once its props have fully arrived, so `render` always sees complete props. Opt into rendering from **partial props** with `streamProperties`. When you do, `render` receives an injected `$status` prop that discriminates the props: while `"streaming"` they are `Partial`, and once complete they are full.

### Deeper Explanation: Generated Interfaces Need Governance

The frontier of generative UI is a component registry plus a strict schema plus a renderer that never executes model output. That combination makes the feature safe by construction: the model composes known components with validated props, and anything unexpected degrades to a fallback.

What the frontier adds is *persistence and evaluation*: store the validated spec (not the rendered HTML) so views can be diffed, themed, and re-rendered; keep a fixture set of prompts with expected node types so prompt/catalogue changes are measurable; and treat the generated tree as untrusted data throughout the pipeline. Accessibility and layout stability (fixed skeletons) are part of the definition of done.

### Additional Pitfalls
- **Rendering model output as HTML or JS.** Injection and unstylable UI in one step.
- **Storing rendered output instead of the spec.** You lose re-rendering, theming, and migration.
- **No evaluation fixtures.** Regressions become invisible and prompt changes are guesswork.
- **Unbounded node counts.** Cap nodes, depth, and rows in the schema.
- **Accessibility bolted on.** Semantic components and live regions must be the only path.

### Real-World Deal-Breakers
- **`dangerouslySetInnerHTML` for LLM output** → XSS vulnerability. Use typed component trees.
- **No Zod validation at the stream boundary** → malformed JSON crashes the renderer.
- **No component registry** → JSON types don't map to React components.
- **No layout shift prevention** → content reflows as it streams in.
