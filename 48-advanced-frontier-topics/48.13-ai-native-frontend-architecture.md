## 48.13 AI-Native Frontend Architecture

### Subtopic Tree
- **Intent-based architecture** (replacing responsive/adaptive)
- **Zero-UI paradigm** and predictive prefetching
- Component registry + tool definitions + backend agent
- Four-layer generative UI system: component library → tool definitions → agent → deployment
- Latency < 200ms
- Generative UI as "the new frontend"

### The Architectural Shift
With 2026, the paradigm shifts fundamentally from **Responsive to Intent-based Architecture**. The Responsive Web addressed device constraints. The Adaptive Web reacted to network conditions. The **Intent-based Web now addresses cognitive constraints** - instead of hard-coding state transitions, the interface adapts to user intent.

### The Four-Layer System
A generative UI system has **four layers, each with clear responsibilities**:
1. **Component library layer** - the catalog of approved components
2. **Tool definitions layer** - what the agent can do
3. **Backend agent layer** - the LLM and orchestration
4. **Deployment layer** - serving the UI with < 200ms latency

### Deeper Explanation: Latency Bands Shape The Architecture

An AI-native frontend is designed around three latency bands (<200 ms, 0.5-3 s, >3 s) and each demands different mechanics: instant features avoid spinners entirely, interactive features stream with optimistic placeholders, and long-running work runs as a durable background job with progress and resumption. That is why the architecture looks the way it does: keys and prompts on the server, retrieval behind a permission-filtered API, streams resumed by run id, and rendering componentised so generated and streamed regions update independently.

The corollary for teams: this is backend-shaped infrastructure on the frontend. Cost accounting, rate limits, evals, and observability are part of the feature, not later work.

### Additional Pitfalls
- **One rendering strategy for all bands.** Instant work with spinners and long work blocking navigation are both failures.
- **No durable run state.** Refresh or navigation loses the generation.
- **Model calls scattered across components.** No central retries, timeouts, or cost tracking.
- **Synchronous long generations on a request path.** Platform timeouts will find you.
- **No evals or flags.** Prompt and model changes ship unmeasured and unkillable.

### Real-World Deal-Breakers
- **No component registry** → the AI can't map intents to components.
- **No intent representation** → the AI guesses what the user wants.
- **No latency budget** → generative UI with > 200ms latency feels broken.
