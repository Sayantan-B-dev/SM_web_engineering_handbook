### What Local-First Is
Local-first is an approach that **combines the collaboration features of cloud software with the data ownership and performance of traditional local applications**. The technical foundation is the **sync engine**.

### The Three-Layer Architecture
A typical local-first React stack has three components:
1. **Client-side UI and database** - React + SQLite WASM
2. **Syncing engine** - PowerSync
3. **Database of record** - Supabase

### Trellis Architecture
Trellis is organized around a **local-first runtime core with optional compatibility adapters**. It must work fully without a cloud server. Local graph state is primary. Relays and gateways are optional adapters.

### Deeper Explanation: The Device Becomes The Primary Replica

Local-first systems invert the default: the local store is authoritative for the user's experience, and sync reconciles replicas. That delivers instant interactions, offline capability, and data ownership, and it requires convergent data structures, durable storage, and a sync protocol with conflict semantics.

The engineering checklist that comes from production experience: choose CRDT types per data shape rather than one universal type; persist updates incrementally and compact periodically; design permissioning (which member may write which field) at the operation level; keep an export path; and measure document load time, memory, and sync payloads as product metrics.

### Additional Pitfalls
- **A schema that cannot merge.** Concurrent edits silently overwrite; model state as mergeable data.
- **No compaction.** Update logs and tombstones grow until load times suffer.
- **Permissions bolted on afterwards.** Local writes need authorisation at the operation level.
- **No export.** Data ownership is the promise; make it real.
- **Ignoring storage eviction.** A cleared store must be recoverable from the server or peers.

### Real-World Deal-Breakers
- **No sync engine** → local-first without sync is just a local database.
- **Server as source of truth** → you're building offline-first, not local-first.
- **No conflict resolution strategy** → concurrent edits overwrite each other. Use CRDTs.
