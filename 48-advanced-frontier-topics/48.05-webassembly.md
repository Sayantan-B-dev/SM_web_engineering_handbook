### What's New in WASM 3.0
Wasm 3.0 - **stable in Chrome 119+, Firefox 120+, and Safari 18.2+** - ships **WasmGC, Memory64, Relaxed SIMD**, and threads unlocked by SharedArrayBuffer (which requires the COOP and COEP headers). WebAssembly 3.0 brings GC, threads, Memory64, and SIMD to browsers. As of late 2025, these aren't proposals anymore - they ship in all major browsers.

### WASM GC
WASM GC support means that managed languages like **Kotlin, Dart, and eventually Java can compile to WebAssembly without shipping their own garbage collector**.

### Threads
Threads + Atomics are **stable with COOP/COEP**. Real parallel workers backed by SharedArrayBuffer. Wasm structs cannot be used with Wasm's existing concurrency features and are prevented by the language's type system from being shared between multiple threads. A broad industrial project named **shared-everything threads** seeks to relax these restrictions.

### Deeper Explanation: WASM At The Frontier Means Multi-Language And Portable Compute

Beyond "a faster kernel", the frontier uses WASM as a **portable compute substrate**: the same module runs in a browser worker, an edge function, and a Node service; managed languages compile to it via GC types; and WASI components compose modules across languages. That changes deployment topology â€” compute can move to wherever the data or the user is.

The practical judgement remains a budget question (startup, boundary cost, memory) and a maintenance question (who writes and debugs the Rust/C++ at 2am). The pattern that pays: extract a stable, hot, well-bounded kernel with existing native code, wrap it behind a typed interface, and keep the JS fallback.

### Additional Pitfalls
- **Rewriting logic in Rust without a measured bottleneck.** Most slowness is architectural, not arithmetic.
- **Ignoring startup and boundary costs.** Compilation and marshalling can exceed the kernel win.
- **No fallback.** Unsupported devices and CSP restrictions happen.
- **Debugging without symbols.** Keep a debug build per release for readable stack traces.
- **Multi-language complexity without ownership.** Someone must own the toolchain in CI.

### Real-World Deal-Breakers
- **SharedArrayBuffer without COOP/COEP** → throws. Requires cross-origin isolation headers.
- **Assuming WASM is always faster** → interop overhead makes small tasks slower than JS.
- **WASM on the main thread** → still blocks UI. Always run in a Web Worker.
