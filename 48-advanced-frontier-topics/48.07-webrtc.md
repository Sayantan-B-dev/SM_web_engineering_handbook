### What's New in 2026
QWBP (QR-WebRTC Bootstrap Protocol) is a binary protocol for establishing WebRTC DataChannel connections using **QR codes as the signaling channel**. QWBP achieves a **97.79% reduction in signaling payload size** compared to standard Session Description Protocol (SDP), enabling **serverless peer-to-peer connections through a visual, air-gapped channel**.

### rtc.io - Socket.io Ergonomics
rtc.io provides WebRTC peer-to-peer media and data channels with **socket.io-style ergonomics**: `socket.emit('chat', msg)` on a peer-to-peer DataChannel.

### p2p_dart - Serverless P2P
A production-ready Dart package for **serverless peer-to-peer networking** using WebRTC data channels and a **Kademlia-based DHT**, enabling secure, encrypted, NAT-traversing direct connections without a central server.

### Deeper Explanation: Peer Transport For Collaboration And Media

At the frontier, WebRTC is the transport for data that must not pass through a server: collaborative document updates, live media, screen sharing, and local-network cooperation. Its constraints shape the products built on it â€” NAT traversal needs TURN, connections drop when networks change, and authorisation must be designed rather than inherited from a request context.

The architecture that works: signalling as a thin, authenticated relay; per-document or per-room encryption so the relay cannot read content; presence and sync on separate channels with different TTLs; and a fallback path (server relay) when peers cannot connect. Treat "direct connection" as an optimisation, and always have a working relay path.

### Additional Pitfalls
- **No TURN.** A meaningful share of pairs cannot connect directly; the feature fails silently for them.
- **Trusting the relay with plaintext.** The relay is infrastructure, not a peer; encrypt end to end.
- **No reconnection strategy.** Networks change constantly; ICE restart and resync are mandatory.
- **Mesh topologies at scale.** Uplink grows quadratically; use an SFU for media.
- **Signalling carrying state.** Keep it a dumb relay; application state belongs elsewhere.

### Real-World Deal-Breakers
- **No TURN server** → WebRTC fails behind symmetric NATs (corporate networks). 10-20% of connections need TURN.
- **No signaling fallback** → if the signaling server goes down, no new connections can be established.
- **Unreliable data channel for critical data** → `{ ordered: false }` drops packets. Use ordered/reliable for chat.
