## 48.9 CRDTs

### Subtopic Tree
- Yjs: most widely used, optimized for collaborative text editing using YATA algorithm
- Automerge: JSON-document CRDT, Rust core + JS bindings, full history
- Loro: Rust + JS/Wasm, sequence/text/list/map/tree, movable tree, based on Replayable Event Graph
- Loro is the **fastest in benchmarks but youngest in ecosystem maturity**
- Loro leads in every category except initial WASM load time
- Yjs wins when bundle size matters (no WASM overhead)

### Deeper Explanation: Convergence As A Design Primitive

At the frontier, CRDTs are used as a general convergence primitive beyond text: presence, counters, sets, ordered lists, and configuration all become mergeable types so features work offline and across peers without a central arbiter. The engineering questions move from "how do I merge?" to "how do I bound the metadata?".

Practical guidance: compose library-provided types rather than writing merge functions; classify each field by merge semantics (LWW for scalars, OR-Set for membership, RGA/YATA text for sequences); keep documents scoped (per file/board) so load time and memory stay bounded; and instrument sync payload sizes plus convergence checks in tests (fuzz with random operation orderings).

### Additional Pitfalls
- **Hand-written merge logic.** Convergence bugs appear only under unusual interleavings.
- **Unbounded metadata.** Per-element ids and tombstones dominate memory; compact and GC.
- **One CRDT for everything.** Different data shapes want different types.
- **No convergence testing.** Fuzz random operations and assert identical final state.
- **Ignoring authorisation.** Convergent data still needs access control at the operation level.

### Real-World Deal-Breakers
- **Choosing Yjs for JSON-heavy apps** → Automerge is better for JSON-shaped data.
- **Choosing Automerge for text-heavy apps** → Yjs has a speed advantage for text.
- **No garbage collection** → tombstones accumulate indefinitely.
