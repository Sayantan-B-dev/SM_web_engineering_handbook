### What It Is
React Compiler hit **stable v1.0 in October 2025**. It analyzes your components at build time and inserts memoization automatically, eliminating most manual `useMemo` and `useCallback` calls. The React Compiler (babel-plugin-react-compiler, v1.0 stable as of early 2026) can automatically memoize components and their inline values, eliminating the need for many manual `React.memo`, `useMemo`, and `useCallback` declarations while also catching re-render cases that manual memoization missed. React 19's compiler is the **primary approach to render optimization in 2026**.

### How It Works
The compiler **analyzes component code at build time and inserts memoization automatically**. It uses reactive scopes and cache slots (`_c` hook) to achieve granular memoization that is more precise than manual memoization - including **conditional memoization**, which manual memoization cannot do.

### Rust Port (Meta, 2026)
Meta has ported the React Compiler to **Rust** for faster builds and tighter toolchain integration. The React Compiler, formerly known as React Forget, automatically memoizes components and hooks so developers no longer need to reach for `useMemo` and `useCallback` by hand.

### Next.js 16 Integration
**Next.js 16 ships built-in support for the React Compiler**, which automatically inserts memoization at build time via Babel - eliminating unnecessary re-renders across all client components with **zero manual code changes**.

### Deeper Explanation: From Rules To Guarantees

The React Compiler analyses components and hooks and inserts memoisation automatically, which removes the manual `useMemo`/`useCallback`/`memo` ritual. The important shift is from convention to enforcement: code that violates the Rules of React (mutating props/state during render, conditional hooks, reading mutable values during render) cannot be safely optimised, so the compiler either bails out or reports the violation.

Practical adoption: enable it project-wide, run the lint rules it ships, and treat the reported violations as bugs (they are the same patterns that cause subtle re-render bugs today). Expect the biggest wins in components with many children or expensive derived values; expect no change in code that was already fine.

### Additional Pitfalls
- **Expecting it to fix slow algorithms.** It removes redundant work, not expensive work; a 50 ms function call is still 50 ms.
- **Ignoring its diagnostics.** Bailed-out components silently keep the old behaviour.
- **Mutating props/state during render.** It is a correctness bug that also blocks optimisation.
- **Measuring nothing.** Compare render counts and interaction latency before/after.
- **Removing memoisation blindly in a large codebase.** Migrate gradually and watch for regressions.

### Real-World Deal-Breakers
- **Relying on referential equality for correctness** → the compiler may memoize differently than you expect. If your app depends on a specific object identity, the compiler can break it.
- **Manual memoization that doesn't match compiler output** → the compiler bails out of the **entire component** to avoid breaking your code. Remove manual memo when the compiler handles it.
- **Not checking the "Memo ✨" badge in DevTools** → components may be silently skipped due to Rules of React violations.
