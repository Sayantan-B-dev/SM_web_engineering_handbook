### The Core Threat
With WebMCP, web developers can build and expose structured tools to AI agents instrumenting the browser. Agents in the browser can operate within a **user's authenticated session**, so it's critical that agent developers design protections against **malicious input from untrusted content**. Security researchers have repeatedly demonstrated prompt injection attacks against agentic state-of-the-art LLMs, and the prevalence of attacks on the web is increasing.

### The Defense Pipeline
```
User input → [scan] → LLM → [gate] → tool → [scan result] → LLM → [scan] → response
```
Every stage has a validation gate. The scan validates LLM inputs before they reach the model. The gate validates tool calls before execution. The result scan validates tool outputs before they re-enter the model.

### Deeper Explanation: Assume The Model Is Compromised

The frontier posture is to treat model output and everything that can influence it (retrieved documents, files, tickets, web pages) as untrusted input, and to design what it can reach rather than what it will say. That inverts the usual approach: instead of asking the model to behave, you bound its capabilities, validate its output, and require approval for consequential effects.

The layers: a separate agent identity with narrow scopes, structural input/output validation, capability-limited tools with per-call authorisation, human gates on destructive actions, sandboxed execution with egress allow-lists, and full observability of prompts and tool calls. ### Additional Pitfalls
- **Guardrails implemented only in prompts.** Text is not enforcement.
- **Tool arguments trusted.** Validate and authorise per call against the session, not the payload.
- **Untrusted content in a tool-enabled loop.** The classic indirect-injection configuration.
- **No audit trail.** Without logs of prompts and tool calls, incidents are unexplainable.
- **No incident playbook.** Kill switches, revocation, and user communication need to exist before an incident.

### Real-World Deal-Breakers
- **No prompt-injection guard** → malicious input reaches the model. Block or review before execution.
- **Excessive agency** → the agent has too many permissions. Use least privilege.
- **System prompt leakage** → secrets in the system prompt are extracted. Never put API keys in prompts.
- **No output validation** → tool outputs carry injection payloads back into the model.
