## 15.9 TanStack Router - File-Based vs Code-Based

### Subtopic Tree
- File-based: `createFileRoute`, file structure = route tree
- Code-based: `createRoute({ getParentRoute, path })`
- Both support identical core features
- File-based requires less code, better DX
- Route tree generation
- `autoCodeSplitting` in file-based mode

### File-Based (Recommended)
File-based routes are the recommended option for most projects. The plugin watches the routes directory and generates the tree. Routes are declared with `createFileRoute("/path")`, the path string is checked against the file's location, and **autoCodeSplitting splits each route for free**.

```
src/routes/
├── __root.tsx          # root layout
├── index.tsx           # /
├── about.tsx           # /about
├── users/
│   ├── index.tsx       # /users
│   └── $userId.tsx     # /users/:userId
└── posts/
    ├── index.tsx       # /posts
    └── $postId.tsx     # /posts/:postId
```

### Code-Based
Code-based routes are assembled by hand with `createRoute({ getParentRoute, path })`. Use this when you prefer to define routes programmatically or need full control over routing logic. No plugin required.

```tsx
const rootRoute = createRootRoute({ component: Root });
const usersRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/users',
});
const userRoute = createRoute({
  getParentRoute: () => usersRoute,
  path: '$userId',
  loader: ({ params }) => fetchUser(params.userId),
});
const routeTree = rootRoute.addChildren([usersRoute.addChildren([userRoute])]);
```

### Real-World Deal-Breakers
- **Mixing file-based and code-based** → confusing; pick one.
- **File-based without `autoCodeSplitting`** → all routes in one bundle.
- **Code-based without `getParentRoute`** → route not nested; URL doesn't match.
