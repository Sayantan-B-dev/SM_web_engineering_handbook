### Core Mental Model
A router is a **URL-to-UI mapping system**. It listens to URL changes, matches the URL against a route tree, loads any required data, and renders the matched component tree. Modern routers also handle data loading, mutations, error boundaries, and code splitting - they are application architecture frameworks, not just navigation helpers.

```jsx
// The route tree is the application contract
const routes = [
  { path: '/', Component: Home },
  { path: '/users', Component: UsersLayout, children: [
    { index: true, Component: UsersIndex },
    { path: ':userId', Component: UserPage },
  ]},
];
```

### Navigation Lifecycle
Every navigation in a data router follows this sequence:

| Phase | What happens |
|-------|-------------|
| **Match** | URL is matched against the route tree |
| **Load** | Route loaders run (data fetching) |
| **Render** | Components render with loaded data |
| **Commit** | DOM is updated, pending states resolve |

React Router v7 performs **synchronous route matching, executes loaders, then renders route components** in the most optimistic manner without introducing waterfalls.

### Real-World Deal-Breakers
- **Treating routing as "just navigation"** → missing data loading, error handling, and code splitting capabilities.
- **Manual URL parsing** → `window.location.pathname.split('/')` is fragile; routers handle path params, search params, and encoding.
- **No route boundaries** → a single loader error crashes the entire page.
- **Fetching in `useEffect` instead of loaders** → waterfall (render → effect → fetch → re-render).
