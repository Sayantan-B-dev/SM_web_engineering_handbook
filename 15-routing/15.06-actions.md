## 15.6 Actions

### Subtopic Tree
- `action` function (route property)
- `useActionData` hook
- Called from `<Form>`, `useSubmit`, `useFetcher`
- Automatic revalidation of all loaders after action
- Form data parsing (`request.formData()`)
- Redirect after action
- Error handling in actions
- `useNavigation` for pending states

### Basic Action
```tsx
async function createPostAction({ request }) {
  const formData = await request.formData();
  const post = await db.post.create({
    data: { title: formData.get('title'), body: formData.get('body') },
  });
  return redirect(`/posts/${post.id}`);
}

function NewPostPage() {
  const actionData = useActionData();
  return (
    <Form method="post">
      <input name="title" />
      <textarea name="body" />
      <button type="submit">Publish</button>
    </Form>
  );
}

const router = createBrowserRouter([
  { path: '/posts/new', action: createPostAction, Component: NewPostPage },
]);
```

### Automatic Revalidation
When an action completes, **all loader data on the page is revalidated**. The list updates automatically.

### `useNavigation` for Pending States
```tsx
function NewPostPage() {
  const navigation = useNavigation();
  const isSubmitting = navigation.state === 'submitting';
  return (
    <Form method="post">
      <input name="title" />
      <button disabled={isSubmitting}>
        {isSubmitting ? 'Publishing...' : 'Publish'}
      </button>
    </Form>
  );
}
```

### Real-World Deal-Breakers
- **No `redirect` after action** → user stays on form; may resubmit on refresh.
- **Not returning anything from action** → `useActionData()` is `undefined`.
- **Action without error handling** → server error crashes the route.
- **Forgetting `method="post"` on `<Form>`** → defaults to GET; action not called.
