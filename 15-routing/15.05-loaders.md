## 15.5 Loaders

### Subtopic Tree
- `loader` function (route property)
- `useLoaderData` hook
- Loader args: `params`, `request`, `context`
- Loader execution timing (before render)
- Automatic revalidation after actions
- `shouldRevalidate` for opt-out
- `clientLoader` for client-side loading
- Parallel loader execution
- Loader error handling (throw `data()`)

### Basic Loader
Route loaders provide data to route components **before they are rendered**.

```tsx
import { useLoaderData, createBrowserRouter } from 'react-router';

async function userLoader({ params }) {
  const user = await getUser(params.userId);
  if (!user) throw data('User not found', { status: 404 });
  return { user };
}

function UserPage() {
  const { user } = useLoaderData();
  return <h1>{user.name}</h1>;
}

const router = createBrowserRouter([
  { path: '/users/:userId', loader: userLoader, Component: UserPage },
]);
```

### Automatic Revalidation
Route actions allow server-side data mutations with **automatic revalidation of all loader data on the page** when called from `<Form>`, `useFetcher`, and `useSubmit`.

### `shouldRevalidate` (Opt-Out)
```tsx
function shouldRevalidate({ currentUrl, nextUrl, formAction, defaultShouldRevalidate }) {
  // return false to skip revalidation
  return defaultShouldRevalidate;
}
```

### Real-World Deal-Breakers
- **Fetching in `useEffect` instead of loader** → waterfall; render → effect → fetch → re-render.
- **Not throwing on error** → loader returns `undefined`; component crashes later.
- **Loader without error boundary** → error propagates to nearest boundary; if none, app crashes.
- **Sequential loaders** → React Router runs loaders in parallel by default; don't `await` them sequentially.
