## 15.3 Nested Routing

### Subtopic Tree
- Parent-child route relationships
- `<Outlet>` for rendering child routes
- Layout routes (no path segment)
- Index routes (default child)
- Pathless routes (grouping without URL change)
- Relative vs absolute paths
- Layout persistence across navigation

### How Nested Routing Works
Routes nest inside parent routes. Child routes render through the `<Outlet>` in the parent component. Index routes render into their parent's `<Outlet>` as the default child.

```jsx
const router = createBrowserRouter([
  {
    path: '/',
    Component: Root, // renders <Outlet />
    children: [
      { index: true, Component: Home },        // renders at "/"
      { path: 'about', Component: About },      // renders at "/about"
      {
        path: 'dashboard',
        Component: DashboardLayout,             // nested layout
        children: [
          { index: true, Component: DashboardOverview },
          { path: 'settings', Component: Settings },
        ],
      },
    ],
  },
]);

function Root() {
  return (
    <div>
      <Navbar />
      <Outlet /> {/* child routes render here */}
      <Footer />
    </div>
  );
}
```

### Layout Routes
Layout routes create new nesting for their children **without adding segments to the URL**. Use a pathless route:

```jsx
{
  path: '/',
  Component: Root,
  children: [
    {
      // no path - layout route
      Component: AuthLayout,
      children: [
        { path: 'login', Component: Login },
        { path: 'register', Component: Register },
      ],
    },
  ],
}
```

### Real-World Deal-Breakers
- **Missing `<Outlet>` in parent** → child routes never render.
- **Using absolute paths in nested routes** → breaks nesting; use relative paths.
- **Index route without `index: true`** → parent renders without a child at the root path.
- **Layout re-rendering on every navigation** → layouts persist; if state resets, check that the parent component isn't remounting.
