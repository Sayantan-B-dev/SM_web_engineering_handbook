## 15.4 Data Routers

### Subtopic Tree
- `createBrowserRouter`
- `<RouterProvider>`
- Route objects (vs `<Route>` elements)
- `loader` and `action` as route properties
- `ErrorBoundary` per route
- `HydrateFallback`
- `lazy` for code splitting
- `shouldRevalidate`
- `dataStrategy` for custom loader/action execution

### `createBrowserRouter`
`createBrowserRouter` creates a data router that manages application path via `history.pushState` and `history.replaceState`. This is the recommended router for all React Router web applications and is used for data-driven applications with loaders and actions.

```jsx
import { createBrowserRouter, RouterProvider } from 'react-router';

const router = createBrowserRouter([
  {
    path: '/',
    Component: Root,
    ErrorBoundary: RootError,
    loader: rootLoader,
    children: [
      {
        path: 'users',
        Component: UsersLayout,
        children: [
          { index: true, Component: UsersIndex, loader: usersLoader },
          { path: ':userId', Component: UserPage, loader: userLoader },
        ],
      },
    ],
  },
]);

function App() {
  return <RouterProvider router={router} />;
}
```

### `lazy` for Code Splitting
```jsx
const router = createBrowserRouter([
  {
    path: '/app',
    lazy: async () => {
      const [Component, loader] = await Promise.all([
        import('./app'),
        import('./app-loader'),
      ]);
      return { Component, loader };
    },
  },
]);
```

### Real-World Deal-Breakers
- **`createBrowserRouter` without `<RouterProvider>`** → router not mounted.
- **Mixing `element` and `Component`** → inconsistent; `Component` is the v7 convention.
- **No `HydrateFallback` with client loaders** → blank screen during client-side data loading.
- **`lazy` without error boundary** → chunk load failure crashes the route.
