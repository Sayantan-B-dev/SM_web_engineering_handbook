## 15.12 TanStack Router - Preloading

### Subtopic Tree
- Preload strategies: `intent`, `viewport`, `render`
- `preloadDelay` for debouncing
- Preloading code + data
- `router.preload` global config
- Link-level `preload` prop
- Cancellation on hover end / viewport exit

### Preload Strategies

| Strategy | Trigger |
|----------|---------|
| `'intent'` | Hover or `touchstart` on `<Link>` |
| `'viewport'` | Intersection Observer - link enters viewport |
| `'render'` | On mount |
| `false` | Disabled |

```tsx
<Link to="/users/$userId" params={{ userId }} preload="intent">
  View User
</Link>

<Link to="/dashboard" preload="viewport">
  Dashboard
</Link>
```

### How It Works
Preloading by **"intent"** works by using hover and touch start events on `<Link>` components to preload the dependencies for the destination route. Preloading by **"viewport"** works by using the Intersection Observer API to preload the dependencies for the destination route when the `<Link>` component is in the viewport.

### Global Configuration
```tsx
const router = createRouter({
  routeTree,
  defaultPreload: 'intent',
  defaultPreloadDelay: 50,
});
```

### Real-World Deal-Breakers
- **No `preloadDelay`** → every hover triggers a preload; excessive network calls.
- **Preloading all links with `viewport`** → wasted bandwidth for links users never click.
- **No preloading** → "broken button" feel when clicking links to data-heavy routes.
