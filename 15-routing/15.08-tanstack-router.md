### Two Routing Philosophies
React Router's default is **UI-first**: a URL maps to a component, and data fetching, search-param parsing, and types get layered on top. TanStack Router's default is **state-first**: a URL maps to validated state, then to loader data, then to UI, with type inference for path params, search params, and loader data falling out of the route definition automatically. Neither default is correct in the abstract.

### Type Safety - The Core Differentiator
TanStack Router's file-based setup starts with a **generated route tree**. The Vite plugin or CLI generates a `routeTree.gen.ts` file from your filesystem, then TypeScript inference carries types through the routing APIs: **path params are inferred from route paths, search params from validated schemas, and loader data from loader return types**. This means refactors fail in the editor instead of after deployment.

```tsx
// routes/users.$userId.tsx
export const Route = createFileRoute('/users/$userId')({
  loader: ({ params }) => fetchUser(params.userId), // params.userId: string
  component: UserPage,
});

function UserPage() {
  const user = Route.useLoaderData();  // User - inferred
  const { userId } = Route.useParams(); // string - inferred
  return <h1>{user.name}</h1>;
}
```

### Real-World Deal-Breakers
- **Using code-based routing when file-based is recommended** → more boilerplate, manual route tree assembly.
- **Not running the Vite plugin** → `routeTree.gen.ts` not generated; imports fail.
- **`as Type` casts** → TanStack Router is fully type-inferred; casts defeat the purpose.
- **Missing `strictNullChecks: true`** → TanStack Router requires it for proper type inference.
