### What Atlas Must Prove

Four properties, in priority order:

1. **Documents converge.** Two clients, interleaved edits, identical result.
2. **Authorisation holds.** A viewer cannot write; another tenant cannot read.
3. **Offline work is not lost.** Queue, reconnect, reconcile.
4. **The editor renders and responds.** Keystrokes appear, presence works.

Everything else is a normal web app.

### The Convergence Test

This is the test that justifies the architecture. Make it deterministic by driving two `Y.Doc` instances with no timers:

```typescript
import * as Y from 'yjs';
import { describe, it, expect } from 'vitest';

function sync(...docs: Y.Doc[]) {
  // Exchange full state both ways, repeatedly, until no further change
  let changed = true;
  while (changed) {
    changed = false;
    for (const from of docs) {
      const update = Y.encodeStateAsUpdate(from);
      for (const to of docs) {
        if (from === to) continue;
        const before = Y.encodeStateVector(to);
        Y.applyUpdate(to, update);
        if (!Y.encodeStateVector(to).equals(before)) changed = true;
      }
    }
  }
}

describe('CRDT convergence', () => {
  it('converges when two clients edit the same paragraph concurrently', () => {
    const a = new Y.Doc(); const b = new Y.Doc();
    a.getText('content').insert(0, 'The quick brown fox');
    sync(a, b);                                            // start from a shared base

    a.getText('content').insert(0, 'Fast: ');
    b.getText('content').delete(4, 6);                     // delete "quick "

    sync(a, b);

    expect(a.getText('content').toString()).toBe(b.getText('content').toString());
    expect(a.getText('content').toString()).toContain('Fast');
    expect(a.getText('content').toString()).toContain('fox');
  });

  it('is idempotent when the same update is applied twice', () => {
    const a = new Y.Doc(); const b = new Y.Doc();
    a.getText('content').insert(0, 'hello');
    const update = Y.encodeStateAsUpdate(a);
    Y.applyUpdate(b, update);
    Y.applyUpdate(b, update);                              // duplicate delivery
    expect(b.getText('content').toString()).toBe('hello');
  });
});
```

The idempotency case is not theoretical: WebSocket reconnect, retries and a flaky mobile network will deliver duplicates.

### Authorisation Tests (The Ones That Matter)

```typescript
describe('authorization', () => {
  it('blocks a viewer from writing', async () => {
    const { doc, viewer } = await seedWorkspace({ viewerRole: 'viewer' });
    const res = await renameDocument({ documentId: doc.id, workspaceId: doc.workspaceId, title: 'Hacked' }, viewer);
    expect(res.ok).toBe(false);
    expect(await db.documents.find(doc.id)).toMatchObject({ title: doc.title });   // unchanged
  });

  it('cannot read a document from another workspace', async () => {
    const { doc } = await seedWorkspace();
    const { user: outsider } = await seedWorkspace();
    const res = await getDocument(doc.id, outsider);
    expect(res.ok).toBe(false);                            // NOT_FOUND, never FORBIDDEN
  });
});
```

These are the highest-value tests in the codebase. A single missing assignment check is a multi-tenant breach; a suite that proves it exists on every save is cheap insurance.

### Test Data Builders

```typescript
export function buildDocument(over: Partial<Document> = {}): Document {
  return {
    id: crypto.randomUUID(),
    workspaceId: crypto.randomUUID(),
    title: 'Untitled',
    content: '',
    version: 1,
    createdAt: new Date(),
    ...over,
  };
}
```

Builders keep tests readable and survive schema changes with one edit. Object literals duplicated across 40 tests do not.

### Determinism

- **Time:** inject a clock (`now: () => number`) rather than calling `Date.now()` in domain logic.
- **Randomness:** inject an ID generator (`newId: () => string`) in tests.
- **Timers:** use `vi.useFakeTimers()` for debounce and backoff; never `await sleep(500)`.
- **Async ordering:** never rely on scheduling; assert on explicit state transitions.

### Deeper Explanation: Test The Contract, Not The Code

A junior tests that `formatDate` returns the right string. A professional tests that *a viewer cannot rename a document*, *two concurrent edits converge*, and *a queued offline edit survives a reconnect*.

The difference is granularity of intent. Tests written against behaviour keep passing through a refactor - which is precisely when you need them most. Tests written against implementation break on every refactor, get deleted or `.skip`ped, and quietly stop protecting anything.

The pragmatic rule for Atlas: **if a bug would be a data-loss or security incident, it gets a test.** If it would be a cosmetic bug, the test is optional.

### Additional Pitfalls

- **Mocking the module you are testing.** You assert that the mock was called; the real code never runs.
- **Snapshot tests on large component trees.** They pass on a colour change and fail on a whitespace change; nobody reads the diff.
- **`await sleep()` for debounce.** Slow, flaky, and it hides real scheduling bugs.
- **One giant E2E suite for everything.** Minutes per run, flakes everywhere, and the team stops trusting it.
- **Coverage thresholds in CI with no policy.** People test getters to raise the number.

### Real-World Deal-Breakers
- **No authorisation tests** - a missing tenant check reaches production; the next report is from a customer, not CI.
- **No convergence test** - a CRDT or binding upgrade silently breaks merging and users lose paragraphs.
- **Only E2E coverage of collaboration** - flaky tests get quarantined until nothing verifies the core feature.
- **Testing implementation details** - the suite breaks on every refactor and is deleted, leaving no protection.
- **No deterministic time or IDs** - intermittent failures that the team learns to re-run instead of investigate.
