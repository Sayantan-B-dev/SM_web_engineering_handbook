## 49.4 Server Components

### The Core Idea

A server component is a React component that **runs only on the server and ships zero JavaScript**. It can be `async`, it can talk to the database directly, and it can import a 2 MB markdown parser without adding a byte to the client bundle.

In Atlas this is the majority of the tree: the sidebar, the document body, the comment thread, the settings pages, the share dialog's read-only state.

```tsx
// No 'use client' - runs on the server, ships nothing
export default async function DocumentView({ id }: { id: DocumentId }) {
  const doc = await db.documents.byId(id);         // direct DB access
  const author = await db.users.byId(doc.authorId);
  const rendered = await renderMarkdown(doc.content); // heavy lib, server-only

  return (
    <article className="prose">
      <header>
        <h1>{doc.title}</h1>
        <Byline name={author.name} at={doc.updatedAt} />
      </header>
      <div dangerouslySetInnerHTML={{ __html: rendered }} />
    </article>
  );
}
```

Compare that with the classic SPA version: `useEffect` -> `fetch('/api/doc/:id')` -> loading state -> error state -> cache state -> *then* paint. Four round trips and a spinner to show text that was sitting in the database the whole time.

### The Rules Of Composition

These are enforced by React and they are not stylistic preferences:

1. Server components **can** render client components.
2. Client components **cannot** import server components.
3. Client components **can** receive server components as `children` or props.

Rule 3 is the one that unlocks real UI. You keep the interactive shell on the client and slot server-rendered content into it:

```tsx
// Client component - owns state, ships to browser
'use client';
export function CollapsiblePanel({ title, children }: { title: string; children: React.ReactNode }) {
  const [open, setOpen] = useState(true);
  return (
    <section>
      <button onClick={() => setOpen((o) => !o)} aria-expanded={open}>{title}</button>
      {open && <div>{children}</div>}
    </section>
  );
}
```

```tsx
// Server component - passes server-rendered children IN
export default async function DocumentPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const comments = await listComments(asDocumentId(id));

  return (
    <CollapsiblePanel title="Comments">
      <CommentList comments={comments} />   {/* rendered on the server */}
    </CollapsiblePanel>
  );
}
```

`CommentList` never ships to the browser. Only the toggle button does.

### Serialisation Is The Boundary

Props crossing into a client component must be serialisable. This is where juniors get confusing errors.

```tsx
// Fails: a class instance crossing the boundary
<Editor doc={new Y.Doc()} />

// Fine: plain data
<Editor docId={doc.id} initialContent={doc.content} />
```

Allowed: strings, numbers, booleans, `null`, `undefined`, plain objects, arrays, `Date`, `Map`, `Set`, `Promise`, and React elements. Not allowed: functions (except server actions), class instances, Symbols, and anything with a prototype chain you care about.

### Streaming With Suspense

Server components can await slow things without blocking the page, because React streams the shell first:

```tsx
export default function Page() {
  return (
    <main>
      <DocumentHeader />                          {/* fast - in the shell */}
      <Suspense fallback={<RevisionsSkeleton />}>
        <RevisionTimeline />                      {/* slow query - streams later */}
      </Suspense>
      <Suspense fallback={<AIInsightsSkeleton />}>
        <AIInsights />                            {/* slow model call - streams later */}
      </Suspense>
    </main>
  );
}
```

The user sees the header and skeleton immediately. Each boundary fills in when its data arrives. No spinner blocks the whole page.

### Deeper Explanation: Server Components Are A Security Boundary Too

The security benefit is underrated. In a client-heavy app, every API key, database URL and privileged query is one bundler mistake away from the browser. With server components:

- `process.env.ANTHROPIC_API_KEY` is used in a function that physically cannot be bundled for the client.
- Database credentials never appear in a client chunk.
- Heavy admin queries run where the user cannot inspect or replay them.

The rule that makes this real: **anything that touches a secret lives in a server component, a server action, or a route handler.** There is no other option, and no `NEXT_PUBLIC_` prefix in a dotenv file for a secret.

### Additional Pitfalls

- **Passing huge objects as props.** Every serialised byte crosses the RSC boundary. Pass IDs and let the client fetch, or pass only the fields the client needs.
- **Fetching in a loop of server components.** Each child awaiting its own query produces an N+1 of server round trips; batch with `Promise.all` at the parent.
- **Using `dangerouslySetInnerHTML` on user content.** Markdown rendering must sanitise; a stored XSS in a collaborative document spreads to every collaborator.
- **Assuming server components can hold state.** They re-run on every request. Module-level mutation is a shared-state bug across all users.
- **Importing a client-only library (charts, editors) in a server component.** It either fails to render or drags the library into the server bundle for nothing.

### Real-World Deal-Breakers
- **Secrets in client components** - keys reach the browser and are scraped within hours.
- **`'use client'` wrapping a server tree** - the whole subtree converts to client components; the architecture collapses into an SPA with extra steps.
- **Unsantised markdown rendered as HTML** - stored XSS propagated to every viewer of the document.
- **Module-level mutable cache in a server component** - state leaks across users on the same instance; a multi-tenant correctness disaster.
- **No `Suspense` around slow server work** - the shell cannot stream, so the whole page blocks on the slowest query.
- **Serialising a database client or connection** - props cross the boundary as a runtime error, and the error message points at the wrong file.
