## 49.2 TypeScript

### Subtopic Tree
- Strict mode as the non-negotiable baseline
- Domain modelling with discriminated unions
- Branded types for IDs and units
- `Result` types instead of thrown errors at boundaries
- Exhaustive `switch` with `never`
- Zod schemas as the single source of truth (type + runtime)
- Typing the CRDT and sync layer without `any`
- Generic repository and API client patterns
- `satisfies` for config objects
- Keeping `any` out of the codebase with lint enforcement

### Why TypeScript Owns This Project

Atlas has one hard property: **the client and the server must agree**. The client sends an operation, the server validates it, the CRDT merges it, and a second client applies it. A type mismatch anywhere in that chain is a data-corruption bug, not a crash you can debug from a stack trace.

TypeScript is not decoration here. It is the specification of every boundary in the system.

### The Baseline

```jsonc
// tsconfig.json - no exceptions
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,   // arr[0] is T | undefined
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "verbatimModuleSyntax": true,
    "target": "ES2023",
    "moduleResolution": "bundler"
  }
}
```

`noUncheckedIndexedAccess` is the one people disable. Do not. It forces you to handle the empty-array case, which is exactly the case that crashes collaborative apps.

### Model The Domain As A Union

An operation in the sync protocol is a closed set. Encode it as a discriminated union so that adding a variant forces you to handle it everywhere:

```typescript
type DocumentOp =
  | { kind: 'insert'; pos: number; text: string; clock: Clock }
  | { kind: 'delete'; pos: number; len: number; clock: Clock }
  | { kind: 'format'; range: [number, number]; mark: Mark; clock: Clock }
  | { kind: 'comment'; anchor: string; body: string; author: UserId; clock: Clock };

function applyOp(doc: DocState, op: DocumentOp): DocState {
  switch (op.kind) {
    case 'insert':  return insert(doc, op.pos, op.text, op.clock);
    case 'delete':  return remove(doc, op.pos, op.len, op.clock);
    case 'format':  return mark(doc, op.range, op.mark, op.clock);
    case 'comment': return annotate(doc, op.anchor, op.body, op.author);
    default: {
      const _exhaustive: never = op;           // compile error if a case is missed
      throw new Error(`Unhandled op: ${JSON.stringify(_exhaustive)}`);
    }
  }
}
```

The `never` assignment is the whole trick: the day someone adds `kind: 'move'`, every `switch` in the codebase fails to compile until it is handled.

### Branded IDs

Passing a `UserId` where a `DocumentId` is expected is a real bug class in multi-tenant systems, and both are `string`. Brand them:

```typescript
declare const brand: unique symbol;
type Brand<T, B> = T & { readonly [brand]: B };

type UserId     = Brand<string, 'UserId'>;
type DocumentId = Brand<string, 'DocumentId'>;
type WorkspaceId = Brand<string, 'WorkspaceId'>;

const asUserId     = (s: string) => s as UserId;
const asDocumentId = (s: string) => s as DocumentId;

function loadDocument(id: DocumentId) { /* ... */ }

const user = asUserId('u_123');
loadDocument(user);        // Compile error: UserId is not assignable to DocumentId
loadDocument(asDocumentId('d_9'));   // fine
```

Zero runtime cost, and the compiler now polices tenant isolation for you.

### Result Types At The Boundary

Never let a database error become an untyped throw that unwinds through your UI. Model failure explicitly where it is expected:

```typescript
type Result<T, E = AppError> =
  | { ok: true; value: T }
  | { ok: false; error: E };

type AppError =
  | { code: 'NOT_FOUND'; resource: string }
  | { code: 'FORBIDDEN'; action: string }
  | { code: 'CONFLICT'; reason: string }   // CRDT/optimistic update collision
  | { code: 'RATE_LIMITED'; retryAfter: number };

async function renameDocument(id: DocumentId, title: string): Promise<Result<DocMeta>> {
  const doc = await db.findDocument(id);
  if (!doc) return { ok: false, error: { code: 'NOT_FOUND', resource: 'document' } };
  if (doc.title === title) return { ok: true, value: doc };
  const updated = await db.updateDocument(id, { title });
  return { ok: true, value: updated };
}
```

Callers must check `ok`, so "we forgot to handle the 404" stops being possible.

### Zod As The Single Source Of Truth

Two sources of truth for the shape of a request is a guaranteed drift bug. Define the schema once and derive the type:

```typescript
import { z } from 'zod';

export const createDocumentSchema = z.object({
  title: z.string().min(1).max(200),
  workspaceId: z.uuid(),
  parentId: z.uuid().nullable().default(null),
  content: z.string().max(1_000_000).default(''),
});

export type CreateDocumentInput = z.infer<typeof createDocumentSchema>;
```

Use the same schema in the server action and in the client form resolver (49.12). If the shape changes, it changes in one place and both ends fail to compile together.

### Typing The Sync Layer

The hardest typing problem in Atlas is the CRDT layer, because it is deliberately dynamic. Confine the `unknown`:

```typescript
import * as Y from 'yjs';

/** The only place we touch Yjs internals. Everything above this line is typed. */
export function applyUpdate(doc: Y.Doc, payload: unknown): void {
  const parsed = updateSchema.safeParse(payload);
  if (!parsed.success) {
    reportInvalidUpdate(parsed.error);       // observability hook (49.28)
    return;                                  // drop hostile / malformed updates
  }
  Y.applyUpdate(doc, parsed.data);
}
```

Rule for the whole project: **exactly one module is allowed to import `Y.Doc` types directly.** Everything else talks in your own domain types. When Yjs is upgraded or replaced, one file changes.

### `satisfies` For Configuration

```typescript
const DOC_LIMITS = {
  maxTitleLength: 200,
  maxContentBytes: 1_000_000,
  maxCollaborators: 50,
  autosaveDebounceMs: 400,
} satisfies Record<string, number>;

// DOC_LIMITS.autosaveDebounceMs is number, not the literal 400 (mutable)
// but a typo in a key is still a compile error.
```

### Deeper Explanation: Types Are Tests That Run At Compile Time

A junior treats TypeScript as "JavaScript with extra words". A professional treats it as an executable specification. Every claim you make about the system - "a document always has an owner", "an op is always one of four kinds", "this function never throws" - becomes a compile-time check that runs on every save, for free, forever.

That is why the strict flags above matter more than any library choice. `noUncheckedIndexedAccess` prevents the class of bug where the last collaborator disconnects and `peers[0]` is `undefined` while the UI assumes it exists.

### Additional Pitfalls

- **`as` to silence the compiler.** Each cast is a promise you cannot keep. Cast only at true boundaries (after validation), and only once.
- **Deriving types with `ReturnType<typeof fn>` across module boundaries.** It couples distant files invisibly; export the type explicitly instead.
- **`enum`.** Use `const` objects with `as const` or union types; TypeScript enums have runtime semantics that surprise people and complicate tree-shaking.
- **Optional properties for "not loaded".** `title?: string` cannot distinguish "absent" from "empty". Model loading explicitly: `{ status: 'loading' } | { status: 'ready'; title: string }`.
- **`any` in a `catch`.** It is `unknown` and you must narrow it before use. Swallowing an error because typing it was annoying is how silent data loss ships.

### Real-World Deal-Breakers
- **`strict: false` anywhere** - the type layer is now documentation with no enforcement value.
- **Unvalidated `as` on network or user input** - the type says `TextOp`, the payload is hostile JSON. Validate at the boundary with Zod.
- **No `never` exhaustiveness check** - someone adds an op kind, one switch silently ignores it, and documents diverge undetectably.
- **`string` for every ID** - workspace A can read workspace B because the compiler cannot tell the IDs apart.
- **Thrown errors for expected outcomes** - a 404 becomes a 500 because nobody could see the failure in the signature.
- **Two schema definitions (Zod and a hand-written interface)** - they drift within a sprint and the drift is a production bug.
