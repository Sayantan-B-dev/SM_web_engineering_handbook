### Schema For Atlas

```sql
create table workspaces (
  id          uuid primary key default gen_random_uuid(),
  name        text not null,
  slug        text not null unique,
  created_at  timestamptz not null default now()
);

create table memberships (
  workspace_id uuid not null references workspaces(id) on delete cascade,
  user_id      uuid not null references users(id) on delete cascade,
  role         text not null check (role in ('owner','admin','editor','viewer')),
  created_at   timestamptz not null default now(),
  primary key (workspace_id, user_id)
);

create table documents (
  id            uuid primary key default gen_random_uuid(),
  workspace_id  uuid not null references workspaces(id) on delete cascade,
  title         text not null default 'Untitled',
  -- CRDT state, not the rendered text: the client is the author of this value
  crdt_state    bytea,
  version       bigint not null default 1,     -- optimistic concurrency
  deleted_at    timestamptz,                   -- soft delete
  created_by    uuid not null references users(id),
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

-- The index that makes the sidebar fast
create index documents_workspace_active_idx
  on documents (workspace_id, updated_at desc)
  where deleted_at is null;

-- Operation log: append-only, the durable history behind the CRDT
create table document_ops (
  seq         bigserial primary key,
  document_id uuid not null references documents(id) on delete cascade,
  actor       uuid not null references users(id),
  payload     jsonb not null,
  created_at  timestamptz not null default now()
);
create index document_ops_doc_seq_idx on document_ops (document_id, seq);
```

### The Partial Index Is The Point

`where deleted_at is null` keeps the hot index small. A generic `(workspace_id)` index on a table where 90% of rows are soft-deleted makes the sidebar scan dead tuples. Partial indexes are the single highest-leverage Postgres trick in this schema.

### Tenant Isolation With RLS

Application-level `where workspace_id = ?` is one forgotten clause away from cross-tenant leakage. Enforce it in the database:

```sql
alter table documents enable row level security;

create policy documents_member_read on documents
  for select using (
    exists (
      select 1 from memberships m
      where m.workspace_id = documents.workspace_id
        and m.user_id = current_setting('app.user_id')::uuid
    )
  );

create policy documents_editor_write on documents
  for update using (
    exists (
      select 1 from memberships m
      where m.workspace_id = documents.workspace_id
        and m.user_id = current_setting('app.user_id')::uuid
        and m.role in ('owner','admin','editor')
    )
  );
```

The app then sets `app.user_id` per transaction. A missing `where` clause in application code no longer leaks another tenant's documents.

### Expand-Contract Migrations

Never make a destructive change in one step. Anything that breaks the *currently running* deploy is an outage.

```text
Step 1 (expand)   add nullable column / new table
Step 2 (backfill) write both old and new from app code; backfill in batches
Step 3 (switch)   read from new; keep writing both
Step 4 (contract) drop the old column in a later deploy
```

```typescript
// Drizzle schema fragment
export const documents = pgTable('documents', {
  id: uuid('id').primaryKey().defaultRandom(),
  workspaceId: uuid('workspace_id').notNull().references(() => workspaces.id, { onDelete: 'cascade' }),
  title: text('title').notNull().default('Untitled'),
  crdtState: customType<{ data: Uint8Array }>({ dataType: () => 'bytea' })('crdt_state'),
  version: bigint('version', { mode: 'number' }).notNull().default(1),
  deletedAt: timestamp('deleted_at', { withTimezone: true }),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});
```

### Optimistic Concurrency On Metadata

The CRDT handles concurrent *text*. Metadata (title, permissions) needs its own guard:

```sql
update documents
   set title = $2, version = version + 1, updated_at = now()
 where id = $1
   and version = $3        -- the version the client last saw
   and deleted_at is null
 returning version;
```

Zero rows updated means someone else changed it first. Return a `CONFLICT` error (49.02) and let the UI merge, rather than silently clobbering a collaborator's rename.

### Deeper Explanation: The Database Is Your Last Line Of Defence

Every layer above the database can be bypassed: the UI, the server action, the API, the cache. The database cannot. That is why constraints, foreign keys, checks and RLS belong in the schema rather than only in application code.

For a multi-tenant collaborative product, an application-only invariant is a future incident. `not null`, `check (role in (...))`, `on delete cascade`, `unique (workspace_id, slug)` and RLS together mean that even a buggy query cannot produce a corrupt or leaked row.

### Additional Pitfalls

- **`select *` in hot paths.** It breaks index-only scans and pulls `crdt_state` blobs you do not need in the sidebar.
- **N+1 queries from a server component loop.** Batch with a single `where id = any($1)` or a join.
- **`OFFSET` pagination over 100k rows.** It degrades linearly; use keyset pagination on `(updated_at, id)`.
- **Long transactions holding locks while calling an external API.** Keep transactions short and side-effect-free.
- **`timestamptz` confusion.** Always store timezone-aware timestamps in UTC; never `timestamp without time zone`.
- **Serverless connection storms.** Each Lambda opening its own pool exhausts Postgres; use a pooler.

### Real-World Deal-Breakers
- **No RLS or tenant check in the query** - a missing `where` clause leaks another customer's documents; a reportable breach.
- **Destructive migration in a single deploy** - the old code is still running when the column disappears; outage.
- **No index on the sidebar query** - a full scan per page load; the app slows as customers succeed.
- **Unbounded `OFFSET`** - page 400 of the activity feed takes seconds and holds a connection.
- **Soft deletes with no partial index** - the hot query scans dead rows forever; performance decays invisibly.
- **No restore drill** - backups that have never been restored are an untested assumption, discovered during an incident.
