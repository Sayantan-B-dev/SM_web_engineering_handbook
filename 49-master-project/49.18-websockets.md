### Transport Choice

| Need | Transport | Why |
|---|---|---|
| Assistant streaming one-way | SSE | simple, HTTP-friendly, auto-reconnect |
| Presence + CRDT updates (bidirectional) | WebSocket | lowest latency both ways |
| Infrequent updates, legacy environments | long-poll | universal fallback |

Atlas uses WebSockets for document sessions and SSE for AI responses. They are different problems and deserve different tools.

### Authenticate At Upgrade

```typescript
// server/sync.ts (Node runtime behind Fly/Render - NOT a serverless function)
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ noServer: true });

server.on('upgrade', async (req, socket, head) => {
  // 1. Authenticate from the cookie BEFORE the socket exists
  const userId = await userIdFromCookieHeader(req.headers.cookie);
  if (!userId) return socket.destroy();

  const url = new URL(req.url!, 'http://x');
  const documentId = url.searchParams.get('doc');
  if (!documentId) return socket.destroy();

  // 2. Authorise per document, every connection, every time
  const auth = await authorize('document:read', { workspaceId: await wsOf(documentId), documentId }, userId);
  if (!auth.ok) return socket.destroy();          // no error detail: do not leak existence

  const ttl = await sessionTtl(userId);
  wss.handleUpgrade(req, socket, head, (ws) => {
    const session = new DocSession(ws, { userId, documentId, expiresAt: ttl });
    session.start();
  });
});
```

An unauthenticated socket that "authenticates later via a message" is a connection that can be held open for free by an attacker, and a race where messages arrive before the identity is known.

### The Envelope Protocol

Never send bare payloads. Version the protocol on day one:

```typescript
type ClientMessage =
  | { v: 1; t: 'join'; doc: string; sinceSeq: number }
  | { v: 1; t: 'update'; update: string }        // base64 CRDT update
  | { v: 1; t: 'awareness'; state: string }
  | { v: 1; t: 'ping'; at: number };

type ServerMessage =
  | { v: 1; t: 'ready'; seq: number; peers: Peer[] }
  | { v: 1; t: 'update'; seq: number; update: string; actor: string }
  | { v: 1; t: 'awareness'; peers: Peer[] }
  | { v: 1; t: 'error'; code: 'RATE_LIMITED' | 'TOO_LARGE' | 'FORBIDDEN' }
  | { v: 1; t: 'pong'; at: number };
```

`schemaVersion` in the envelope lets you deploy a new client before the server (or vice versa) without a protocol mismatch breaking every open socket.

### Heartbeats And Reconnect

```typescript
const HEARTBEAT_MS = 10_000;

// Server: kill sockets that stopped answering
setInterval(() => {
  for (const session of sessions) {
    if (Date.now() - session.lastSeen > HEARTBEAT_MS * 3) {
      session.close(1001, 'heartbeat timeout');       // half-open TCP connections
    } else {
      session.ws.ping();
    }
  }
}, HEARTBEAT_MS);
```

```typescript
// Client: reconnect with exponential backoff and full jitter
function connect(url: string, onMessage: (m: ServerMessage) => void) {
  let attempt = 0;
  const open = () => {
    const ws = new WebSocket(url);

    ws.onopen = () => { attempt = 0; syncSince(lastSeq); };   // catch up from the op log
    ws.onmessage = (e) => onMessage(JSON.parse(e.data));
    ws.onclose = () => {
      const base = Math.min(30_000, 500 * 2 ** attempt++);
      setTimeout(open, Math.random() * base);                 // jitter avoids a reconnect storm
    };
    ws.onerror = () => ws.close();                            // onerror alone does not reconnect
  };
  open();
}
```

Note `syncSince(lastSeq)`: on reconnect the client must replay the operations it missed, not assume its in-memory CRDT is current. This is where the Postgres op log (49.10) earns its place.

### Deeper Explanation: The Hard Part Is State, Not Sockets

Opening a WebSocket is easy. The engineering is in what happens when one drops: a laptop lid closes for 40 minutes, a phone moves from Wi-Fi to cellular, a deploy restarts the server mid-session.

The invariant that makes Atlas correct: **the socket is a transport, never the source of truth.** The durable state lives in Postgres, the CRDT state converges regardless of message order, and reconnection replays from `sinceSeq`. With that design, a dropped connection is a latency event rather than a data-loss event.

### Additional Pitfalls

- **No ping/pong.** Half-open TCP connections sit in your server's memory showing ghost collaborators.
- **Unbounded send queue.** A slow client builds a queue until the process dies; cap it and drop or disconnect.
- **One socket per document.** A user with 20 open tabs holds 20 connections and hits per-IP limits.
- **No message size limit.** A 50 MB "update" is a trivial DoS; enforce a byte cap at the framing layer.
- **Serverless deployment.** Lambda/Edge functions cannot hold sockets; you need a long-running runtime or a managed realtime service.

### Real-World Deal-Breakers
- **Auth checked after upgrade** - unauthenticated sockets and a race where messages precede identity.
- **No authorisation per document** - any authenticated user can join any document ID they guess.
- **No reconnect catch-up** - users silently edit a stale copy and lose work on the next merge.
- **Reconnect with no jitter** - a rolling deploy triggers a synchronised stampede that takes the fleet down.
- **Deploying to a serverless platform without checking socket support** - the feature works locally and never in production.
