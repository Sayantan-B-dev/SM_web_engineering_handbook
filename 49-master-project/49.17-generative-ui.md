## 49.17 Generative UI

### Subtopic Tree
- What generative UI is (and the three levels of it)
- Level 1: text and markdown
- Level 2: tool-driven UI (the model picks a component, you render it)
- Level 3: fully generated component trees (and when not to)
- Streaming partial UI safely
- A constrained component registry, not `eval`
- Schema-first props between model and renderer
- Interaction back-channels: the UI calls back into the model
- Accessibility and trust: users must know what is machine-generated
- Fallbacks when generation fails or times out
- Evaluation and guardrails

### The Three Levels

| Level | Mechanism | Risk | Use in Atlas |
|---|---|---|---|
| 1. Text | Markdown rendering | XSS via raw HTML | Default answer rendering |
| 2. Tool UI | Model selects a component with validated props | Wrong component, bad props | Charts, tables, edit proposals |
| 3. Generated tree | Model emits component structure | Unbounded, unverifiable | Not used |

Level 3 - letting the model generate arbitrary JSX - is where teams get burned. You lose type safety, you lose design-system compliance, and you gain an injection surface. Atlas uses level 2: the model picks **from a fixed registry** and fills **validated props**.

### A Registry, Not A String Of JSX

```typescript
// The model can only ever name a component that exists in this map.
export const UI_REGISTRY = {
  Table: z.object({
    columns: z.array(z.string().min(1).max(60)).min(1).max(8),
    rows: z.array(z.array(z.string().max(200))).max(100),
  }),
  Metric: z.object({
    label: z.string().max(60),
    value: z.string().max(40),
    trend: z.enum(['up', 'down', 'flat']).default('flat'),
  }),
  Diff: z.object({
    documentId: z.uuid(),
    before: z.string().max(2000),
    after: z.string().max(2000),
  }),
} as const;

type UIName = keyof typeof UI_REGISTRY;
type UIProps = { [K in UIName]: z.infer<(typeof UI_REGISTRY)[K]> };

/** Validate before render: an invalid payload degrades to text, never renders. */
export function renderGeneratedUI(name: string, props: unknown) {
  if (!(name in UI_REGISTRY)) return null;                       // unknown component -> ignore
  const schema = UI_REGISTRY[name as UIName];
  const parsed = schema.safeParse(props);
  if (!parsed.success) return null;                              // bad props -> fall back to text
  return { name: name as UIName, props: parsed.data };
}
```

```tsx
// Renderer: a closed switch, so every generated component has a real implementation
function GeneratedNode({ node }: { node: { name: UIName; props: UIProps[UIName] } }) {
  switch (node.name) {
    case 'Table':  return <DataTable {...(node.props as UIProps['Table'])} />;
    case 'Metric': return <MetricCard {...(node.props as UIProps['Metric'])} />;
    case 'Diff':   return <DiffView {...(node.props as UIProps['Diff'])} />;
    default:       return null;
  }
}
```

The registry does three jobs at once: it bounds what can appear, it validates props at runtime, and it makes the design system unavoidable - generated UI looks native because the components *are* the design system (49.08).

### Streaming Partial UI

Render the skeleton the moment the component name arrives, and fill props as they stream. Never show a half-parsed table:

```tsx
function StreamedBlock({ stream }: { stream: PartialUIPayload }) {
  // Parse only complete JSON; until then show the shape's skeleton
  const parsed = stream.propsJson ? tryParse(stream.propsJson) : null;
  if (!parsed) return <ComponentSkeleton name={stream.name} />;
  const node = renderGeneratedUI(stream.name, parsed);
  if (!node) return <MarkdownBlock text={stream.fallbackText} />;   // graceful degradation
  return <GeneratedNode node={node} />;
}
```

### Labelling And Trust

Machine-generated UI must be visibly attributed. An unlabelled AI-generated chart that contradicts the data is a trust incident:

```tsx
<figure aria-label="AI generated">
  <GeneratedNode node={node} />
  <figcaption className="text-xs text-ink-muted">Generated by Atlas AI. Verify against the source document.</figcaption>
</figure>
```

### Deeper Explanation: Constraint Is What Makes This Shippable

A fully generative UI sounds more impressive and is strictly worse for a product like Atlas. The value of constrained generative UI is that it keeps three guarantees that level 3 gives up:

1. **It always renders.** Unknown or invalid payloads degrade to text instead of a blank panel.
2. **It always looks right.** Generated UI is composed from the design system, so it cannot break the theme or accessibility baseline.
3. **It is safe.** There is no `eval`, no dynamic `import` from a model string, and no way to reach a component the registry does not list.

The professional judgment is recognising that "the model can build any UI" is a demo, and "the model can select the right component with valid data" is a product.

### Additional Pitfalls

- **`dangerouslySetInnerHTML` with model output.** Generated HTML is untrusted input; sanitise or render as markdown.
- **Trusting `name` as a path.** `../secrets` or an import path in a model string is a code-execution vector if you ever `import()` it.
- **No prop limits.** An unbounded `rows` array from a hallucinating model freezes the tab; cap sizes in the schema.
- **Silent fallbacks.** If generation failed and the user sees plain text, log it; otherwise you never learn your success rate.
- **No evaluation set.** You cannot tell whether a prompt change improved selection accuracy without a labelled set of requests.

### Real-World Deal-Breakers
- **Model output rendered as raw HTML or JSX** - XSS and layout destruction from a single crafted document.
- **Arbitrary component names resolved dynamically** - remote code execution through a model-controlled import.
- **Unbounded generated payloads** - a 100k-row table locks the browser tab.
- **Unlabelled AI content** - users treat generated numbers as authoritative and act on fabricated data.
- **No fallback path** - one malformed payload leaves a permanently broken panel in the document.
