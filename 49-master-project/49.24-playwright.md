### What E2E Is For

Keep this suite tiny. E2E is for the paths where a unit test cannot prove the whole system works: sign in, open a document, type, see the change persisted, see a second user's edit appear. Everything else belongs in component or integration tests (49.23).

### Fixtures And Page Objects

```typescript
// e2e/fixtures.ts
import { test as base, expect } from '@playwright/test';

type Fixtures = { editor: EditorPage; secondUser: EditorPage };

export const test = base.extend<Fixtures>({
  editor: async ({ page }, use) => {
    const editor = new EditorPage(page);
    await editor.gotoSeededDocument();          // seeded id from a test API endpoint
    await use(editor);
  },

  secondUser: async ({ browser }, use) => {
    const ctx = await browser.newContext({ storageState: 'e2e/.auth/user-b.json' });
    const page = await ctx.newPage();
    const editor = new EditorPage(page);
    await editor.gotoSeededDocument();
    await use(editor);
    await ctx.close();
  },
});

export class EditorPage {
  constructor(private page: Page) {}

  async gotoSeededDocument() {
    await this.page.goto(`/w/${process.env.E2E_WORKSPACE}/doc/${process.env.E2E_DOC}`);
    await this.page.getByRole('textbox', { name: /document content/i }).waitFor();
  }

  async type(text: string) {
    await this.page.getByRole('textbox', { name: /document content/i }).type(text);
  }

  async body() {
    return this.page.getByRole('textbox', { name: /document content/i }).innerText();
  }

  async expectSaved() {
    await expect(this.page.getByRole('status')).toHaveText(/saved/i, { timeout: 10_000 });
  }
}
```

### The Test That Justifies E2E

```typescript
test('two users see each other\'s edits and presence', async ({ editor, secondUser }) => {
  await editor.type('Hello from user A');
  await secondUser.page.getByText(/Hello from user A/).waitFor({ timeout: 10_000 });   // propagated

  // Presence: the other user's avatar appears
  await expect(secondUser.page.getByRole('img', { name: /user a/i })).toBeVisible();

  await secondUser.type('\nReply from user B');
  await expect.poll(() => editor.body(), { timeout: 10_000 }).toContain('Reply from user B');
});
```

No unit test can prove a CRDT, a socket, a server and two browsers agree. This one can.

### Determinism Rules

```typescript
// BANNED: arbitrary sleeps
await page.waitForTimeout(3000);

// REQUIRED: wait for a condition the app exposes
await expect(page.getByRole('status')).toHaveText('Saved');

// REQUIRED for sync: poll until the condition holds, with a real timeout
await expect.poll(() => editor.body()).toContain('Reply from user B');
```

```typescript
// Freeze the AI endpoint so responses are deterministic and cheap
await page.route('**/api/chat', (route) =>
  route.fulfill({
    status: 200,
    contentType: 'text/event-stream',
    body: 'data: {"type":"text-delta","delta":"Deterministic answer"}\n\ndata: [DONE]\n\n',
  }),
);
```

Never call a real LLM from an E2E test: it is slow, non-deterministic and costs money on every CI run.

### Auth State And Configuration

import { test as setup } from '@playwright/test';

setup('authenticate', async ({ page }) => {
  await page.goto('/login');

### Deeper Explanation: Flake Is A Bug, Not A Cost

A flaky E2E suite is worse than no E2E suite, because the team learns to re-run it and then to ignore it. Every flake has a cause: an unawaited condition, shared state between tests, a real network call, or a race the app itself has.

The professional policy: **a flake is triaged like a defect.** If it cannot be fixed within a day, it is deleted rather than quarantined indefinitely, because a test nobody trusts provides no protection while still consuming CI minutes.

### Additional Pitfalls

- **Shared seeded document across parallel tests.** Two workers edit the same document and interfere; seed per test.
- **Asserting on implementation selectors.** `data-testid` and roles only; class names change constantly.
- **Testing through the UI for things the API can set up.** Seed via API, then assert the UI.
- **Real emails or webhooks in E2E.** Intercept and assert instead; you cannot un-send an email.
- **Visual tests on a non-pinned browser image.** Different font rendering fails the suite on the runner's OS update.

### Real-World Deal-Breakers
- **No E2E on collaboration** - the product's central feature is only ever verified by hand.
- **Sleep-based waits** - the suite is slow and flaky, and eventually gets disabled entirely.
- **Real AI calls in CI** - nondeterministic failures plus a monthly bill for running tests.
- **Auth state committed to the repo** - session tokens in version control, granting workspace access to anyone with the repo.
- **Retries masking real races** - a genuine concurrency bug is filed as "flaky" and ships again.
