### OT Or CRDT

| | OT | CRDT |
|---|---|---|
| Needs a server to transform | Yes | No |
| Offline editing | Hard | Native |
| Memory overhead | Low | Higher (tombstones, IDs) |
| Correctness burden | On your server | On the library |
| Best for | Server-authoritative docs | Offline-first, peer-to-peer |

Atlas is offline-first (49.21), which decides it: **CRDT**. OT is a fine choice for a strictly server-authoritative editor, and a painful one the moment a user goes offline.

### Why Yjs

Yjs is not "a CRDT library" - it is a CRDT library plus a mature ecosystem of bindings and providers. The binding is what you actually depend on, because the hard part of collaborative editing is not the merge algorithm; it is reconciling a CRDT with an editor's own document model (positions, marks, decorations).

```tsx
'use client';
import * as Y from 'yjs';
import { WebsocketProvider } from 'y-websocket';
import Collaboration from '@tiptap/extension-collaboration';
import CollaborationCursor from '@tiptap/extension-collaboration-cursor';

export function useCollaborativeEditor(documentId: string, userId: string, initial: Uint8Array) {
  const ydoc = useMemo(() => {
    const doc = new Y.Doc();
    Y.applyUpdate(doc, initial);       // server snapshot, so the first paint has content
    return doc;
  }, [documentId]);

  useEffect(() => {
    const provider = new WebsocketProvider(WS_URL, `doc:${documentId}`, ydoc, {
      params: { token: undefined },     // auth via cookie on upgrade (49.18)
      resyncInterval: 10_000,           // heal silently dropped updates
    });
    provider.awareness.setLocalStateField('user', {
      id: userId,
      name: displayName,
      color: pickColor(userId),         // deterministic, so everyone sees the same colour
    });
    return () => provider.destroy();
  }, [documentId, userId, ydoc]);

  const extensions = [
    Collaboration.configure({ document: ydoc }),
    CollaborationCursor.configure({ provider, user: { id: userId } }),
  ];
  return { ydoc, extensions };
}
```

```typescript
/** Deterministic colour: no coordination needed, everyone computes the same value. */
function pickColor(userId: string) {
  let h = 0;
  for (const ch of userId) h = (h * 31 + ch.charCodeAt(0)) % 360;
  return `hsl(${h} 70% 45%)`;
}
```

### Presence

```typescript
provider.awareness.on('change', () => {
  const peers = [...provider.awareness.getStates().entries()]
    .filter(([clientId]) => clientId !== ydoc.clientID)
    .map(([clientId, state]) => ({ clientId, ...(state as { user: Peer }) }));

  setPeers(dedupeByUserId(peers));    // two tabs, one person -> one avatar
});
```

Awareness is ephemeral by design: it lives only as long as the connection. Do not persist cursors; do not treat them as data.

### Undo/Redo Is Not A Stack Of Strings

In a collaborative editor, `Ctrl+Z` must undo **your** changes without reverting a collaborator's interleaved edits. Yjs's UndoManager tracks the origin of each transaction:

```typescript
const undoManager = new Y.UndoManager(ydoc.getText('content'), {
  trackedOrigins: new Set([provider.awareness.clientID, null]),   // only local edits
  captureTimeout: 400,                                            // group rapid keystrokes
});

// Bind to the editor's undo, never to a naive content-string history
```

### Persistence: Snapshot Plus Log

```typescript
// Server: append every update, snapshot periodically
session.on('update', async (update: Uint8Array) => {
  await db.documentOps.insert({ documentId, actor: userId, payload: Buffer.from(update) });
  opsSinceSnapshot++;
  if (opsSinceSnapshot > 500) {
    await db.documents.update(documentId, { crdtState: Y.encodeStateAsUpdate(ydoc) });
    opsSinceSnapshot = 0;
  }
});
```

The snapshot keeps load time bounded; the op log makes the snapshot recoverable. Storing only one or only the other is a common and expensive design error.

### Deeper Explanation: Convergence Is Guaranteed; Convergence Of *Intent* Is Not

CRDTs guarantee that every replica ends in the same state. They do not guarantee that the resulting text means what either author intended. Two people editing the same sentence produce a syntactically valid, semantically surprising paragraph.

This is why the product layer matters more than the algorithm: presence so people avoid collisions, comments anchored to stable positions so discussion survives edits, and suggestion mode so high-stakes edits are reviewed rather than merged silently.

### Additional Pitfalls

- **One `Y.Doc` per render.** Creates a fresh document each render and drops all history. Memoise on `documentId`.
- **Never destroying the provider.** Leaks sockets and awareness entries on route change.
- **Storing only the snapshot.** Every reload loses everything since the last snapshot.
- **Undo bound to a content string.** Undo reverts collaborators' work; users lose edits and trust.
- **Comments anchored to character indices.** An insert above shifts every anchor and comments point at unrelated text; anchor to a relative CRDT position.

### Real-World Deal-Breakers
- **No server-side storage of updates** - a workspace power cut loses hours of collaborative work.
- **Last-write-wins on the whole document** - one stale client overwrites everyone; the classic collaborative data-loss bug.
- **Unbounded document growth with tombstones** - memory per document climbs forever; add periodic compaction.
- **Presence without TTL** - ghost cursors make users believe a colleague is editing when they are not.
- **Testing collaboration with humans only** - without a deterministic two-client test, merge regressions ship silently.
