### Threat Model First

Rank the risks for *this* product rather than reciting a generic list:

| Rank | Threat | Impact |
|---|---|---|
| 1 | Cross-tenant data access (IDOR) | breach, reportable |
| 2 | Stored XSS via document content | session theft, worm propagation |
| 3 | Prompt injection -> data exfiltration | silent data loss |
| 4 | Broken authorisation in realtime layer | unauthorised document access |
| 5 | Secret leakage in client bundle | full backend compromise |
| 6 | Dependency compromise | arbitrary code in prod |

Items 1-3 are the ones that would be front-page incidents for Atlas. Everything else is important but secondary.

### XSS: The Document Is Untrusted

```typescript
import DOMPurify from 'isomorphic-dompurify';
import { marked } from 'marked';

/** Markdown -> HTML -> sanitised HTML. Never skip the last step. */
export function renderMarkdown(md: string): string {
  const html = marked.parse(md, { async: false }) as string;
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['p','br','strong','em','code','pre','ul','ol','li','blockquote','h1','h2','h3','a','table','thead','tbody','tr','th','td'],
    ALLOWED_ATTR: ['href', 'title', 'colspan', 'rowspan'],
    ALLOW_DATA_ATTR: false,
    FORBID_TAGS: ['script', 'style', 'iframe', 'object', 'embed', 'form'],
  });
}
```

```typescript
// Links from user content must not be able to run script or leak the referrer
const safeUrl = (href: string) =>
  /^(https?:|mailto:)/i.test(href) ? href : '#';
```

A stored XSS in a collaborative editor is the worst case: it runs for every collaborator who opens the document, which makes it a worm.

### SSRF In AI And Fetch Features

```typescript
import { isIP } from 'node:net';
import { lookup } from 'node:dns/promises';

const BLOCKED = [
  /^10\./, /^127\./, /^169\.254\./, /^172\.(1[6-9]|2\d|3[01])\./, /^192\.168\./, /^::1$/, /^fc00:/i, /^fe80:/i,
];

export async function assertSafeUrl(raw: string) {
  const url = new URL(raw);
  if (!['http:', 'https:'].includes(url.protocol)) throw new Error('SSRF_PROTOCOL');
  if (url.hostname === 'localhost' || url.hostname.endsWith('.internal')) throw new Error('SSRF_HOST');

  const { address } = await lookup(url.hostname);        // resolve, then check the IP
  if (isIP(address) && BLOCKED.some((r) => r.test(address))) throw new Error('SSRF_PRIVATE_IP');
  return url;
}
```

Checking only the hostname string is insufficient: an attacker points a domain at `169.254.169.254` and reads your cloud metadata and credentials.

### Security Headers

```typescript
// middleware.ts
export function middleware(req: NextRequest) {
  const res = NextResponse.next();
  const nonce = randomBytes(16).toString('base64');

  res.headers.set('Content-Security-Policy', [
    `default-src 'self'`,
    `script-src 'self' 'nonce-${nonce}' 'strict-dynamic'`,
    `style-src 'self' 'unsafe-inline'`,          // pragma for CSS-in-JS; tighten where possible
    `img-src 'self' data: blob: https:`,
    `connect-src 'self' https://api.anthropic.com wss://sync.atlas.app`,
    `frame-ancestors 'none'`,
    `object-src 'none'`,
    `base-uri 'none'`,
  ].join('; '));

  res.headers.set('Strict-Transport-Security', 'max-age=63072000; includeSubDomains; preload');
  res.headers.set('X-Content-Type-Options', 'nosniff');
  res.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
  res.headers.set('Permissions-Policy', 'camera=(), microphone=(), geolocation=()');
  return res;
}
```

`frame-ancestors 'none'` prevents clickjacking; `object-src 'none'` closes legacy plugin vectors; `connect-src` is the one most often left wide open.

Pin GitHub Actions to a commit SHA, not a tag: a moved tag is an arbitrary-code-execution path into your CI with your secrets.

### Deeper Explanation: Defence In Depth Is Structural

No single control stops a determined attacker. What works is layering controls so that each one *alone* being bypassed is not catastrophic:

- Validate input (Zod) - stops malformed data.
- Escape output (sanitise, React's default escaping) - stops XSS.
- Authorise in the server function - stops unauthorised action.
- Enforce RLS in Postgres - stops unauthorised rows.
- Scope secrets to server-only modules - limits blast radius.

Each layer assumes the one above it failed. That assumption is what makes the design resilient rather than optimistic.

### Additional Pitfalls

- **`dangerouslySetInnerHTML` from a markdown library without sanitising.** Non-negotiable.
- **CSP with `unsafe-inline` on `script-src`.** Effectively no XSS protection.
- **Secrets in `NEXT_PUBLIC_*`.** That prefix inlines the value into the client bundle.
- **Trusting the `Host`/`Origin` header for authorisation decisions.** Both are attacker-controlled in some paths.
- **No dependency review on PRs.** A malicious transitive dependency lands with a feature PR and nobody sees it.

### Real-World Deal-Breakers
- **Stored XSS in shared documents** - a worm that spreads to every collaborator and steals sessions.
- **Missing tenant check on a read endpoint** - a reportable breach and loss of customer trust.
- **SSRF with access to cloud metadata** - full cloud credential theft from a single URL field.
- **Secrets in the client bundle** - anyone can extract the key and run up your bill or read your data.
- **Unpinned CI actions** - one upstream compromise executes arbitrary code with your deploy credentials.
- **No incident response plan** - the breach is discovered by a journalist, not by your team.
