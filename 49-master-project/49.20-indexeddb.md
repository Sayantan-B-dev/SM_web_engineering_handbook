### Why Not `localStorage`

| | `localStorage` | IndexedDB |
|---|---|---|
| Size | ~5 MB | hundreds of MB to GB |
| API | synchronous (blocks the main thread) | async |
| Types | strings only | structured objects, `Blob`, `ArrayBuffer` |
| Transactions | none | atomic, per-store |
| Concurrent tabs | no coordination | shared, with `BroadcastChannel` |

A single document can exceed 5 MB of CRDT history. `localStorage` also blocks the main thread on every write, which in an editor means a dropped frame per keystroke. It is the wrong tool, and using it is the most common mistake in offline-first prototypes.

### A Dexie Schema For Atlas

```typescript
import Dexie, { type Table } from 'dexie';

export interface LocalDoc {
  id: string;
  workspaceId: string;
  title: string;
  snapshot: Uint8Array;          // latest compacted CRDT state
  updatedAt: number;
  dirty: 0 | 1;                  // 1 = has unsynced local changes
}

export interface LocalOp {
  ++seq?: number;
  docId: string;
  update: Uint8Array;
  createdAt: number;
  synced: 0 | 1;
}

export class AtlasDB extends Dexie {
  docs!: Table<LocalDoc, string>;
  ops!: Table<LocalOp, number>;
  attachments!: Table<{ id: string; docId: string; blob: Blob; size: number }, string>;

  constructor() {
    super('atlas');
    this.version(1).stores({
      docs: 'id, workspaceId, updatedAt, dirty',
      ops: '++seq, docId, synced, createdAt',
      attachments: 'id, docId, size',
    });
  }
}

export const db = new AtlasDB();
```

Version bumps are additive: add stores and indexes in a new `version(n).stores({...})` block and let `onupgradeneeded` run. Never mutate an existing version's definition - existing installs will not re-run it.

### Durability Guarantees

```typescript
// Ask for persistent storage so the browser does not evict under pressure
export async function ensurePersistent() {
  if (!navigator.storage?.persist) return false;
  if (await navigator.storage.persisted()) return true;
  return navigator.storage.persist();       // must be called on user interaction in some browsers
}

export async function storageHeadroom() {
  const { usage = 0, quota = 0 } = await navigator.storage.estimate();
  return { usage, quota, ratio: quota ? usage / quota : 0 };
}
```

```typescript
// Refuse to keep working locally if we are about to run out of room
const { ratio } = await storageHeadroom();
if (ratio > 0.9) {
  await flushCriticalOps();                   // push first
  await compactSnapshots();                   // then free space
}
```

### Binary Attachments

```typescript
export async function putAttachment(docId: string, file: File) {
  if (file.size > 10 * 1024 * 1024) throw new Error('ATTACHMENT_TOO_LARGE');
  await db.attachments.put({
    id: crypto.randomUUID(),
    docId,
    blob: file,                               // Blobs are stored natively, no base64 blowup
    size: file.size,
  });
}
```

Storing attachments as base64 in a text field inflates them ~33% and forces a full decode on read. IndexedDB stores `Blob` directly.

### Deeper Explanation: The Local Database Is A Real Database

Once Atlas works offline, the device is no longer a cache - it is a replica with its own lifecycle, migrations, quota and failure modes.

That reframing is what separates a professional offline implementation from a demo. A demo writes to IndexedDB and hopes. A professional system versions its local schema, asks for persistence, monitors quota, compacts history, and boots confidently when the store is corrupted or evicted - because it treats local storage as durable-but-unreliable infrastructure, which is exactly what it is.

### Additional Pitfalls

- **Reading a stale schema version.** Browsers run `onupgradeneeded` once per version; if it throws, the DB is left broken.
- **`transaction` auto-commit.** Awaiting a non-IDB promise inside a transaction closes it and the next operation fails; do all awaits first.
- **One huge `put` per keystroke.** Batch writes and flush on an interval; IndexedDB writes are not free.
- **No eviction handling.** Storage can be cleared by the browser; the app must recover by re-fetching from the server.
- **Testing against real IndexedDB.** Use `fake-indexeddb` in Vitest for deterministic, fast tests.

### Real-World Deal-Breakers
- **`localStorage` for document state** - quota exceeded mid-edit and a blocked main thread; content is lost.
- **No schema versioning** - a release changes the store shape and every existing install throws on open.
- **Never requesting persistence** - the browser silently evicts the offline copy and users lose unsynced work.
- **Unbounded op history in the browser** - quota fills, writes start failing, and the editor appears to save while discarding.
- **No `dirty` flag** - the app cannot tell what still needs uploading after a reconnect.
