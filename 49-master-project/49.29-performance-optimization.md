### Budgets Before Optimisation

| Metric | Target | Breaks when |
|---|---|---|
| LCP | < 2.5s | hero render waits on a query |
| INP | < 200ms | keystroke re-renders the tree |
| CLS | < 0.1 | skeletons do not match final layout |
| Editor keystroke -> paint | < 50ms | the whole doc re-renders per character |
| Initial JS | < 180 KB gzip | editor + chart libs in the main chunk |

Write these into CI so a regression fails the build rather than being discovered by users.

### The Editor Is A Different Kind Of Performance Problem

Web Vitals describe page load. A collaborative editor fails on a different axis: **per-keystroke latency**. A 2.5s LCP is excellent if typing then feels laggy.

The four fixes, in order of impact:

```tsx
// 1. Isolate the text surface: only it re-renders per keystroke
<DocumentShell>                       {/* static */}
  <Toolbar />                         {/* subscribes to selection only */}
  <TextSurface />                     {/* the only per-keystroke subscriber */}
  <Sidebar />                         {/* never re-renders on typing */}
</DocumentShell>
```

```tsx
// 2. Virtualise large lists: render the viewport, not the document
import { useVirtualizer } from '@tanstack/react-virtual';

function BlockList({ blocks }: { blocks: Block[] }) {
  const parentRef = useRef<HTMLDivElement>(null);
  const virt = useVirtualizer({
    count: blocks.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 32,
    overscan: 8,
  });
  return (
    <div ref={parentRef} className="h-full overflow-auto">
      <div style={{ height: virt.getTotalSize(), position: 'relative' }}>
        {virt.getVirtualItems().map((v) => (
          <div key={blocks[v.index].id} style={{ position: 'absolute', top: v.start, width: '100%' }}>
            <Block block={blocks[v.index]} />
          </div>
        ))}
      </div>
    </div>
  );
}
```

### Database Performance Under Real Load

```sql
-- The sidebar query, on a workspace with 200k documents
explain (analyze, buffers)
select id, title, updated_at
  from documents
 where workspace_id = $1 and deleted_at is null
 order by updated_at desc
 limit 50;
```

```
Limit  (cost=0.43..118.7 rows=50) (actual time=0.03..0.6 rows=50 loops=1)
  Buffers: shared hit=8
  ->  Index Scan using documents_workspace_active_idx on documents
```

An `Index Scan` hitting 8 buffers is correct. A `Seq Scan` with 40,000 buffers means the partial index is missing and the app degrades as customers succeed.

### Deeper Explanation: Performance Is A Feature You Cannot Retrofit

Every optimisation here is cheap when designed in and expensive when added later. Isolating the text surface is a component-boundary decision. Virtualising is an architectural decision about how blocks are rendered. Splitting the bundle is a routing decision.

Trying to add keystroke latency fixes to a tree that lifts content into a page-level store means rewriting the editor. That is why the professional approach is to *set the budget first*, instrument it in CI, and design each component against it.

### Additional Pitfalls

- **Optimising without measurement.** You make the code harder to read and the metric does not move.
- **`useMemo` everywhere.** Adds bookkeeping cost and indirection; measure before adding.
- **Skeleton that does not match layout.** Invisible CLS, and it looks like sloppiness rather than a bug.
- **Loading the AI panel eagerly.** It is the largest dependency and the least used on first paint.
- **Ignoring the low-end device.** A 2020 mid-range Android is the real target, not an M-series laptop.

### Real-World Deal-Breakers
- **No keystroke budget** - the editor feels laggy on real phones and the product's core interaction is unacceptable.
- **Monolithic bundle with an editor and charts** - multi-second TTI on mobile networks.
- **Unbounded list rendering** - a long document freezes the tab and the user assumes the app lost their work.
- **Seq scan on the sidebar** - page load degrades as the account grows; the largest customers have the worst experience.
- **No CI performance gate** - regressions accumulate one dependency at a time until the app is slow and the cause is untraceable.
