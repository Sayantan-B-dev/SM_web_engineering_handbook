## 49.7 Tailwind

### Subtopic Tree

- Semantic colour tokens instead of raw palette values

### Tailwind v4 In One Paragraph

Tailwind v4 compiles a small CSS file from the utilities you actually use, configured in CSS instead of JavaScript. There is no runtime, no style object, and no cascade to reason about beyond the single-scope utility model.

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  /* Design tokens live here once. Every utility class derives from them. */
  --color-surface:        oklch(0.99 0.002 250);
  --color-surface-muted:  oklch(0.96 0.004 250);
  --color-ink:            oklch(0.22 0.01 250);
  --color-ink-muted:      oklch(0.48 0.01 250);
  --color-accent:         oklch(0.62 0.18 265);
  --color-danger:         oklch(0.58 0.20 25);

  --radius-card: 0.75rem;
  --font-display: "Inter", system-ui, sans-serif;
}

@custom-variant dark (&:where(.dark, .dark *));
```

```html
<!-- Every utility below resolves to the tokens above -->
<button class="rounded-[--radius-card] bg-accent text-white px-3 py-2">Save</button>
```

### Conditional Classes Without Spaghetti

The problem Tailwind creates is string concatenation. `cn()` solves it deterministically:

```typescript
import { clsx, type ClassValue } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

```tsx
function Button({ variant = 'primary', size = 'md', className, ...props }: ButtonProps) {
  return (
    <button
      {...props}
      className={cn(
        'inline-flex items-center justify-center rounded-md font-medium transition',
        'focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent',
        'disabled:opacity-50 disabled:pointer-events-none',
        size === 'sm' && 'h-8 px-3 text-sm',
        size === 'md' && 'h-10 px-4 text-sm',
        size === 'lg' && 'h-12 px-6 text-base',
        variant === 'primary' && 'bg-accent text-white hover:brightness-110',
        variant === 'ghost' && 'hover:bg-surface-muted',
        variant === 'danger' && 'bg-danger text-white',
        className,                              // caller overrides win - twMerge resolves conflicts
      )}
    />
  );
}
```

`twMerge` is the part that matters: without it, `cn('p-2', 'p-4')` emits `p-2 p-4` and the winner depends on stylesheet order. With it, the later value wins predictably.

### Components, Not Class Soup

Rule of thumb for Atlas: **the third time you copy a class list, extract a component.** Tailwind is the styling mechanism; React components are the abstraction.

```tsx
// Bad: the same 30-character class string copy-pasted 14 times
<div class="rounded-lg border border-gray-200 bg-white p-4 shadow-sm">...</div>

// Good: extracted, and the token changes in one place
export function Card({ className, ...props }: React.ComponentProps<'div'>) {
  return (
    <div
      {...props}
      className={cn('rounded-[--radius-card] border border-black/5 bg-surface p-4 shadow-sm', className)}
    />
  );
}
```

### Dark Mode Through Tokens

Do not scatter `dark:` variants across the codebase. Define semantic tokens and flip one class on the root:

```css
@theme {
  --color-surface: oklch(0.99 0.002 250);
  --color-ink: oklch(0.22 0.01 250);
}

.dark {
  --color-surface: oklch(0.18 0.01 250);
  --color-ink: oklch(0.96 0.002 250);
}
```

```tsx
// One class, and both themes work
<div className="bg-surface text-ink">…</div>
```

### Deeper Explanation: Constraint Is The Point

A junior sees Tailwind as "ugly class names". A professional sees a *design system with a compiler behind it*.

When the palette only exists as `--color-accent`, nobody can invent `#3b82f6` on line 400 of a component. When spacing derives from a scale, nobody ships `margin-top: 13px`. Tailwind's real contribution to a codebase like Atlas is that it makes inconsistency *uncomfortable* rather than *easy* - which is the same reason design tokens exist.

Combine it with the design system file (49.08) and you get the property you actually want: **a redesign is a token change, not a find-and-replace across 300 files.**

### Additional Pitfalls

- **Dynamic class names.** `` `bg-${color}-500` `` is invisible to the scanner and the class never gets generated. Map to full class strings in a lookup object.
- **Fighting specificity with `!important`.** You have a design problem; restructure the component instead.
- **`@apply` as your main tool.** It recreates CSS files with extra steps and hides the token. Prefer a component.
- **Untokenised brand colours.** One-off hex values defeat the theme and break dark mode.
- **Ignoring focus styles.** `focus:outline-none` with no replacement removes keyboard accessibility; use `focus-visible`.

### Real-World Deal-Breakers
- **Dynamic class-string construction** - styles silently vanish in production because the scanner never saw the class.
- **Raw hex values in components** - dark mode breaks and the design system cannot be retheme'd.
- **`outline: none` with no focus replacement** - the app becomes keyboard-unusable; a WCAG failure and a legal risk in some jurisdictions.
- **No `twMerge` in a `cn()` helper** - conflicting utilities produce unpredictable winners and "why is the padding different here" bugs.
- **Extracting every utility into `@apply`** - you rebuild hand-written CSS and lose locality.
- **Mixing a component library's stylesheet with Tailwind preflight** - global resets fight each other and spacing drifts site-wide.
