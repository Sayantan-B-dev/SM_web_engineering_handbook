### When A Loop Is Justified

Most "agent" requests should be a single model call with tools. Use a loop only when the task genuinely requires *repeated* decisions based on *observations* - for example: "find every document in this workspace that mentions the old API name and update the code samples."

```typescript
const MAX_STEPS = 12;
const MAX_COST_USD = 0.50;

export async function runAgent(task: string, ctx: AgentContext) {
  const trace: Step[] = [];
  let cost = 0;

  for (let step = 0; step < MAX_STEPS; step++) {
    const decision = await model.decide({ task, trace, tools: TOOL_SCHEMAS });
    cost += decision.usage.costUsd;
    if (cost > MAX_COST_USD) return finish('budget_exceeded', trace);

    if (decision.type === 'final') return finish('done', trace, decision.answer);

    // Authorisation is enforced inside every tool executor, not here
    const result = await TOOLS[decision.tool].execute(decision.args, ctx);
    trace.push({ step, thought: decision.thought, tool: decision.tool, args: decision.args, result });

    if (result.needsApproval) {
      return pauseForApproval(trace, decision, result);   // human in the loop
    }
  }
  return finish('step_limit', trace);
}
```

### Tool Design Rules

| Rule | Why |
|---|---|
| One job per tool | Ambiguous tools get called with wrong arguments |
| Idempotent or explicitly non-idempotent | Retries must not double-apply |
| Returns structured, bounded data | A truncated dump wastes the next step's context |
| Takes IDs, not whole objects | The model should not invent content it never saw |
| Declares reversibility | Destructive tools require an approval gate |

```typescript
const TOOLS = {
  searchDocuments: tool({
    description: 'Full-text search across the workspace. Returns up to 10 IDs with titles and snippets.',
    inputSchema: z.object({ query: z.string().min(2).max(200) }),
    reversible: true,
    execute: async ({ query }, ctx) => searchWorkspace(query, ctx.workspaceId, ctx.userId),
  }),

  proposeEdit: tool({
    description: 'Propose a text replacement in a document. Does NOT apply; returns a diff for approval.',
    inputSchema: z.object({ documentId: z.uuid(), range: z.tuple([z.number(), z.number()]), replacement: z.string().max(2000) }),
    reversible: true,
    execute: async (args, ctx) => {
      const auth = await authorize('document:write', { workspaceId: ctx.workspaceId, documentId: args.documentId }, ctx.userId);
      if (!auth.ok) return { error: 'FORBIDDEN' };
      return { diff: buildDiff(args), applyToken: await stashEdit(args) };   // applied only on approval
    },
  }),

  deleteDocument: tool({
    description: 'Permanently delete a document.',
    inputSchema: z.object({ documentId: z.uuid() }),
    reversible: false,                       // forces the approval gate
    execute: async (args, ctx) => {
      const auth = await authorize('document:delete', { workspaceId: ctx.workspaceId, documentId: args.documentId }, ctx.userId);
      if (!auth.ok) return { error: 'FORBIDDEN' };
      return { needsApproval: true, proposed: args };
    },
  }),
};
```

### Deeper Explanation: Autonomy Must Be Bounded In Four Dimensions

An unbounded agent is not an advanced feature; it is an incident generator. Every agent in Atlas is bounded on four axes, and all four limits are enforced in code the model cannot influence:

1. **Steps** - hard iteration cap.
2. **Time** - wall-clock deadline, propagated as an abort signal.
3. **Cost** - cumulative spend cap per run and per user per day.
4. **Blast radius** - irreversible tools require explicit human approval.

The professional instinct here is to notice that all four limits are *outside* the prompt. Instructions like "do not exceed 10 steps" are suggestions to a stochastic system; code is a guarantee.

### Additional Pitfalls

- **Tools that return unbounded output.** One step with a 40k-token result destroys the remaining context.
- **No idempotency key on write tools.** A retry after a timeout applies the edit twice.
- **Looping on the same failing tool.** Detect repeated identical (tool, args) pairs and abort with a clear error.
- **No trace.** Debugging an agent without a step-by-step record is guessing.
- **Multi-agent by default.** Two agents chatting multiplies cost and latency without improving correctness; add a second only when a role genuinely needs a different tool set.

### Real-World Deal-Breakers
- **No step, time or cost limit** - a stuck loop burns budget and hammers your own API until someone notices.
- **Irreversible tools without approval** - an agent deletes production documents on a misread instruction.
- **Model-supplied resource IDs used directly** - prompt injection escalates to cross-tenant writes.
- **Code execution without a sandbox** - arbitrary code in the same container as your database credentials.
- **No structured trace** - you cannot explain to a customer what the agent did to their data.
