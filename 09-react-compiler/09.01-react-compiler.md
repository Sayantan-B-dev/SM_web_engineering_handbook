### What It Is
React Compiler is a **build-time optimizing compiler** that automatically memoizes React components and hooks. It eliminates the need for manual `useMemo`, `useCallback`, and `React.memo` by analyzing your code statically and inserting memoization where safe.

It works on both React and React Native, and is **fully production-ready** - battle-tested on major apps at Meta.

### The Long Road to v1.0
The React team's compiler efforts span almost a decade:
1. **2017** - Prepack (eventually shut down, but lessons informed Hooks).
2. **2021** - Xuan Huang demoed the first new compiler iteration.
3. **2022-2024** - Rewritten around a Control Flow Graph (CFG) based High-Level Intermediate Representation (HIR).
4. **2025** - React Compiler 1.0 stable release.

### How It Works (Under the Hood)
Although implemented as a Babel plugin, the compiler is largely **decoupled from Babel**. It:
1. Takes the AST from Babel.
2. Lowers it into its own **HIR (High-Level Intermediate Representation)**.
3. Runs multiple compiler passes to understand data-flow and mutability.
4. Granularly memoizes values used in rendering - including **conditional memoization**, which manual memoization cannot do.

### Installation
```bash
npm install -D babel-plugin-react-compiler@latest
```

**Critical rule:** React Compiler must run **first** in your Babel plugin pipeline. It needs the original source before other transforms rewrite it.

```javascript
// babel.config.js
module.exports = {
  plugins: [
    'babel-plugin-react-compiler', // must run first!
    // ... other plugins
  ],
};
```

### Build Tool Setup
| Tool | Setup |
|------|-------|
| **Babel** | Add plugin first in `babel.config.js` |
| **Vite** | Add to `@vitejs/plugin-react`'s babel config |
| **Next.js** | Set `reactCompiler: true` in `next.config.js` |
| **Webpack** | Community `react-compiler-webpack` loader |
| **Expo** | Enable via Expo docs |
| **Metro (RN)** | Uses Babel via Metro - same as Babel |
| **Rspack/Rsbuild** | Refer to their docs |

### Real-World Deal-Breakers
- **Adding compiler after other Babel plugins** → compiler sees transformed code, not original → wrong analysis.
- **Using `eval` or `with`** → compiler cannot statically analyze these → component silently skipped.
- **Assuming compiler works on any React version** → designed for React 19, supports 17/18 with caveats.
- **Expecting it to fix performance problems** → it only optimizes safe patterns; heavy algorithmic work still needs human attention.
