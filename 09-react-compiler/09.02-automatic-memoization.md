## 9.2 Automatic Memoization

### Subtopic Tree
- What the compiler memoizes
- Reactive scopes (memoization units)
- Cache slots (`_c` hook)
- Conditional memoization (impossible manually)
- Granularity: per-scope, not per-hook

### Reactive Scopes - The Unit of Memoization
The compiler groups values into **reactive scopes**. Each scope has:
- A computed list of **reactive dependencies** (inputs that can change between renders).
- One or more **cached outputs**.

These scopes become **cache slots** in a per-component cache array. The compiler emits a special `_c` hook (the "memo cache") and conditional equality checks around each scope.

```javascript
// Your code
function Component({ a, b }) {
  const result = expensive(a);
  const value = result + b;
  return <div>{value}</div>;
}

// Compiler output (simplified)
function Component({ a, b }) {
  const $ = _c(3); // memo cache with 3 slots
  let result;
  if ($[0] !== a) {
    result = expensive(a);
    $[0] = a;
    $[1] = result;
  } else {
    result = $[1];
  }
  let value;
  if ($[2] !== b || $[3] !== result) { // wait, slots...
    value = result + b;
    // ... cache
  }
  return <div>{value}</div>;
}
```

The exact output is more complex, but the principle is: **cache by dependency comparison**.

### Why It's More Granular Than Manual Memoization
Manual memoization:
- You wrap an entire computation in one `useMemo`.
- All outputs share one dependency array.

Compiler memoization:
- Values are grouped into **multiple independent scopes**.
- Each scope recalculates only when its own dependencies change.
- **Conditional memoization** - values computed inside `if` blocks can be memoized separately.

```javascript
// Manual: everything in one useMemo
const processed = useMemo(() => {
  const filtered = items.filter(predicate);
  const sorted = filtered.sort(compare);
  const grouped = groupBy(sorted, key);
  return { filtered, sorted, grouped };
}, [items, predicate, compare, key]);

// Compiler: three independent scopes
// filtered recalculates when items/predicate change
// sorted recalculates when filtered/compare change
// grouped recalculates when sorted/key change
// → only the affected scope recalculates, not all three
```

### What the Compiler Replaces
| Manual | Compiler |
|--------|----------|
| `React.memo(Component)` | Automatic component memoization |
| `useMemo(() => value, deps)` | Automatic value memoization |
| `useCallback(fn, deps)` | Automatic function reference stability |
| Dependency arrays | Inferred automatically |

### Real-World Deal-Breakers
- **Relying on referential equality for correctness** → compiler may memoize differently than you expect. If your app depends on a specific object identity, the compiler can break it.
- **Expecting compiler to memoize everything** → it only memoizes what it can statically prove safe.
- **Manual memoization that doesn't match compiler output** → compiler bails out of the **entire component** to avoid breaking your code.
- **Assuming compiler output is stable** → future compiler versions may change memoization strategy.
