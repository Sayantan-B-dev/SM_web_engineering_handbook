## 9.7 Compiler Limitations

### Subtopic Tree
- Rules of React requirement
- Unsupported syntax (`eval`, `with`)
- Silent bailouts
- No warnings
- Class components
- Conditional hook calls
- Mutating values during render
- Ref access during render
- Memoization-dependent correctness
- Third-party library incompatibilities

### The Fundamental Constraint
**React Compiler only optimizes code that follows the Rules of React.** Components with violations are skipped during compilation.

### Unsupported Syntax
Features like `eval` and `with` make it **impossible to statically understand** what the code does at compile time.

```jsx
// ❌ eval - can't be analyzed
function Component({ code }) {
  const result = eval(code);
  return <div>{result}</div>;
}

// ❌ with - changes scope dynamically
function Component() {
  with (Math) {
    return <div>{sin(PI / 2)}</div>;
  }
}

// ✅ Use normal property access
function Component({ propName, props }) {
  const value = props[propName];
  return <div>{value}</div>;
}
```

### Silent Bailouts
The compiler **silently skips** optimization when it encounters patterns it cannot prove safe. **No warnings are produced** - the component just runs without memoization.

Common bailout triggers:
- `try/catch` wrapping render expressions
- Optional chaining on refs during render
- Mutating values during render
- Class component patterns
- Conditional hook calls
- Hook calls in loops
- Hook calls in nested functions

### The Most Dangerous Limitation: Memoization-Dependent Correctness
> **"One of the main ways React Compiler can break your app is if your code was written to rely on memoization for correctness."**

If your app depends on **specific values staying referentially stable** to work (e.g., `useEffect` deps that must not change, `React.memo` boundaries that must hold), the compiler may memoize differently → **infinite loops, missing updates, or over-firing effects**.

```jsx
// ❌ Relies on useMemo for correctness (not just perf)
const config = useMemo(() => ({ theme, size }), [theme, size]);

useEffect(() => {
  initialize(config);
}, [config]); // must NOT change unless theme/size change

// If compiler doesn't preserve this memoization, effect fires on every render
```

### Real-World Deal-Breakers
- **No warnings on bailout** → you don't know a component wasn't optimized. Use React DevTools "Memo ✨" badge to verify.
- **Rules of React violations that compiler can't detect** → subtle bugs that only surface after optimization.
- **Third-party libraries that mutate props/state** → compiler may break them.
- **Class components** → not optimized at all.
- **Destructuring props into another object** → can lead to under-optimized components.
