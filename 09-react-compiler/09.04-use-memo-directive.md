## 9.4 `use memo`

### What It Does
`"use memo"` is a directive that **opts a function into compilation**. It's a string literal placed at the beginning of a function body or at the top of a module.

```jsx
function MyComponent() {
  "use memo"; // Opt this component into compilation
  return <div>{/* ... */}</div>;
}
```

### Function-Level Directive
```jsx
function OptimizedComponent() {
  "use memo";
  return <div>This will be optimized</div>;
}

function UnoptimizedComponent() {
  // no directive - compiled only if infer mode detects it
  return <div>This depends on compilation mode</div>;
}
```

### Module-Level Directive
```jsx
// At the very top of the file
"use memo";

// All functions in this file will be compiled
function Component1() {
  return <div>Compiled</div>;
}

function Component2() {
  return <div>Also compiled</div>;
}

// Can be overridden at function level
function Component3() {
  "use no memo"; // overrides module directive
  return <div>Not compiled</div>;
}
```

### When to Use `"use memo"`
| Scenario | Why |
|----------|-----|
| **Annotation mode** | Only functions with `"use memo"` are compiled |
| **Infer mode override** | Force compilation of a function the compiler's heuristics skipped |
| **Non-standard naming** | Function isn't named like a component/hook but should be compiled |

**Critical:** In `infer` mode, the compiler detects components by **PascalCase naming** and hooks by **`use` prefix**. If a component isn't being compiled, **fix its naming convention** rather than forcing compilation with `"use memo"`.

### Real-World Deal-Breakers
- **Using `"use memo"` instead of fixing naming** → masks a real code smell.
- **Assuming `"use memo"` guarantees optimization** → if the function violates Rules of React, it still won't compile.
- **Module-level directive on a utility file** → compiles non-React functions unnecessarily.
- **Directive not first statement** → ignored.
