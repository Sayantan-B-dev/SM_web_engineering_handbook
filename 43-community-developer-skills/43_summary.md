# 43. COMMUNITY / DEVELOPER SKILLS - Complete Deep Dive

## 43.13 Summary: Developer Skills Deal-Breaker Checklist

| Area | Deal-Breaker | Consequence |
|------|-------------|-------------|
| **Communication** | Jargon without translation | Audience nods but doesn't understand |
| **Communication** | Mechanism-first explanation | You lose the argument |
| **Communication** | One explanation for all audiences | CEO bored, engineer frustrated |
| **Architecture** | No ADR | Same debate every 6 months |
| **Architecture** | No rejected alternatives | Future teams re-propose rejected options |
| **Tradeoffs** | Only the upside | Team doesn't know what they're giving up |
| **Tradeoffs** | No quantification | "Redis is faster" is not a trade-off |
| **Presentations** | No clear message | Audience remembers nothing |
| **Presentations** | Walls of text on slides | Audience reads instead of listens |
| **Presentations** | Live demo without backup | Demo fails, talk collapses |
| **Lightning Talks** | Covering too much | Audience remembers nothing |
| **Lightning Talks** | Code too small | Audience can't read it |
| **Public Speaking** | No practice | Talk is a first draft |
| **Public Speaking** | Reading from slides | Audience disengages |
| **Q&A** | No preparation | Hostile question throws you off |
| **Q&A** | Pretending to know | Audience sees through it |
| **Mentoring** | No structured plan | Junior flounders |
| **Mentoring** | Answer-first mentoring | Junior never learns to think |
| **Mentoring** | Ignoring AI in mentoring | Juniors ship code they don't understand |
| **Networking** | Only when you need something | Transactional and off-putting |
| **Networking** | No follow-up | Connections fade within weeks |
| **Code Review** | Approving without reading | Bugs ship to production |
| **Code Review** | No response to comments | PR stalls indefinitely |
| **Feedback** | Vague feedback | Author doesn't know what to fix |
| **Feedback** | Only critical feedback | Author feels attacked |
| **Community** | Thinking contribution = code | You miss 80% of opportunities |
| **Community** | Not reading `CONTRIBUTING.md` | Contribution rejected |

---

**The Big Rule:** Developer skills are **not soft skills**. They are the hard skills of explaining, deciding, presenting, and contributing. Every developer can write code. The ones who get promoted, lead projects, and build lasting careers are the ones who can **translate complexity into clarity, make decisions with transparency, present with confidence, and contribute beyond their own commits**. Practice these skills deliberately - the same way you practice writing code.
