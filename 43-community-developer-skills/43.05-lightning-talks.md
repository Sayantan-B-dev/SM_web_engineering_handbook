### What a Lightning Talk Is
A lightning talk is a **short presentation, typically 5 minutes** (some formats allow 3-7 minutes). They are a standard practice in the tech industry. Lightning talks are ideal to **practice public speaking and experiment with explaining or pitching something in a short time**.

### Why Lightning Talks Are the Best Entry Point
- **Short enough to prepare carefully.** A 5-minute talk is easier to prepare than a 30-minute talk.
- **Low stakes.** If it goes badly, it's over in 5 minutes.
- **High learning density.** You learn more from one 5-minute talk than from 10 hours of reading about public speaking.
- **Community-friendly.** Meetups love lightning talks because they fit many speakers into one event.

### The One-Message Rule (Intensified)
In a 5-minute talk, you have time for **exactly one idea**. Not two. Not three. One. Every sentence must serve that one idea.

```text
✅ Good lightning talk topic: "How to use React Server Components
   to eliminate loading spinners"

❌ Bad lightning talk topic: "An overview of React Server Components,
   Client Components, Server Actions, Streaming, and Hydration"
```

### Code in Lightning Talks
When showing code, it needs to be **understandable for people unfamiliar with the language, and within the 30 seconds or so that the code is on the screen**.

```text
✅ Good code slide:
  - 5-10 lines maximum
  - Large font (18pt+)
  - Comments explaining intent
  - No boilerplate (imports, setup)

❌ Bad code slide:
  - 50 lines of code
  - Small font
  - No comments
  - Imports, setup, and boilerplate included
```

### Timing
- **Practice with a timer.** A 5-minute talk that runs 8 minutes is a failure.
- **Plan for 4 minutes of content.** Leave 1 minute for buffer.
- **Cut ruthlessly.** If a slide doesn't serve the one message, remove it.
- **Have a hard stop.** Know which slide you'll skip if you're running long.

---

### Deeper Explanation: Constraint Is The Format

Five minutes forces clarity: one idea, one demo, one takeaway. The structure that fits: 30 seconds of context, 3 minutes of the core insight with a live or recorded demo, 1 minute of implications, 30 seconds of how to try it. Slides: five to seven maximum, each one visual.

Lightning talks are the cheapest way to build speaking confidence and visibility, precisely because the scope is small enough to prepare in an hour. The failure mode is trying to present a 20-minute talk faster â€” cut content, do not speed up.

### Additional Pitfalls
- **Too much content.** You will rush and land nothing; cut it by half, then half again.
- **Live demo without a fallback.** Record it; networks fail at the worst moment.
- **No takeaway.** The audience should leave able to repeat your one sentence.
- **Over-polished slides.** They signal priority inversion; content clarity matters more.
- **Skipping rehearsal.** Five minutes is short enough that timing is unforgiving.

### Real-World Deal-Breakers
- **Trying to cover too much** → the audience remembers nothing. One idea per talk.
- **No timer** → you run over and get cut off. Practice with a timer.
- **Code slides too small** → the audience can't read them. 18pt minimum.
- **No practice** → the talk sounds like a first draft. Practice out loud at least 3 times.
- **Choosing a topic you don't care about** → the audience won't care either.
