### The Official Repository
React Kolkata maintains an official GitHub repository (`reactplay/react-kolkata`) - a TypeScript project with 22 stars and 45 forks. It's the community's open-source home. 

### ReactPlay
ReactPlay is both an **open-source project and a community** with online discussions and offline chapters. Its platform allows developers to create small projects called **"plays."** Participants can contribute to the platform itself or build something within it. This offers a manageable starting point - contributing doesn't have to begin with a major architectural change. 

### The AI Slop Crisis
GitHub's Octoverse report names a widening **"contributor-to-maintainer gap,"** worsened by **"AI slop"** - low-quality, auto-generated pull requests that consume maintainer time without adding real value. The **Jazzband collective** shut down entirely in 2025, citing the unsustainable volume of AI-generated spam PRs as a primary driver.

### Deeper Explanation: Local Community Is The Best On-Ramp To Open Source

Contributing to open source is easier with people: a local community provides reviewers, context, and accountability. The practical path: pick one project used by the community, start with documentation or tests, ask the maintainer (often someone in the group) what would help, and participate in issue triage.

The habit that leads to real contributions: keep a list of bugs you hit in dependencies, then fix one. That produces genuine, small, valuable fixes and a contribution record built on your own experience rather than "good first issue" tourism.

### Additional Pitfalls
- **Drive-by PRs without discussion.** Maintainers cannot tell if it is wanted; open an issue first.
- **Ignoring contribution guidelines.** It costs a review cycle and goodwill.
- **Giving up after one rejected PR.** Ask why, adjust, and try a smaller change.
- **Contributing only to hype projects.** Fixing things you actually use creates impact and learning.
- **No follow-up on reviews.** Abandoned PRs are worse than unopened ones.

### Real-World Deal-Breakers
- **Submitting AI-generated PRs without review** → you become part of the problem. Review every line before submitting.
- **Not reading `CONTRIBUTING.md`** → your PR violates project conventions and is rejected.
- **Starting with a huge PR** → maintainers can't review it. Start with a small fix, a doc update, or a test.
