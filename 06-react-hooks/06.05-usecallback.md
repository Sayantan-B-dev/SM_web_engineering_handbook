### Syntax
```jsx
const memoizedFn = useCallback(() => {
  doSomething(a, b);
}, [a, b]);
```

### Why It Exists
Functions are re-created on every render. `useCallback` returns the same function reference as long as deps haven't changed.

```jsx
// ❌ Without useCallback - new function every render
function Parent() {
  const [count, setCount] = useState(0);
  const handleClick = () => setCount(c => c + 1); // new function each render
  return <MemoChild onClick={handleClick} />;
}

// ✅ With useCallback - same function when deps unchanged
function Parent() {
  const [count, setCount] = useState(0);
  const handleClick = useCallback(() => setCount(c => c + 1), []);
  return <MemoChild onClick={handleClick} />;
}

const MemoChild = React.memo(({ onClick }) => <button onClick={onClick}>+1</button>);
```

### `useCallback` vs `useMemo`
```jsx
// These are equivalent:
const fn = useCallback(() => doSomething(a), [a]);
const fn = useMemo(() => () => doSomething(a), [a]);
```

- `useCallback(fn, deps)` = memoize a function.
- `useMemo(fn, deps)` = memoize the **result** of calling `fn`.

### When NOT to Use
- **Passing callback to a non-memoized child** → no benefit; child re-renders anyway.
- **Callback used locally, not passed down** → no need.
- **Callback depends on everything** → deps change every render → no memoization.

### Common Pattern
```jsx
function SearchBox() {
  const [query, setQuery] = useState('');

  const handleChange = useCallback((e) => {
    setQuery(e.target.value);
  }, []);

  const handleClear = useCallback(() => {
    setQuery('');
  }, []);

  return (
    <>
      <input value={query} onChange={handleChange} />
      <button onClick={handleClear}>Clear</button>
    </>
  );
}
```

### Real-World Deal-Breakers
- **Missing deps** → stale closures (callback captures old values).
- **`useCallback` everywhere** → adds memory and complexity with no benefit unless the child is memoized.
- **Empty deps but reading props/state** → stale values inside the callback.
- **Not memoizing the child** → `useCallback` has zero effect.
- **Over-memoization** → premature optimization; profile first.
