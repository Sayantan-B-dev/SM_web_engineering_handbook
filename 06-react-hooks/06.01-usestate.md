## 6.1 useState

### Subtopic Tree
- Basic syntax
- Lazy initialization
- Functional updates
- State batching
- Object & array state
- Multiple state variables
- State updates are async
- State resets via key
- Common pitfalls

### Syntax
```jsx
const [state, setState] = useState(initialValue);
```

```jsx
// Basic
const [count, setCount] = useState(0);

// Object
const [user, setUser] = useState({ name: '', age: 0 });

// Array
const [items, setItems] = useState([]);

// Lazy init (expensive computation)
const [data, setData] = useState(() => computeExpensiveValue());
```

### Functional Updates
```jsx
// ❌ Uses stale value if multiple updates in same tick
setCount(count + 1);
setCount(count + 1); // still +1

// ✅ Always uses latest state
setCount(prev => prev + 1);
setCount(prev => prev + 1); // +2
```

**Rule:** Use functional updates when new state depends on previous state.

### Object State Updates
```jsx
const [user, setUser] = useState({ name: 'Alice', age: 30 });

// ❌ Mutates - no re-render
user.name = 'Bob';

// ❌ Loses other fields
setUser({ name: 'Bob' });

// ✅ Merge - create new object
setUser(prev => ({ ...prev, name: 'Bob' }));
```

### Array State Updates
```jsx
const [items, setItems] = useState([]);

// Add
setItems(prev => [...prev, newItem]);

// Remove
setItems(prev => prev.filter(i => i.id !== id));

// Update one
setItems(prev => prev.map(i => i.id === id ? { ...i, done: true } : i));

// Insert at index
setItems(prev => [...prev.slice(0, i), newItem, ...prev.slice(i)]);

// Sort (must copy - sort mutates)
setItems(prev => [...prev].sort((a, b) => a.name.localeCompare(b.name)));
```

### State Resets via Key
```jsx
// Resetting component state by changing key
function App() {
  const [userId, setUserId] = useState(1);
  return <UserProfile key={userId} userId={userId} />;
  // When userId changes, UserProfile unmounts + remounts → fresh state
}
```

### Real-World Deal-Breakers
- **Reading state right after `setState`** → stale value; state updates are async.
- **Mutating state directly** → no re-render, breaks memoization.
- **Storing derived state** → causes sync bugs; compute during render.
- **Storing props in state** → won't update when props change.
- **Too many `useState` calls** → consider `useReducer` for related state.
- **Initializing with prop and expecting updates** → `useState(props.value)` only uses the initial value.
