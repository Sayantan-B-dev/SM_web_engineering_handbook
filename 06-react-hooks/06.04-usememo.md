### Syntax
```jsx
const memoizedValue = useMemo(() => computeValue(a, b), [a, b]);
```

### Example: Expensive Filter
```jsx
function ProductList({ products, query }) {
  const filtered = useMemo(() => {
    console.log('Filtering...');
    return products.filter(p => p.name.toLowerCase().includes(query.toLowerCase()));
  }, [products, query]);

  return <ul>{filtered.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}
```

Without `useMemo`, the filter runs on every render (even if `products` and `query` haven't changed).

### Example: Stable Object Reference
```jsx
function Parent() {
  const [count, setCount] = useState(0);

  // Without useMemo: new object every render → Child re-renders
  const options = useMemo(() => ({ theme: 'dark', size: 'lg' }), []);

  return <MemoizedChild options={options} />;
}

const MemoizedChild = React.memo(({ options }) => {
  console.log('Child rendered');
  return <div>{options.theme}</div>;
});
```

### When NOT to Use `useMemo`
- **Cheap computations** → memoization overhead > recompute cost.
- **Values that change every render** → no benefit.
- **Primitives** → `useMemo` returns the same primitive when deps don't change anyway.

```jsx
// ❌ Pointless
const doubled = useMemo(() => count * 2, [count]);

// ✅ Just compute directly
const doubled = count * 2;
```

**Rule of thumb:** Profile first. Only memoize when you've measured a real performance problem.

### Real-World Deal-Breakers
- **`useMemo` isn't a guarantee** → React may drop the cache for memory. Never rely on it for correctness.
- **Missing dependencies** → stale memoized value.
- **Object/array in deps** → new reference each render → memo recomputes every time.
- **Memoizing everything** → memory overhead, complex code, no benefit for cheap computations.
- **Using `useMemo` for side effects** → use `useEffect`. `useMemo` should be pure.
