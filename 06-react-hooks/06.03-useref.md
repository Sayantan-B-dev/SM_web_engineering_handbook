## 6.3 useRef

### Subtopic Tree
- Mutable container (`.current`)
- DOM references
- Persisting values across renders
- No re-render on change
- Combining with forwardRef
- useRef vs useState
- useRef vs createRef

### Syntax
```jsx
const ref = useRef(initialValue);
ref.current; // mutable value
```

### Use Case 1: DOM References
```jsx
function TextInput() {
  const inputRef = useRef(null);

  function focus() {
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focus}>Focus</button>
    </>
  );
}
```

### Use Case 2: Persisting Values (no re-render)
```jsx
function Timer() {
  const [count, setCount] = useState(0);
  const startTimeRef = useRef(Date.now());

  // startTimeRef.current persists across renders but doesn't trigger re-renders
  return <p>Elapsed: {Date.now() - startTimeRef.current}ms</p>;
}
```

### Use Case 3: Storing Latest Value
```jsx
function useInterval(callback, delay) {
  const savedCallback = useRef(callback);

  useEffect(() => {
    savedCallback.current = callback;
  }, [callback]);

  useEffect(() => {
    if (delay == null) return;
    const id = setInterval(() => savedCallback.current(), delay);
    return () => clearInterval(id);
  }, [delay]);
}
```

### Use Case 4: Render Count / Previous Value
```jsx
function usePrevious(value) {
  const ref = useRef();

  useEffect(() => {
    ref.current = value;
  }, [value]);

  return ref.current; // previous value
}

function Counter() {
  const [count, setCount] = useState(0);
  const prev = usePrevious(count);

  return (
    <>
      <p>Now: {count}, Before: {prev}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </>
  );
}
```

### useRef vs useState

| Feature | `useRef` | `useState` |
|---------|----------|-----------|
| Triggers re-render | ❌ | ✅ |
| Persists across renders | ✅ | ✅ |
| Mutable | ✅ (`.current = x`) | ❌ (must use setter) |
| Use for | DOM, timers, flags | UI-driving values |

### Real-World Deal-Breakers
- **Reading `ref.current` during render** → unreliable in concurrent mode. Read in effects or handlers.
- **Conditionally assigning refs** → `ref={cond ? refA : refB}` makes `refA.current` unpredictable.
- **Overusing refs** → if a value drives the UI, it should be state.
- **Refs don't trigger re-render** → changing `ref.current` won't update UI. Use state if UI depends on it.
- **Forwarding refs to function components** → must use `forwardRef` (or React 19: refs are props).
