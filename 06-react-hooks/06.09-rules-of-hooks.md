## 6.9 Rules of Hooks

### Subtopic Tree
- Only call hooks at top level
- Only call hooks from React functions
- Order matters
- ESLint enforcement
- What breaks and why

### The Two Rules
1. **Top level only** - no hooks inside conditions, loops, or nested functions.
2. **React functions only** - call hooks from components or custom hooks.

### Why Order Matters
React tracks hooks by **call order**, not name. Each render must call the same hooks in the same order.

```jsx
// ❌ Conditional hook call - order changes between renders
function Bad({ flag }) {
  if (flag) {
    const [a, setA] = useState(0); // only called when flag is true
  }
  const [b, setB] = useState(0);
}
// Render 1 (flag=true): [a, b]
// Render 2 (flag=false): [b]  → b's state is actually from a's slot!

// ✅ Always call hooks in the same order
function Good({ flag }) {
  const [a, setA] = useState(0);
  const [b, setB] = useState(0);
  if (flag) { /* use a */ }
}
```

### Common Violations
```jsx
// ❌ Inside a loop
for (let i = 0; i < 3; i++) {
  useEffect(() => {}, []);
}

// ❌ Inside a nested function
function outer() {
  function inner() {
    useState(0);
  }
}

// ❌ After early return
function Bad({ data }) {
  if (!data) return null;
  const [x, setX] = useState(0); // ❌ called conditionally
}

// ✅ Before early return
function Good({ data }) {
  const [x, setX] = useState(0);
  if (!data) return null;
}
```

### ESLint
Install `eslint-plugin-react-hooks`:
```json
{
  "extends": ["plugin:react-hooks/recommended"]
}
```
Catches:
- Rules of hooks violations
- Missing deps in `useEffect`

### Real-World Deal-Breakers
- **Early returns before hooks** → hooks skipped on some renders → corrupted state.
- **Conditional hooks** → React throws "Rendered more hooks than during the previous render".
- **Hooks in class components** → only function components can use hooks.
- **Hooks in plain JS functions** → must be React functions or custom hooks.
