### Setup
```tsx
import { WagmiProvider } from 'wagmi';
import { RainbowKitProvider, getDefaultConfig } from '@rainbow-me/rainbowkit';
import { mainnet, polygon, optimism, arbitrum, base } from 'wagmi/chains';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const config = getDefaultConfig({
  appName: 'My Web3 App',
  projectId: 'YOUR_REOWN_PROJECT_ID', // Required
  chains: [mainnet, polygon, optimism, arbitrum, base],
});

const queryClient = new QueryClient();

function App() {
  return (
    <WagmiProvider config={config}>
      <QueryClientProvider client={queryClient}>
        <RainbowKitProvider>
          <YourApp />
        </RainbowKitProvider>
      </QueryClientProvider>
    </WagmiProvider>
  );
}
```

### Reading Contracts
```tsx
import { useReadContract } from 'wagmi';
import { erc20Abi } from 'viem';

function TokenBalance({ address }: { address: `0x${string}` }) {
  const { data: balance } = useReadContract({
    address: '0x...', // token contract
    abi: erc20Abi,
    functionName: 'balanceOf',
    args: [address],
  });

  return <p>Balance: {balance?.toString()}</p>;
}
```

### Writing Contracts
```tsx
import { useWriteContract, useWaitForTransactionReceipt } from 'wagmi';

function TransferToken() {
  const { writeContract, data: hash } = useWriteContract();
  const { isLoading, isSuccess } = useWaitForTransactionReceipt({ hash });

  function transfer() {
    writeContract({
      address: '0x...',
      abi: erc20Abi,
      functionName: 'transfer',
      args: ['0xRecipient...', 1000000000000000000n],
    });
  }

  return (
    <button onClick={transfer} disabled={isLoading}>
      {isLoading ? 'Confirming...' : isSuccess ? 'Done!' : 'Transfer'}
    </button>
  );
}
```

### Important Compatibility Note (2026)
**Wagmi v3 is out, but RainbowKit doesn't support it yet** - it still pins wagmi v2. ConnectKit and Reown AppKit (ex-Web3Modal) also haven't shipped wagmi v3 support, so swapping the kit wouldn't unblock the upgrade.

### Deeper Explanation: Hooks Over Providers, Providers Over Globals

The mature React pattern (wagmi + viem, or RainbowKit for UI) wraps wallet state in a provider and exposes typed hooks: connection state, chain, balance, read hooks with caching, write hooks that return transaction lifecycle state, and typed contract calls generated from ABIs. That structure is what keeps the app testable â€” components consume typed data instead of reaching into a global provider.

```tsx
// One provider at the root, then typed hooks in components
function App({ children }: { children: React.ReactNode }) {
  const config = createConfig({
    chains: [mainnet, base],
    connectors: [injected(), walletConnect({ projectId: env.WC_PROJECT_ID }), coinbaseWallet()],
    transports: { [mainnet.id]: http(env.RPC_MAINNET), [base.id]: http(env.RPC_BASE) },
  });
  return (
    <WagmiProvider config={config}>
      <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>
    </WagmiProvider>
  );
}

// Write with full lifecycle state instead of a bare promise
const { writeContractAsync, isPending } = useWriteContract();
const { isLoading: isConfirming, isSuccess } = useWaitForTransactionReceipt({ hash });

async function mint() {
  try {
    const hash = await writeContractAsync({ address, abi, functionName: 'mint', args: [1n] });
    setHash(hash);                       // show pending + explorer link
  } catch (err) {
    if (isUserRejection(err)) return;    // expected path, no toast needed
    toast.error(humanizeChainError(err));
  }
}
```

### Additional Pitfalls
- **Reading `window.ethereum` directly in components.** Not SSR-safe, not multi-wallet, not testable.
- **Ignoring the query cache.** On-chain reads must be cached and invalidated on new blocks or after writes.
- **No chain guard.** If the user is on the wrong network, writes fail confusingly; prompt a switch.
- **Sending a transaction without simulation or gas margin.** Users pay for reverts.
- **Hydration mismatches from wallet state during SSR.** Render wallet-dependent UI only after mount.
- **Not showing the explorer link.** Users need independent confirmation of what happened.

### Real-World Deal-Breakers
- **Not using TanStack Query** → wagmi requires it for caching and background refetch. Without it, you get stale data.
- **RainbowKit without a Reown Project ID** → RainbowKit projects require a Reown project ID.
- **Wagmi v3 with RainbowKit** → RainbowKit pins wagmi v2. Don't upgrade to v3 until RainbowKit ships support.
- **No multi-chain support** → users expect to switch chains. Configure multiple chains from day one.
- **Hardcoding contract addresses** → addresses differ per chain. Use a chain-aware config.
- **No error handling** → `useWriteContract` can fail silently. Always handle the error state.
