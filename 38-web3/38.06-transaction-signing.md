### EIP-1559 - The Standard
EIP-1559 is the post-London fee market standard. It separates the base fee and the tip for predictable pricing, using `max_fee_per_gas` and `max_priority_fee_per_gas`. The transaction format is:

```
0x02 || RLP([chainId, nonce, maxPriorityFee, maxFee, gasLimit, to, value, data, accessList, v, r, s])
```

### EIP-712 - Typed Structured Data Signing
EIP-712 defines a standard for signing structured data, making signatures human-readable in wallets. Instead of signing an opaque hex string, users see:

```
Sign in to My Dapp

Domain: mydapp.com
Address: 0xAb5801...aeC9B
Statement: I accept the Terms of Service
Nonce: 32891757
```

This is the foundation of SIWE (Sign-In with Ethereum) and many DeFi protocols. EIP-712 signing is used for user decryption requests in Zama's FHEVM, and for authorizing typed data payloads in OpenZeppelin's Relayer.

### Deeper Explanation: A Transaction Has A Lifecycle, Design For All Of It

Signing is the user's authorisation; submission is only the start. The states a UI must model: `idle â†’ simulating â†’ awaiting-signature â†’ submitted â†’ pending â†’ confirmed | failed | replaced | dropped`. Each transition has UX consequences: a signature prompt can be rejected, a submitted transaction can sit pending for minutes, and a drop (low fee, node eviction) needs a re-submit with a higher fee.

EIP-1559 fee fields (`maxFeePerGas`, `maxPriorityFeePerGas`) plus nonce management are what determine whether a transaction lands. **Simulation before signing** (`eth_call`/`eth_estimateGas` or a simulation API) is the single most valuable safety feature: it turns "unknown revert after gas spent" into a clear message before the user signs. For batch actions, multicall (`aggregate`) reduces cost and round trips.

### Additional Pitfalls
- **No pending state.** Users re-click and send a second transaction; disable and show progress with the explorer link.
- **Not handling rejection.** It is a normal path; clear the pending state without an error toast.
- **Ignoring nonce conflicts.** Sequential user actions need queueing or an explicit pending model.
- **No simulation.** Users pay gas to discover a revert they could have seen.
- **Dropped transactions.** Detection (time-based) and a re-submit with the same nonce at a higher fee.

### Real-World Deal-Breakers
- **Signing raw hex** → users can't verify what they're signing. EIP-712 makes the signed data human-readable.
- **No nonce management** → concurrent transactions with the same nonce fail. Track nonces carefully.
- **Hardcoding gas limits** → gas costs fluctuate. Use `eth_estimateGas` and add a buffer.
- **Signing without domain binding** → a signature valid on one dApp can be replayed on another. EIP-712 includes domain binding.
