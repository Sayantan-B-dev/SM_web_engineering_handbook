### What Ethereum Is
Ethereum is a programmable blockchain supporting smart contracts. It operates using a proof-of-stake consensus mechanism. Ethereum is Turing-complete, meaning you can program pretty much anything on it.

### The 2025-2026 Upgrade Cascade

| Upgrade | Key Change | Impact on L2 |
|---------|-----------|-------------|
| **Dencun** (2024) | EIP-4844 (proto-danksharding) introduced blobs | Dramatically reduced L2 data posting costs |
| **Pectra** (April 2025) | Expanded blob capacity | Further reduced L2 costs |
| **Fusaka** (November 2025) | PeerDAS, blob parameter-only forks | Increased blob throughput |

Source: 

The Dencun upgrade introduced blobs - a new data format created specifically to help layer-2 rollups post their compressed transactions more cheaply and securely on Ethereum. Pectra then expanded blob capacity, and Fusaka integrated PeerDAS with plans for "blob parameter only" forks to further increase throughput.

**A Fusaka follow-up will increase blob capacity from 6/9 to 10/15 per block, and a second in early 2026 will increase it again to 14/21**.

### The L2 Economic Shift (2026)
After Vitalik Buterin publicly drew the line between "true rollups" and "glorified multisigs," the L2 competition shifted from price to **minimum trust model**. When transaction fees dropped from "expensive" to "nearly free," the focus moved to what level of security guarantee users actually receive.

The L2BEAT Stages Framework (Stage 0 → Stage 1 → Stage 2) quantifies this: if upgrades can happen rapidly without exit time for users, if fraud proofs aren't fully live, if a small group can override transaction results - then the chain may still be useful, but it's hard to argue it's an extension of Ethereum's minimum-trust principles.

### Additional Pitfalls
- **Reading state by scanning blocks.** Very slow and rate-limited; use events and an indexer.
- **Ignoring nonce management for users sending multiple transactions.** A stuck nonce blocks the queue.
- **Hard-coding gas limits.** Estimation plus margin, with a clear failure path.
- **Treating testnet and mainnet as configuration only.** Contract addresses, tokens, and liquidity all differ.
- **Assuming instant confirmation.** Show pending state and handle reorgs.

### Real-World Deal-Breakers
- **Assuming all L2s are equally secure** → Stage 0 rollups (training wheels) vs Stage 2 rollups (fully trustless) have vastly different security properties.
- **Ignoring blob capacity expansion** → the economic model of L2s changes with each upgrade. Monitor Fusaka's blob parameter-only forks.
- **Sequencer centralization** → most L2 sequencers are still centralized. This is a trust assumption users don't see.
- **Not checking L2BEAT** → before bridging to any L2, check its stage. A Stage 0 rollup can upgrade without user exit time.
