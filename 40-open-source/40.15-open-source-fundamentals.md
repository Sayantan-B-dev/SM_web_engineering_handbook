### The Core Mental Model
Open source is not just "free code." It's a **collaborative development model** where the source code is publicly available, and contributions are welcome from anyone. The Linux Foundation's 2026 report frames it directly: "Open source is how most modern software gets built, and the projects behind it depend on a steady supply of new contributors. That supply never arrives through traditional hiring. The development model is voluntary".

### The 2026 Scale
GitHub added **36 million new developers in 2025** - roughly one new account every second - pushing the platform past **180 million developers total**. Nearly **a billion commits** were pushed over the year (up 25%), and **43.2 million pull requests were merged every month**.

### The Crisis: Contributor-to-Maintainer Gap
GitHub's own Octoverse report names a widening **"contributor-to-maintainer gap,"** made worse by what the industry has started calling **"AI slop"**: low-quality, auto-generated pull requests that consume maintainer time without adding real value. The **Jazzband collective**, a well-known hub for Python projects, shut down entirely in 2025, with its lead maintainer citing the unsustainable volume of AI-generated spam PRs and issues as a primary driver.

### Free Software vs Open Source
People often confuse free software with open source, but the nuance matters. **Free software**, as defined by the Free Software Foundation (FSF), rests on four fundamental freedoms: run the program, study its workings, redistribute copies, and distribute modified versions. The emphasis is on ethics and user freedom. **Open source**, promoted by the Open Source Initiative (OSI), shares most of these principles but takes a more pragmatic approach - better quality, faster innovation, reduced costs. A project that declares itself free software will often favour a strong copyleft licence like the GPL, whereas an open-source-oriented project may opt for a permissive licence such as MIT or Apache.

### Deeper Explanation: The Social Contract Of A Repository

An open source project is a codebase plus an explicit social contract: a licence (what others may do), a contribution guide (how to participate), a code of conduct (how to behave), and a governance model (who decides). The technical work is only half of it; the other half is making it possible for strangers to help and to trust the result.

The artefacts worth having before you need them:

| Artefact | Purpose | When it matters |
|---|---|---|
| `LICENSE` | Grants rights (without it, code is "all rights reserved") | Immediately |
| `README` | What it does, how to install, how to get help | Immediately |
| `CONTRIBUTING.md` | Setup, conventions, review expectations | Before the first PR |
| `CODE_OF_CONDUCT.md` | Behaviour baseline and enforcement | Before the first conflict |
| `SECURITY.md` | How to report vulnerabilities privately | Before the first CVE |
| `CHANGELOG.md` | What changed, per version | Before the first release |

### Additional Pitfalls
- **No licence.** Public code without a licence is not usable by companies; adoption dies quietly.
- **A contribution guide that describes a workflow the CI does not enforce.** Contributors do work twice.
- **No security policy.** Vulnerability reports arrive as public issues and become an incident.
- **Governance left implicit.** Decision ambiguity is the main source of community friction.

### Real-World Deal-Breakers
- **Treating open source as free labour** → maintainers burn out. The Jazzband collective shut down entirely due to AI-generated spam.
- **Submitting AI-generated PRs without review** → you become part of the problem maintainers are drowning in.
- **Confusing free software with open source** → they have different philosophical roots and attract different contributors.
- **Assuming all open source is the same** → licenses, governance, and community health vary wildly.
