### The Mental Model
Open source contribution is **collaboration under time constraints**: maintainers are volunteers with limited attention, so a contribution's value includes how easy it is to review. The winning pattern is small, focused, well-explained changes that respect the project's existing conventions and arrive with tests.

```text
Before opening a PR, check (and state in the description):
  [ ] I read CONTRIBUTING.md and the code of conduct
  [ ] There is an issue (or I explained why there is not)
  [ ] The change is one logical unit, not three
  [ ] Tests and docs updated; existing suite passes locally
  [ ] I followed the commit message convention
  [ ] The diff is small enough to review in one sitting
```

### Real-World Deal-Breakers
- **Skipping the contribution guide.** A PR that ignores conventions wastes a review cycle.
- **Large unrequested rewrites.** They will be closed regardless of quality; discuss scope first.
- **Drive-by PRs with no issue.** Maintainers cannot tell if the change is wanted.
- **Arguing in review instead of asking.** Ask about constraints; most disagreements are about information you lack.
- **Abandoning a PR after review comments.** Responding, or explicitly stepping away, keeps the queue honest.
- **Pinging maintainers repeatedly.** It costs goodwill; be patient and useful.
