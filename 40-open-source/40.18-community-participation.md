### Contribution Beyond Code
Contributing does not mean writing code. Contribution spans **documentation, testing, design, community management, issue triage, and code**. Anyone who has added any of these to a project is a contributor, full stop - no asterisk for "but real contributors write code".

### Writing a Good Bug Report
```markdown
## Description
The login form throws "Cannot read property 'email' of undefined" when submitting with an empty password field.

## Steps to Reproduce
1. Go to /login
2. Enter "test@example.com" in email
3. Leave password empty
4. Click "Sign In"

## Expected Behavior
Show validation error: "Password is required"

## Actual Behavior
Uncaught TypeError: Cannot read property 'email' of undefined

## Environment
- OS: macOS 15.2
- Browser: Chrome 131
- Node: 22.11.0

## Possible Fix
In `LoginForm.tsx` line 42, `handleSubmit` doesn't check `formData.password` before accessing it.
```

### The Code of Conduct
Every open source project should have a **Code of Conduct** (Contributor Covenant is the standard). It sets expectations for behaviour and provides a mechanism for reporting violations. Without it, marginalized contributors have no recourse.

### Deeper Explanation: Contributions Beyond Code

Healthy projects need people who do the unglamorous, high-leverage work: triage, support, documentation, translations, design, release management, and community moderation. That work is what lets a project absorb contributors at scale, and it is often the fastest path for a newcomer to become trusted.

### Additional Pitfalls
- **Contributions only counted as merged code.** That framing undervalues the work that makes code possible.
- **Unanswered "how do Iâ€¦" questions.** Newcomers leave; a pinned FAQ and a discussion category fix most of it.
- **Documentation drift.** Docs need owners and a review step like code.
- **No recognition.** Acknowledging triage and docs in release notes retains contributors.
- **Moderation gaps.** Unmanaged conflict drives away the people who make projects sustainable.

### Real-World Deal-Breakers
- **Vague bug reports** ("it doesn't work") → maintainers can't reproduce. Always include steps, expected vs actual, environment.
- **Demanding features** → open source is voluntary. "When will this be done?" is not a question; it's a demand.
- **No Code of Conduct** → toxic behaviour drives contributors away. The Contributor Covenant is a one-page fix.
- **Ignoring documentation contributions** → docs are often the highest-impact contribution. A typo fix helps thousands.
