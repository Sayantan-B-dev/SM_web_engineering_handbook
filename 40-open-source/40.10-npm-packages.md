### The Mental Model
A published package is a **versioned public API plus a build contract**. Every field in `package.json` is a promise: `exports` decides what consumers can import, `types` decides what TypeScript sees, `peerDependencies` decides which React versions are supported, and `files` decides what actually ships. Getting these wrong produces bugs that only appear in consumers' builds.

```json
{
  "name": "@acme/ui",
  "version": "2.3.0",
  "type": "module",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js", "require": "./dist/index.cjs" },
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "sideEffects": ["**/*.css"],
  "peerDependencies": { "react": ">=18", "react-dom": ">=18" },
  "publishConfig": { "access": "public", "provenance": true }
}
```

### Versioning Rules That Prevent Pain
- **Major**: removed/renamed exports, changed prop semantics, dropped peer dependency range.
- **Minor**: new exports, new optional props, widened peer ranges.
- **Patch**: fixes with no API change.
- Bump the peer range deliberately; claiming `>=18` while using a React 19-only API is a lie consumers discover at runtime.

### Real-World Deal-Breakers
- **`exports` missing.** Consumers deep-import internals, and you cannot refactor.
- **Bundling React into the library.** Duplicate React instances break hooks; use `peerDependencies`.
- **Types not shipped.** Every TS consumer needs `@types` or gets `any`.
- **CSS shipped without `sideEffects`.** Bundlers tree-shake your styles away.
- **Publishing without provenance or 2FA.** Supply-chain risk for everyone who installs you.
- **No deprecation period.** Removing an export in a minor version breaks builds silently.
