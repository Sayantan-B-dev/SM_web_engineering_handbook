### The Mental Model
An issue is a **unit of untriaged work plus a conversation**. Its value is that it forces a problem statement to exist before code does â€” and its failure mode is becoming a graveyard nobody prunes. The discipline is small and consistent: every issue gets triaged into one of a few states, has enough information to be actionable, and is closed with a reason.

For maintainers, triage is the highest-leverage habit: a fast, kind first response ("thanks â€” can you share X?") converts a vague report into a fixable bug, and label hygiene keeps the backlog honest.

### Labels That Actually Help
- **Type**: bug, feature, docs, chore
- **Status**: needs triage, needs info, blocked, good first issue, help wanted
- **Priority**: p0 outage, p1 next, p2 backlog
- **Area**: one label per package or subsystem, matching the repository layout

### Real-World Deal-Breakers
- **Bug reports without reproduction steps.** They cannot be fixed; add a template that requires them.
- **No triage cadence.** The backlog grows; schedule a rotating 30 minutes per week.
- **Closing without explanation.** "Not planned" without a reason pushes contributors away.
- **Using issues as the only design record.** Decisions belong in ADRs or discussions.
- **Duplicate detection ignored.** Search first, and link duplicates rather than closing silently.
