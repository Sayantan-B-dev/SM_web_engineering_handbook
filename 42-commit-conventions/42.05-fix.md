### The Mental Model
A `fix:` corrects behaviour that was wrong â€” as opposed to adding capability. The two expectations attached to it are a **regression test** (so the bug cannot silently return) and a **root-cause explanation** in the body (so the next reader learns something). Security fixes need extra care: they may need coordinated disclosure and must not describe the exploit in detail in a public message.

```text
fix(cart): apply locale when formatting currency totals

formatCurrency ignored the locale argument when a currency was passed,
so de-DE users saw "$10.00" instead of "10,00 â‚¬" (fixes #412).

Adds a regression test for en-US, de-DE and ja-JP.
```

### Real-World Deal-Breakers
- **A fix without a regression test.** The same bug returns in a later refactor.
- **Root cause omitted.** "Fix cache bug" teaches nothing and invites recurrence.
- **Cleanup bundled into the fix.** The revert becomes dangerous; keep the diff minimal.
- **Security detail in a public commit.** It becomes an exploit recipe; coordinate disclosure.
- **Wrong backport.** Cherry-picking a fix without its test or dependency.
