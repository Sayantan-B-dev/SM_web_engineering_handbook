### The Mental Model
`test:` marks changes that only affect the verification apparatus. Keeping it separate lets reviewers and CI treat the change differently (faster checks, no release-note entry) and makes flake work visible in history, which matters because test-suite trust is a shared asset.

```text
test(checkout): cover expired-card and 3DS-challenge paths

Adds MSW handlers for the two failure modes and asserts the retry UI.
Raises checkout statement coverage from 71% to 88%.
```

### Real-World Deal-Breakers
- **Bug fixes labelled `test:`.** Release notes and automation miss the fix.
- **Weakened assertions committed as "test updates".** A red flag; review test diffs closely.
- **Flaky tests disabled permanently.** Quarantine with an owner and a deadline instead.
- **Snapshots updated without review.** They become a rubber stamp.
- **Slow suites left unmanaged.** Rising runtime reduces how often anyone runs them.
