### What Commitlint Does
`commitlint` checks if your commit messages meet the Conventional Commits format. It runs as a **commit-msg Git hook** and rejects commits that don't conform.

```bash
npm install --save-dev @commitlint/config-conventional @commitlint/cli
echo "export default {extends: ['@commitlint/config-conventional']};" > commitlint.config.js
```

### Default Rules (`@commitlint/config-conventional`)

| Rule | Condition | Value | Pass example | Fail example |
|------|-----------|-------|-------------|-------------|
| `type-enum` | Type is in list | `['build', 'chore', 'ci', 'docs', 'feat', 'fix', 'perf', 'refactor', 'revert', 'style', 'test']` | `fix: ...` | `foo: ...` |
| `type-case` | Type is lowercase | `lowerCase` | `fix: ...` | `FIX: ...` |
| `type-empty` | Type is not empty | `never` | `fix: ...` | `: ...` |
| `subject-case` | Subject is not sentence-case, start-case, pascal-case, or upper-case | `never` | `fix(scope): some message` | `fix(SCOPE): Some Message` |
| `subject-empty` | Subject is not empty | `never` | `fix: some message` | `fix:` |
| `subject-full-stop` | Subject does not end with `.` | `never` | `fix: some message` | `fix: some message.` |
| `header-max-length` | Header ≤ 100 characters | `always` | Short header | Header > 100 chars |

### The `type-enum` Rule
The default `type-enum` restricts the type to **11 values**: `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`, `style`, `test`.

```bash
# ✅ Passes
fix: some message

# ❌ Fails - "foo" is not in the enum
foo: some message
```

### The `subject-case` Rule
The `subject-case` rule **rejects sentence-case, start-case, pascal-case, and upper-case subjects**.

```bash
# ✅ Passes
fix(scope): some message
fix(scope): some Message

# ❌ Fails
fix(SCOPE): Some message
fix(SCOPE): SomeMessage
fix(SCOPE): SOMEMESSAGE
```

### Configuration File Formats
`commitlint` supports multiple config formats:
- `commitlint.config.js` (ES module)
- `.commitlintrc.yml`
- `.commitlintrc.json`

```javascript
// commitlint.config.js
export default {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'header-max-length': [2, 'always', 72], // stricter than default
    'body-max-line-length': [0],             // disable body line length
  },
};
```

### CI Integration
```yaml
# .github/workflows/commitlint.yml
name: Commitlint
on: [pull_request]
jobs:
  commitlint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: wagoid/commitlint-github-action@v6
```

### Husky Integration
```bash
# .husky/commit-msg
npx --no -- commitlint --edit $1
```

### Real-World Deal-Breakers
- **No `commitlint`** → developers write whatever they want. History becomes unparseable.
- **`type-enum` without `revert`** → revert commits fail. Add `revert` to the enum.
- **`header-max-length: 100`** → 100-character subjects are truncated in `git log --oneline`. Use 72.
- **No CI integration** → `commitlint` runs locally but not on PRs. PRs with bad commits merge.
