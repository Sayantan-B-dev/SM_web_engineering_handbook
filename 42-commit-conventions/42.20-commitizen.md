## 42.11 Commitizen

### Subtopic Tree
- Interactive CLI for standardized commits
- `cz commit` / `git cz`
- `cz_conventional_commits` ruleset
- Version bumping (`cz bump`)
- Changelog generation (`cz changelog`)
- Configuration in `pyproject.toml` or `.cz.toml`
- Custom rulesets
- `use_shortcuts` for faster commits

### What Commitizen Does
Commitizen is a **CLI tool to generate conventional commits**. It provides an interactive prompt that guides you through writing a structured commit message.

```bash
# Install
npm install -g commitizen
# Or with Python
pip install commitizen

# Interactive commit
cz commit
# Or the classic
git cz
```

### The Interactive Prompt
```
? Select the type of change you are committing:
  feat: A new feature
  fix: A bug fix
  docs: Documentation only changes
  style: Changes that do not affect the meaning of the code
  refactor: A code change that neither fixes a bug nor adds a feature
  perf: A code change that improves performance
  test: Adding missing tests or correcting existing tests
  build: Changes that affect the build system or external dependencies
  ci: Changes to our CI configuration files and scripts
  chore: Other changes that don't modify src or test files
  revert: Reverts a previous commit

? What is the scope of this change? (press enter to skip)
? Write a short, imperative tense description of the change:
? Provide a longer description of the change: (press enter to skip)
? Are there any breaking changes? (y/N)
? Does this change affect any open issues? (y/N)
```

### Version Bumping
```bash
# Determine the next version from conventional commits
cz bump

# Result: reads commit history → determines bump type → updates version → creates tag
# Example: feat: add feature → 1.2.3 → 1.3.0
```

### Changelog Generation
```bash
# Generate a changelog from commit history
cz changelog
```

Commitizen **automatically manages version numbers using semantic versioning** and **generates and maintains changelogs**.

### Configuration
```toml
# pyproject.toml
[tool.commitizen]
name = "cz_conventional_commits"
version = "1.2.3"
tag_format = "v$version"
update_changelog_on_bump = true
```

### Real-World Deal-Breakers
- **No Commitizen for new contributors** → they don't know the convention. Interactive prompts guide them.
- **`use_shortcuts = true` without training** → contributors use shortcuts but don't understand the underlying convention.
- **Commitizen without `commitlint`** → Commitizen guides, but `commitlint` enforces. Use both.
