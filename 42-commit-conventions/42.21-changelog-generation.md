## 42.12 Changelog Generation

### Subtopic Tree

### Conventional Changelog
```bash
# Generate a changelog from conventional commits
npx conventional-changelog -i CHANGELOG.md -s
```

The command scans commit history, generates a changelog, writes it to `CHANGELOG.md`, and updates the file in place.

### Keep a Changelog Format
```markdown
# Changelog

## [1.3.0] - 2026-05-29
### Added
- Google OAuth login (#142)
- Dark mode toggle (#156)

### Fixed
- Token refresh loop (#149)

### Deprecated
- v1 user endpoints (#456)

### Removed
- Node 6 support (#789)

### Security
- Upgrade bcrypt to 5.0.0 (#890)
```

### Categories

| Category | From commit type/footer |
|----------|------------------------|
| **Added** | `feat` |
| **Fixed** | `fix` |
| **Changed** | `refactor`, `perf` |
| **Deprecated** | `Deprecation:` footer |
| **Removed** | `BREAKING CHANGE:` (removal) |
| **Security** | `fix` with security keyword |

### Semantic Release
```yaml
# .releaserc
{
  "branches": ["main"],
  "plugins": [
    "@semantic-release/commit-analyzer",
    "@semantic-release/release-notes-generator",
    "@semantic-release/changelog",
    "@semantic-release/npm",
    "@semantic-release/github"
  ]
}
```

### Real-World Deal-Breakers
- **No changelog** → users don't know what changed between versions. They read the commit log (if at all).
- **Manual changelog** → out of date within a week. Automate it.
- **No `Deprecation:` footer** → deprecations are invisible in the changelog.
- **`BREAKING CHANGE:` without details** → the changelog says "breaking change" but doesn't say what.
