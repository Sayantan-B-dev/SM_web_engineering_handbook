## docs

### Subtopic Tree
- What belongs in `docs:` (README, guides, JSDoc, ADRs, examples, comments)
- docs vs feat vs fix
- Documentation that must accompany behaviour changes
- Changelogs vs docs
- Generating docs (TypeDoc, Storybook, OpenAPI)
- Typos and link fixes
- Keeping code examples executable

### The Mental Model
`docs:` isolates changes whose only effect is comprehension. The type matters most as a **signal to reviewers**: documentation-only changes can be reviewed quickly without running the test suite, while a behaviour change that happens to update docs must remain a `feat:`/`fix:`.

```text
docs(readme): document the offline cache strategy and its limits
docs(api): add JSDoc for useDebouncedValue including the cancel behaviour
docs(adr): record the decision to use cursor pagination for the issues list
```

### Real-World Deal-Breakers
- **Behaviour changes hidden in `docs:`.** Reviewers skip the run; regressions reach production.
- **Docs not updated with the behaviour change.** They drift and mislead; pair them in the same PR.
- **Copy-pasted examples that no longer compile.** Test snippets or extract them.
- **README-only documentation.** Long guides belong in a docs directory with navigation.
- **Generated docs committed by hand.** Regenerate in CI instead of editing output.
