## Shared Workers

### Subtopic Tree
- One worker instance shared by every same-origin tab
- `new SharedWorker(url, { name })` and the `port` model
- `onconnect` and `MessagePort` per connection
- Cross-tab state without `BroadcastChannel`
- Lifetime: lives while at least one client is connected
- Debugging (chrome://inspect â†’ Shared workers)
- Where shared workers beat a dedicated worker

### The Mental Model
A dedicated worker belongs to the document that created it. A shared worker belongs to the **origin**: the first tab to construct it starts it, later tabs attach to the same instance, and the browser keeps it alive until the last connected tab goes away. Communication is not `postMessage` on the worker object â€” it is `postMessage` on a `MessagePort` handed to each connection.

```js
// shared-worker.js
const clients = new Set();

onconnect = (event) => {
  const port = event.ports[0];
  clients.add(port);
  port.start();

  port.onmessage = ({ data }) => {
    // fan out to every other tab â€” one websocket, many subscribers
    for (const client of clients) {
      if (client !== port) client.postMessage({ type: 'state', payload: data.payload });
    }
  };

  port.onmessageerror = () => clients.delete(port);
};
```

```js
// app.js â€” every tab attaches to the same worker
const worker = new SharedWorker(new URL('./shared-worker.js', import.meta.url), { name: 'app-state' });
worker.port.start();
worker.port.postMessage({ type: 'subscribe', payload: { channel: 'cart' } });
worker.port.onmessage = ({ data }) => store.dispatch(data);
```

### What It Is Good For
- A single websocket/SSE connection multiplexed across tabs instead of one per tab.
- A single source of truth for auth refresh or a shared token cache.
- Cross-tab coordination for caching and background sync.
- Expensive warm state (parsed models, indexes) that every tab would otherwise rebuild.

### Real-World Deal-Breakers
- **Assuming Safari support for the same lifecycle.** Shared workers exist in Safari but behave differently around page restoration; always fall back to `BroadcastChannel` or a dedicated worker.
- **Confusing `worker.port.postMessage` with `worker.postMessage`.** The latter does not exist for shared workers.
- **Forgetting `port.start()`.** Without it (or an `onmessage` assignment) queued messages never dispatch.
- **No reconnection logic.** When the last client disconnects the worker dies; the next tab starts a *new* instance with empty memory.
- **Using a shared worker for per-tab state.** Shared means shared; tab-local state belongs in the tab.
