### The Mental Model
The Cache API is a **programmable HTTP cache**: a map from `Request` to `Response` that you control, independent of the browser's own HTTP cache and available only in a secure context (and inside service workers it does the actual serving). It is a store of *network responses*, not of application data â€” application data belongs in IndexedDB, and the two are often used together.

```js
const STATIC = 'static-v4';
const PAGES = 'pages-v4';

async function staleWhileRevalidate(request) {
  const cache = await caches.open(PAGES);
  const cached = await cache.match(request);

  const network = fetch(request)
    .then((res) => {
      if (res.ok && res.type === 'basic') cache.put(request, res.clone());
      return res;
    })
    .catch(() => cached);           // offline: fall back to whatever we have

  // Serve instantly if we have something, refresh in the background.
  return cached ?? network;
}

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);
  if (event.request.method !== 'GET' || url.origin !== location.origin) return;

  if (url.pathname.startsWith('/api/')) {
    // never cache API responses containing personal data
    return;
  }
  event.respondWith(staleWhileRevalidate(event.request));
});
```

### Cache API vs HTTP Cache
| Aspect | HTTP cache | Cache API |
|---|---|---|
| Controlled by | Server headers | Your code |
| Works offline | Only with a service worker | Yes |
| Key | URL + Vary headers | The `Request` you pass |
| Inspectable in devtools | Yes (Network) | Application â†’ Cache Storage |
| Best for | Repeat visits online | Offline shell, precached assets |

### Real-World Deal-Breakers
- **Caching authenticated API responses.** The cache is shared across tabs and users on the same origin/profile; keep it to static assets and public pages.
- **`cache.addAll` with one bad URL.** The whole batch rejects; precache in resilient groups or handle failures explicitly.
- **Unbounded cache growth.** Nothing expires automatically â€” version the cache name and delete stale caches in `activate`.
- **Ignoring `Vary` semantics.** Storing by URL alone can serve a response for the wrong `Accept-Encoding` or locale.
- **Using it as a data store.** It holds HTTP responses only; store your domain objects in IndexedDB.
