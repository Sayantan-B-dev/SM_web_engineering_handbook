### 2026 Browser Landscape
The web platform shipped more genuinely new capability in 2024-2026 than in the entire decade before it. WebGPU crossed Baseline in January 2026. WebTransport followed in March. WebCodecs is one Safari point release away. View Transitions made cross-document animation a tag, not a framework.

### Deeper Explanation: Modern APIs Are Capability-Gated

The 2026 web platform is rich, but almost every powerful API is behind a gate: a secure context, a permission, an origin trial, or a browser flag. The engineering pattern is therefore **capability detection with graceful degradation**, not version sniffing:

- **Feature-detect the specific method**, not the browser: `'showOpenFilePicker' in window`, `CSS.supports('view-transition-name: none')`.
- **Assume the API can fail at call time** even after a successful detection (permissions revoked, user cancels, quota exceeded) â€” wrap in try/catch and return a typed result.
- **Prefer progressive enhancement**: the page must be usable before you attach the enhancement.
- **Check for existing shims** for high-value APIs (`:has` support, `view-transition` polyfills, `Popover` API) before shipping a custom implementation.

### Extended Example: Capability Map Instead Of Browser Sniffing

```ts
export const can = {
  viewTransitions: typeof document.startViewTransition === 'function',
  popover: 'showPopover' in HTMLElement.prototype,
  fileSystem: 'showOpenFilePicker' in window,
  idleCallback: 'requestIdleCallback' in window,
  storageEstimate: 'storage' in navigator && 'estimate' in navigator.storage,
  badging: 'setAppBadge' in navigator,
} as const;

export async function withFallback<T>(
  feature: () => Promise<T>,
  fallback: () => Promise<T>,
): Promise<T> {
  try {
    return await feature();
  } catch {
    return fallback();
  }
}
```

### Additional Pitfalls
- **UA-string sniffing.** It is unreliable, brittle, and increasingly meaningless; detect capabilities.
- **Shipping a feature with only the happy path.** Cancel dialogs, revoked permissions, and quota errors are the normal cases.
- **Assuming a polyfill is transparent.** Shims change timing and memory characteristics; measure the fallback path too.
- **Not testing the degraded path.** If nobody ever runs it, it is broken.

### Real-World Deal-Breakers
- **WebGPU without WebGL2 fallback** → Safari < 26 and Linux Firefox users see nothing.
- **WebTransport without WebSocket fallback** → older browsers can't connect.
- **View Transitions as a hard dependency** → Firefox users get no transition.
- **Speculation Rules without prefetch fallback** → Chromium users get instant navigation, everyone else gets normal.
- **WebUSB/WebHID/WebSerial** → permanent single-vendor. Don't plan cross-browser support.
