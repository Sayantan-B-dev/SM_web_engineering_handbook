## BroadcastChannel

### Subtopic Tree
- Same-origin publish/subscribe between tabs, windows, and workers
- `new BroadcastChannel(name)` / `postMessage` / `onmessage` / `close()`
- Messages do not reach the sender's own channel
- Structured clone payloads (no functions)
- Logout propagation, theme sync, cart updates
- Relation to `storage` events and shared workers

### The Mental Model
`BroadcastChannel` is the browser's built-in **same-origin event bus across browsing contexts**. Any tab, iframe, or worker can publish a named message and every other listener on that channel name receives a structured-clone copy. It is the cheapest correct answer to "my other tabs are now stale".

```ts
// lib/bus.ts â€” typed wrapper, one channel per concern
type Messages = {
  'auth:logout': { reason: 'manual' | 'expired' };
  'cart:changed': { items: number; totalCents: number };
  'theme:changed': { theme: 'light' | 'dark' };
};

const channel = new BroadcastChannel('app');

export function publish<K extends keyof Messages>(type: K, payload: Messages[K]) {
  channel.postMessage({ type, payload });
}

export function subscribe<K extends keyof Messages>(type: K, fn: (payload: Messages[K]) => void) {
  const handler = (e: MessageEvent<{ type: K; payload: Messages[K] }>) => {
    if (e.data.type === type) fn(e.data.payload);
  };
  channel.addEventListener('message', handler);
  return () => channel.removeEventListener('message', handler);
}
```

```ts
// logout in one tab must clear the session everywhere
subscribe('auth:logout', () => queryClient.clear());
await fetch('/api/logout', { method: 'POST' });
publish('auth:logout', { reason: 'manual' });
```

### Real-World Deal-Breakers
- **Expecting the sender to receive its own broadcast.** It does not â€” update local state directly and publish for the others.
- **Sending large objects repeatedly.** Every message is cloned into every listener; send identifiers and let each tab read the data.
- **Treating it as durable.** There is no queue and no replay; the message is gone for tabs opened later.
- **Using it for shared computation.** It has no shared state; a shared worker does.
- **Forgetting to close channels in tests and SPAs.** Leaked channels hold closures and can keep memory alive.
