### The Mental Model
A stream is a **pull-based channel with backpressure**: the consumer requests chunks, the producer knows when the consumer is behind, and memory stays bounded because nothing is buffered beyond the queue. That is exactly the property that makes streaming LLM output, huge file downloads, and progressive rendering possible in a browser tab.

```ts
// Consume a streaming HTTP response and render tokens as they arrive
async function streamChat(prompt: string, onToken: (t: string) => void) {
  const res = await fetch('/api/chat', {
    method: 'POST',
    body: JSON.stringify({ prompt }),
    headers: { 'content-type': 'application/json' },
  });
  if (!res.body) throw new Error('no body');

  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = '';
  for (;;) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += value;
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';
    for (const line of lines) {
      if (line.startsWith('data: ')) onToken(line.slice(6));
    }
  }
}
```

```ts
// Produce a stream with bounded memory: backpressure respected automatically
function numbers(n: number) {
  return new ReadableStream<number>({
    start(controller) {
      for (let i = 0; i < n; i++) controller.enqueue(i);
      controller.close();
    },
  });
}

const controller = new AbortController();
```

### Real-World Deal-Breakers
- **Ignoring `desiredSize` to "go faster".** Unbounded producers turn streams into memory leaks; respect backpressure or you have just built an array.
- **Not handling `done` and errors.** A stream that throws mid-read must surface an error state, not hang on a spinner forever.
- **Reading a stream twice.** Streams are single-use; `tee()` if two consumers genuinely need it, and accept the memory cost.
- **Assuming `fetch` streams everywhere.** Full duplex and some streaming features vary by browser; feature-detect and fall back.
- **Forgetting cancellation.** Users navigate away constantly â€” abort the reader (`reader.cancel()`) or you leak connections.
