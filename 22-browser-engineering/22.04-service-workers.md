### The Mental Model
A service worker is not a worker you talk to â€” it is a **proxy the browser consults for every request** in scope. It has no DOM, it can be terminated at any moment, and it only controls pages loaded after activation (unless it claims clients). That is why every design decision reduces to: *what should happen when the network is slow, down, or lying?*

```js
// sw.js
const VERSION = 'v3';
const PRECACHE = `precache-${VERSION}`;
const RUNTIME = `runtime-${VERSION}`;
const SHELL = ['/', '/offline', '/assets/app.js', '/assets/app.css'];

self.addEventListener('install', (event) => {
  event.waitUntil(caches.open(PRECACHE).then((c) => c.addAll(SHELL)));
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys()
      .then((keys) => Promise.all(keys.filter((k) => k !== PRECACHE && k !== RUNTIME).map((k) => caches.delete(k))))
      .then(() => self.clients.claim()),
  );
});

self.addEventListener('fetch', (event) => {
  const { request } = event;
  if (request.mode === 'navigate') {
    // network-first HTML, offline shell on failure
    event.respondWith(
      fetch(request)
        .then((res) => {
          const copy = res.clone();
          caches.open(RUNTIME).then((c) => c.put(request, copy));
          return res;
        })
        .catch(() => caches.match(request).then((r) => r ?? caches.match('/offline'))),
    );
    return;
  }

  if (new URL(request.url).pathname.startsWith('/assets/')) {
    // immutable hashed assets: cache-first
    event.respondWith(
      caches.match(request).then((hit) => hit ?? fetch(request).then((res) => {
        const copy = res.clone();
        caches.open(PRECACHE).then((c) => c.put(request, copy));
        return res;
      })),
    );
  }
});
```

### Update Rules That Bite
- A new worker **waits** until every controlled tab is closed unless you call `skipWaiting()` â€” and skipping mid-session can mix old HTML with new JS. Gate the reload prompt behind a user-visible "Update available" banner.
- Never cache an HTML response with a long TTL; the shell should revalidate so a deploy is picked up.
- Precaching only helps if it is *complete*: a missing chunk means the offline route breaks on the first cold start.

### Real-World Deal-Breakers
- **Caching responses containing `Set-Cookie`/personalised HTML.** Users get each other's pages from the shared cache.
- **Forgetting scope.** A worker at `/app/sw.js` cannot control `/`; register at the root for a full-site proxy.
- **No update UX.** Users keep running a stale bundle for weeks because the new worker waits forever.
- **Dev habits leaking to production.** Aggressive caching makes local debugging lie to you; disable the worker in development.
- **Ignoring quota and private mode.** Storage can be evicted or unavailable; the app must work without the cache.
- **Requesting a service worker on an insecure origin.** It requires HTTPS (or localhost).
