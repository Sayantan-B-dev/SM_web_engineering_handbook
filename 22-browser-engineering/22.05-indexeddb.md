### The Mental Model
IndexedDB is a **transactional key-value/object database in the browser**: stores hold structured clones of objects, every read and write happens in a transaction with a defined scope, and a version bump runs a migration during `upgradeneeded`. It is the only storage that combines realistic capacity (hundreds of MB with permission), asynchronous access without blocking the main thread, indexes, and transactions â€” which is exactly what offline-first needs.

```ts
// db.ts â€” thin promise wrapper (the `idb` library does this for you)
export function openDb(): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open('app', 3);
    req.onupgradeneeded = () => {
      const db = req.result;
      if (!db.objectStoreNames.contains('notes')) {
        const notes = db.createObjectStore('notes', { keyPath: 'id' });
        notes.createIndex('by_updated', 'updatedAt');
        notes.createIndex('by_tag_status', ['tag', 'status']);
      }
      if (!db.objectStoreNames.contains('outbox')) {
        db.createObjectStore('outbox', { keyPath: 'id', autoIncrement: true });
      }
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}

export async function listByTag(db: IDBDatabase, tag: string) {
  return new Promise<Note[]>((resolve, reject) => {
    const tx = db.transaction('notes', 'readonly');
    const idx = tx.objectStore('notes').index('by_tag_status');
    const range = IDBKeyRange.bound([tag, ''], [tag, '\uffff']);
    const out: Note[] = [];
    idx.openCursor(range).onsuccess = (e) => {
      const cursor = (e.target as IDBRequest<IDBCursorWithValue>).result;
      if (cursor) { out.push(cursor.value); cursor.continue(); } else resolve(out);
    };
    tx.onerror = () => reject(tx.error);
  });
}
```

### Migrations And Durability
- Version bumps are **forward-only**; every client upgrade path must be handled in one `upgradeneeded`.
- A transaction commits when the event loop returns to idle â€” do not `await fetch()` inside one, or it auto-closes.
- `navigator.storage.persist()` asks the browser not to evict your data; check `navigator.storage.estimate()` before assuming capacity.

### Real-World Deal-Breakers
- **`await` inside a transaction.** The transaction commits invisibly and later writes throw `TransactionInactiveError`.
- **One giant object store.** Range queries and compound indexes are the reason to model stores by access pattern.
- **No schema version strategy.** Users with an old DB break forever; plan migrations with a migration table.
- **Assuming storage is permanent.** Browsers evict under pressure, especially in private mode â€” treat IndexedDB as a cache with a rebuild path.
- **Reading the whole store to filter in JS.** Cursors over indexes exist precisely to avoid that.
