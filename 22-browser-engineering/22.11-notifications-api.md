### The Mental Model
Notifications are the one browser API where **the user's attention is the resource**. Permission is per-origin, denial is effectively permanent, and both push services and browsers increasingly suppress noisy senders. So the design rule is inverted compared with every other API: ask late, ask rarely, and only after the user has opted into the specific thing you want to tell them about.

```js
// sw.js â€” display from the service worker so it works when all tabs are closed
self.addEventListener('push', (event) => {
  const { title, body, url } = event.data?.json() ?? {};
  event.waitUntil(
    self.registration.showNotification(title, {
      body,
      icon: '/icons/192.png',
      badge: '/icons/badge.png',
      tag: 'order-update',            // replaces an earlier notification with the same tag
      data: { url },
      renotify: false,
    }),
  );
});

self.addEventListener('notificationclick', (event) => {
  event.notification.close();
  event.waitUntil(
    clients.matchAll({ type: 'window', includeUncontrolled: true }).then((list) => {
      const existing = list.find((c) => c.url.startsWith(event.notification.data.url));
      return existing ? existing.focus() : clients.openWindow(event.notification.data.url);
    }),
  );
});
```

```ts
// Subscribe only after the user explicitly asks for order updates
async function enableOrderUpdates() {
  const permission = await Notification.requestPermission();
  if (permission !== 'granted') return false;

  const reg = await navigator.serviceWorker.ready;
  const sub = await reg.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: urlBase64ToUint8Array(VAPID_PUBLIC_KEY),
  });
  await api.post('/push/subscriptions', sub.toJSON());
  return true;
}
```

### Real-World Deal-Breakers
- **Requesting permission on page load.** Browsers auto-deny and some will block the origin outright; ask from a user-initiated action with context.
- **Sending every event as a push.** Noisy senders get suppressed by the platform and muted by users; batch and rate-limit on the server.
- **No `notificationclick` handler.** Tapping does nothing and the user learns to ignore your notifications.
- **Using page-context `new Notification`.** It cannot fire when the tab is closed; use the service worker registration.
- **Assuming `pushManager` exists.** Safari, Firefox fences, and some privacy modes differ; feature-detect and degrade to in-app messaging.
