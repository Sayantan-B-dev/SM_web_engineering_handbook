## Permissions API

### Subtopic Tree
- `navigator.permissions.query({ name })`
- Permission states: `granted`, `denied`, `prompt`
- `onchange` listeners for reactive UI
- Which permissions are queryable (name list varies)
- Permissions policy (`Permissions-Policy` header)
- Cross-origin iframe delegation
- Sensible prompts: contextual, user-initiated, explainable

### The Mental Model
The Permissions API answers "has the user already decided?" **without triggering a prompt**. That lets you render the right UI ahead of time â€” hide a camera button instead of showing one that will fail, or explain what a permission is for before asking. It does not grant anything and it does not tell you the user's settings; it reports state for permissions the browser exposes.

```ts
async function canUseCamera(): Promise<PermissionState | 'unsupported'> {
  if (!('permissions' in navigator)) return 'unsupported';
  try {
    const { state } = await navigator.permissions.query({ name: 'camera' as PermissionName });
    return state;
  } catch {
    return 'unsupported';   // some names are not queryable in every browser
  }
}

// React hook: reflect permission changes live (user toggles the setting in another tab)
export function usePermission(name: PermissionName) {
  const [state, setState] = useState<PermissionState | 'unsupported'>('unsupported');

  useEffect(() => {
    let status: PermissionStatus | undefined;
    if ('permissions' in navigator) {
      navigator.permissions.query({ name }).then((s) => {
        status = s;
        setState(s.state);
        s.onchange = () => setState(s.state);
      }).catch(() => setState('unsupported'));
    }
    return () => { if (status) status.onchange = null; };
  }, [name]);

  return state;
}
```

```tsx
// Ask in context, with the reason attached, and prefer the constrained API
const location = usePermission('geolocation');

return location === 'denied' ? (
  <p>Location is blocked for this site. Enable it in your browser settings to see nearby stores.</p>
) : (
  <button onClick={() => getCurrentPosition({ timeout: 5000 })}>Find stores near me</button>
);
```

### Real-World Deal-Breakers
- **Querying a non-queryable name.** Not every permission is exposed everywhere; always catch and treat as unknown.
- **Treating `granted` as permanent.** Users revoke permissions, and browser settings can reset on update â€” handle failure at call time regardless.
- **No fallback UI for `denied`.** The feature silently disappears; tell the user why and how to change it.
- **Prompting without context.** A permission prompt shown on load is denied at a high rate and often costs you the ability to ask again.
- **Ignoring `Permissions-Policy`.** A header that blocks the feature for the origin or iframes makes the API fail regardless of the user's choice.
