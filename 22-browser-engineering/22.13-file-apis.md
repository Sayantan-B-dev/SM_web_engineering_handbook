### The Mental Model
Browser file access is **user-mediated**: the user hands you a handle for a specific file (through a picker or a drop), and you can read it efficiently as a stream. Newer APIs go further, giving read/write handles that persist across sessions with permission â€” which is what makes local-first editors possible without an upload round-trip.

```ts
// Chunked, resumable upload with progress â€” never read a 2 GB file into memory
export async function uploadInChunks(file: File, url: string, chunkSize = 5 * 1024 * 1024) {
  const chunkCount = Math.ceil(file.size / chunkSize);
  const uploadId = crypto.randomUUID();

  for (let i = 0; i < chunkCount; i++) {
    const chunk = file.slice(i * chunkSize, (i + 1) * chunkSize);
    await fetch(`${url}/${uploadId}/${i}`, { method: 'PUT', body: chunk });
    onProgress((i + 1) / chunkCount);
  }

  return fetch(url, { method: 'POST', body: JSON.stringify({ uploadId, chunkCount }) });
}
```

```ts
// File System Access: a real handle the user can re-grant next session
async function openProject() {
  const [handle] = await window.showOpenFilePicker({ multiple: false });
  const file = await handle.getFile();
  const text = await file.text();

  const contents = await handle.getFileHandle('notes.md', { create: true });
  const writable = await contents.createWritable();
  await writable.write('# updated\n');
  await writable.close();
  return text;
}

// Object URLs must be revoked or the Blob is retained forever
const previewUrl = URL.createObjectURL(file);
img.src = previewUrl;
img.onload = () => URL.revokeObjectURL(previewUrl);
```

### Real-World Deal-Breakers
- **`FileReader.readAsDataURL` for large files.** It base64-inflates (about 33% larger) and loads everything into memory; use a stream or a chunked upload.
- **Never revoking `createObjectURL`.** Each call retains the underlying Blob for the lifetime of the document â€” a classic memory leak in galleries and uploaders.
- **Trusting the MIME type or extension.** Validate on the server; the client's `file.type` is user-controlled.
- **Assuming the File System Access API exists.** Chromium-only in most cases; offer a download/upload fallback.
- **Uploading as one request.** Mobile networks drop; chunking plus resumption turns a failed 3-minute upload into a 5-second retry.
- **Reading a dropped file synchronously.** Reads are async, and drag-and-drop needs `preventDefault` on `dragover` to receive the drop at all.
