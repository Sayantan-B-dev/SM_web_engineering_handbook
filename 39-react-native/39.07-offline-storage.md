## Offline Storage

### Subtopic Tree
- Storage options: AsyncStorage, MMKV, SQLite (expo-sqlite/op-sqlite), filesystem
- When to use which: preferences vs relational data vs large blobs
- Schema migrations on device
- Encryption at rest and key handling
- Sync integration: outbox, conflict handling, resumable uploads
- Cache invalidation and TTLs
- Storage limits, eviction, and user-visible data controls
- Testing offline behaviour on real devices

### The Mental Model
Mobile offline storage is closer to a local database than to a browser cache: it survives restarts, it is fast, and the user expects the app to work without a network. The architecture is the same as offline-first web â€” read from local, queue writes, reconcile later â€” with different primitives.

| Need | Choice | Note |
|---|---|---|
| Small key-value (tokens, prefs) | MMKV / SecureStore | MMKV is fast; secrets belong in the keychain |
| Structured, queried data | SQLite (`expo-sqlite`, `op-sqlite`) | Support indexes and migrations |
| Large files/media | Filesystem + a metadata table | Never store big blobs in the key-value store |
| Secrets | Keychain/Keystore via SecureStore | Not in AsyncStorage or plain files |

```ts
// SQLite with a migration table + outbox: the backbone of offline-first on device
import * as SQLite from 'expo-sqlite';

const db = await SQLite.openDatabaseAsync('app.db');
const MIGRATIONS = [
  `CREATE TABLE IF NOT EXISTS notes (id TEXT PRIMARY KEY, title TEXT, body TEXT, updated_at INTEGER)`,
  `CREATE TABLE IF NOT EXISTS outbox (id TEXT PRIMARY KEY, method TEXT, path TEXT, body TEXT, created_at INTEGER, attempts INTEGER DEFAULT 0)`,
  `CREATE INDEX IF NOT EXISTS notes_updated ON notes (updated_at DESC)`,
];

await db.withTransactionAsync(async () => {
  const { user_version: v } = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  for (let i = v; i < MIGRATIONS.length; i++) await db.execAsync(MIGRATIONS[i]);
  await db.execAsync(`PRAGMA user_version = ${MIGRATIONS.length}`);
});

// Writes go local first, then the outbox drains when connectivity returns
export async function saveNote(note: Note) {
  await db.runAsync('INSERT OR REPLACE INTO notes (id,title,body,updated_at) VALUES (?,?,?,?)',
    [note.id, note.title, note.body, Date.now()]);
  await db.runAsync('INSERT INTO outbox (id,method,path,body,created_at) VALUES (?,?,?,?,?)',
    [crypto.randomUUID(), 'PUT', `/api/notes/${note.id}`, JSON.stringify(note), Date.now()]);
  await drainOutbox();
}
```

### Real-World Deal-Breakers
- **Storing secrets outside the keychain.** Plain files and AsyncStorage are readable on a rooted/compromised device.
- **No migrations.** Schema changes break existing installs permanently; version with `PRAGMA user_version`.
- **Unbounded local growth.** Media and logs fill the device; enforce limits with eviction.
- **Assuming storage is private by default on all platforms.** Use the platform APIs for encryption and per-app storage.
- **No sync/conflict design.** Two devices editing offline is normal; the outbox needs idempotency and a merge rule.
- **Never testing in airplane mode.** The offline path is where the bugs are; make it part of the release checklist.
