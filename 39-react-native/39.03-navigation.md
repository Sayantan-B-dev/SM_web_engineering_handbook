### Expo Router v56 - The Big Fork
Expo Router v56 **forked from React Navigation**, shipped **streaming SSR**, and closed the platform gap with a new **Android toolbar** and **Native Tabs updates**.

**Why the fork?** Expo Router needed deeper control over React Navigation internals for file-based routing, web, server rendering, and other Expo Router use cases. Some improvements wouldn't apply to React Navigation users directly, and carrying them upstream would add complexity for everyone. Forking also solves dependency versioning issues - projects could end up with multiple React Navigation versions installed.

### Migration from React Navigation
In SDK 56 and later, **Expo Router no longer supports importing from `@react-navigation/*` packages**. Use the codemod to migrate:

```bash
npx expo-codemod sdk-56-expo-router-react-navigation-replace src
```
This replaces imports from `@react-navigation/*` with their `expo-router` equivalents.

### File-Based Routing Structure
```
app/
├── _layout.tsx          # Root layout
├── index.tsx            # Home route (/)
├── about.tsx            # /about
├── users/
│   ├── index.tsx        # /users
│   └── [id].tsx         # /users/:id (dynamic route)
└── (tabs)/              # Tab group
    ├── _layout.tsx      # Tab navigator
    ├── home.tsx
    └── settings.tsx
```

### Deeper Explanation: Navigation Is Platform Behaviour, Not Just Routing

Mobile navigation has platform semantics: a stack with push/pop and back gestures, tabs that preserve state, modals that present, deep links that must resolve into the same hierarchy, and hardware back presses on Android. React Navigation (or Expo Router for file-based routing) models these explicitly, and the mental shift from web routing is that **the back stack is part of the user's model** â€” not a URL you can freely rewrite.

Practical rules: keep navigation state serialisable (for deep links, restoration, and analytics), avoid losing in-progress work on unmount by hoisting drafts to a store, and type your routes so a typo is a compile error rather than a runtime crash. Screen-by-screen deep linking should be testable: a link must land on a screen with the data it needs, or degrade to a sensible fallback.

### Additional Pitfalls
- **Deep links that bypass required data.** The screen crashes because the link did not load the entity.
- **Routing with untyped params.** Params arrive as strings; parse and validate them.
- **State loss on unmount.** Drafts and scroll positions vanish; persist or hoist them.
- **Android back handling ignored.** Users expect the hardware button to work everywhere, including modals.
- **One giant navigator.** Split by feature so screens can be code-split and owned separately.

### Real-World Deal-Breakers
- **Importing from `@react-navigation/*` in SDK 56+** → breaking change. Use the codemod to migrate.
- **Not using typed routes** → runtime errors from typos in navigation calls. Expo Router provides automatic typing.
- **Using Expo Router without the `app/` directory** → file-based routing requires the convention.
- **Ignoring the codemod** → ~25% of import sites may be missed by manual migration.
