### The Core Mental Model
React Native lets you write mobile apps in JavaScript/React while rendering **native UI components** - not WebViews. Your React components map to real `UIView` on iOS and `android.view.View` on Android. The framework handles the translation between your React tree and the native platform.

```jsx
// This renders a real native button on iOS and Android
<Pressable onPress={handlePress}>
  <Text>Click me</Text>
</Pressable>
```

### The 2026 Landscape
React Native has nearly **4.5 million weekly downloads** on npm. The New Architecture is now the **only** architecture - legacy was frozen in June 2025, and from React Native 0.82 onwards it is **mandatory**. Hermes V1 became the default JavaScript engine in React Native 0.84 (February 2026).

### Deeper Explanation: The Same Mental Model, A Different Runtime

React Native keeps React's component and state model but replaces the DOM with native views and the browser runtime with Hermes plus platform APIs. That produces both the leverage (one codebase, native feel) and the friction (platform differences, native modules, build tooling, app store release cycles).

| Web concept | React Native equivalent | Difference that bites |
|---|---|---|
| `div`/`span` | `View`/`Text` | Text must be inside `Text`; no CSS cascade |
| CSS | `StyleSheet` + flexbox | No cascading, no media queries, no `px`-based layout units |
| `fetch` | `fetch` (plus native networking) | No CORS, but app-level auth and retries matter more |
| DOM events | `Pressable`, gesture handlers | No synthetic events; touch handling is native |
| Local storage | AsyncStorage / SQLite / MMKV | Async and persistent, but no service worker |
| Deploy | JS bundle release | Store review; you cannot hotfix instantly (unless using OTA updates) |

The architectural rule that keeps RN projects healthy: keep platform-agnostic logic (state, data, types, design tokens) shared, and keep platform-specific code thin and explicitly separated.

### Additional Pitfalls
- **Writing web CSS in RN.** Flexbox is the only layout system; many properties do not exist.
- **Assuming instant releases.** Store review means bundling an OTA update strategy from day one for hotfixes.
- **Ignoring Hermes/JSC differences.** Some JS features and performance characteristics differ by engine.
- **Deep platform divergence.** Two code paths everywhere means double the bugs; enforce a shared core.

### Real-World Deal-Breakers
- **Attempting to disable the New Architecture** → build will fail in React Native 0.82+. The legacy architecture is gone.
- **Using JavaScriptCore** → Hermes is the only supported engine in the New Architecture.
- **Assuming React Native = WebView** → it renders native components, not web views. Gestures, scrolling, and animations use native primitives.
- **Ignoring the New Architecture migration** → if you're on 0.75 or earlier, you carry technical debt that compounds with every release.
