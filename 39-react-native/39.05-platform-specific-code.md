### Two Approaches

| Approach | When to Use | Example |
|----------|-------------|---------|
| **`Platform.OS` / `Platform.select()`** | Small, inline differences | Different padding, colors |
| **Platform-specific files** | Entire components differ | Different UI for iOS vs Android |

### `Platform.OS` - Runtime Detection
```tsx
import {Platform, StyleSheet} from 'react-native';

const styles = StyleSheet.create({
  height: Platform.OS === 'ios' ? 200 : 100,
});
```
`Platform.OS` is `'ios'` on iOS and `'android'` on Android.

### `Platform.select()` - Value Selection
```tsx
const styles = StyleSheet.create({
  container: {
    flex: 1,
    ...Platform.select({
      ios: { backgroundColor: 'red' },
      android: { backgroundColor: 'green' },
      default: { backgroundColor: 'blue' }, // web, etc.
    }),
  },
});
```
This results in a container with `flex: 1` on all platforms, red background on iOS, green on Android, and blue on other platforms.

`Platform.select()` can also return platform-specific components:
```tsx
const Component = Platform.select({
  ios: () => require('ComponentIOS'),
  android: () => require('ComponentAndroid'),
})();
```

### Platform-Specific File Extensions
When platform-specific code is more complex, **split it into separate files**. React Native detects `.ios.` or `.android.` extensions and loads the relevant file.

```
BigButton.ios.js      → loaded on iOS
BigButton.android.js  → loaded on Android
```

Import normally - React Native picks the right file:
```tsx
import BigButton from './BigButton'; // Auto-resolves per platform
```

### `.native.js` Extension
Use `.native.js` for code shared across native platforms (iOS + Android) but different from web:
```
Component.native.js → iOS + Android
Component.web.js    → Web only
```
Configure your web bundler to ignore `.native.js` extensions to avoid unused code in your production bundle.

### Detecting OS Version
```tsx
// Android
if (Platform.Version === 25) {
  // Android API 25 (Nougat)
}

// iOS
const majorVersionIOS = parseInt(Platform.Version, 10);
if (majorVersionIOS <= 9) {
  // iOS 9 or older
}
```
On Android, `Platform.Version` is the **API version**, not the OS version. On iOS, it's the `UIDevice.systemVersion` string.

---

### Deeper Explanation: Prefer Capability Detection Over Platform Checks

`Platform.OS === 'ios'` is easy and usually wrong: iPads, Android tablets, foldables, and OS versions create behaviour differences that a platform check cannot express. The better ladder is capability â†’ platform â†’ version, in that order:

- **Capability/shape detection**: screen size buckets, `Platform.isPad`, `Dimensions`, pointer/mouse support, `AccessibilityInfo` preferences.
- **Platform differences**: genuinely different UX conventions (back gesture, tab bar, permission flows) or API availability.
- **Version differences**: only when an OS API differs, and always with a fallback.

File-splitting (`.ios.tsx` / `.android.tsx`) is the cleanest way to isolate divergence; keeping a shared core with thin platform shells prevents the "two apps in one repo" failure mode.

### Additional Pitfalls
- **Scattered `if (Platform.OS)` across components.** Consolidate into one platform layer or file split.
- **Assuming all iPhones are the same size.** Layout on the smallest and the largest.
- **Ignoring Android hardware back and permission differences.** Both are user-visible.
- **Duplicating business logic in platform files.** Share the core; split only the presentation or API call.
- **Forgetting web/desktop targets.** Expo web and RN desktop widen the matrix; capability detection helps here too.

### Real-World Deal-Breakers
- **Using `Platform.OS` for large components** → inline conditionals become unreadable. Split into platform-specific files.
- **Forgetting `.native.js` bundler config** → unused code remains in web bundles.
- **Assuming `Platform.Version` is the OS version on Android** → it's the API version (e.g., 25 = Nougat).
- **Not gating newer APIs by OS version** → crashes on older devices.
- **Duplicating logic across `.ios.tsx` and `.android.tsx`** → keep shared logic in a common file and only branch where genuinely required.
