### What TurboModules Are
TurboModules are the **New Architecture's native module system**. They replace the legacy `NativeModules` system with:
- **Lazy loading** - modules loaded on demand, not at startup
- **Type-safe interoperability** - spec files define the contract
- **JSI-based communication** - direct C++ calls, no JSON serialization

### Creating a Turbo Native Module (Step by Step)

**Step 1: Create the spec file**
All spec files must have the prefix `Native`, otherwise Codegen will ignore them.

```typescript
// specs/NativeSampleModule.ts
import type {TurboModule} from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  readonly reverseString: (input: string) => string;
}

export default TurboModuleRegistry.getEnforcing<Spec>('NativeSampleModule');
```

**Step 2: Configure Codegen**
```json
// package.json
"codegenConfig": {
  "name": "AppSpecs",
  "type": "modules",
  "jsSrcsDir": "specs",
  "android": {
    "javaPackageName": "com.sampleapp.specs"
  }
}
```
This tells Codegen to look for spec files in the `specs` folder and generate code for modules.

**Step 3: Write the native code (C++ for cross-platform)**
Writing a module in C++ is the best way to share platform-agnostic code between Android and iOS. Write your logic **once** and reuse it on all platforms.

```cpp
// shared/NativeSampleModule.h
#pragma once
#include <AppSpecsJSI.h>
#include <memory>
#include <string>

namespace facebook::react {
class NativeSampleModule : public NativeSampleModuleCxxSpec<NativeSampleModule> {
 public:
  NativeSampleModule(std::shared_ptr<CallInvoker> jsInvoker);
  std::string reverseString(jsi::Runtime& rt, std::string input);
};
}
```

### TurboModule Lifecycle
For Android, all native modules implement a TurboModule interface with two methods:
- `initialize()` - called when the module is first loaded
- `invalidate()` - called when the module is no longer needed

On iOS, native modules follow the `RCTTurboModule` protocol.

### Migration from Legacy NativeModules
React Native Firebase v26 is a major example of a full migration to TurboModules: "Every React Native Firebase package with a native bridge now requires the new architecture (Codegen TurboModules)".

---

### Deeper Explanation: The Boundary Is Where Bugs Live

A native module is a typed contract across two languages and two runtimes. Most problems are boundary problems: argument types that do not map (numbers vs ints, null vs undefined), threading (native callbacks arriving on a non-JS thread), memory (large arrays crossing repeatedly), and error propagation (a native exception must become a JS rejection).

Practical guidance: use TurboModules/JSI with codegen'd specs so the interface is typed and validated; keep the API coarse-grained (one call that does the work, not a chatty loop); marshal large data as base64/binary rather than nested objects; define error codes rather than strings; and make every async method return a promise that rejects rather than throwing natively. Then test the module's JS-facing API in the app, and keep a thin TypeScript wrapper so the rest of the app never touches the raw bridge.

### Additional Pitfalls
- **Chatty calls in a render path.** Each crossing costs more than the work.
- **Blocking the main/native UI thread.** Native work must be off the UI thread.
- **Unhandled native errors.** They crash the app instead of surfacing a rejection.
- **Unversioned native interfaces.** App and native binary can drift with OTA updates; version the contract.
- **No fallback when a module is missing.** Feature-detect and degrade.

### Real-World Deal-Breakers
- **Spec file without `Native` prefix** → Codegen ignores it. Always prefix with `Native`.
- **No Codegen configuration** → scaffolding code is never generated; module won't work.
- **Platform-specific native code instead of C++** → duplicates logic across iOS and Android. Use C++ for shared logic.
- **Library not supporting TurboModules** → crashes or no-op native calls. Check React Native Directory.
- **Assuming lazy loading is automatic** → only TurboModules support lazy initialization. Legacy modules are still eager.
