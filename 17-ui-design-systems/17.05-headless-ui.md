## 17.5 Headless UI

### Subtopic Tree

### The Shift
> "The headless and primitive layer (unstyled, accessible behavior you style yourself) is the structural winner in React UI; shadcn/ui is copy-in components built on it."

### Three Options Dominate

| Library | What it is | Notes |
|---------|-----------|-------|
| **Radix Primitives** | Unstyled, accessible, 30+ components | The base under shadcn/ui; still fully supported |
| **Base UI** | Radix alternative from MUI team | v1.0 stable Feb 2026; shadcn/ui now defaults to Base UI |
| **React Aria** | Adobe's accessibility-first primitives | `react-aria-components` high-level API; drop to hooks for full control |

### Radix Primitives in Practice
```tsx
// ❌ Don't fight pre-styled components
<Button className="override-everything" />

// ✅ Radix gives you behavior, you add styling
<Dialog.Root>
  <Dialog.Trigger className="your-button-styles" />
  <Dialog.Content className="your-modal-styles" />
</Dialog.Root>
```

### Data Attributes for Styling
Radix primitives expose state via `data-*` attributes:
```css
[data-state="open"] { /* open state styles */ }
[data-state="closed"] { /* closed state styles */ }
[data-disabled] { /* disabled styles */ }
```

### Real-World Deal-Breakers
- **Using headless when you need styled components** → shadcn/ui, Mantine exist for a reason.
- **Overriding primitive behavior** → Radix handles keyboard/focus/ARIA. Enhance, don't replace.
- **No focus management** → dialogs, menus, popovers must trap focus. Primitives handle this; don't fight it.
- **Mixing Radix Primitives with Radix Themes** → Primitives are headless behavior; Themes is a styled library on top.
