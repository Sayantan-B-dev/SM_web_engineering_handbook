## 17.9 CSS Modules

### Subtopic Tree
- Scoped class names (build-time hashing)

### How CSS Modules Work
CSS Modules are a **build-time module system** - the bundler (Vite, webpack) transforms class names to unique hashes at build time. This provides automatic scoping with **zero runtime cost**.

```css
/* Button.module.css */
.button { padding: 0.5rem 1rem; border-radius: 6px; }
.primary { composes: button; background: var(--color-primary); }
```

```tsx
import styles from './Button.module.css';
<button className={styles.primary}>Click</button>
```

### TypeScript Declaration (Required)
```typescript
// src/types/css.d.ts
declare module '*.module.css' {
  const classes: { readonly [key: string]: string };
  export default classes;
}
```

### CSS Modules vs Tailwind

| | CSS Modules | Tailwind |
|--|-------------|----------|
| Scoping | Automatic (hashed) | Via utilities |
| Runtime cost | Zero | Zero |
| TypeScript | Via declarations | Via `cn()` |
| Best for | Complex components, teams that prefer CSS | Rapid prototyping, design systems |
| RSC-safe | ✅ | ✅ |

### Real-World Deal-Breakers
- **No `.module.css` suffix** → plain `.css` imports are **global** and will cause style collisions.
- **No TypeScript declaration** → import errors; no autocomplete.
- **Using CSS Modules for everything** → Tailwind's utility approach is faster for prototyping.
- **Global styles not managed** → resets, variables, and fonts should be in a global stylesheet, not modules.
