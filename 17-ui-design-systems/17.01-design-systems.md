## 17.0 Design Systems - The Foundation

### Core Mental Model
A design system is not a component library. It is a **shared contract** between design and engineering, enforced through tokens, primitives, and components. The component library is the delivery mechanism; the contract is the system itself.

```text
Design System = Tokens + Primitives + Components + Documentation + Governance
```

### The Three Layers

| Layer | What it is | Who owns it |
|-------|-----------|-------------|
| **Tokens** | Design decisions as data (color, spacing, typography) | Design + Engineering |
| **Primitives** | Accessible, unstyled behavior (Radix, Base UI, React Aria) | Engineering |
| **Components** | Styled, composed, opinionated UI (Button, Dialog, Table) | Engineering + Design |

### Real-World Deal-Breakers
- **Building components before tokens** → every component hardcodes its own values; changing a brand color requires editing 40 files.
- **Design system as a gatekeeper** → slow approvals kill adoption; teams fork components and the system dies.
- **No governance model** → anyone adds anything; the system becomes a dumping ground.
- **Accessibility bolted on** → retrofitting a11y to 50 components costs 10× more than building it in from the start.
