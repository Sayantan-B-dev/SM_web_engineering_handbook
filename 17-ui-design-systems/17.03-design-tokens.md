## 17.3 Design Tokens

### Subtopic Tree
- Three-tier hierarchy: primitive → semantic → component
- DTCG format (`$value`, `$type`, `$description`)
- Style Dictionary v4 transformation
- CSS custom properties as the web output
- Typed TS token map (fail the build, not the UI)
- Theming via semantic-layer swap
- Dark mode as a semantic-value swap
- Multi-brand theming
- Token naming conventions
- Token documentation

### Three-Tier Hierarchy

| Tier | Purpose | Example | Stability |
|------|---------|---------|-----------|
| **Primitive** | Raw values, the palette | `--color-blue-500: #3b82f6` | Very stable |
| **Semantic** | Purpose-driven mapping | `--color-primary: var(--color-blue-500)` | Stable |
| **Component** | Component-specific | `--button-bg: var(--color-primary)` | Changes often |

**The rule:** Components consume **component tokens** (or semantic tokens). Only the semantic tier is themed. Primitives never change between themes.

```css
/* Tier 1: Primitive tokens */
:root {
  --color-blue-500: #3b82f6;
  --color-gray-100: #f3f4f6;
  --space-4: 16px;
}

/* Tier 2: Semantic tokens (themed) */
:root {
  --color-primary: var(--color-blue-500);
  --color-background: var(--color-gray-100);
}
[data-theme="dark"] {
  --color-primary: var(--color-blue-400);
  --color-background: var(--color-gray-900);
}

/* Tier 3: Component tokens */
:root {
  --button-bg: var(--color-primary);
  --button-padding: var(--space-4);
}
.button { background: var(--button-bg); padding: var(--button-padding); }
```

### Theming Is a Value Swap
Theming works by swapping the **semantic layer** while primitives stay constant. Never fork a component for a theme.

### DTCG Format
```json
{
  "color": {
    "blue": {
      "500": {
        "$value": "#3b82f6",
        "$type": "color",
        "$description": "Primary brand blue"
      }
    }
  }
}
```
The DTCG format is the interoperability target - it's tool-agnostic and exportable from Figma Variables.

### Real-World Deal-Breakers
- **Tokens only in Figma** → engineers hardcode hex values. The design system is aspirational, not real.
- **No typed TS token map** → `bg-primry` renders wrong instead of failing the build.
- **Theming at the component tier** → every theme forks components. Theme at the semantic tier only.
- **Primitives changing between themes** → `--color-blue-500` is different in dark mode. Primitives must be constant; only semantics change.
