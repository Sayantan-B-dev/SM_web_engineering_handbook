## 17.2 Component Libraries

### Subtopic Tree
- Distribution models: npm package, monorepo package, copy-paste (shadcn/ui)
- Peer dependencies (React must be singleton)
- Tree-shaking (per-component subpath exports)
- Styling approach (Tailwind, CSS Modules, CSS-in-JS, StyleX)
- Theming (light/dark, brand variants)
- Documentation (Storybook, Histoire)
- API patterns: compound components, controlled/uncontrolled, `forwardRef` + prop spread
- Accessibility baseline
- Testing (visual regression, a11y tests)
- Versioning strategy

### Distribution Models

| Model | Example | Pros | Cons |
|-------|---------|------|------|
| **npm package** | MUI, Mantine, Chakra | Clean versioning, install once | Publish cycle slows iteration; forking is painful |
| **Monorepo package** | Internal `@acme/ui` | Instant iteration, atomic changes | Requires monorepo tooling |
| **Copy-paste (shadcn/ui)** | shadcn/ui | Full ownership, no dependency, full customization | No automatic updates; code duplication |

### API Patterns

| Pattern | What it does | Example |
|---------|-------------|---------|
| **Compound components** | Parent + named children share state via Context | `<Tabs.Root><Tabs.List><Tabs.Trigger>...` |
| **Controlled + uncontrolled** | Dual API: `value`/`onChange` or `defaultValue` | `<Select value={v} onChange={fn} />` or `<Select defaultValue="a" />` |
| **`forwardRef` + prop spread** | Escape hatches for consumers | `<Button ref={ref} {...rest} />` |

### Tree-Shaking
Every component should be importable via a subpath:
```typescript
import { Button } from 'acme-ui/button';  // only Button + its deps
// NOT: import { Button } from 'acme-ui'; // pulls entire library
```

### Real-World Deal-Breakers
- **React not a peer dependency** → two React copies → "Invalid hook call" errors.
- **No tree-shaking** → importing one Button ships the whole library (500KB+).
- **Boolean prop explosion** → `<Button primary secondary danger loading disabled rounded />` → 128 combinations. Use variants.
- **Breaking changes without major bump** → downstream apps break silently.
- **No Storybook or visual tests** → components break without anyone noticing.
