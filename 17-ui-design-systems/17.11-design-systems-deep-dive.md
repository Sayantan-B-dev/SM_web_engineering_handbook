### The Token Pipeline (2026 State)

| Concern | 2026 state | Durable principle |
|---------|-----------|-------------------|
| **Source format** | W3C DTCG (`$value`, `$type`, `$description`) is the interoperability target; Figma Variables export toward it | One framework-agnostic source of truth |
| **Transform tool** | Style Dictionary v4 transforms DTCG JSON → CSS vars / JS / iOS / Android | Transform, never hand-duplicate tokens |
| **Web output** | CSS custom properties (theme-swappable) + typed TS token map | A mistyped token should fail the build, not render wrong |
| **Theming** | Semantic-value maps scoped by `[data-theme]` / `[data-brand]` | Theming is a semantic-tier value swap - never a component fork |

### Accessibility at v1
Atlassian's design system updates color tokens to meet contrast guidelines in light and dark themes while maintaining brand hierarchy. They adjusted typography size and weight for legibility across densities. **Token-level changes allow future components to inherit fixes automatically**.

This is the killer argument for token-first design systems: fix the token, fix every component.

### Real-World Deal-Breakers
- **No typed TS token map** → `bg-primry` (typo) silently renders wrong. Type the token outputs.
- **Components generated from Figma** → full component generation from Figma remains lossy. Treat generated code as a starting point, not the source of truth.
- **No changelog derived from changesets** → users don't know what changed; they pin old versions.
- **Breaking changes without codemods** → downstream teams can't upgrade; the system stagnates.
