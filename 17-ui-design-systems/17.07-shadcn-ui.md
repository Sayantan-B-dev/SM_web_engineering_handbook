### The Copy-Paste Model
> "Instead of installing components as a package from npm, you pull the source files directly into your repo using the shadcn CLI. The components land in your codebase, and from that point on, your team reads, edits, and versions them like any other component you'd author yourself."

```bash
npx shadcn@latest add button
# → Writes components/ui/button.tsx into your repo
# → You own it, edit it, version it
```

### Architecture
shadcn/ui is built on:
- **Radix Primitives** (or Base UI as of July 2026) - behavior, accessibility
- **Tailwind CSS** - visual styling
- **`tailwind-merge`** - conflict resolution
- **`class-variance-authority` (CVA)** - variant → class mapping

```tsx
// Variants are data, not conditionals
const buttonVariants = cva('base-classes', {
  variants: {
    variant: {
      primary: 'bg-primary text-white',
      secondary: 'bg-secondary text-black',
    },
    size: { sm: 'h-8 px-3', lg: 'h-12 px-6' },
  },
  defaultVariants: { variant: 'primary', size: 'sm' },
});
```

### Blocks and v0
Beyond individual components, shadcn/ui ships **pre-composed UI patterns called Blocks** - dashboards, authentication flows, sidebar layouts. v0 (Vercel's AI product) generates React code using Tailwind CSS and shadcn/ui as part of its default stack.

### Base UI Default (July 2026)
Since July 2026, new shadcn projects **default to Base UI**, with Radix still fully supported (`shadcn init -b radix`).

### Real-World Deal-Breakers
- **No update mechanism** → once you copy the component, you don't get upstream fixes automatically. Manual diffing required.
- **Tailwind is a required dependency** → shadcn/ui is an architectural commitment, not a pluggable library.
- **Customizing without understanding CVA** → variants become conditional class strings; unmaintainable.
- **No registry for internal components** → teams that build on shadcn should create a **custom registry** for their own components.
