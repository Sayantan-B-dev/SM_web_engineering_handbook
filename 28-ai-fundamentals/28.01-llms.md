### How LLMs Work (For Developers)
An LLM is a function: `f(prompt) → completion`. It predicts the most likely next token given the input tokens. There is no database lookup, no reasoning engine, no knowledge graph. It's pattern matching at scale.

```typescript
// The simplest possible LLM call
const response = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`,
  },
  body: JSON.stringify({
    model: 'gpt-4.1',
    messages: [
      { role: 'system', content: 'You are a helpful assistant.' },
      { role: 'user', content: 'Explain closures in JavaScript.' },
    ],
    temperature: 0.7,
  }),
});

const data = await response.json();
console.log(data.choices[0].message.content);
```

### Sampling Parameters

| Parameter | What it does | Typical values |
|-----------|-------------|---------------|
| `temperature` | Randomness (higher = more creative, lower = more deterministic) | 0-2, default 1 |
| `top_p` | Nucleus sampling - only consider tokens whose cumulative probability ≤ p | 0-1 |
| `top_k` | Only consider the top k tokens | 1-100 |
| `max_tokens` | Maximum output length | Varies by model |
| `presence_penalty` | Penalize tokens that already appeared | -2 to 2 |
| `frequency_penalty` | Penalize tokens based on frequency | -2 to 2 |

**Rule:** For deterministic outputs (code, structured data), use `temperature: 0`. For creative writing, use `temperature: 0.7-1.0`.

### System Prompts vs User Prompts
```typescript
{
  messages: [
    { role: 'system', content: 'You are a senior React engineer. Always provide TypeScript examples.' },
    { role: 'user', content: 'How do I optimize this component?' },
  ]
}
```
The **system prompt** sets behavior, persona, and constraints. The **user prompt** is the actual query. System prompts are **not** a security boundary - they can be overridden by prompt injection.

### Deeper Explanation: What The Model Actually Is

A large language model is a next-token predictor over a fixed-size context. Everything practical follows from that:

- **No memory between calls** â€” the conversation must be resent. State lives in your application, not the model.
- **No built-in facts** â€” knowledge is baked into weights at training time, so fresher or private data must be supplied in the context (that is RAG).
- **Probabilistic** â€” the same input can produce different output; deterministic output needs low temperature *plus* structured decoding plus validation.
- **Token-driven cost and latency** â€” input tokens dominate on every call in a long conversation, so prompt size is a product decision.
- **Instruction-following is not compliance** â€” "do not reveal the system prompt" is a request, not a guarantee; enforce boundaries in code.

For app design, the important split is between **completion-shaped work** (summarise, classify, extract, transform) and **agentic work** (multi-step tool use with side effects). The first is cheap and reliable enough to sit on a user path; the second needs permissions, human confirmation, and sandboxing.

### Additional Pitfalls
- **Assuming the model remembers the last request.** Statelessness means you own conversation history, truncation, and summarisation.
- **Sending the full history forever.** Cost and latency grow linearly; summarise or window.
- **Expecting exact answers.** Models paraphrase, hallucinate details, and drift in formatting.
- **Ignoring model/version changes.** A pinned version that gets deprecated can change behaviour overnight; run evals on upgrade.

### Real-World Deal-Breakers
- **Using `temperature: 0` and expecting deterministic output** → LLMs are still probabilistic; floating-point non-determinism exists across GPU runs.
- **Putting secrets in the system prompt** → prompt injection can extract them. Never put API keys or PII in prompts.
- **Ignoring streaming** → users stare at a blank screen for 5-30 seconds. Always stream long responses.
- **Assuming the model knows current events** → training data has a cutoff. Use RAG for fresh data.
- **Not handling token limits** → long conversations overflow the context window. Implement context compaction.
