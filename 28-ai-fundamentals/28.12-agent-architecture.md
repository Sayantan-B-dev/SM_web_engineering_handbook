### The Six Runtime Patterns (2026)

| Pattern | Category | Description |
|---------|----------|-------------|
| **Hierarchical Delegation** | Coordination | Parent agent delegates subtasks to child agents |
| **Scatter-Gather + Saga** | Coordination | Fan out to multiple agents, gather results, compensate on failure |
| **Event-Driven Sequencing** | State | Agents react to events in a shared stream |
| **Shared State Machine** | State | Agents read/write a shared state machine |
| **Supervisor + Gate** | Control | Supervisor agent validates before actions execute |
| **Tiered Routing** | Control | Route to different models based on complexity |

### Governance and Guardrails
A reference architecture for governed enterprise agentic AI systems combines governed data, retrieval-augmented generation, large language models, tool execution, policy controls, and human approval.

**Key principles:**
- **Least-privilege tool access** - agents only have tools they need.
- **Separation of AI reasoning from execution** - the agent decides, but a deterministic layer executes.
- **Human approval** - destructive or high-cost actions require confirmation.
- **Policy controls** - enforce rate limits, cost caps, and content filters.

### Deeper Explanation: Five Patterns, One Decision Axis

Agent architectures differ along one axis: **who decides the next step, and how much structure is imposed?**

| Pattern | Shape | Fits | Risk |
|---|---|---|---|
| Single-agent ReAct | Think â†’ act â†’ observe loop | Focused tools, short tasks | Loops, drift |
| Plan-and-execute | Up-front plan, then execute steps | Predictable multi-step jobs | Plan invalidated by reality |
| Router / dispatcher | Classify intent, delegate to specialists | Many distinct capabilities | Misrouting |
| Multi-agent (supervisor + workers) | Orchestrator assigns subtasks | Parallel, heterogeneous work | Coordination cost explodes |
| Deterministic workflow + LLM steps | Code owns control flow, LLM fills slots | High-reliability products | Less flexible |

For product code the last row is the strongest default: **put the control flow in code and the intelligence in steps**. Deterministic orchestration with LLM-powered nodes is easier to test, cheaper, and far safer than a fully autonomous loop â€” and you can still expose autonomy for the parts that genuinely need it.

### Additional Pitfalls
- **Multi-agent for a single-step task.** Coordination overhead exceeds the value; start simple.
- **Plans treated as contracts.** Reality invalidates plans; the executor must be able to re-plan.
- **Shared mutable state between agents.** Race conditions and confused summaries; keep messages explicit and immutable.
- **No observability per step.** Without a trace of decisions, prompts, and tool calls, debugging is impossible.
- **Autonomy where determinism would do.** If the steps are known, code them; reserve agency for genuine uncertainty.

### Real-World Deal-Breakers
- **No guardrails** → the agent executes destructive actions without validation.
- **No observability** → you can't debug why the agent made a decision. Log every LLM call, tool call, and result.
- **No evaluation** → you don't know if the agent is succeeding. Track task completion rate, latency, and cost.
- **Single-agent architecture for complex tasks** → use hierarchical delegation or supervisor patterns.
- **No cost caps** → an agent loop can burn thousands in API fees. Enforce per-task and per-user budgets.
