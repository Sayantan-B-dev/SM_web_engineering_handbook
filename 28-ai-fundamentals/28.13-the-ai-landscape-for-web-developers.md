### Core Mental Model
Large Language Models are neural networks trained on large datasets to understand and generate text. Training usually starts from a broad base model and adds fine-tuning for specific tasks. LLMs can help with scenarios such as code completion and chat, but they also have limits, including context windows and possible bias in training data.

For web developers, the key insight is: **you don't train models**. You call them through APIs. Python is the common choice for training AI models, but most application developers consume models through web APIs. Because JavaScript runs across browsers and servers and handles HTTP calls, it's a practical choice for building AI applications.

```text
Your React/Next.js app
  → API call to OpenAI/Anthropic/Google (or local Ollama)
  → LLM generates response
  → You render, store, or act on it
```

### Deeper Explanation: The Frontend Engineer's Actual Surface Area

You will not train a model. The web-facing AI surface is four jobs, and they are mostly integration and product work:

1. **Prompt and context assembly** â€” deciding what the model sees (system prompt, retrieved documents, conversation window, tool schemas). This is where most quality wins live.
2. **Streaming and UI state** â€” rendering tokens as they arrive, handling cancellation, partial tool calls, and optimistic UI while the model thinks.
3. **Safety and cost control** â€” rate limits, token budgets, output validation, prompt-injection defence, and caching so a viral moment does not produce a five-figure bill.
4. **Evaluation** â€” a small, versioned set of realistic cases with expected properties, run in CI, so prompt and model changes are not vibes-based.

The mental shift: a model is a **probabilistic dependency**. Treat it like a flaky third-party API with variable latency, non-deterministic output, and a per-call price â€” which is exactly why schemas, timeouts, retries, and fallbacks matter more than clever prompting.

### Additional Pitfalls
- **Shipping without an eval set.** Prompt changes become unmeasurable and regressions invisible.
- **Calling the model from the browser with your key.** Anything shipped to a client is public; proxy through your server.
- **No token or cost budget per user.** One loop or a prompt-injection can burn the month's quota.
- **Treating output as trustworthy data.** Validate, parse, and constrain it before it reaches your state or your database.

### Real-World Deal-Breakers
- **Treating AI as magic** → it's a probabilistic text generator. It will hallucinate. Plan for it.
- **Not measuring cost** → token costs scale with usage. A viral feature can burn thousands in API fees overnight.
- **Ignoring latency** → LLM calls take 500ms-30s depending on model and context. Design for streaming and loading states.
- **Assuming one model fits all** → small models for simple tasks, large models for complex reasoning.
