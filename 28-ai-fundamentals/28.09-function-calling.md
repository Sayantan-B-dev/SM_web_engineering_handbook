### The Mental Model
Function calling is **structured output plus a dispatch loop**. The model does not execute anything: it emits a tool call with JSON arguments, your code validates and executes it, and you feed the result back as a message. Everything important therefore lives in three places â€” the schema, the validation, and the loop that decides when to stop.

```ts
import { z } from 'zod';

const SearchInput = z.object({
  query: z.string().min(1).max(200).describe('Natural-language search query'),
  filters: z.object({
    status: z.enum(['open', 'closed', 'all']).default('all'),
    since: z.iso.date().optional().describe('ISO date; omit for all time'),
  }).optional(),
  limit: z.int().min(1).max(50).default(10).describe('Maximum rows to return'),
});

export const tools = [
  {
    type: 'function',
    function: {
      name: 'search_issues',
      description: 'Search issues by keyword. Use when the user asks about existing issues or their status.',
      parameters: z.toJSONSchema(SearchInput),   // one schema, used for validation too
      strict: true,
    },
  },
];
```

```ts
// The dispatch loop: validate, execute, feed back, stop deliberately.
for (let step = 0; step < 5; step++) {
  const res = await llm.chat({ messages, tools });
  const call = res.toolCalls?.[0];
  if (!call) return res.content;

  // 1. Validate the model's arguments before trusting them; repair once, then fail loudly.
  const parsed = SearchInput.safeParse(JSON.parse(call.arguments));
  const output = parsed.success
    ? await runTool(parsed.data)                                   // 2. Execute with timeout + idempotency
    : { error: zodToModelMessage(parsed.error) };                  // 3. Return a fixable error, not a crash

  messages.push({ role: 'tool', toolCallId: call.id, content: JSON.stringify(output).slice(0, 8_000) });
}
```

### Schema Design That Actually Works
- **Fewer, well-named tools beat many overlapping ones.** If descriptions overlap, the model picks wrong; if you merge unrelated capabilities, arguments get murky.
- **Enums, not free strings.** Anything with a bounded domain belongs in an enum; `strict: true` (or equivalent) makes the provider enforce it.
- **Descriptions are prompts.** "ISO date string" does not help; "ISO date; omit for all time" does.
- **Truncate tool output.** A 200 KB API response destroys the context budget; return the fields that matter.
- **Never execute unvalidated arguments.** The model invents fields, sends wrong types, and hallucinates ids.

### Real-World Deal-Breakers
- **Executing the model's JSON directly.** Validate against the same schema you advertised, or you will run `delete` with a hallucinated id.
- **No step or token limit in the loop.** An agent that calls tools indefinitely is a fork bomb with a credit card.
- **Idempotency ignored.** Retries and duplicate steps repeat side effects; require an idempotency key on any mutating tool.
- **Errors hidden from the model.** "Something went wrong" stalls the loop; return actionable messages it can recover from.
- **Unbounded tool output.** Truncate and summarise before returning results to the model.
- **Authorisation inside the model's judgement.** Permissions are enforced by your code per call, never by the prompt.
