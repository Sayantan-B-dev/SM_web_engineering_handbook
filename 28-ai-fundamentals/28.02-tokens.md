### What a Token Is
A token is a chunk of text - a word, a character set, or a combination of words and punctuation - that a tokenizer produces. The model never sees raw text. Text is converted into tokens by a tokenizer, then each token maps to an integer ID that indexes into an embedding table.

```typescript
// OpenAI's tiktoken
import { encoding_for_model } from 'tiktoken';

const enc = encoding_for_model('gpt-4');
const tokens = enc.encode('Hello, world!');
console.log(tokens); // [9906, 11, 1917, 0]
console.log(tokens.length); // 4 tokens

enc.free();
```

### Tokenization Example
```text
"tokenization" → ["token", "ization"]  (2 tokens)
"the"          → ["the"]                (1 token)
"const"        → ["const"]              (1 token)
"camelCase"    → ["camel", "Case"]      (2 tokens)
"🚀"           → ["🚀"]                 (1-2 tokens depending on tokenizer)
```

Code tokenizes less efficiently than prose because special characters (`{ } => //`), indentation, and camelCase variable names produce more tokens per character.

### Cost Calculation
```typescript
function estimateCost(inputTokens: number, outputTokens: number, model: string): number {
  const pricing = {
    'gpt-4.1': { input: 0.000002, output: 0.000008 }, // per token
    'claude-sonnet-4': { input: 0.000003, output: 0.000015 },
    'gemini-2.5-pro': { input: 0.00000125, output: 0.00001 },
  };

  const p = pricing[model];
  return inputTokens * p.input + outputTokens * p.output;
}

// Example: 10K input, 2K output on GPT-4.1
estimateCost(10_000, 2_000, 'gpt-4.1'); // $0.036
```

### Deeper Explanation: Tokens Are The Unit Of Everything

Tokens are subword units: roughly ~4 characters or ~0.75 words in English, and much worse for code, non-Latin scripts (Hindi, Bengali, Arabic can be 2-4Ã- more tokens per character), JSON punctuation, and emoji. Three consequences drive real design decisions:

- **Cost**: prompt tokens are charged on *every* call, so a 6 000-token system prompt in a chat loop is a recurring fee, not a one-off.
- **Latency**: time-to-first-token plus tokens-per-second Ã- output length. Output is generated serially, so length dominates perceived speed.
- **Truncation**: exceeding the context window silently drops content if you truncate carelessly (usually from the middle, where the instructions and the question live).

Practical counting: use the provider's tokeniser (`tiktoken`-style) for budgeting, keep a margin, and measure with real content â€” a table or a stack trace can be 5-10Ã- denser than prose.

### Additional Pitfalls
- **Estimating with `chars / 4` for non-English text.** Bengali, Hindi, and CJK text can be 3-4Ã- that ratio; budgets blow up.
- **Counting only output.** Input tokens usually cost more in aggregate in chat products.
- **Truncating from the front blindly.** You lose the system instructions, then wonder why the model behaves differently on long chats.
- **No per-request max output.** An unbounded generation can run for a minute and cost cents per call.
- **Forgetting tool schemas and retrieved docs in the count.** They are part of the prompt and often the largest part.

### Real-World Deal-Breakers
- **Assuming 1 token = 1 word** → it's ~0.75 words per token. Underestimating tokens means underestimating cost.
- **Not counting tokens before sending** → you can hit the context limit and get a truncated or failed request.
- **Using the wrong tokenizer** → different models use different tokenizers. OpenAI's `tiktoken`, Anthropic's tokenizer, and Google's SentencePiece each split text differently.
- **Ignoring code tokenization** → code uses 2-3× more tokens per character than prose. Budget accordingly.
