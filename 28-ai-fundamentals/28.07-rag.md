### What RAG Is
Retrieval-augmented generation (RAG) is the industry-standard approach to building applications that use language models to process specific or proprietary data that the model doesn't already know. RAG enhances LLM performance by using external knowledge sources.

```text
User query → Embed → Vector search → Top-K chunks
                                      → Prompt with chunks → LLM → Response
```

### The Two Phases
**Ingestion phase:** documents are preprocessed, chunked, enriched with metadata, embedded, and stored in a vector index.

**Inference pipeline phase:** the user query is embedded, relevant chunks are retrieved, and the query + chunks are sent to the LLM for generation.

### Naive RAG vs Advanced RAG
**Naive RAG** helps you understand the basic parts and roles in a RAG-based chat system. **Advanced RAG** needs more preprocessing and post-processing to handle articles, queries, and responses.

| Naive RAG | Advanced RAG |
|-----------|-------------|
| Fixed chunking | Semantic chunking |
| Single retrieval | Hybrid + reranking |
| No metadata | Metadata filtering |
| Direct query | Query expansion |
| No evaluation | Faithfulness + relevance metrics |

### Chunking Strategies
```typescript
// Fixed-size chunking (simple, fast)
function chunkFixed(text: string, size: number, overlap: number) {
  const chunks = [];
  for (let i = 0; i < text.length; i += size - overlap) {
    chunks.push(text.slice(i, i + size));
  }
  return chunks;
}

// Semantic chunking (better, slower)
async function chunkSemantic(text: string) {
  const sentences = splitSentences(text);
  const chunks = [];
  let current = [];
  for (const sentence of sentences) {
    current.push(sentence);
    const similarity = await cosineSimilarity(
      embed(current.join(' ')),
      embed(sentence)
    );
    if (similarity < 0.7) { // topic shift
      chunks.push(current.join(' '));
      current = [sentence];
    }
  }
  if (current.length) chunks.push(current.join(' '));
  return chunks;
}
```

### RAG vs Fine-Tuning

| RAG | Fine-Tuning |
|-----|------------|
| Grounds responses in external data | Changes model weights |
| No training required | Requires training data + compute |
| Easy to update (just re-index) | Must retrain for updates |
| Lower cost | Higher cost |
| No hallucination guarantee | Can reduce hallucinations |

### Deeper Explanation: RAG Is A Pipeline, And The Pipeline Is Debuggable

Retrieval-augmented generation is four stages; each can be tested independently, which is the point:

1. **Ingest** â€” extract text (PDF/HTML cleanly), chunk semantically, attach metadata, embed, upsert idempotently.
2. **Retrieve** â€” hybrid search, filter by permission and metadata, rerank, then build a context block with the best k documents.
3. **Generate** â€” instruct the model to answer *only* from the provided context, cite sources, and say "I don't know" when the context is insufficient.
4. **Verify** â€” validate the output, attribute claims to sources, and log the retrieved ids for debugging.

The failure taxonomy is small and memorable: bad extraction (garbage in), bad chunking (context split), bad retrieval (missed evidence), bad grounding (the model ignores context), bad verification (no citation). Instrument those five, and quality work becomes targeted instead of ritual.

### Additional Pitfalls
- **No citations.** Users cannot verify, you cannot debug, and hallucinations become indistinguishable from retrieval.
- **Ignoring permission filtering.** Retrieval is where data leaks most often happen; filter at query time, per user.
- **Stuffing every retrieved chunk in.** Relevance drops with volume; 5-8 well-ranked chunks beat 30.
- **No "no answer" path.** Models will answer anyway; instruct and enforce an explicit insufficient-context response.
- **No cached embeddings.** Re-embedding unchanged documents on every deploy is a silent cost leak.

### Real-World Deal-Breakers
- **No chunking strategy** → chunks are too large (noise) or too small (missing context). Test chunk sizes.
- **No metadata filtering** → you retrieve chunks from the wrong document or time period.
- **No evaluation** → you don't know if the retrieved chunks are relevant or if the response is faithful.
- **Using RAG for everything** → for small, static datasets, long context may be simpler.
- **No reranking** → top-K vector results are often not the most relevant.
