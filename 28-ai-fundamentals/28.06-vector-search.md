### Semantic vs Keyword Search

| Keyword Search | Semantic Search |
|---------------|----------------|
| Matches exact words | Matches meaning |
| Misses synonyms | Handles synonyms |

### Hybrid Search (Vector + BM25)
```typescript
async function hybridSearch(query: string, limit = 10) {
  const queryEmbedding = await embed(query);

  // Vector search
  const vectorResults = await vectorDB.search({
    vector: queryEmbedding,
    limit: limit * 2,
  });

  // Keyword search (BM25)
  const keywordResults = await bm25Search(query, limit * 2);

  // Merge with Reciprocal Rank Fusion
  const merged = reciprocalRankFusion([vectorResults, keywordResults]);
  return merged.slice(0, limit);
}

function reciprocalRankFusion(resultSets: any[][], k = 60) {
  const scores = new Map<string, number>();
  for (const results of resultSets) {
    results.forEach((doc, rank) => {
      const score = 1 / (k + rank + 1);
      scores.set(doc.id, (scores.get(doc.id) ?? 0) + score);
    });
  }
  return [...scores.entries()]
    .sort((a, b) => b[1] - a[1])
    .map(([id]) => id);
}
```

### Reranking
```typescript
// After retrieval, rerank with a cross-encoder
async function rerank(query: string, documents: Document[], topK = 5) {
  const pairs = documents.map((doc) => ({ query, document: doc.content }));
  const scores = await crossEncoder.score(pairs);
  return documents
    .map((doc, i) => ({ doc, score: scores[i] }))
    .sort((a, b) => b.score - a.score)
    .slice(0, topK);
}
```

### Deeper Explanation: Retrieval Quality Is Mostly Ranking And Chunking

Nearest-neighbour search is the easy part. Quality comes from four choices:

1. **Chunking strategy** â€” semantic boundaries (headings, functions) beat fixed windows; 200-500 tokens with 10-20% overlap is a solid default.
2. **Hybrid retrieval** â€” combine dense (embedding) and sparse (BM25/keyword) results with reciprocal rank fusion, then optionally rerank with a cross-encoder.
3. **Query transformation** â€” rewriting the user's question, expanding acronyms, or generating multiple sub-queries measurably improves recall.
4. **Reranking** â€” retrieve 50 candidates, rerank to the best 5-8 with a cross-encoder; this is usually the single biggest quality jump per unit of effort.

Then evaluate: a small labelled set of question â†’ expected-source pairs, measuring recall@k and answer correctness. Without that, every change is guesswork.

### Additional Pitfalls
- **Trusting top-1 similarity.** Scores are not calibrated probabilities; thresholds must be tuned per model and corpus.
- **No reranking budget.** Cross-encoders cost latency; cap the candidate set.
- **Ignoring metadata filters in the query.** User-scoped retrieval must filter by user/permission at query time.
- **Evaluating with the same queries you tuned on.** Hold out a set of realistic questions.
- **Assuming freshness.** Indexes lag writes; document the staleness window and expose it in the UI when it matters.

### Real-World Deal-Breakers
- **Pure vector search for exact matches** → "React 19" and "React 18" are semantically similar. Use hybrid search for product codes, names, and IDs.
- **No reranking** → the top-K vector results are often not the most relevant. Rerank with a cross-encoder.
- **No metadata filtering** → you retrieve irrelevant results from the wrong category or time period.
