### What a Copilot Is
A copilot is an AI assistant **embedded in the application** that understands the current context (what page the user is on, what data they're viewing, what they just did) and can take actions on their behalf. Unlike a standalone chatbot, a copilot has tools that interact with your app.

### Vercel AI SDK Integration
The Vercel AI SDK is the TypeScript toolkit for building AI applications and agents with React, Next.js, Vue, Svelte, Node.js, and more. It provides a `useChat()` React hook that manages the entire chat lifecycle on the frontend, uses Zod schemas for type-safe tool validation, and enables generative UI where the AI returns rendered React components.

### Context-Aware UI
Context-aware UI binds chats to **context keys** that automatically flip tool availability, default models, and confirmation policies per page or feature. Tools are declared once, reused across contexts, and wired to custom launchers or approval flows.

```tsx
// Define tools once
const tools = {
  createProject: { ... },
  deleteProject: { ... },
  searchDocs: { ... },
};

// Context determines which tools are available
const contexts = {
  '/projects': { tools: ['createProject', 'deleteProject', 'searchDocs'] },
  '/docs': { tools: ['searchDocs'] },
  '/settings': { tools: [], defaultModel: 'gpt-4.1-mini' },
};
```

### Approval Flows for Risky Actions
```tsx
function ToolApproval({ toolCall, onApprove, onReject }: Props) {
  if (!toolCall.requiresApproval) return null;

  return (
    <div className="rounded-lg border border-amber-200 bg-amber-50 p-4">
      <p className="font-medium">The assistant wants to {toolCall.name}.</p>
      <pre className="text-sm">{JSON.stringify(toolCall.args, null, 2)}</pre>
      <div className="mt-2 flex gap-2">
        <button onClick={onApprove}>Approve</button>
        <button onClick={onReject}>Reject</button>
      </div>
    </div>
  );
}
```
`@anythic/ui` provides React components for AI interfaces including streaming replies, reasoning, tool calls, approvals, plans, diffs, and terminals. It includes approvals before risky actions, plans, file diffs with accept/reject, terminals with ANSI colors, and context usage.

### use-ai - AI Controls the Frontend
`use-ai` is a React client/framework for easily enabling AI to control your users' frontend. Components call `useAI` to declare their tools and state (`prompt`) to `use-ai`. The `UseAIProvider` provides a floating-action-button chat UI and aggregates `useAI` tools and prompts from all child components.

### Deeper Explanation: The Context Is The Product

A copilot's usefulness is bounded by what it can see. Four context sources, in order of value:

1. **The user's current selection and intent** â€” what is selected, what they were about to do.
2. **The immediate document** â€” the open file/page/record, summarised rather than dumped when large.
3. **Product knowledge** â€” schemas, docs, and policies retrieved on demand (RAG), not embedded in the prompt.
4. **History** â€” prior accepted/rejected suggestions for the same context, which is how quality improves per user.

Interaction design rules that separate usable copilots from demos: suggestions must be **non-blocking and dismissible**, **undoable in one action**, and **scoped to something the user can see**. Latency above ~1 second needs a visible progress affordance; anything that mutates data needs a preview and an explicit accept.

### Additional Pitfalls
- **Dumping the whole document into every request.** Cost and latency grow with the file; send the selection plus a summary.
- **Suggestions the user cannot refuse.** Every suggestion must be ignorable without consequence.
- **No undo.** One-click revert is the difference between "helpful" and "dangerous".
- **Silent side effects.** A copilot that writes to production data without confirmation is an incident generator.
- **No evaluation loop over accepted/rejected suggestions.** That data is the quality signal.

### Real-World Deal-Breakers
- **No context awareness** → the copilot suggests actions that don't apply to the current page.
- **No approval flow** → the copilot deletes production data without confirmation. Require approval for destructive tools.
- **Tools declared per-page** → duplication and drift. Declare tools once in a registry.
- **No fallback model** → the copilot breaks when the primary model is unavailable. Support browser and cloud fallback.
