## 29.0 The AI-Native React Stack (2026)

### Subtopic Tree

- Core layers: model layer → streaming layer → state layer → UI layer
- The Vercel AI SDK as the de facto standard for React AI integration

### Deeper Explanation: The Stack Changes Shape Around Latency

An AI-native React app differs from a CRUD app in one structural way: **the server is in the interaction loop at human-perceptible speed**. A 300 ms database query fits inside a request; a 6-second generation does not. So the architecture moves three things:

- **Data flow inverts**: the UI starts with a stream, not a response. You render a skeleton immediately and mutate it token by token.
- **State must be resumable**: the generation outlives the component, so the stream lives in a store (or a server-side session) rather than a `useEffect` closure.
- **Rendering must be interruptible**: users stop, edit, and redirect; cancellation is a first-class action, not an abort on unmount.

The idiomatic 2026 stack: Next.js (App Router with Server Actions and route handlers) + a streaming SDK (Vercel AI SDK or the provider SDK) + TanStack Query for non-AI data + a virtualised message list + Zod at every model boundary. Client components stay thin; the intelligence lives behind the route handler so keys never reach the browser and prompts can be versioned server-side.

### Additional Pitfalls
- **Treating generation like a fetch.** A single `await` for a 6-second response wastes the product's best asset (perceived speed).
- **State in the component.** Navigating away aborts the generation and loses the answer; put it in a store or persist it.
- **No cancellation.** Users change their mind constantly; `AbortController` wired to the UI is mandatory.
- **Model calls from the client.** Keys leak; rate limits, safety filters, and cost accounting become impossible to centralise.

### Real-World Deal-Breakers
- **Building chat UI from scratch** → you'll spend weeks on streaming, markdown rendering, scroll management, and message branching. Use assistant-ui or AI Elements.
- **No streaming layer** → users stare at a blank screen for 5-30 seconds.
- **State scattered across components** → prop drilling, stale closures, and re-render storms.
- **Assuming one model provider** → the stack must support fallback (browser → cloud, primary → secondary).
