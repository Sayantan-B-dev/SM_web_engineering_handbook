### assistant-ui - Headless Runtime
assistant-ui is a headless React UI framework for AI chat. It provides a full runtime layer-thread management, message branching, attachment handling-that connects to `useStream` via the `useExternalStoreRuntime` adapter.

```tsx
import { AssistantRuntimeProvider, useExternalStoreRuntime, type ThreadMessageLike } from "@assistant-ui/react";
import { useStream } from "@langchain/react";
import { Thread } from "@assistant-ui/react";

export function Chat() {
  const stream = useStream({ apiUrl: "http://localhost:2024", assistantId: "claude" });

  const runtime = useExternalStoreRuntime<ThreadMessageLike>({
    messages: toThreadMessages(stream.messages),
    onNew: async (message) => {
      const text = message.content.filter((c) => c.type === "text").map((c) => c.text).join("");
      await stream.submit({ messages: [{ type: "human", content: text }] });
    },
    onCancel: () => stream.stop(),
    convertMessage: (m) => m,
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```
The runtime layer handles message conversion, tool-call rendering, and reasoning token display automatically.

### AI Elements - Composabale shadcn/ui Components
AI Elements is a composable, shadcn/ui-based component library purpose-built for AI chat interfaces. Components like `Conversation`, `Message`, `Tool`, `Reasoning`, and `PromptInput` are designed to drop directly into any React project and wire to `stream.messages` with minimal glue code.

```tsx
import { Conversation, ConversationContent, ConversationScrollButton } from "@/components/ai-elements/conversation";
import { Message, MessageContent } from "@/components/ai-elements/message";
import { Tool, ToolHeader, ToolContent, ToolInput, ToolOutput } from "@/components/ai-elements/tool";
import { Reasoning, ReasoningTrigger, ReasoningContent } from "@/components/ai-elements/reasoning";

function Chat() {
  const stream = useStream({ apiUrl: "http://localhost:2024", assistantId: "ai_elements" });

  return (
    <Conversation className="flex-1">
      <ConversationContent>
        {stream.messages.map((msg, i) => {
          if (HumanMessage.isInstance(msg)) {
            return <Message key={i} from="user"><MessageContent>{msg.text}</MessageContent></Message>;
          }
          if (AIMessage.isInstance(msg)) {
            return (
              <div key={i}>
                <Reasoning>
                  <ReasoningTrigger />
                  <ReasoningContent>{getReasoningText(msg)}</ReasoningContent>
                </Reasoning>
                {getToolCalls(msg).map((tc) => (
                  <Tool key={tc.id} defaultOpen>
                    <ToolHeader type={`tool-${tc.name}`} state={tc.state} />
                    <ToolContent>
                      <ToolInput input={tc.args} />
                      {tc.output && <ToolOutput output={tc.output} />}
                    </ToolContent>
                  </Tool>
                ))}
              </div>
            );
          }
        })}
      </ConversationContent>
      <ConversationScrollButton />
    </Conversation>
  );
}
```
AI Elements ships via a CLI that adds components directly to your project (shadcn/ui registry style).

### Streaming Token Handling (Incomplete Tokens)
```tsx
// Problem: Markdown tokens arrive incomplete
// "**bold" → "**bold**" (unclosed)
// Code blocks: ```tsx\nconst x = → incomplete

// Solution: Buffer and render only complete tokens
function StreamingMessage({ content }: { content: string }) {
  // Harden against incomplete Markdown
  const safeContent = useMemo(() => hardenIncompleteMarkdown(content), [content]);
  return <Markdown remarkPlugins={[remarkGfm]}>{safeContent}</Markdown>;
}
```
The Chrome for Developers blog demonstrates rendering GitHub-style Markdown during streaming while handling incomplete tokens, showing a "thinking..." shimmer while waiting for the first token, and auto-scrolling to new messages with a scroll-to-bottom button when the user scrolls up.

### Deeper Explanation: Chat Is A List With Hard Problems

The surface looks like a message list; the difficulty is in the details users notice immediately:

- **Autoscroll that respects the user.** Auto-follow while near the bottom, stop following the moment the user scrolls up ("scroll lock"), and offer a jump-to-latest affordance.
- **Virtualisation.** Thousands of messages with markdown, code, and images must not all render; virtualise by message with measured heights.
- **Markdown safety.** Render with a sanitiser and a strict component allow-list; model output is untrusted input.
- **Input affordances.** Enter to send / Shift+Enter for newline, IME composition safety for CJK input, and a stop button that appears during generation.
- **Message identity.** Streaming messages need stable ids from the first token, and "regenerate" needs to replace in place, not append.
- **Error and retry states.** A failed generation must be visibly retryable without re-typing the prompt.

### Extended Example: Scroll-Safe Streaming List

```tsx
function useAutoScroll(deps: unknown[]) {
  const ref = useRef<HTMLDivElement>(null);
  const locked = useRef(false);

  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const onScroll = () => {
      // "near bottom" = within 64px; user scrolling up locks auto-follow
      locked.current = el.scrollHeight - el.scrollTop - el.clientHeight > 64;
    };
    el.addEventListener('scroll', onScroll, { passive: true });
    return () => el.removeEventListener('scroll', onScroll);
  }, []);

  useEffect(() => {
    const el = ref.current;
    if (el && !locked.current) el.scrollTop = el.scrollHeight;
  }, deps);

  return ref;
}
```

### Additional Pitfalls
- **Auto-scrolling on every token.** It fights the user; check distance-from-bottom before following.
- **`dangerouslySetInnerHTML` on model output.** Unsanitised markdown/HTML is a stored-XSS vector.
- **Rendering every message.** Virtualise; long sessions with code blocks are the common case.
- **Losing drafts on navigation.** Persist the composer per conversation or users will retype.
- **No "thinking" state.** Silence reads as broken; show progress, partial output, or an explicit status.

### Real-World Deal-Breakers
- **Building chat UI from scratch** → weeks of work on streaming, markdown, scroll, branching. Use assistant-ui or AI Elements.
- **Rendering raw Markdown during streaming** → incomplete tokens (`**bold`, `` ```tsx ``) render as broken HTML. Harden with a buffer.
- **No scroll management** → the chat doesn't auto-scroll, or it fights the user when they scroll up to read history.
- **No message branching** → users can't edit a previous message and explore alternatives.
- **No multimodal support** → users expect to paste images, not just text.
