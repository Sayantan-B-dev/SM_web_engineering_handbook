### Generative UI
Generative UI changes the rendering target from post-hoc HTML to typed component trees. Rather than treating LLM output as raw text that gets shoved into a `dangerouslySetInnerHTML` call, generative UI treats model output as structured component trees, rendering interactive, type-safe React components directly from streaming JSON schemas.

```text
LLM output → Streaming JSON → Zod validation → Component registry → React tree
```

### json-render (Vercel)
Vercel has open sourced **json-render**, a framework it describes as "Generative UI," allowing AI models to generate structured user interfaces from streaming JSON. json-render defines component catalogs, generates specs with AI, and renders them safely across React, Vue, Svelte, and Angular.

```json
{
  "type": "Card",
  "props": { "title": "Weather in Kolkata" },
  "children": [
    { "type": "Text", "props": { "value": "32°C, Sunny" } },
    { "type": "Button", "props": { "label": "Refresh", "action": "refresh_weather" } }
  ]
}
```

### Streaming JSON → React Server Components
The architecture uses an incremental JSON stream parser, a Zod-validated component contract, and hydration into type-safe React Server Component trees in Next.js, all without proprietary library lock-in. The data flow is linear: LLM token stream → incremental JSON parser → Zod validation → component registry → React tree.

```typescript
// Zod schema for UI nodes
const UINodeSchema: z.ZodType<UINode> = z.lazy(() =>
  z.discriminatedUnion('type', [
    z.object({ type: z.literal('Text'), props: z.object({ value: z.string() }) }),
    z.object({ type: z.literal('Button'), props: z.object({ label: z.string(), action: z.string() }) }),
    z.object({ type: z.literal('Card'), props: z.object({ title: z.string() }), children: z.array(UINodeSchema) }),
  ])
);
```

### AI-Agent-Ready Design Systems (Meta's Astryx)
Meta has released **Astryx**, an open-source React design system engineered with an MCP server, designed to interface with AI agents so they can build user interfaces without guesswork. It includes specific architectural features designed to interface with AI coding agents.

### Deeper Explanation: The Architecture Follows The Latency Budget

AI features have three latency bands and each implies a different architecture:

| Band | Example | Architecture |
|---|---|---|
| < 200 ms | autocomplete, classification | Static/edge model or cached predictions; no spinner |
| 0.5-3 s | summarise selection, single-turn answer | Optimistic UI + streaming; skeleton behind the cursor |
| > 3 s | agents, long documents, multi-step | Background run with a durable session, progress UI, notifications |

Everything else is a consequence: keys and prompts stay server-side (route handlers or Server Actions), retrieval lives behind an API with permission filters, streams are resumed by run id, and rendering is componentised so the parts that depend on the model (answer, citations, tool cards) can update independently of the rest of the page. The resulting rule of thumb: **the model is a backend service; React renders its state machine**.

### Additional Pitfalls
- **One rendering strategy for all three bands.** Instant features must not show spinners; long runs must not block navigation.
- **Model calls scattered across components.** Centralise in one client module with retries, timeouts, and cost accounting.
- **Synchronous long generations.** A 30-second agent on a request path will time out at the platform edge.
- **No observability per feature.** Track latency, token cost, and success rate per feature, not once for the app.
- **Missing feature flags.** Model/prompt rollouts need canaries and a kill switch like any backend change.

### Real-World Deal-Breakers
- **`dangerouslySetInnerHTML` for LLM output** → XSS vulnerability. Use typed component trees instead.
- **No Zod validation at the stream boundary** → malformed JSON crashes the renderer.
- **No component registry** → you can't map JSON types to React components.
- **No layout shift prevention** → content reflows as it streams in. Use `contain: layout` and dimension-matched skeletons.
- **Proprietary lock-in** → using a proprietary streaming library ties you to a vendor. The architecture works with raw SSE, Zod, and React 19.
