### Principle: State Should Live at the Lowest Common Ancestor
If two components need the same state, lift it up to their common parent.

```jsx
// Two siblings need `value`
function Parent() {
  const [value, setValue] = useState('');
  return (
    <>
      <Input value={value} onChange={setValue} />
      <Preview value={value} />
    </>
  );
}
```

### Principle: Co-locate State
If only one component needs the state, keep it there - don't lift unnecessarily.

```jsx
// ❌ Unnecessary lifting - Parent re-renders for no reason
function Parent() {
  const [open, setOpen] = useState(false);
  return <Modal open={open} onToggle={() => setOpen(o => !o)} />;
}

// ✅ Co-located
function Modal() {
  const [open, setOpen] = useState(false);
  return <>{open && <div className="modal" />}</>;
}
```

### Principle: Move State Down
If a component re-renders a big subtree unnecessarily, move the state into a smaller branch.

```jsx
// ❌ App state makes everything re-render
function App() {
  const [search, setSearch] = useState('');
  return (
    <>
      <SearchInput value={search} onChange={setSearch} />
      <ExpensiveTree />
    </>
  );
}

// ✅ Move search into SearchInput's owner
function App() {
  return (
    <>
      <SearchBox />
      <ExpensiveTree />
    </>
  );
}
```

### Real-World Deal-Breakers
- **State too high** → entire app re-renders on unrelated changes.
- **State too low** → prop drilling, duplicate sources of truth.
- **Global state for local UI** → open/closed modal in Redux is a smell.
- **Context as state bucket** → "context hell"; use it surgically.
- **Multiple sources of truth** → bugs where one UI element lags behind another.
