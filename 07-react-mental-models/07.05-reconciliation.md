## 7.5 Reconciliation

### Subtopic Tree
- Diffing algorithm
- Element type comparison
- Key-based matching
- Same type → update props
- Different type → unmount + remount
- Children reconciliation
- List reconciliation with keys
- O(n) algorithm assumptions
- Fiber tree

### The Algorithm
React compares the new element tree to the previous one and computes the minimum set of changes.

**Rules:**
1. **Different element types** → tear down the old tree, build a new one.
2. **Same element type** → keep the DOM node, update changed attributes.
3. **Lists** → use `key` to match items.

```jsx
// Render 1
<div><Counter /></div>

// Render 2
<span><Counter /></span>

// div → span: React destroys Counter, mounts a new one
// Counter state is LOST
```

```jsx
// Render 1
<div className="a"><Counter /></div>

// Render 2
<div className="b"><Counter /></div>

// Same type (div): React keeps DOM node, updates className
// Counter preserves state
```

### Reconciliation of Lists
```jsx
// Without keys - position-based matching
<ul>
  <li>A</li>
  <li>B</li>
</ul>

// Insert "X" at top - React updates A→X, B→A, mounts B
// All items re-render

// With keys - identity-based matching
<ul>
  <li key="a">A</li>
  <li key="b">B</li>
</ul>

// Insert "X" with key "x" - React mounts one new li, leaves others
```

### Type Change Example
```jsx
function Wrapper({ isLink, children }) {
  const Component = isLink ? 'a' : 'div';
  return <Component>{children}</Component>;
}

// Toggling isLink destroys and recreates the DOM node
// Any internal state below Wrapper is LOST
```

### O(n) Heuristic
React's diffing is O(n), not O(n³) - it makes two assumptions:
1. Two elements of different types produce different trees.
2. Keys identify stable children across renders.

These heuristics trade optimality for speed and work well in practice.

### Real-World Deal-Breakers
- **Conditional rendering that flips element type** → full unmount; state lost:
```jsx
// ❌ Toggling between these destroys state
{isEditing ? <input value={text} /> : <span>{text}</span>}
```
- **Wrapping in `<div>` vs `<span>`** → different tree → remount.
- **Missing keys in lists** → wrong items updated, inputs jump.
- **Random keys** → full remount every render.
- **Assuming reconciliation is stateful** → it's structural. State is tied to position in the tree.
