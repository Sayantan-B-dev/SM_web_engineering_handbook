## 7.11 Derived State

### The Rule
**If you can compute it from props/state during render, do NOT store it in state.**

```jsx
// ❌ Derived stored in state - sync bugs
function NameForm() {
  const [first, setFirst] = useState('');
  const [last, setLast] = useState('');
  const [full, setFull] = useState(''); // duplicate

  useEffect(() => {
    setFull(`${first} ${last}`);
  }, [first, last]);
}

// ✅ Compute during render
function NameForm() {
  const [first, setFirst] = useState('');
  const [last, setLast] = useState('');
  const full = `${first} ${last}`; // always in sync
}
```

### Expensive Derivation
```jsx
const sorted = useMemo(() => [...items].sort(cmp), [items]);
```

Use `useMemo` only when derivation is expensive.

### Syncing Props → State
Two valid patterns:

**1. Fully controlled - state lives in parent:**
```jsx
function Input({ value, onChange }) {
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}
```

**2. State initialized from prop, then owned by child:**
```jsx
function Input({ initialValue }) {
  const [value, setValue] = useState(initialValue);
  // Only the initial value is taken; prop changes are ignored
  return <input value={value} onChange={e => setValue(e.target.value)} />;
}
```

**3. Reset via key when prop changes:**
```jsx
<UserForm key={userId} initialName={user.name} />
```

**4. Sync state to prop with a "reset" pattern:**
```jsx
function Form({ userId, initialData }) {
  const [data, setData] = useState(initialData);
  const [prevUserId, setPrevUserId] = useState(userId);

  if (userId !== prevUserId) {
    setPrevUserId(userId);
    setData(initialData); // reset during render (allowed by React)
  }
}
```

### Real-World Deal-Breakers
- **Duplicating state for "convenience"** → sync bugs, stale UI.
- **`useEffect` to keep two states in sync** → one extra render, potential flicker.
- **Overwriting props with state on every render** → breaks controlled pattern.
- **`getDerivedStateFromProps`** → legacy; avoid in modern React.
