### The Re-Render Cascade
When a component re-renders, **all its children re-render too**, unless memoized.

```jsx
function Parent() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>{count}</button>
      <Child />         {/* re-renders even though it has no props */}
      <MemoChild />     {/* doesn't re-render (React.memo) */}
    </div>
  );
}

function Child() {
  console.log('Child re-rendered');
  return <p>Static</p>;
}

const MemoChild = React.memo(function MemoChild() {
  console.log('MemoChild re-rendered');
  return <p>Static memoized</p>;
});
```

Clicking the button:
- `Parent` re-renders.
- `Child` re-renders (parent re-rendered).
- `MemoChild` **does not** re-render (props unchanged).

### Re-render ≠ Re-mount
- **Re-render** → function called again, React reconciles output.
- **Re-mount** → component unmounts, state destroyed, effects re-run fresh.

```jsx
// Re-render: state preserved
<Child prop={x} />

// Re-mount: state reset
<Child key={x} />
```

### Re-render Scope Example
```jsx
function App() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <ExpensiveList />  {/* re-renders on count change */}
      <button onClick={() => setCount(c => c + 1)}>{count}</button>
    </div>
  );
}
```

`ExpensiveList` re-renders even though `count` is unrelated. Fix:
- Move `count` state into a separate component.
- Memoize `ExpensiveList` with `React.memo`.
- Extract state to a sibling component.

### Real-World Deal-Breakers
- **Assuming re-render is bad** → re-renders are normal; only expensive ones matter.
- **Deep component trees re-rendering from top-level state** → move state down.
- **Using `React.memo` blindly** → adds prop-comparison overhead; only use when props are stable.
- **Context value changing** → every consumer re-renders, even those that don't use the changed part.
- **Passing new object/function props** → breaks `React.memo`; use `useMemo`/`useCallback`.
