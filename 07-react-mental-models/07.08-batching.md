### What Batching Does
Multiple `setState` calls in the same tick are combined into **one render**.

```jsx
function handleClick() {
  setCount(c => c + 1);
  setFlag(f => !f);
  setName('Alice');
  // Only 1 re-render, not 3
}
```

### React 17 vs React 18
- **React 17** - batching only inside React event handlers.
- **React 18** - batching everywhere (automatic batching): promises, timeouts, native event handlers.

```jsx
// React 17: 2 renders (one for each update)
setTimeout(() => {
  setCount(c => c + 1); // render
  setFlag(f => !f);     // render
}, 0);

// React 18: 1 render (batched)
setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
}, 0);
```

### Async Batching Example
```jsx
async function handleSubmit() {
  setLoading(true);
  const data = await fetchData();
  setData(data);
  setLoading(false);
  // React 18: still batched per async block
}
```

**Note:** `await` splits the tick. Updates before the `await` batch together; updates after the `await` batch together.

### Opting Out with `flushSync`
```jsx
import { flushSync } from 'react-dom';

flushSync(() => setCount(c => c + 1)); // render now
flushSync(() => setFlag(f => !f));     // separate render
```
Rarely needed; can hurt performance.

### Real-World Deal-Breakers
- **Expecting separate renders per `setState`** → updates batch.
- **Reading state after `setState` in same tick** → still stale.
- **Using `flushSync` for "correctness"** → usually indicates a design problem.
- **Assuming React 17 batching in a React 18 app** → behavior changed subtly.
