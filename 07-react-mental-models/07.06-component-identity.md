## 7.6 Component Identity

### Subtopic Tree
- What "identity" means in React
- Type + position = identity

### The Identity Rule
React identifies a component by:
1. **Element type** (function/class reference).
2. **Position in the tree** (parent + index/path).
3. **Key** (if provided).

If any of these change, React treats it as a **new component** - unmount old, mount new.

```jsx
// Same identity - state preserved
{show ? <Counter /> : null}
{show ? <Counter /> : null}
// (as long as position and type are the same)

// Different identity - state reset
{show ? <Counter /> : <Other />}
```

### State Is Tied to Position, Not Component
```jsx
function App() {
  const [reverse, setReverse] = useState(false);

  return (
    <>
      {reverse ? <Input label="A" /> : <Input label="B" />}
      <button onClick={() => setReverse(r => !r)}>Swap</button>
    </>
  );
}
```

Both branches are `<Input>` at the same position → **same identity** → state preserved across the swap (even though `label` changed). Not always what you want.

Fix: give each branch a different key:
```jsx
{reverse ? <Input key="a" label="A" /> : <Input key="b" label="B" />}
```

### Definition Identity Matters
```jsx
// ❌ New function component every render → full remount
function Parent() {
  const Child = () => <div />;
  return <Child />;
}

// ✅ Stable definition
const Child = () => <div />;
function Parent() {
  return <Child />;
}
```

Every render of `Parent` creates a new `Child` function → React sees a different type → unmounts and remounts → loses state, breaks animations, re-runs effects.

### Real-World Deal-Breakers
- **Defining components inside components** → remount every render.
- **Changing wrapper element type** → subtree remounts.
- **Conditional rendering between two different components** → state lost.
- **Reordering siblings without keys** → state attaches to wrong items.
