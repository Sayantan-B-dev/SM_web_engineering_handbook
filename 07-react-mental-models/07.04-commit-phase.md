## 7.4 Commit Phase

### Subtopic Tree
- What happens during commit
- DOM mutations applied
- Effects run after commit
- Layout effects (`useLayoutEffect`)
- Passive effects (`useEffect`)
- Ref assignments
- Commit is synchronous
- Cannot be interrupted

### What Happens in Commit Phase
1. React applies all DOM mutations from the render phase.
2. React updates refs (`ref.current` set to DOM node).
3. React runs layout effects (`useLayoutEffect`) synchronously.
4. Browser paints.
5. React runs passive effects (`useEffect`) asynchronously after paint.

### Timeline
```
Render phase (interruptible, pure)
   ↓
Commit phase (synchronous, side effects)
   ├─ DOM mutations
   ├─ Ref assignment
   ├─ useLayoutEffect cleanup + run
   ↓
Browser paints
   ↓
useEffect cleanup + run (async)
```

### Effects Order
```jsx
function App() {
  console.log('App render');

  useLayoutEffect(() => {
    console.log('App layout effect');
  });

  useEffect(() => {
    console.log('App passive effect');
  });

  return <Child />;
}

function Child() {
  console.log('Child render');

  useLayoutEffect(() => {
    console.log('Child layout effect');
  });

  useEffect(() => {
    console.log('Child passive effect');
  });

  return <p>Hi</p>;
}

// Output:
// App render
// Child render
// Child layout effect   ← children first (bottom-up for effects)
// App layout effect
// Child passive effect
// App passive effect
```

**Rules:**
- Render phase: parent → child (top-down).
- Commit effects: child → parent (bottom-up).

### `useLayoutEffect` vs `useEffect`

| Feature | `useLayoutEffect` | `useEffect` |
|---------|-------------------|-------------|
| Timing | After DOM mutations, before paint | After paint |
| Blocking | Blocks paint | Non-blocking |
| Use for | Measuring DOM, sync visual updates | Data fetching, subscriptions |
| SSR | Warning (no DOM on server) | Safe |

### Real-World Deal-Breakers
- **`useLayoutEffect` for data fetching** → blocks paint; use `useEffect`.
- **`useLayoutEffect` in SSR** → warns because there's no DOM; guard with `typeof window !== 'undefined'` or use `useEffect`.
- **Expecting effects to run in parent-first order** → effects run child-first.
- **Assuming commit is interruptible** → it's synchronous; heavy DOM work in commit blocks paint.
