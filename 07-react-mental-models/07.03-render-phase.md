## 7.3 Render Phase

### Subtopic Tree
- What happens during render
- Pure computation
- No side effects
- Can be interrupted (concurrent mode)
- Double-invocation in StrictMode
- Order of execution (parent → child)
- Reconciliation starts here

### What Happens in Render Phase
1. React calls component functions (from top of tree downward).
2. Each returns React elements (plain objects).
3. React reconciles the new tree with the previous tree.
4. React collects a list of changes to apply.

**Render phase is where React decides *what* to change - nothing is changed yet.**

```jsx
function Parent() {
  console.log('Parent render');
  return <Child />;
}

function Child() {
  console.log('Child render');
  return <p>Hi</p>;
}

// On mount:
// 1. "Parent render"
// 2. "Child render"
```

### Rules of Render Phase
- **Pure** - same input → same output.
- **No side effects** - no DOM writes, no fetches, no subscriptions.
- **May be interrupted** - React can pause, resume, or discard renders in concurrent mode.
- **May be discarded** - a render that started may never commit.

```jsx
// ❌ Side effect in render
function Bad() {
  document.title = 'New title'; // runs during render
  return <p>Hi</p>;
}

// ✅ Side effect in useEffect (commit phase)
function Good() {
  useEffect(() => {
    document.title = 'New title';
  }, []);
  return <p>Hi</p>;
}
```

### StrictMode Double Render
In dev, React calls each component **twice** during render to surface impurity:

```
Render 1 → Render 2 (discarded) → Commit
```

This is why `console.log` fires twice in StrictMode. Production renders once.

### Real-World Deal-Breakers
- **Side effects in render** → executed multiple times, on discarded renders, or during Suspense fallback.
- **Reading mutable external values in render** → non-deterministic output.
- **Assuming render order is guaranteed** → React may batch, defer, or skip renders.
- **Reading refs during render** → unreliable in concurrent mode.
