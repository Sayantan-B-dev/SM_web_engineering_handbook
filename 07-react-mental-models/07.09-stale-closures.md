## 7.9 Stale Closures

### Subtopic Tree
- What a stale closure is
- State captured at render time
- `useEffect` with empty deps
- Callbacks capturing old props/state
- Timer/subscription bugs
- Functional updates as fix
- `useRef` as fix
- `useEffectEvent` (experimental)

### The Problem
Every render creates a new scope with its own values of state/props. A function created in render 1 captures **render 1's values**, even if called later.

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      console.log(count); // ❌ always logs 0
    }, 1000);
    return () => clearInterval(id);
  }, []); // empty deps → closure captures initial count

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

The interval callback is a closure created during the first render. It "sees" `count === 0` forever.

### Fix 1: Functional Updates
```jsx
useEffect(() => {
  const id = setInterval(() => {
    setCount(prev => prev + 1); // reads latest inside setter
  }, 1000);
  return () => clearInterval(id);
}, []);
```

### Fix 2: Include Deps
```jsx
useEffect(() => {
  const id = setInterval(() => {
    console.log(count); // fresh value
  }, 1000);
  return () => clearInterval(id);
}, [count]); // effect re-runs on every count change
```
Downside: interval resets each time.

### Fix 3: `useRef` for Latest Value
```jsx
const countRef = useRef(count);
useEffect(() => { countRef.current = count; }, [count]);

useEffect(() => {
  const id = setInterval(() => {
    console.log(countRef.current); // always latest
  }, 1000);
  return () => clearInterval(id);
}, []);
```

### Fix 4: `useEffectEvent` (Experimental)
```jsx
const onTick = useEffectEvent(() => {
  console.log(count); // always latest, not a dep
});

useEffect(() => {
  const id = setInterval(onTick, 1000);
  return () => clearInterval(id);
}, []);
```

### Real-World Deal-Breakers
- **Empty deps + reading state/props** → stale values inside closures.
- **`useCallback` with empty deps but reads props** → stale props in callback.
- **Timers/subscriptions capturing old values** → use functional updates or refs.
- **`setTimeout` capturing state** → same problem; the callback sees the state at schedule time.
- **Not trusting ESLint `exhaustive-deps`** → it flags exactly these bugs.
