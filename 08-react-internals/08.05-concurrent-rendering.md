### What Concurrent Means
Concurrent rendering means React can:
- **Start** rendering a tree,
- **Pause** it,
- **Discard** it,
- **Restart** it,
- All without committing anything to the DOM until ready.

It is **not** multithreading. It's still single-threaded; React just interleaves work.

### Start vs Commit
- **Start** - a render begins with some state.
- **Commit** - the result is applied to the DOM.

In concurrent React, renders can be thrown away before commit. Effects only run for committed renders.

### Tearing
Without external store integration, concurrent rendering could read inconsistent state across components (some read old value, some read new). React solves this with `useSyncExternalStore`.

```jsx
import { useSyncExternalStore } from 'react';

function useOnlineStatus() {
  return useSyncExternalStore(
    (cb) => {
      window.addEventListener('online', cb);
      window.addEventListener('offline', cb);
      return () => {
        window.removeEventListener('online', cb);
        window.removeEventListener('offline', cb);
      };
    },
    () => navigator.onLine,
    () => true,
  );
}
```

### Enabling Concurrent Features
React 18 requires `createRoot`:
```jsx
import { createRoot } from 'react-dom/client';
createRoot(document.getElementById('root')).render(<App />);
```
Legacy `ReactDOM.render` disables concurrent features.

### Real-World Deal-Breakers
- **Impure components** → break concurrent rendering (a discarded render may have mutated state).
- **Reading mutable external state during render** → tearing. Use `useSyncExternalStore`.
- **Assuming renders are one-per-update** → a single update may cause multiple discarded renders.
- **Legacy `ReactDOM.render`** → no concurrent features at all.
