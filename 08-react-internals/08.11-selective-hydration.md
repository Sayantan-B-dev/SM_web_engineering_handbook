## 8.11 Selective Hydration

### Subtopic Tree
- Traditional hydration bottleneck

### The Problem
Traditional hydration waits for **all** JS to load, then hydrates the entire tree top-down. If one slow component is in the way, interactions elsewhere are dead.

### Selective Hydration
React 18 hydrates Suspense boundaries independently. If a user interacts with a boundary that isn't hydrated yet, React **prioritizes** hydrating that boundary first.

```jsx
<Suspense fallback={<Skeleton />}>
  <Sidebar />   {/* may hydrate first if user clicks it */}
</Suspense>
<Suspense fallback={<Skeleton />}>
  <Feed />
</Suspense>
```

### How It Works
1. Server sends HTML with Suspense fallbacks.
2. Client JS loads.
3. React hydrates boundaries in priority order:
   - Boundaries the user is interacting with.
   - Boundaries that are already in viewport.
   - Others in the background.
4. A click inside an unhydrated boundary can bump its priority - React hydrates that boundary synchronously.

### Real-World Deal-Breakers
- **Hydrating without Suspense boundaries** → no benefit; whole tree waits.
- **Very heavy boundaries** → hydration of a single boundary can still be slow.
- **Mismatches inside a boundary** → that boundary re-renders from scratch, wasting the streaming cost.
- **Assuming interactivity in a not-yet-hydrated boundary** → clicks before hydration queue and fire after.
