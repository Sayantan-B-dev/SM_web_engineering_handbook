### What It Actually Is
The Virtual DOM is **not** a separate DOM. It's a tree of **plain JavaScript objects** describing what the UI should look like. React builds this tree, compares it to the previous one, then applies the minimum changes to the real DOM.

```jsx
// This JSX:
const element = <button className="primary">Click</button>;

// Becomes this object (simplified):
const element = {
  type: 'button',
  props: {
    className: 'primary',
    children: 'Click',
  },
};
```

That's it. Just an object. No magic, no hidden DOM.

### React Elements vs Components vs DOM Nodes

| Term | What it is |
|------|------------|
| **Element** | Plain object: `{ type, props, key, ref }`. Immutable. Cheap to create. |
| **Component** | Function or class that returns elements. |
| **Fiber node** | Internal mutable object tracking a component's state, effects, position. |
| **DOM node** | Real browser node (`HTMLButtonElement`, etc.). Expensive to mutate. |

### The Flow
```
Render → new element tree
       ↓
Reconcile against previous tree
       ↓
Collect minimal DOM mutations
       ↓
Commit → apply to real DOM
```

### "Virtual DOM Is Fast" - The Truth
Virtual DOM is **not** faster than hand-written DOM code. It's faster than **naive** DOM updates at scale, and it provides a declarative programming model.

Real deal-breaker: if you're animating 60fps with heavy updates, hand-rolled DOM code or CSS/`transform` animations will beat React. React wins on developer ergonomics + predictable updates, not raw speed.

### Cross-Platform
Because the Virtual DOM is just objects, React can target different hosts:
- `react-dom` → browser DOM
- `react-native` → native iOS/Android views
- `react-three-fiber` → WebGL
- `react-pdf` → PDF

```jsx
// Same component, different renderer
function Box() {
  return <View><Text>Hi</Text></View>; // RN
}
```

### Real-World Deal-Breakers
- **Believing Virtual DOM is "free"** → every render creates a new tree; large trees cost CPU and memory.
- **Assuming Virtual DOM always touches the DOM** → often it doesn't; that's the point.
- **Using `key` incorrectly** → destroys the diffing benefit (see 8.3).
- **Reading DOM inside render** → bypasses the model, leads to bugs.
