### Why Lanes
React 16-17 used expiration times (numbers). React 18 switched to **lanes** - a 31-bit bitmask where each bit is a priority lane. Lanes allow:
- Multiple priorities to coexist.
- Precise merging (bitwise OR).
- Cheap checks (`lanes & SyncLane`).

### Lane Constants (Simplified)
```javascript
SyncLane                = 0b0000000000000000000000000000010;
InputContinuousLane     = 0b0000000000000000000000000001000;
DefaultLane             = 0b0000000000000000000000000100000;
TransitionLane1..16     = 0b0000000000000000000000010000000; // ... up to 16
IdleLane                = 0b0010000000000000000000000000000;
```

### How Updates Get Lanes
```jsx
// Sync (discrete input)
setCount(c => c + 1); // SyncLane

// Inside startTransition
startTransition(() => setFilter(f)); // a TransitionLane

// Inside useDeferredValue
// → a TransitionLane
```

When React renders, it processes the highest-priority lanes first. Lower-priority lanes are deferred.

### Merging & Checking
```javascript
const updateLanes = SyncLane | InputContinuousLane;
if (updateLanes & SyncLane) { /* includes SyncLane */ }
```

### Real-World Deal-Breakers
- **Assuming one lane per update** → updates can merge into multiple lanes.
- **Starving low-priority lanes** → continuous high-priority input can delay transitions; React handles some starvation, but keep transitions light.
- **Direct use of lanes in app code** → this is internal; use `startTransition` / `useDeferredValue` instead.
