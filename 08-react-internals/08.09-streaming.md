### What Streaming SSR Is
Traditionally, SSR blocked until the whole page rendered on the server, then shipped one HTML blob. Streaming SSR sends HTML in chunks as soon as each piece is ready.

```jsx
// server.js
import { renderToPipeableStream } from 'react-dom/server';

const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ['/main.js'],
  onShellReady() {
    res.setHeader('Content-Type', 'text/html');
    pipe(res);
  },
  onError(err) {
    console.error(err);
  },
});
```

The **shell** (header + Suspense fallbacks) is flushed first, then chunks arrive as Suspense boundaries resolve.

### Out-of-Order Streaming
Late-arriving content (e.g., a slow recommendation widget) doesn't block the rest of the page. When ready, React injects the HTML into the right slot via hidden `<template>` + a small script.

### Suspense on the Server
```jsx
function Page() {
  return (
    <>
      <Header />
      <Suspense fallback={<Skeleton />}>
        <SlowData />
      </Suspense>
      <Footer />
    </>
  );
}
```
Server sends the shell (with skeleton) immediately; `<SlowData />` streams when ready.

### Real-World Deal-Breakers
- **Streaming without Suspense boundaries** → nothing to stream; whole page waits.
- **Fallback that's very different from content** → CLS on hydration; use skeletons that match layout.
- **Not declaring `bootstrapScripts`** → no client hydration.
- **Blocking the shell** → a slow non-suspended data fetch at the top blocks everything.
- **Streaming + old browsers** → fine; HTML chunks are still HTML.
