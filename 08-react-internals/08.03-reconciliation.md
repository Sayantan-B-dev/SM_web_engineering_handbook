## 8.3 Reconciliation

### Subtopic Tree
- Diffing algorithm
- Element type + key as identity
- Same type → update props
- Different type → unmount/remount
- Children reconciliation
- List reconciliation with keys
- Text node handling
- `shouldComponentUpdate` / `React.memo`
- `bailout` optimization
- Strict equality bailout

### The Two Heuristics
React's O(n) diffing relies on two assumptions:
1. **Different types → different trees.** React destroys the old subtree.
2. **Same type → same tree.** React keeps the node, updates props.

### Same Type Example
```jsx
// Render 1
<div className="a" title="hi" />

// Render 2
<div className="b" title="hi" />

// React updates className only; DOM node is preserved.
```

### Different Type Example
```jsx
// Render 1
<div><Counter /></div>

// Render 2
<span><Counter /></span>

// div → span: React destroys the div and Counter
// Counter state is LOST
```

### Reconciliation of Lists
```jsx
// Without keys - index-based
[A, B, C] → insert X at front → [X, A, B, C]
React matches:
  index 0: A → X (update)
  index 1: B → A (update)
  index 2: C → B (update)
  index 3: new    (mount)
// 3 updates + 1 mount

// With keys - identity-based
[A:keyA, B:keyB, C:keyC] → [X:keyX, A:keyA, B:keyB, C:keyC]
React matches:
  keyX: mount
  keyA: unchanged
  keyB: unchanged
  keyC: unchanged
// 1 mount
```

### Bailout Optimizations
React skips work when:
- Props are `Object.is`-equal to memoized props **and** the fiber has no pending updates.
- A component returns the exact same element reference.
- `React.memo` comparison returns true.

```jsx
const Child = React.memo(function Child({ name }) { ... });

// If parent re-renders but `name` is the same, React bails out.
```

### Real-World Deal-Breakers
- **Missing keys** → wrong reconciliation, inputs swap values, animations break.
- **Index keys on reorderable lists** → same problem.
- **Conditional type flips** (`<input>` vs `<span>`) → full remount, state loss.
- **`React.memo` with new inline props** → bails out never; memo useless.
- **Mutating props/state** → reconciliation compares references; mutation hides changes.
