### What Suspense Does
Suspense lets a component **suspend** rendering while waiting for something (data, code, image, stylesheet) and show a fallback in the meantime.

```jsx
<Suspense fallback={<Spinner />}>
  <Profile userId={id} />
</Suspense>
```

If `Profile` throws a Promise (or is a `lazy` component still loading), React shows `<Spinner />`.

### Two Main Uses
**1. Code splitting:**
```jsx
const Chart = React.lazy(() => import('./Chart'));

<Suspense fallback={<Spinner />}>
  <Chart />
</Suspense>
```

**2. Data fetching** (via framework integrations like React Query, Next.js Server Components, Relay):
```jsx
<Suspense fallback={<Skeleton />}>
  <UserProfile id={id} />
</Suspense>
```
`UserProfile` reads data via a Suspense-aware library; while waiting, it throws a Promise.

### Throwing a Promise (Simplified)
```jsx
function wrapPromise(promise) {
  let status = 'pending';
  let result;
  const suspender = promise.then(
    (r) => { status = 'success'; result = r; },
    (e) => { status = 'error'; result = e; },
  );

  return {
    read() {
      if (status === 'pending') throw suspender;
      if (status === 'error') throw result;
      return result;
    },
  };
}

function User({ resource }) {
  const user = resource.read(); // may throw
  return <p>{user.name}</p>;
}
```

### Nested Suspense
```jsx
<Suspense fallback={<PageSkeleton />}>
  <Suspense fallback={<SidebarSkeleton />}>
    <Sidebar />
  </Suspense>
  <Suspense fallback={<FeedSkeleton />}>
    <Feed />
  </Suspense>
</Suspense>
```
Each boundary is independent; only the innermost showing a pending tree triggers its own fallback.

### Suspense vs Error Boundaries
- **Suspense** handles "loading".
- **Error boundary** handles "failed".

```jsx
<ErrorBoundary fallback={<Error />}>
  <Suspense fallback={<Spinner />}>
    <AsyncComponent />
  </Suspense>
</ErrorBoundary>
```

### Real-World Deal-Breakers
- **Wrapping too much in one Suspense** → whole page flashes spinner instead of just a section.
- **Suspense without fallback** → error.
- **Suspense without an error boundary around it** → if the suspended component throws a real error, it propagates upward and can crash the app.
- **Assuming Suspense fetches data by itself** → it doesn't; the component must integrate with a Suspense-aware data source.
- **Suspense in legacy mode** → works only for `lazy`, not data.
