### The Concept
A transition marks updates as **non-urgent**. React keeps the old UI interactive while preparing the new one in the background.

```jsx
import { startTransition } from 'react';

function Search() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  function handleChange(e) {
    const value = e.target.value;

    // Urgent: input value must update immediately
    setQuery(value);

    // Non-urgent: heavy result computation can lag
    startTransition(() => {
      setResults(computeResults(value));
    });
  }
}
```

### `useTransition`
```jsx
const [isPending, startTransition] = useTransition();

function handleClick() {
  startTransition(() => {
    setTab('posts');
  });
}

return (
  <>
    <TabButton isActive={tab === 'posts'} onClick={handleClick}>Posts</TabButton>
    {isPending && <Spinner />}
  </>
);
```

### `useDeferredValue`
```jsx
function Search() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);

  // Render expensive results using deferredQuery
  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <Results query={deferredQuery} /> {/* lags behind, stays responsive */}
    </>
  );
}
```

### What Transitions Give You
- **Keeps input responsive** - typing never lags behind.
- **Time slicing** - background render is chunked.
- **Interruptible** - a new urgent update cancels the transition.
- **Suspense integration** - a suspended transition keeps showing the old UI instead of a fallback.

### When NOT to Use
- **Controlled inputs value itself** → the input's own `value` must be urgent.
- **Small updates** → overhead not worth it.
- **Side effects** → transitions don't run effects until commit.

### Real-World Deal-Breakers
- **Wrapping the input value in `startTransition`** → typing becomes laggy; a classic mistake.
- **Expecting `isPending` to be `true` on the first render** → it's `false` until a transition starts.
- **Transitions outside React 18** → not available (needs `createRoot`).
- **`useDeferredValue` on primitive-only state with cheap render** → no benefit.
- **Assuming all updates inside transition are low priority** → updates scheduled with `flushSync` inside a transition are still sync.
