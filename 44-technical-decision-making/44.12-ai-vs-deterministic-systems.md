### Deeper Explanation: Use AI Where Being Roughly Right Is Acceptable

A model is a probabilistic component: variable output, latency, and cost. A deterministic system is repeatable, testable, auditable, and cheap per call. The decision rule is about **tolerance for error and need for explanation**:

| Task | Prefer | Why |
|---|---|---|
| Classification, summarisation, extraction, generation | AI (with validation) | Variation is acceptable; value is high |
| Arithmetic, pricing, permissions, state transitions | Deterministic code | Must be exact and auditable |
| User intent mapping | AI proposes, code validates | Bounded vocabulary |
| Search ranking | Hybrid (retrieval + model rerank) | Determinism where it matters |
| Compliance decisions | Deterministic + human | Explainability required |

The robust architecture for most products is **deterministic orchestration with AI steps**: code owns control flow, permissions, and validation; the model does the language-shaped work inside strict schemas.

### Real-World Deal-Breakers
- **Model output used for money, quotas, or permissions.** Unbounded downside; compute and verify in code.
- **No validation boundary.** Untrusted output reaching state or the database.
- **Deterministic work sent to a model.** Slower, costlier, and less testable than a function.
- **No evaluation.** Without a labelled set, model changes are unmeasurable.
- **Ignoring cost and latency variance.** A probabilistic dependency in a strict latency budget breaks the product.
