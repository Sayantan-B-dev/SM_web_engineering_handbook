## 3.22 Event Delegation

### Subtopic Tree
- Concept: attach one listener to parent
- `event.target` and `closest()`
- Benefits: memory, dynamic elements
- Limitations
- Common patterns

### Syntax
```javascript
// ❌ Individual listeners (memory heavy, breaks for dynamic elements)
document.querySelectorAll('.btn').forEach(btn => {
  btn.addEventListener('click', handleClick);
});

// ✅ Event delegation (one listener)
document.querySelector('.container').addEventListener('click', (event) => {
  const btn = event.target.closest('.btn');
  if (!btn) return;
  handleClick(btn);
});
```

### Real-World Pattern: Dynamic Lists
```javascript
const list = document.querySelector('#todo-list');

list.addEventListener('click', (event) => {
  const deleteBtn = event.target.closest('[data-action="delete"]');
  if (deleteBtn) {
    const item = deleteBtn.closest('li');
    item.remove();
    return;
  }

  const toggleBtn = event.target.closest('[data-action="toggle"]');
  if (toggleBtn) {
    toggleBtn.closest('li').classList.toggle('done');
  }
});
```

### Real-World Tricks
- **`closest()` handles nested elements** → clicking an icon inside a button still finds the button.
- **Data attributes for action routing**:
```html
<button data-action="save">Save</button>
<button data-action="cancel">Cancel</button>
```
```javascript
container.addEventListener('click', (e) => {
  const action = e.target.closest('[data-action]')?.dataset.action;
  if (!action) return;
  actions[action]?.();
});
```

### Real-World Deal-Breakers
- **`stopPropagation` in children** → breaks delegation; avoid unless necessary.
- **Events that don't bubble** → `focus`, `blur`, `mouseenter`, `mouseleave` don't bubble. Use `focusin`/`focusout` instead.
- **`event.target` is the deepest element** → always use `closest()` to find the intended element.
- **Delegation on `document`** → can catch events you don't want; attach to the nearest common ancestor instead.
