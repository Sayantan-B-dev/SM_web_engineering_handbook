## 3.12 Callbacks

### Subtopic Tree
- Definition: function passed as argument
- Synchronous callbacks
- Asynchronous callbacks
- Error-first callbacks (Node.js convention)
- Callback hell
- Inversion of control

### Synchronous Callbacks
```javascript
[1, 2, 3].forEach(n => console.log(n)); // callback runs immediately
[1, 2, 3].map(n => n * 2);
```

### Asynchronous Callbacks
```javascript
setTimeout(() => console.log('Later'), 1000);
button.addEventListener('click', () => console.log('Clicked'));
fs.readFile('file.txt', (err, data) => { ... });
```

### Error-First Callbacks (Node.js)
```javascript
fs.readFile('data.json', (err, data) => {
  if (err) {
    console.error('Error:', err);
    return;
  }
  console.log(data);
});
```

### Callback Hell
```javascript
getUser(userId, (err, user) => {
  if (err) return handleError(err);
  getPosts(user.id, (err, posts) => {
    if (err) return handleError(err);
    getComments(posts[0].id, (err, comments) => {
      if (err) return handleError(err);
      getReplies(comments[0].id, (err, replies) => {
        if (err) return handleError(err);
        console.log(replies);
      });
    });
  });
});
```

**Problems**: Deeply nested, hard to read, error handling repeated, inversion of control (you trust the callback is called exactly once, with correct args).

### Callback vs Promise vs Async/Await
```javascript
// Callback
getUser(id, (err, user) => {
  if (err) return handleError(err);
  console.log(user);
});

// Promise
getUser(id)
  .then(user => console.log(user))
  .catch(handleError);

// Async/await
try {
  const user = await getUser(id);
  console.log(user);
} catch (err) {
  handleError(err);
}
```

### Real-World Deal-Breakers
- **Calling callback multiple times** → in Node.js, calling a callback twice causes "Callback was already called" errors. Wrap with `once()`.
- **Zalgo** → function sometimes calls callback synchronously, sometimes asynchronously — causes unpredictable ordering. Always defer with `queueMicrotask` or `setTimeout(fn, 0)`.
- **Thrown errors in async callbacks** → `setTimeout(() => { throw new Error() })` crashes the process; can't be caught by outer try/catch.
- **Callback hell** → use Promises/async-await for sequential async operations.
