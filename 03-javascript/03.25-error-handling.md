## 3.25 Error Handling

### Subtopic Tree
- `try` / `catch` / `finally`
- `throw` statement
- Error types (`Error`, `TypeError`, `ReferenceError`, `SyntaxError`, `RangeError`, `URIError`, `EvalError`)
- Custom errors (`class MyError extends Error`)
- Error properties (`message`, `name`, `stack`, `cause`)
- Async errors (`try/catch` with `await`, `.catch()`)
- Global error handling (`window.onerror`, `unhandledrejection`)
- Error boundaries (React)
- Best practices

### Syntax
```javascript
try {
  riskyOperation();
} catch (error) {
  console.error(error.message);
  console.error(error.stack);
} finally {
  cleanup(); // always runs
}
```

### Error Types

| Error | When |
|-------|------|
| `Error` | Base class |
| `TypeError` | Wrong type (e.g., `null.foo`) |
| `ReferenceError` | Undefined variable |
| `SyntaxError` | Invalid syntax (parse time) |
| `RangeError` | Number out of range (e.g., `new Array(-1)`) |
| `URIError` | Invalid URI (`decodeURIComponent('%')`) |

### Custom Errors
```javascript
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}

class NetworkError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.name = 'NetworkError';
    this.statusCode = statusCode;
  }
}

try {
  throw new ValidationError('Invalid email', 'email');
} catch (err) {
  if (err instanceof ValidationError) {
    console.log(`Field ${err.field}: ${err.message}`);
  }
}
```

### Error `cause` (ES2022)
```javascript
try {
  await fetchData();
} catch (err) {
  throw new Error('Failed to load user profile', { cause: err });
}

// Access original error
catch (err) {
  console.log(err.message);      // 'Failed to load user profile'
  console.log(err.cause);        // original fetch error
}
```

### Global Error Handling
```javascript
// Uncaught synchronous errors
window.addEventListener('error', (event) => {
  console.error('Global error:', event.error);
  // Send to error tracking service
});

// Unhandled promise rejections
window.addEventListener('unhandledrejection', (event) => {
  console.error('Unhandled rejection:', event.reason);
  event.preventDefault(); // prevent default logging
});

// Node.js
process.on('uncaughtException', (err) => { ... });
process.on('unhandledRejection', (err) => { ... });
```

### Real-World Tricks
- **Always re-throw unexpected errors**:
```javascript
try {
  await doSomething();
} catch (err) {
  if (err instanceof KnownError) {
    handleKnown(err);
  } else {
    throw err; // don't swallow unexpected errors
  }
}
```

- **Error cause chain** for debugging:
```javascript
throw new Error('Database query failed', { cause: originalError });
```

- **Never swallow errors silently**:
```javascript
// ❌ Silent failure
try { doSomething(); } catch (e) {}

// ✅ At minimum, log
try { doSomething(); } catch (e) { console.error(e); }
```

### Real-World Deal-Breakers
- **Catching and ignoring** → `catch (e) {}` hides bugs. Always log or handle.
- **Throwing strings instead of Errors** → `throw 'Something failed'` loses stack trace. Always throw `Error` instances.
- **`try/catch` around async code without `await`** → the catch won't fire for unawaited promises.
- **No global handler** → unhandled errors crash the app silently in production. Add `window.onerror` and `unhandledrejection`.
- **Error messages containing sensitive data** → don't include passwords, tokens, or PII in error messages that get logged/sent to monitoring.
