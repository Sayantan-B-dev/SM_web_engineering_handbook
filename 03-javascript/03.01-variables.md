## 3.1 Variables

### Subtopic Tree
- `var` (function-scoped, hoisted, redeclarable)
- `let` (block-scoped, TDZ, reassignable)
- `const` (block-scoped, TDZ, not reassignable — but mutable contents)
- Temporal Dead Zone (TDZ)
- Hoisting behavior
- Naming conventions
- Global object pollution

### Syntax & Comparison

| Feature | `var` | `let` | `const` |
|---------|-------|-------|---------|
| Scope | Function | Block | Block |
| Hoisted | Yes (initialized `undefined`) | Yes (TDZ) | Yes (TDZ) |
| Redeclarable | Yes | No | No |
| Reassignable | Yes | Yes | No |
| Must initialize | No | No | Yes |

```javascript
// var — function scoped, hoisted as undefined
console.log(x); // undefined (not error!)
var x = 10;

// let — block scoped, TDZ
console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 20;

// const — must initialize, can't reassign
const z = 30;
z = 40; // TypeError: Assignment to constant variable

// BUT: const object contents CAN be mutated
const user = { name: 'Alice' };
user.name = 'Bob';        // ✅ allowed
user = {};                 // ❌ TypeError

// Block scoping
{
  var a = 1;
  let b = 2;
  const c = 3;
}
console.log(a); // 1
console.log(b); // ReferenceError
```

### Temporal Dead Zone (TDZ)
The TDZ is the period between entering a scope and the variable's declaration where accessing the variable throws a `ReferenceError`.

```javascript
{
  // TDZ starts here for `name`
  console.log(name); // ReferenceError
  let name = 'Alice'; // TDZ ends
  console.log(name);  // 'Alice'
}
```

### Real-World Tricks
- **Default to `const`** → prevents accidental reassignment, clearer intent.
- **Use `let` only when reassignment is needed** (loops, counters).
- **Never use `var`** in modern code → function scoping causes bugs in loops and blocks.
- **`const` for objects/arrays** → signals "binding won't change" even if contents do.
- **Freeze for true immutability**: `Object.freeze(obj)` prevents property changes.

### Real-World Deal-Breakers
- **`var` in loops with closures** → classic bug:
```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3 (not 0, 1, 2)
}
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2 ✅
}
```
- **Redeclaring with `var`** → silently overwrites previous value; no error.
- **Global pollution** → undeclared variables become global (`x = 10` without `let`/`const`). Always use `'use strict'` or ES modules (strict by default).
- **`const` doesn't make objects immutable** → `const arr = []; arr.push(1)` works. Use `Object.freeze()` for shallow immutability.
