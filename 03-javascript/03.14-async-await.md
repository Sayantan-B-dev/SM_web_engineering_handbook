## 3.14 Async/Await

### Subtopic Tree
- `async` function always returns a Promise
- `await` pauses execution
- Error handling with `try/catch`
- Sequential vs parallel execution
- `await` in loops
- Top-level await (ESM)
- Async iteration (`for await...of`)
- Common pitfalls

### Syntax
```javascript
async function fetchUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const user = await res.json();
    return user;
  } catch (err) {
    console.error('Failed to fetch user:', err);
    throw err; // re-throw if caller should handle
  }
}

// Usage
const user = await fetchUser(1);
```

### Sequential vs Parallel
```javascript
// ❌ Sequential — 3 seconds total
const user = await fetchUser(1);     // 1s
const posts = await fetchPosts(1);   // 1s
const comments = await fetchComments(1); // 1s

// ✅ Parallel — 1 second total
const [user, posts, comments] = await Promise.all([
  fetchUser(1),
  fetchPosts(1),
  fetchComments(1),
]);
```

### `await` in Loops
```javascript
// ❌ Sequential — slow
for (const id of ids) {
  const user = await fetchUser(id); // waits for each
  users.push(user);
}

// ✅ Parallel — fast
const users = await Promise.all(ids.map(id => fetchUser(id)));

// ✅ Controlled concurrency (batch)
async function batchFetch(ids, batchSize = 5) {
  const results = [];
  for (let i = 0; i < ids.length; i += batchSize) {
    const batch = ids.slice(i, i + batchSize);
    const batchResults = await Promise.all(batch.map(fetchUser));
    results.push(...batchResults);
  }
  return results;
}
```

### `for await...of` (Async Iteration)
```javascript
async function* fetchPages(url) {
  let nextUrl = url;
  while (nextUrl) {
    const res = await fetch(nextUrl);
    const data = await res.json();
    yield data.items;
    nextUrl = data.next;
  }
}

for await (const items of fetchPages('/api/items')) {
  console.log(items);
}
```

### Real-World Tricks
- **`await` with non-Promise values** → `await 42` returns `42` immediately. Useful for consistent APIs.
- **Parallel with error isolation**:
```javascript
const results = await Promise.allSettled(tasks);
const successes = results.filter(r => r.status === 'fulfilled').map(r => r.value);
const failures = results.filter(r => r.status === 'rejected').map(r => r.reason);
```
- **AbortController with async/await**:
```javascript
async function fetchWithCancel(url, signal) {
  const res = await fetch(url, { signal });
  return res.json();
}
```

### Real-World Deal-Breakers
- **`await` in a loop** → sequential execution; use `Promise.all` for independent operations.
- **No `try/catch`** → unhandled rejection crashes the process.
- **`async` function in `forEach`** → `await` inside `forEach` doesn't pause the outer function:
```javascript
// ❌ forEach doesn't await
ids.forEach(async (id) => {
  await fetchUser(id); // runs in parallel, but forEach returns immediately
});

// ✅ Use for...of or Promise.all
for (const id of ids) {
  await fetchUser(id);
}
```
- **Floating promises** → calling an async function without `await` or `.catch()`:
```javascript
// ❌ Error silently swallowed
async function init() {
  doSomethingAsync(); // no await, no catch
}

// ✅
async function init() {
  await doSomethingAsync();
}
```
- **`async` function returning `await promise` unnecessarily** → `return await promise` adds an extra microtask tick. Only needed inside `try/catch`.
