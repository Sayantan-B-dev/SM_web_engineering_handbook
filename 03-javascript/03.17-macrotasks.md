## 3.17 Macrotasks

### Subtopic Tree
- What creates macrotasks: `setTimeout`, `setInterval`, `setImmediate` (Node), I/O, UI events, `MessageChannel`
- One macrotask per event loop iteration
- Minimum delays
- Timer throttling in background tabs
- `setTimeout` vs `setInterval` drift

### Examples
```javascript
setTimeout(() => console.log('macrotask 1'), 0);
setTimeout(() => console.log('macrotask 2'), 0);

Promise.resolve().then(() => console.log('microtask'));

// Output: microtask, macrotask 1, macrotask 2
```

### Timer Throttling
Browsers throttle `setTimeout` and `setInterval` in background tabs to save battery:
- Active tab: ~4ms minimum
- Background tab: ~1000ms minimum (or more)
- Nested timers > 5 levels: ~4ms minimum

### `setInterval` Drift
```javascript
// ❌ setInterval drifts if callback takes longer than interval
setInterval(() => {
  // If this takes 200ms and interval is 100ms,
  // callbacks pile up or skip
}, 100);

// ✅ Self-correcting with setTimeout
function repeat(fn, interval) {
  let start = Date.now();
  function loop() {
    fn();
    const elapsed = Date.now() - start;
    const delay = Math.max(0, interval - elapsed);
    start += interval;
    setTimeout(loop, delay);
  }
  setTimeout(loop, interval);
}
```

### Real-World Deal-Breakers
- **`setTimeout(fn, 0)` is not 0ms** → minimum ~4ms after nesting; use `queueMicrotask` for true immediate deferral.
- **`setInterval` with async callback** → overlapping executions if callback is async. Use recursive `setTimeout`.
- **Background tab throttling** → timers may not fire on time; use Web Workers for critical timing.
