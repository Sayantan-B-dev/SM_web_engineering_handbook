## 3.19 AbortController

### Subtopic Tree
- Creating a controller
- `signal` property
- `abort()` method
- `AbortError`
- Aborting fetch
- Aborting multiple operations
- `AbortSignal.timeout()`
- `AbortSignal.any()`
- Cleanup patterns

### Syntax
```javascript
const controller = new AbortController();
const { signal } = controller;

fetch('/api/data', { signal })
  .then(res => res.json())
  .catch(err => {
    if (err.name === 'AbortError') {
      console.log('Request aborted');
    }
  });

// Cancel after 3 seconds
setTimeout(() => controller.abort(), 3000);
```

### `AbortSignal.timeout()` (Modern)
```javascript
// Auto-abort after 5 seconds
const res = await fetch('/api/data', {
  signal: AbortSignal.timeout(5000),
});
```

### `AbortSignal.any()` (Modern)
```javascript
// Combine multiple signals — aborts when ANY aborts
const userController = new AbortController();
const timeoutSignal = AbortSignal.timeout(5000);
const combined = AbortSignal.any([userController.signal, timeoutSignal]);

fetch('/api/data', { signal: combined });
```

### Real-World Patterns
- **Cancel on component unmount (React)**:
```javascript
useEffect(() => {
  const controller = new AbortController();

  fetch('/api/data', { signal: controller.signal })
    .then(res => res.json())
    .then(setData)
    .catch(err => {
      if (err.name !== 'AbortError') setError(err);
    });

  return () => controller.abort();
}, []);
```

- **Cancel previous request on new input (search)**:
```javascript
let controller;

async function search(query) {
  controller?.abort(); // cancel previous
  controller = new AbortController();

  try {
    const res = await fetch(`/api/search?q=${query}`, {
      signal: controller.signal,
    });
    const results = await res.json();
    renderResults(results);
  } catch (err) {
    if (err.name !== 'AbortError') throw err;
  }
}
```

### Real-World Deal-Breakers
- **Reusing an aborted controller** → once aborted, a signal stays aborted forever. Create a new controller per request.
- **Not handling `AbortError`** → the error propagates as a rejection; filter it out if you don't want to show it.
- **Aborting doesn't cancel server-side work** → the HTTP request may still complete on the server; abort only stops the client from waiting.
- **Memory leaks without abort** → unmounted components updating state after fetch resolves → React warning "Can't perform a React state update on an unmounted component".
