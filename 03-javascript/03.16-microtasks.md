## 3.16 Microtasks

### Subtopic Tree
- What creates microtasks: `.then()`, `.catch()`, `.finally()`, `queueMicrotask()`, `MutationObserver`, `await`
- Microtask queue draining
- Priority over macrotasks
- Starvation risk
- Ordering guarantees

### Examples
```javascript
// Promise callbacks are microtasks
Promise.resolve().then(() => console.log('microtask 1'));
Promise.resolve().then(() => console.log('microtask 2'));

// queueMicrotask
queueMicrotask(() => console.log('microtask 3'));

console.log('sync');

// Output: sync, microtask 1, microtask 2, microtask 3
```

### `await` Creates Microtasks
```javascript
async function foo() {
  console.log('foo start');
  await null; // yields to microtask queue
  console.log('foo end');
}

console.log('script start');
foo();
console.log('script end');

// Output:
// script start
// foo start
// script end
// foo end
```

### Microtask Ordering
```javascript
Promise.resolve()
  .then(() => console.log('A'))
  .then(() => console.log('B'))
  .then(() => console.log('C'));

Promise.resolve()
  .then(() => console.log('D'))
  .then(() => console.log('E'));

// Output: A, D, B, E, C
// Each .then() is a separate microtask; they interleave
```

### Real-World Deal-Breakers
- **Microtask starvation** → infinite `.then()` chain blocks rendering and timers.
- **Assuming synchronous resolution** → `.then()` callbacks never run before the current synchronous code finishes.
- **MutationObserver timing** → runs as a microtask before rendering, useful for batching DOM changes.
