## 26.3 IndexedDB

### Subtopic Tree
- Asynchronous, transactional, object-oriented database
- Object stores (like tables)
- Indexes (for fast queries)
- Transactions (readonly, readwrite)
- Cursors (iterate over records)
- Versioning and migrations
- `idb` and `Dexie` wrappers
- Storage limits (typically 50% of free disk space)
- OPFS (Origin Private File System) as an alternative

### Basic IndexedDB (No Wrapper)
```javascript
const request = indexedDB.open('app-db', 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;

  const store = db.createObjectStore('users', { keyPath: 'id' });
  store.createIndex('email', 'email', { unique: true });
  store.createIndex('name', 'name', { unique: false });
};

request.onsuccess = (event) => {
  const db = event.target.result;

  // Write
  const tx = db.transaction('users', 'readwrite');
  tx.objectStore('users').put({ id: 1, name: 'Alice', email: 'alice@example.com' });
  tx.oncomplete = () => console.log('Saved');

  // Read
  const readTx = db.transaction('users', 'readonly');
  const getReq = readTx.objectStore('users').get(1);
  getReq.onsuccess = () => console.log(getReq.result);
};
```

### Dexie (Promise-Based Wrapper)
```javascript
import Dexie from 'dexie';

const db = new Dexie('app-db');
db.version(1).stores({
  users: 'id, name, email',
  posts: 'id, userId, createdAt',
});

// Write
await db.users.put({ id: 1, name: 'Alice', email: 'alice@example.com' });

// Read
const user = await db.users.get(1);
const alice = await db.users.where('name').equals('Alice').toArray();

// Transaction
await db.transaction('rw', db.users, db.posts, async () => {
  await db.users.put({ id: 1, name: 'Alice' });
  await db.posts.put({ id: 1, userId: 1, title: 'Hello' });
});

// Live query (React)
import { useLiveQuery } from 'dexie-react-hooks';

function UserList() {
  const users = useLiveQuery(() => db.users.toArray());
  return <ul>{users?.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

### Storage Limits
```javascript
// Check storage usage and quota
const estimate = await navigator.storage.estimate();
console.log(`Used: ${estimate.usage / 1024 / 1024} MB`);
console.log(`Quota: ${estimate.quota / 1024 / 1024} MB`);

// Request persistent storage (prevents eviction)
const persisted = await navigator.storage.persist();
console.log('Persisted:', persisted);
```

### OPFS (Origin Private File System)
OPFS is a high-performance file system API designed for storing file-based content. It's faster than IndexedDB for large binary data.

```javascript
const root = await navigator.storage.getDirectory();
const fileHandle = await root.getFileHandle('data.bin', { create: true });
const writable = await fileHandle.createWritable();
await writable.write(new Uint8Array([1, 2, 3]));
await writable.close();
```

### Deeper Explanation: The Offline Store Needs An Access-Pattern Schema

IndexedDB is an object store with indexes, so performance and ergonomics come from modelling stores by *access pattern*, not by entity. A workable offline schema:

| Store | Key | Indexes | Purpose |
|---|---|---|---|
| `entities` | `id` | `by_type`, `by_updatedAt`, `by_parent` | Read model |
| `outbox` | auto | `by_createdAt` | Ordered write queue |
| `meta` | `key` | â€“ | Cursors, schema version, last sync |
| `blobs` | `id` | `by_entity` | Attachments, images |

Also plan for the parts people forget: schema **migrations** (forward-only, in `onupgradeneeded`), **storage persistence** (`navigator.storage.persist()`), **quota checks** (`storage.estimate()`), and a **rebuild path** (refetch from the server when the local DB is evicted or corrupted).

### Extended Example: Migration Plus A Typed Repository

```ts
const MIGRATIONS: ((db: IDBDatabase, tx: IDBTransaction) => void)[] = [
  // v1
  (db) => {
    const notes = db.createObjectStore('notes', { keyPath: 'id' });
    notes.createIndex('by_updated', 'updatedAt');
  },
  // v2 â€” add an outbox and a tag index without touching existing data
  (db, tx) => {
    db.createObjectStore('outbox', { keyPath: 'id', autoIncrement: true }).createIndex('by_created', 'createdAt');
    tx.objectStore('notes').createIndex('by_tag', 'tag');
  },
];

export function openDb(version = MIGRATIONS.length): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open('app', version);
    req.onupgradeneeded = (e) => {
      const db = req.result;
      const tx = req.transaction!;
      for (let v = e.oldVersion; v < version; v++) MIGRATIONS[v](db, tx);
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
    req.onblocked = () => console.warn('Another tab is holding an old DB version open');
  });
}
```

### Additional Pitfalls
- **Awaiting inside a transaction.** It auto-commits and later operations throw; keep transactions synchronous.
- **`onblocked` unhandled.** An old tab keeps the upgrade from completing and the app hangs on load.
- **No quota handling.** `QuotaExceededError` must trigger a user-visible path (clear cache, export, or refuse the write).
- **Storing blobs inelegantly.** Large binaries in one store slow down list reads; separate `blobs` store.
- **Assuming the DB survives.** Eviction and "clear site data" are normal events; the app must rebuild from the server.

### Real-World Deal-Breakers
- **Using `localStorage` for offline data** → synchronous, 5MB limit, blocks the main thread. Use IndexedDB.
- **No storage quota monitoring** → storage can be evicted under pressure. Request `navigator.storage.persist()` for critical data.
- **No version migration** → schema changes break old data. IndexedDB's `onupgradeneeded` handles migrations.
- **Storing large blobs in IndexedDB** → IndexedDB is slower for large binary data. Use OPFS instead.
- **Safari's 7-day eviction policy** → Safari may evict IndexedDB after 7 days of inactivity unless the site is added to the home screen. Design for re-sync.
