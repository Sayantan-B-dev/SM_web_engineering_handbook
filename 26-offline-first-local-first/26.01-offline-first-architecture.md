## 26.1 Offline-First Architecture

### Subtopic Tree
- Service Worker as the network proxy
- Cache Storage API for assets
- IndexedDB for structured data
- Request queue for mutations
- Background Sync API
- Optimistic UI updates
- Conflict resolution strategies
- Connectivity detection (`navigator.onLine`)
- Storage quota and eviction

### The Three Layers of Offline-First

| Layer | Technology | What it caches |
|-------|-----------|---------------|
| **Assets** | Service Worker + Cache Storage | HTML, JS, CSS, images, fonts |
| **Data** | IndexedDB (or a wrapper like Dexie) | API responses, user data |
| **Mutations** | IndexedDB + Background Sync | Queued POST/PUT/DELETE requests |

### Service Worker Caching Strategies

| Strategy | Behavior | Best for |
|----------|----------|----------|
| **Cache-first** | Serve from cache; fall back to network | Static assets (immutable, hashed) |
| **Network-first** | Try network; fall back to cache | API data that changes often |
| **Stale-while-revalidate** | Serve cache immediately; fetch update in background | API data that's OK slightly stale |
| **Cache-only** | Only serve from cache | Fully offline assets |
| **Network-only** | Always go to network | Non-cacheable requests |

### Service Worker with Stale-While-Revalidate
```javascript
// sw.js
const CACHE = 'app-v1';

self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE).then((cache) => cache.addAll([
      '/', '/index.html', '/app.js', '/styles.css',
    ]))
  );
  self.skipWaiting();
});

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter((k) => k !== CACHE).map((k) => caches.delete(k)))
    )
  );
  self.clients.claim();
});

self.addEventListener('fetch', (event) => {
  const { request } = event;
  if (request.method !== 'GET') return;

  event.respondWith(
    caches.open(CACHE).then(async (cache) => {
      const cached = await cache.match(request);

      const networkPromise = fetch(request)
        .then((response) => {
          if (response.ok) cache.put(request, response.clone());
          return response;
        })
        .catch(() => cached); // network failed → return cached

      // Stale-while-revalidate: return cache immediately, update in background
      return cached || networkPromise;
    })
  );
});
```

### IndexedDB for Data Caching
```javascript
// Use Dexie for a promise-based IndexedDB wrapper
import Dexie from 'dexie';

const db = new Dexie('app-db');
db.version(1).stores({
  users: 'id, name, email',
  posts: 'id, userId, createdAt',
  mutations: '++id, type, endpoint, method, body, createdAt',
});

// Cache API response
async function cacheUsers(users) {
  await db.users.bulkPut(users);
}

// Read from cache when offline
async function getUsers() {
  if (navigator.onLine) {
    try {
      const res = await fetch('/api/users');
      const users = await res.json();
      await cacheUsers(users);
      return users;
    } catch (err) {
      // Network failed → fall back to cache
    }
  }
  return db.users.toArray();
}
```

### Request Queue for Mutations
```javascript
// Queue a mutation when offline
async function queueMutation(mutation) {
  await db.mutations.add({
    ...mutation,
    createdAt: Date.now(),
  });
}

// Replay queued mutations when online
async function replayMutations() {
  const mutations = await db.mutations.orderBy('createdAt').toArray();

  for (const mutation of mutations) {
    try {
      const res = await fetch(mutation.endpoint, {
        method: mutation.method,
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(mutation.body),
      });

      if (res.ok) {
        await db.mutations.delete(mutation.id);
      } else if (res.status >= 400 && res.status < 500) {
        // Client error - don't retry, log and remove
        console.error('Mutation failed permanently:', mutation, await res.text());
        await db.mutations.delete(mutation.id);
      }
      // 5xx errors: leave in queue for retry
    } catch (err) {
      // Network error - stop replaying, try again later
      break;
    }
  }
}

// Listen for online/offline events
window.addEventListener('online', replayMutations);
```

### Background Sync API
```javascript
// Register a background sync when queuing a mutation
async function queueMutation(mutation) {
  await db.mutations.add(mutation);

  if ('serviceWorker' in navigator && 'SyncManager' in window) {
    const registration = await navigator.serviceWorker.ready;
    await registration.sync.register('sync-mutations');
  }
}

// In the service worker
self.addEventListener('sync', (event) => {
  if (event.tag === 'sync-mutations') {
    event.waitUntil(replayMutationsFromSW());
  }
});
```
**Background Sync** lets the browser retry the sync even if the user closes the tab. It's supported in Chrome and Edge, but **not in Safari or Firefox**.

### Connectivity Detection
```javascript
// ❌ navigator.onLine is unreliable - it only tells you if there's a network interface
// It doesn't tell you if the internet is reachable

// ✅ Use a combination of navigator.onLine + a reachability check
async function isOnline() {
  if (!navigator.onLine) return false;
  try {
    const res = await fetch('/api/health', { method: 'HEAD', cache: 'no-store' });
    return res.ok;
  } catch {
    return false;
  }
}
```

### Deeper Explanation: The Four Subsystems

An offline-capable app is four subsystems that must be designed together:

1. **App shell** â€” cached HTML/JS/CSS so the app boots with no network (service worker precache plus hashed assets).
2. **Data cache** â€” read model stored locally (IndexedDB) with freshness metadata: `updatedAt`, `staleAfter`, `source`.
3. **Write queue / outbox** â€” every mutation is written locally first, then replayed in order with idempotency keys.
4. **Sync engine** â€” connectivity detection, replay, retry with backoff, conflict handling, and progress/error surfacing to the UI.

The key architectural decision is where mutations are created: **local-first writes with server confirmation** (optimistic) rather than request-then-update. That inverts the data flow and is what makes the app feel instant and remain usable offline.

### Extended Example: Outbox With Idempotent Replay

```ts
type Mutation = {
  id: string;                        // client-generated â†’ idempotency key
  endpoint: string;
  method: 'POST' | 'PATCH' | 'DELETE';
  body: unknown;
  createdAt: number;
  attempts: number;
};

export async function mutate(m: Omit<Mutation, 'id' | 'createdAt' | 'attempts'>) {
  const record: Mutation = { ...m, id: crypto.randomUUID(), createdAt: Date.now(), attempts: 0 };
  await db.put('outbox', record);            // 1. durable local write
  await db.put('shadow', { ...record });     // 2. optimistic local view (if needed)
  flush();                                   // 3. try immediately, never block the UI
}

export async function flush() {
  if (!navigator.onLine) return;
  for (const record of await db.getAllFromIndex('outbox', 'by_createdAt')) {
    try {
      await fetch(record.endpoint, {
        method: record.method,
        headers: { 'content-type': 'application/json', 'idempotency-key': record.id },
        body: JSON.stringify(record.body),
      });
      await db.delete('outbox', record.id);   // ack â†’ remove (server dedupes on the key)
    } catch (err) {
      await db.put('outbox', { ...record, attempts: record.attempts + 1 });
      if (record.attempts > 5) notify('Some changes could not be saved yet');
      break;                                  // preserve order; retry later
    }
  }
}

addEventListener('online', () => void flush());
```

### Additional Pitfalls
- **Request-first writes.** The app breaks offline and loses the user's intent if the tab closes mid-request.
- **No idempotency key.** Retries create duplicates; every mutation must be deduplicable server-side.
- **Ignoring queue order.** Replaying out of order changes meaning (create before update); flush sequentially.
- **Silent failures.** Users must see pending, failed, and retrying states, with a manual retry.
- **Cache and outbox that disagree.** The UI should render the optimistic view plus a "pending" marker, not two versions of the truth.

### Real-World Deal-Breakers
- **Relying only on `navigator.onLine`** → it returns `true` even when connected to a captive portal or a network with no internet. Always pair with a reachability check.
- **No mutation queue** → offline mutations are lost. Always queue and replay.
- **No cache versioning** → old cached assets are served forever. Use versioned cache names and delete old caches on activate.
- **Cache-first for API data** → stale data is served indefinitely. Use network-first or stale-while-revalidate.
- **No quota monitoring** → `navigator.storage.estimate()` tells you how much space is used. Without it, storage can be evicted without warning.
- **Background Sync not supported in Safari/Firefox** → the user must have the tab open for sync to happen. Provide a manual "Sync now" button as a fallback.
