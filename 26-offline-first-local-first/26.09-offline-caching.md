### Caching Strategy Per Resource Type

| Resource | Strategy | Cache duration |
|----------|----------|---------------|
| HTML | Network-first | Short (must-revalidate) |
| JS/CSS (hashed) | Cache-first | Immutable (1 year) |
| Images | Cache-first | Long (30 days) |
| API data | Stale-while-revalidate | Depends on data |
| Fonts | Cache-first | Immutable |

### Cache Versioning
```javascript
const CACHE = 'app-v2'; // bump version on every deploy

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(
        keys.filter((k) => k !== CACHE).map((k) => caches.delete(k))
      )
    )
  );
});
```

### Cache Eviction (LRU)
```javascript
// Cache Storage API doesn't have built-in eviction
// Implement LRU by tracking access times

async function evictOldest(cacheName, maxEntries) {
  const cache = await caches.open(cacheName);
  const keys = await cache.keys();
  if (keys.length <= maxEntries) return;

  // Delete oldest entries (first in, first out)
  const toDelete = keys.slice(0, keys.length - maxEntries);
  await Promise.all(toDelete.map((k) => cache.delete(k)));
}
```

### Deeper Explanation: Cache Strategy Per Resource Class

Offline caching works when each class of resource has a named strategy and a freshness rule:

| Resource class | Strategy | Freshness |
|---|---|---|
| App shell, hashed assets | Cache-first, versioned precache | Immutable |
| HTML entry points | Network-first, cache fallback | Always revalidate |
| API reads (public, list) | Stale-while-revalidate | TTL 60 s - 24 h |
| API reads (user data) | Network-only + IndexedDB mirror | Per-record `updatedAt` |
| Mutations | Outbox, never cached as responses | Replayed on connect |
| Images/media | Cache-first with size budget | LRU eviction |

The discipline is to write the table down and enforce it in one place (the service worker plus a data layer), instead of letting each feature invent its own caching. Add a **size budget and eviction policy** â€” an unbounded image cache is how an app gets evicted wholesale by the browser.

### Additional Pitfalls
- **Caching error responses.** A cached 500 or an offline page becomes sticky; filter on `res.ok` and status class.
- **Caching authenticated data in `caches`.** Shared across tabs and sessions on the same profile.
- **No eviction policy.** LRU with a byte budget beats "cache everything and hope".
- **Cache and IndexedDB disagreeing.** One source of truth per resource class, with the other derived.
- **Testing only the happy offline path.** Flaky connectivity (slow, failing intermittently) is the realistic case; simulate it in tests.

### Real-World Deal-Breakers
- **No cache versioning** → old assets served forever. Bump the cache name on every deploy.
- **Cache-first for API data** → stale data served indefinitely. Use network-first or stale-while-revalidate.
- **No cache eviction** → storage fills up and the browser evicts everything. Implement LRU or size limits.
- **Caching too much** → storage bloat. Cache selectively.
- **No offline fallback** → when offline and a page isn't cached, the user sees the browser's error page.
