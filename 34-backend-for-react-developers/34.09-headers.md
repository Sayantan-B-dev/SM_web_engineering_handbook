## 34.9 Headers

### Subtopic Tree
- Request headers (Authorization, Content-Type, Accept, User-Agent)
- Response headers (Content-Type, Cache-Control, ETag, Set-Cookie)
- Security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options)
- CORS headers (Access-Control-Allow-Origin, Allow-Methods, Allow-Headers, Allow-Credentials)
- Custom headers (X-Request-ID, X-CSRF-Token)
- Fetch Metadata headers (Sec-Fetch-Site, Sec-Fetch-Mode, Sec-Fetch-Dest)

### Essential Security Headers
```javascript
app.use((req, res, next) => {
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.setHeader('X-Frame-Options', 'DENY');
  res.setHeader('Strict-Transport-Security', 'max-age=63072000; includeSubDomains; preload');
  res.setHeader('Content-Security-Policy', "default-src 'self'");
  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');
  next();
});
```

---

### Deeper Explanation: Headers Are The Policy Layer

Request and response headers carry the policies that make an API safe and operable: caching, security, correlation, content negotiation, and rate-limit signalling. Treat them as configuration with semantics, not decoration.

The set worth standardising across every service: `Cache-Control` (per route class), `ETag`/`Last-Modified` for conditional reads, `Content-Security-Policy`/`Strict-Transport-Security`/`X-Content-Type-Options`/`Referrer-Policy` for browsers, `Access-Control-*` deliberately per origin, `X-Request-Id` plus trace context for correlation, `RateLimit-*` so clients can back off, and `Retry-After` on 429/503. On requests, validate `Origin`/`Referer` for CSRF-sensitive operations and honour `Accept`/`Accept-Encoding` correctly.

### Additional Pitfalls
- **`Access-Control-Allow-Origin: *` with credentials.** Browsers reject it, and echoing the origin without validation is worse.
- **No correlation ids.** Logs from client and server cannot be joined during an incident.
- **Missing `Retry-After`.** Clients hammer a rate-limited endpoint; backoff needs the hint.
- **Hop-by-hop headers forwarded blindly.** `Connection`, `Transfer-Encoding`, and `Upgrade` must not be copied.
- **Security headers set only in the app.** They disappear on error pages and static routes; set them at the edge.

### Real-World Deal-Breakers
- **No CSP** → XSS vulnerability. Add `Content-Security-Policy: default-src 'self'`.
- **No HSTS** → MITM downgrade possible. Add `Strict-Transport-Security`.
- **No `X-Content-Type-Options: nosniff`** → MIME sniffing attacks.
