## 34.3 Fastify

### Subtopic Tree
- High-performance framework (2-3× faster than Express)
- JSON Schema validation built-in (Ajv)
- Schema-based serialization (`fast-json-stringify`)

- TypeScript-first design
- When to use: high-throughput APIs, schema-first teams, new greenfield projects

### What Fastify Is
Fastify is a **high-performance Node.js framework** that operates directly on Node.js internals with `fast-json-stringify`. It consistently outperforms Express with **2-3× higher throughput** - 45,000-50,000 RPS vs Express's 10,000-20,000 RPS. It ships **JSON Schema validation and a smaller default dependency tree**.

```javascript
import Fastify from 'fastify';

const app = Fastify({ logger: true });

// Schema validation is built-in
app.post('/api/users', {
  schema: {
    body: {
      type: 'object',
      required: ['email', 'name'],
      properties: {
        email: { type: 'string', format: 'email' },
        name: { type: 'string', minLength: 1, maxLength: 100 },
      },
      additionalProperties: false,
    },
    response: {
      201: {
        type: 'object',
        properties: {
          id: { type: 'string' },
          email: { type: 'string' },
          name: { type: 'string' },
        },
      },
    },
  },
}, async (request, reply) => {
  const user = await db.user.create({ data: request.body });
  return reply.code(201).send(user);
});

// Malformed payloads rejected with 400 BEFORE the handler runs
app.listen({ port: 3000 });
```

### Fastify's Schema Advantage
Fastify **requires route schemas** and validates every incoming request against them via `ajv` at the framework level, rejecting malformed payloads with a **400 before any application code executes**. This closes an entire class of input-validation bugs.

---

### Deeper Explanation: Schema-First By Construction

Fastify's central idea is that a **route schema is the source of truth**: it validates input, serialises output, and generates documentation. That removes a whole class of bugs (unvalidated bodies, over-serialised responses leaking fields) and makes the framework's performance claims meaningful, since JSON serialisation is compiled from the schema.

Practical structure: encapsulate by plugin rather than by global mutation (plugins get their own scope, which avoids the invisible coupling that accumulates in Express), register hooks for auth and logging, and use the built-in logger (`pino`) instead of `console`. Decorators (`fastify.decorate`) are the idiomatic way to attach services, and `fastify-plugin` opts out of encapsulation deliberately when you need to share.

### Additional Pitfalls
- **Schemas on inputs but not outputs.** Output schemas prevent accidental field leaks (passwords, internal ids).
- **Global mutation via plugins without `fastify-plugin`.** Encapsulation surprises; either scope deliberately or opt out explicitly.
- **Throwing raw objects.** Use `http-errors`-style errors with status codes so the error handler maps them correctly.
- **Ignoring the built-in request id.** Correlating logs with the client's error report is nearly free if you keep it.

### Real-World Deal-Breakers
- **No schema** → Fastify's performance advantage comes from schema-driven serialization. Without schemas, you lose the speed.
- **Plugin encapsulation** → Fastify plugins are encapsulated by default. Use `fastify-plugin` to break encapsulation when needed.
- **Smaller ecosystem** → Express has more middleware; Fastify has a growing but smaller set.
