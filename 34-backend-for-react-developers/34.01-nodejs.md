### What Node.js Is
Node.js is a **JavaScript runtime built on Chrome's V8 engine**. It uses an **event-driven, non-blocking I/O model** that makes it efficient for I/O-heavy workloads (APIs, real-time apps). It is single-threaded for JavaScript execution but uses a thread pool for file system, DNS, and crypto operations.

```javascript
// Node.js HTTP server (no framework)
import { createServer } from 'node:http';

const server = createServer((req, res) => {
  if (req.url === '/api/health') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ status: 'ok' }));
  } else {
    res.writeHead(404);
    res.end();
  }
});

server.listen(3000, () => console.log('Server on http://localhost:3000'));
```

### Deeper Explanation: One Event Loop, Consequences Everywhere

Node is a single-threaded event loop with async I/O, and every backend practice follows from it: never block the loop, always let I/O be awaited, offload CPU work, and treat unhandled rejections as fatal.

| Property | Consequence |
|---|---|
| Single-threaded JS | One synchronous 200 ms task stalls every request |
| Async I/O | Concurrency comes from awaiting, not threads |
| No isolation by default | A thrown error can crash the process; use process managers |
| Worker threads / child processes | CPU-heavy work (image, crypto, ML) needs them |

The modern toolchain is also worth knowing: ESM-first (`"type": "module"`), top-level await in modules, `fetch` built in, `node --watch` for dev, `node:test` for unit tests, and `AbortSignal` for timeouts. Keep the runtime version pinned and typed via `engines` and CI.

### Additional Pitfalls
- **`JSON.parse` on a 50 MB body.** Body size limits are a security and stability requirement.
- **Synchronous filesystem or crypto in a request path.** Use the async APIs or a worker.
- **Unhandled promise rejections.** They terminate the process in modern Node; add handlers and exit deliberately.
- **Reliance on module-level mutable state.** It makes multi-instance deployments wrong; state belongs in a database or cache.
- **No graceful shutdown.** In-flight requests are dropped on deploy unless you stop accepting and drain.

### Real-World Deal-Breakers
- **Blocking the event loop** → `fs.readFileSync`, `crypto.pbkdf2Sync`, and heavy JSON parsing block all concurrent requests. Use async versions or worker threads.
- **Unhandled promise rejections** → crash the process in Node 15+. Always attach `.catch()` or use `process.on('unhandledRejection')`.
- **No cluster mode** → a single Node process uses one CPU core. Use `cluster` or `pm2` to scale across cores.
