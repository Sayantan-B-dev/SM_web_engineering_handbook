### The Core Mental Model
A React frontend needs a backend for three things: **data persistence**, **authentication**, and **business logic**. The 2026 default stack for React developers is **Node.js + Express/Fastify + PostgreSQL + Prisma + tRPC or REST**. For Next.js apps, Server Actions blur the line between frontend and backend entirely. The choice of framework and API paradigm depends on your team size, performance requirements, and type-safety priorities.

---

### Deeper Explanation: Four Jobs, Not Forty Frameworks

A React developer building backend surface area is really doing four jobs: delivering data (API shape), managing identity (authn/authz), protecting resources (validation, rate limits), and staying observable (logs, metrics, tracing). The language and framework matter far less than getting those four right.

| Job | Decision | Common failure |
|---|---|---|
| API shape | REST / GraphQL / RPC | Chatty endpoints, over-fetching, no pagination contract |
| Identity | Session cookies vs tokens, server-side authorisation | Authz in the UI only |
| Protection | Schema validation, rate limits, least privilege | Trusting client input, no limits |
| Operations | Structured logs, metrics, health checks, migrations | Debugging by SSH |

The modern default for a React app is a **colocated backend** (Next.js route handlers, Remix, or a separate Node service) with typed boundaries, cookie sessions, schema validation, and a managed Postgres. ### Additional Pitfalls
- **Choosing a framework before the API contract.** The contract determines the client's ergonomics; pick that first.
- **Duplicating types by hand.** A shared schema/types package removes the drift class of bugs.
- **No pagination or filtering contract.** Every list endpoint needs one from day one.
- **Skipping operations work.** Logs, health checks, and migrations are what make a backend maintainable.

### Real-World Deal-Breakers
- **Choosing a framework by hype** → Express is mature, Fastify is fast, NestJS is structured. Pick based on team size and complexity.
- **Skipping input validation** → Fastify validates at the framework level; Express requires opt-in middleware. Unvalidated routes are the leading cause of injection bugs.
- **Ignoring schema validation** → Fastify's JSON Schema validation closes an entire class of input-validation bugs before any handler runs.
