## 34.11 CORS

### Subtopic Tree
- Same-Origin Policy (SOP) - the browser's default
- CORS - controlled relaxation of SOP
- Preflight requests (`OPTIONS`)
- `Access-Control-Allow-Origin` (never `*` with credentials)
- `Access-Control-Allow-Methods`
- `Access-Control-Allow-Headers`
- `Access-Control-Allow-Credentials`
- `Access-Control-Max-Age` (preflight caching)
- Credentialed requests (`withCredentials: true`)

### The Critical Distinction
> "CORS is not a security boundary. It does not prevent requests from being sent. It governs whether JavaScript on the initiating origin is allowed to read the response."

A well-configured server still receives the request - and if that request can mutate state, you also need a CSRF defense.

### Express CORS Configuration
```javascript
import cors from 'cors';

app.use(cors({
  origin: ['https://myapp.com', 'https://admin.myapp.com'],
  methods: ['GET', 'POST', 'PATCH', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization', 'X-CSRF-Token'],
  credentials: true, // allow cookies
  maxAge: 86400,     // cache preflight for 24h
}));
```

---

### Deeper Explanation: CORS Is A Browser Control, Not An Auth Mechanism

CORS restricts which origins a browser lets *your page* read responses from â€” it does not protect your API from non-browser clients (curl, scripts, servers ignore it). Misunderstanding that produces two classic mistakes: treating CORS as security, and opening it wide to "make it work".

The mechanics: simple requests are sent and the *response* is gated; non-simple requests trigger a preflight `OPTIONS` that must return `Access-Control-Allow-Origin`, `-Methods`, `-Headers` (and `-Credentials` plus an exact origin when cookies are involved). Preflights should be answered at the edge with a long `Access-Control-Max-Age` to avoid a round trip per request.

### Additional Pitfalls
- **`*` with credentials.** Not allowed; echo validated origins from an allow-list instead.
- **Reflecting `Origin` without validation.** That is equivalent to `*` plus credentials.
- **No `Vary: Origin`.** Caches serve one origin's response to another.
- **Preflight handled per request.** Latency and load; cache it at the CDN with a long max-age.
- **Treating CORS as authorisation.** Non-browser clients are unaffected; API auth is separate.

### Real-World Deal-Breakers
- **`Access-Control-Allow-Origin: *` with credentials** → browser rejects the response. Use explicit origins.
- **No preflight caching** → every cross-origin request triggers an `OPTIONS` request. Set `Access-Control-Max-Age`.
- **Confusing CORS with CSRF defense** → CORS doesn't prevent CSRF. Use SameSite cookies and CSRF tokens.
- **Reflected Origin header** → a misconfiguration that allows any origin. Never reflect the Origin header blindly.
