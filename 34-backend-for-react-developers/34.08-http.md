## 34.8 HTTP

### Subtopic Tree
- HTTP/1.1 (head-of-line blocking, 6 connections per domain)
- HTTP/2 (multiplexing, HPACK, server push)
- HTTP/3 (QUIC, UDP, 0-RTT, no HOL blocking)
- Methods (GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD)
- Status codes (1xx, 2xx, 3xx, 4xx, 5xx)
- Headers (request, response, representation, security)
- Cookies (Set-Cookie, Cookie, attributes)
- CORS (preflight, Access-Control-* headers)
- Keep-Alive, connection pooling

### HTTP/2 vs HTTP/3 for React Apps
HTTP/2 multiplexes requests over a single TCP connection, eliminating HTTP/1.1's 6-connection-per-domain limit. HTTP/3 runs over QUIC (UDP), eliminating TCP-level head-of-line blocking and enabling **0-RTT** connection establishment.

### Deeper Explanation: Semantics You Can Rely On

HTTP is not a transport detail; its semantics carry guarantees that clients, proxies, and browsers use. The ones that matter most in day-to-day backend work:

| Concept | Use it for | Note |
|---|---|---|
| Methods (safe/idempotent) | GET safe & idempotent; PUT/DELETE idempotent; POST not | Retries and caching depend on it |
| Status classes | 2xx success, 3xx redirect, 4xx client, 5xx server | Clients and monitors branch on the class |
| Conditional requests | `ETag`/`If-None-Match`, `If-Modified-Since` | Saves bandwidth, enables optimistic concurrency |
| Range requests | Partial content, resumable downloads | Needed for large media |
| Caching headers | `Cache-Control`, `Vary`, `Age` | Correct caching is a performance feature |
| Connection reuse | HTTP/2 multiplexing, keep-alive | Avoid per-request handshakes |

Two modern realities: HTTP/3 (QUIC) removes head-of-line blocking on lossy mobile networks, and buffering at any proxy layer (nginx, CDNs, compressing middleware) breaks streaming responses unless you disable it explicitly.

### Additional Pitfalls
- **`POST` used for idempotent operations.** Retries duplicate writes; use `PUT`/`DELETE` or an idempotency key.
- **No `Vary` on negotiated content.** Caches serve the wrong encoding or locale.
- **Returning `500` for validation errors.** Monitoring cannot distinguish bugs from bad input.
- **Streaming behind buffering middleware.** SSE and chunked responses arrive in one lump.
- **Ignoring `HEAD`.** Health checks and link previews use it; a broken `HEAD` breaks tooling.

### Real-World Deal-Breakers
- **HTTP/1.1 with many small requests** → head-of-line blocking. Upgrade to HTTP/2 or HTTP/3.
- **No `preconnect` to API origin** → DNS + TCP + TLS adds 200-500ms before the first byte.
- **No compression** → 3-4× larger payloads. Enable Brotli/gzip.
