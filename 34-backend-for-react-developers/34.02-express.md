## 34.2 Express

### Subtopic Tree
- Minimal, unopinionated framework
- Middleware pipeline (request → middleware → handler → error handler)
- Routing (`app.get`, `app.post`, `express.Router()`)
- Error handling (4-argument middleware)
- Express 5 (async error propagation)
- Ecosystem: Helmet, CORS, express-rate-limit, cookie-parser
- When to use: brownfield projects, small teams, rapid prototyping

### What Express Is
Express is the **oldest and most widely used Node.js framework** (~35M weekly npm downloads as of mid-2025). It is minimal and unopinionated - you compose your stack from middleware. Express 5 (2025+) automatically forwards rejected promises from async handlers to error middleware.

```javascript
import express from 'express';
import helmet from 'helmet';
import cors from 'cors';
import { rateLimit } from 'express-rate-limit';

const app = express();

// Security middleware (order matters)
app.use(helmet());
app.use(cors({ origin: 'https://myapp.com', credentials: true }));
app.use(express.json({ limit: '1mb' })); // body size cap
app.use(rateLimit({ windowMs: 60_000, max: 100 })); // 100 req/min

// Routes
app.get('/api/users/:id', async (req, res) => {
  const user = await db.user.findUnique({ where: { id: req.params.id } });
  if (!user) return res.status(404).json({ error: 'Not found' });
  res.json(user);
});

// Error handler (MUST be last, MUST have 4 args)
app.use((err, req, res, next) => {
  console.error(err);
  res.status(500).json({ error: 'Internal server error' });
});

app.listen(3000);
```

### Express Middleware Order
```
Request → Logger → CORS → Body Parser → Auth → Validate → Handler → Error Handler → Response
```
Middleware executes **in the order you register it**. Error handlers have **4 parameters** and must be registered **last**.

---

### Deeper Explanation: Middleware As A Pipeline

Express's model is a linear pipeline of middleware, and its strengths and weaknesses both come from that: composability and ubiquity, at the cost of implicit control flow. Order matters, errors propagate differently in sync vs async handlers, and nothing validates your input for you.

For modern (Express 5) usage the discipline is: keep middleware small and single-purpose, attach error handlers last, wrap async handlers so rejections reach the error middleware, validate with a schema library (Zod) in a middleware, and mount features as routers (`app.use('/orders', ordersRouter)`) rather than one big file. Also set security headers and body limits explicitly â€” nothing is on by default.

```ts
const app = express();
app.use(express.json({ limit: '100kb' }));
app.use(securityHeaders);
app.use(rateLimit({ windowMs: 60_000, max: 120 }));

const orders = Router();
orders.post('/', validate(CreateOrderSchema), asyncHandler(async (req, res) => {
  const order = await orderService.create(req.body, req.user);   // authz inside the service
  res.status(201).json(serialize(order));
}));
app.use('/api/orders', requireAuth, orders);

// error middleware last; asyncHandler forwards rejections here
app.use((err, _req, res, _next) => {
  const status = err.status ?? 500;
  res.status(status).json({ error: status === 500 ? 'Internal error' : err.message });
});
```

### Additional Pitfalls
- **No `asyncHandler` wrapper.** Rejected promises skip the error middleware and hang the request.
- **Validation scattered through handlers.** One middleware per route with a schema is testable and consistent.
- **Permissive CORS and `json()` with no limit.** Two of the most common production misconfigurations.
- **Business logic inside route files.** Services are testable without HTTP; handlers should be thin.
- **Leaking stack traces to clients.** Log the detail, return a generic message plus a correlation id.

### Real-World Deal-Breakers
- **No body size limit** → Express accepts a 500MB JSON body by default. Both DoS vectors. Cap with `express.json({ limit: '1mb' })`.
- **No rate limiting** → unlimited requests per second. Use `express-rate-limit` with Redis for distributed limiting.
- **Error handler not last** → errors are not caught. Register error middleware after all routes.
- **Async handler without try/catch** → Express 5 forwards rejections automatically, but Express 4 requires `express-async-errors` or manual try/catch.
- **CVE-2024-45296** → ReDoS in `path-to-regexp` before 0.1.10/3.3.0/6.3.0/8.0.0.
- **CVE-2022-24999** → prototype pollution in `qs` before 6.10.3.
