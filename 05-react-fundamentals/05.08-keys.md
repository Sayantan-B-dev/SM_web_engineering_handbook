### Deep Dive: Why Keys Matter
React's reconciliation compares the new element tree with the previous one. Keys are the identity signal for list items. Without keys (or with unstable keys), React can't tell if an element is the same one or a new one.

```jsx
// Without keys - React re-renders every item on any change
<ul>
  <li>A</li>
  <li>B</li>
</ul>

// With keys - React updates only changed items
<ul>
  <li key="a">A</li>
  <li key="b">B</li>
</ul>
```

### Key Rules
1. **Unique among siblings** - not globally unique.
2. **Stable across renders** - don't regenerate.
3. **Don't use `Math.random()` or `Date.now()`**.
4. **Don't use array index** if list can be reordered/filtered/prepended.
5. **Keys are internal** - not passed to the component as a prop.

### Accessing Keys
```jsx
// ❌ Keys aren't props
function Item({ key }) {
  return <li>{key}</li>; // key is undefined!
}

// ✅ Pass the ID as a separate prop if needed
{items.map(item => <Item key={item.id} id={item.id} item={item} />)}
```

### Key Strategy Examples
```jsx
// ✅ Database IDs (best)
{users.map(user => <UserRow key={user.id} user={user} />)}

// ✅ UUIDs
{todos.map(todo => <TodoItem key={todo.uuid} todo={todo} />)}

// ✅ Composite key when no single ID
{items.map(item => <Row key={`${item.type}:${item.id}`} />)}

// ✅ Index only if list is truly static (never reorders, never filters)
{staticOptions.map((opt, i) => <Option key={i} opt={opt} />)}

// ✅ Prefix to avoid collisions with other keyed elements
{items.map(item => <Row key={`item-${item.id}`} />)}
```

### Real-World Deal-Breakers
- **Duplicate keys across siblings** → React warns; rendering becomes unpredictable.
- **Key changes on every render** → full unmount/remount: state lost, animations reset, DOM churn.
- **Keys only at top of nested map** → each level of nesting needs its own keys.
- **Using key to force re-mount** → intentional but overused: changing key throws away state (sometimes desired for resetting a form/component).
- **Assuming key is passed as prop** → not true; pass the ID separately if the child needs it.
