### Pattern
```jsx
function EmailInput() {
  const [email, setEmail] = useState('');
  const isValid = email.includes('@');

  return (
    <div>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        aria-invalid={!isValid}
      />
      {!isValid && email.length > 0 && (
        <p className="error">Invalid email</p>
      )}
    </div>
  );
}
```

### Benefits
- **Single source of truth** - the React state is always the truth.
- **Immediate validation** - validate on every keystroke.
- **Conditional rendering** - disable buttons, show errors based on current value.
- **Programmatic control** - set value via state (e.g., reset button).
- **Consistent across frameworks** - same pattern in React Native, react-hook-form, etc.

### Performance Considerations
```jsx
// ❌ Every keystroke re-renders the parent + all children
function Parent() {
  const [text, setText] = useState('');
  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <ExpensiveChild />  {/* re-renders on every keystroke */}
    </div>
  );
}

// ✅ Memoize children or isolate state
function Parent() {
  return (
    <div>
      <TextInput />  {/* manages its own state */}
      <ExpensiveChild />
    </div>
  );
}
```

### Real-World Deal-Breakers
- **`value` without `onChange`** → read-only warning + unusable input.
- **Setting `value` from props without a state update mechanism** → input can't be typed into.
- **Synchronous state update assumption** → `setState` doesn't immediately change `value`; controlled inputs work because React re-renders with the new state on the next tick.
- **Not debouncing expensive validation** → synchronous validation on every keystroke for a network call → hundreds of requests.
