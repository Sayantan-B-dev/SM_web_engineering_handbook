### The AI Slop Crisis
GitHub's own Octoverse report names a widening **"contributor-to-maintainer gap,"** made worse by what the industry has started calling **"AI slop"**: low-quality, auto-generated pull requests that consume maintainer time without adding real value. The **Jazzband collective**, a well-known hub for Python projects, shut down entirely in 2025, with its lead maintainer citing the unsustainable volume of AI-generated spam PRs and issues as a primary driver.

### Maintainer Workflow (Four-Step Framework)
1. **Define Contribution Tracks and Roles** - code contributors, documentation writers, triagers, community moderators.
2. **Set Up a Transparent Backlog** - visible issue tracker, milestones, difficulty tags.
3. **Automate the Review Pipeline** - CI on every PR, bots for assignment, flags for stalled PRs.
4. **Measure Community Health, Not Just Velocity** - contributor retention, review latency, issue resolution time.

### Additional Pitfalls
- **No licence or contribution guide.** Adoption by companies stalls and contributors waste effort.
- **No support boundaries.** Unlimited expectations burn out maintainers; publish the rules.
- **Breaking changes in minor releases.** Consumers lose trust in the version numbers.
- **No changelog or releases.** Users cannot tell what changed or whether to upgrade.
- **Ignoring security reports.** A public issue with a working exploit is an incident.

### Real-World Deal-Breakers
- **No license** → no one can legally use your code. It's "all rights reserved" by default.
- **No CONTRIBUTING.md** → contributors don't know how to contribute. They leave.
- **No Code of Conduct** → toxic behaviour drives contributors away.
- **Single maintainer** → bus factor of 1. If they leave, the project dies.
- **No funding** → maintainers burn out working full-time for free.
