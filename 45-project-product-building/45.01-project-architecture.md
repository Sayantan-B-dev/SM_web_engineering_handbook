### The Mental Model
Project architecture is the answer to "where does this go, and who owns it?" â€” decided before habits form. For React apps the structure that ages best is **feature-first**: each feature owns its components, hooks, data access, and tests, with a small shared layer for the design system, utilities, and app shell. That keeps change local (one folder per feature), makes ownership assignable, and makes deletion possible.

```text
src/
  app/            # routing, providers, error boundaries, layout
  features/
    checkout/
      components/  ui/  hooks/  api.ts  types.ts  __tests__/
    cart/
  shared/
    ui/          # design-system primitives
    lib/         # pure utilities
    config/      # env + flags
```

Three rules that keep it honest: imports only flow from feature â†’ shared (never feature â†’ feature directly, use an event or a shared module), every feature exposes one public entry point (`index.ts`), and anything used by two features is either promoted to shared or duplicated deliberately.

### Real-World Deal-Breakers
- **Layer-first organisation.** Every change touches six folders; ownership becomes unclear.
- **Deep imports across features.** Hidden coupling that makes extraction or deletion impossible.
- **A shared "components" folder as a dumping ground.** It grows into an unowned mess.
- **Server and client state mixed in one store.** Cache invalidation becomes guesswork.
- **No error boundaries.** One feature failure takes the whole app down.
- **Configuration read in many places.** Centralise env validation and flag access so tests can substitute them.
