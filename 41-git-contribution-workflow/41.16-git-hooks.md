## 41.14 Git Hooks

### Subtopic Tree
- Client-side hooks (pre-commit, commit-msg, pre-push)
- Server-side hooks (pre-receive, post-receive)
- Husky (Git hooks manager)
- lint-staged (run commands on staged files)
- Commitlint (validate commit messages)
- Pre-commit hooks for secrets scanning (Gitleaks)
- Bypassing hooks (`--no-verify`)

### Common Hooks

| Hook | When it runs | Use for |
|------|-------------|---------|
| `pre-commit` | Before commit is created | Lint, format, secrets scan |
| `commit-msg` | After commit message is written | Commitlint validation |
| `pre-push` | Before push to remote | Run tests |
| `pre-rebase` | Before rebase | Safety checks |
| `post-merge` | After merge | Install deps, run migrations |

### Husky + lint-staged Setup
```bash
npm install --save-dev husky lint-staged
npx husky init
```

```json
// package.json
{
  "lint-staged": {
    "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,md}": ["prettier --write"]
  }
}
```

```bash
# .husky/pre-commit
npx lint-staged
npx gitleaks protect --staged
```

The pre-commit hook runs **security checks before every commit** - Gitleaks scans staged files for secrets and credentials.

### Bypassing Hooks
```bash
# ❌ BAD - bypasses all hooks
git commit --no-verify -m "quick fix"

# ✅ Only bypass when you genuinely need to (e.g., emergency hotfix)
```

---

### Deeper Explanation: Local Hooks For Speed, CI For Enforcement

Hooks split by trust: `pre-commit`/`commit-msg` in the developer's machine (fast feedback, optional), and server-side/CI checks (mandatory, unfakeable). Anything that must hold is enforced in CI; local hooks exist to shorten the feedback loop and keep history clean.

Practical setup: use a hook manager (Husky, lefthook, simple-git-hooks) committed to the repository so everyone gets the same hooks; keep the pre-commit hook fast (lint-staged: format and lint only staged files); make `pre-push` run the test suite only if it is quick; never put secrets or network-dependent checks in local hooks. Remember `--no-verify` exists, so treat local hooks as a convenience and CI as the gate.

### Additional Pitfalls
- **Slow pre-commit hooks.** Developers disable them within a week; keep them under a couple of seconds.
- **Only local enforcement.** Commits via the web UI or with `--no-verify` bypass them.
- **Hooks that modify files unexpectedly.** `lint-staged` should be explicit about what it rewrites.
- **No shared setup.** Uncommitted hooks mean inconsistent developer machines.
- **Secrets or network access in hooks.** Slow, fragile, and a supply-chain risk.

### Real-World Deal-Breakers
- **No pre-commit hooks** → lint errors, formatting issues, and secrets reach CI (or worse, production).
- **`--no-verify` as a habit** → hooks are useless if you always bypass them.
- **Hooks not on all developer machines** → some commits bypass checks. Use Husky to enforce installation via `prepare` script.
- **No secrets scanning** → API keys committed to the repo. Gitleaks catches them before commit.
