### Promise-Based Worker Wrapper
```typescript
class WorkerClient {
  private worker: Worker;
  private id = 0;
  private pending = new Map<number, { resolve: Function; reject: Function }>();

  constructor(url: string) {
    this.worker = new Worker(url);
    this.worker.onmessage = (e) => {
      const { id, result, error } = e.data;
      const p = this.pending.get(id);
      if (!p) return;
      this.pending.delete(id);
      if (error) p.reject(new Error(error));
      else p.resolve(result);
    };
  }

  call<T>(method: string, ...args: any[]): Promise<T> {
    return new Promise((resolve, reject) => {
      const id = ++this.id;
      this.pending.set(id, { resolve, reject });
      this.worker.postMessage({ id, method, args });
    });
  }

  terminate() {
    this.worker.terminate();
    this.pending.clear();
  }
}

// Usage
const client = new WorkerClient('worker.js');
const result = await client.call<number[]>('calculatePrimes', 1000000);
```

### Main-Thread Authoritative State
> "Always keep the main thread as the authoritative copy of state; the worker is only a compute node. Avoid storing critical state only in the worker's global environment."

```typescript
// ✅ Main thread holds state, worker computes
const [state, setState] = useState(initialState);

// Send current state to worker with each task
worker.postMessage({ state, task: 'process' });
worker.onmessage = (e) => setState(e.data.newState);

// ❌ Worker holds state independently
// → state drift between threads
```

### Comlink
Comlink is a library that makes Web Workers feel like local function calls by abstracting `postMessage` behind a proxy.

```javascript
// worker.js
import * as Comlink from 'comlink';

const api = {
  calculatePrimes(limit) { /* ... */ },
  processData(data) { /* ... */ },
};

Comlink.expose(api);

// main.js
import * as Comlink from 'comlink';
const worker = new Worker('worker.js');
const api = Comlink.wrap(worker);

const primes = await api.calculatePrimes(1000000);
```

### Deeper Explanation: Pools, Protocols, And Ownership

A single worker is a start; an architecture is a decision about **how many workers, who owns them, and how jobs are routed**. Three shapes cover most products:

- **Singleton worker** â€” one module worker created at app start, owning one heavy concern (markdown rendering, diffing, image encode). Simplest; queues naturally; blocks unrelated jobs, so keep concerns separate.
- **Pool** â€” N workers sized to hardware concurrency, with a job queue. Right for throughput tasks (search indexing, batch transforms). Add job cancellation and per-job timeouts or a stuck job wedges a slot.
- **Specialised fleet** â€” one worker per concern (search, diffing, crypto, WASM engine), each with its own protocol. Best isolation; more startup cost, so warm them lazily.

Whatever the shape, define the protocol as a typed message union, keep results immutable, and make every job cancellable. Treat the worker side as a service boundary: it can fail, restart, or be throttled.

### Additional Pitfalls
- **Worker created inside a component.** React re-mounts and StrictMode double-invocation leave duplicates; create at module scope or in a provider with cleanup.
- **No request timeout.** A worker that fails to respond (bug or OOM) hangs the UI's promise forever.
- **Shared mutable protocol objects.** Mutating a message after posting is confusing at best (cloned) and dangerous with shared buffers.
- **No versioning between main and worker bundles.** Deploys with cached bundles can mix versions; build them together and hash them.
- **Unhandled worker crash.** Add `error`/`messageerror` handlers that report to your error monitor and restart the worker.

### Real-World Deal-Breakers
- **Worker holding authoritative state** → state drift between threads. Keep state on the main thread.
- **No request/response IDs** → responses can't be matched to requests; race conditions.
- **No worker pool** → spawning per task is expensive.
- **Comlink without TypeScript** → `wrap()` returns `any`; types are lost. Define an interface and cast.
