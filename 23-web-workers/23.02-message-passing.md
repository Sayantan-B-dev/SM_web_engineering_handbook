## 23.3 Message Passing

### Subtopic Tree
- `postMessage()` (main → worker, worker → main)
- `onmessage` / `addEventListener('message')`
- `MessageEvent` shape (`data`, `origin`, `source`, `ports`)
- `MessageChannel` and `MessagePort`
- `BroadcastChannel` (cross-tab)
- Structured clone algorithm
- Transferable objects (zero-copy)
- `messageerror` event
- Backpressure and batching

### Basic Pattern
```javascript
// main.js
const worker = new Worker('worker.js');
worker.postMessage({ type: 'CALCULATE', limit: 1000000 });
worker.onmessage = (e) => {
  if (e.data.type === 'PROGRESS') updateProgress(e.data.value);
  if (e.data.type === 'RESULT') showResult(e.data.value);
};
```

```javascript
// worker.js
self.onmessage = (e) => {
  const { type, limit } = e.data;
  if (type === 'CALCULATE') {
    const result = calculate(limit, (progress) => {
      self.postMessage({ type: 'PROGRESS', value: progress });
    });
    self.postMessage({ type: 'RESULT', value: result });
  }
};
```

### `MessageChannel` for Direct Ports
`MessageChannel` creates a pair of `MessagePort` objects that can be transferred to a worker, enabling direct communication without going through the main thread's event loop.

```javascript
// main.js
const channel = new MessageChannel();
worker.postMessage({ type: 'INIT', port: channel.port1 }, [channel.port1]);
channel.port2.onmessage = (e) => console.log('From worker:', e.data);

// worker.js
self.onmessage = (e) => {
  if (e.data.type === 'INIT') {
    const port = e.data.port;
    port.postMessage('Hello from worker');
  }
};
```

### `BroadcastChannel` for Cross-Tab
```javascript
const bc = new BroadcastChannel('app-sync');
bc.postMessage({ type: 'THEME_CHANGED', theme: 'dark' });
bc.onmessage = (e) => console.log('Other tab:', e.data);
```

### Message Event Shape
```typescript
interface MessageEvent {
  data: any;         // the payload (structured-cloned)
  origin: string;    // origin of the sender
  source: Window | Worker | null;
  ports: MessagePort[]; // transferred ports
  lastEventId: string;
}
```

---

### Deeper Explanation: One Channel, Three Semantics

`postMessage` looks simple but carries three separable concerns: **what can be sent** (structured clone), **who receives** (dedicated = the other side; shared = a specific `MessagePort`), and **when it is delivered** (asynchronously, in order per channel). Recognising them explains the constraining rules:

- Functions, class prototypes, DOM nodes, and symbols cannot be cloned â€” only values. Sending an object sends a *copy* with the same data and no methods.
- Ordering is guaranteed **per port**, so a request/response protocol must carry its own correlation id.
- Backpressure does not exist: a fast producer can queue thousands of messages and grow memory. Implement your own ack or use `Atomics.wait` on a `SharedArrayBuffer` when flow control matters.

For structured protocols, define a discriminated union on the `type` field and validate at the boundary â€” messages arrive from a different thread, so treat them like network input.

### Additional Pitfalls
- **Sending class instances.** Methods vanish; send plain data and reconstruct on the other side.
- **No correlation id in a request/response protocol.** Concurrent requests get mismatched replies.
- **Assuming a message is delivered "soon".** A busy worker delays every message behind the current job.
- **Unbounded queueing.** Without flow control, a 1 Hz producer with a 10 s consumer accumulates 10 messages â€” and now 10Ã- the payload in memory.
- **Throwing inside `onmessage`.** It surfaces as an unhandled error in the worker and the response never arrives; wrap handlers.

### Real-World Deal-Breakers
- **Passing large objects repeatedly** → structured clone copies everything. Use Transferable Objects for `ArrayBuffer`.
- **No `messageerror` handler** → structured clone failures are silent.
- **Assuming `postMessage` is synchronous** → it's always asynchronous; the message is queued.
- **No backpressure** → spamming `postMessage` from the worker floods the main thread's event loop.
- **`MessageChannel` ports not transferred** → ports are not cloned; they must be in the transfer list.
