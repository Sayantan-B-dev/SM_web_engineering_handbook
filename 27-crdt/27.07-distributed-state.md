### The Mental Model
Frontend engineers meet distributed state the moment two clients can write the same thing. The relevant model is **replication**: a logical state, a set of replicas, and a rule that makes all replicas converge. Everything else follows from what you are willing to give up:

| Model | Guarantee | Cost | Typical frontend use |
|---|---|---|---|
| Strong (linearisable) | Reads see the latest write | Round trip, unavailable when partitioned | Payments, inventory, permissions |
| Causal | Preserves cause/effect | Needs causal metadata | Comments, replies, edit histories |
| Eventual | Converges without ordering | Complex merges | Counters, presence, CRDT documents |

The important frontend insight: **most UI state is derived**, and derived state never needs to be replicated â€” only the inputs do. Replicating the inputs and recomputing views keeps the conflict surface small.

### Garbage Collection
Distributed state grows unless you plan for it: version vectors accumulate replicas, tombstones accumulate deletes, and update logs accumulate forever. Three practices keep it bounded â€” snapshot-and-prune on a schedule, treat replicas as session-scoped (fresh id per device session) rather than permanent, and keep tombstones only as long as the maximum plausible offline window (for example 90 days), then compact.

### Real-World Deal-Breakers
- **Replicating derived state.** Views, computed totals, and formatted strings recreate conflicts that the inputs never had.
- **Assuming strong consistency from a mobile client.** Offline devices are, by definition, stale; design reads that tolerate it.
- **Wall clocks as version metadata.** Drift is unbounded; use logical or hybrid clocks.
- **Permanent replica ids.** Version vectors grow one entry per device ever seen; scope replicas to sessions.
- **Unbounded tombstones.** They are necessary for correctness and must still be compacted.
- **No authoritative source for permissions.** Security decisions cannot be eventually consistent; keep authorisation server-side.
