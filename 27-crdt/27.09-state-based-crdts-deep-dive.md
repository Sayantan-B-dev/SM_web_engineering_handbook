### The Semilattice Requirement
In state-based CRDTs, all states in the system - across different replicas and different moments - form a **monotonic join-semilattice**. For any two states X and Y, both can be "joined" (merged, or form a union) and the result is a new state corresponding to the **Least Upper Bound (LUB)** of the two.

The join operation (⊔) must satisfy three laws:
- **Idempotent:** X ⊔ X = X
- **Commutative:** X ⊔ Y = Y ⊔ X
- **Associative:** (X ⊔ Y) ⊔ Z = X ⊔ (Y ⊔ Z)

These laws ensure that merge order does not matter and duplicate merges are harmless.

### G-Set (Grow-Only Set)
The simplest CRDT. Elements can only be added, never removed. The join operation is set union.

```typescript
class GSet<T> {
  private elements: Set<T> = new Set();

  add(element: T): void {
    this.elements.add(element);
  }

  merge(other: GSet<T>): GSet<T> {
    const merged = new GSet<T>();
    merged.elements = new Set([...this.elements, ...other.elements]);
    return merged;
  }

  has(element: T): boolean {
    return this.elements.has(element);
  }

  value(): T[] {
    return [...this.elements];
  }
}
```

**Why it works:** Set union is idempotent, commutative, and associative. The state only grows (monotonic).

### G-Counter (Grow-Only Counter)
A counter that can only increment. Each replica maintains its own count. The total is the sum of all replica counts.

```typescript
class GCounter {
  private counts: Map<string, number> = new Map(); // replicaId → count

  constructor(private replicaId: string) {
    this.counts.set(replicaId, 0);
  }

  increment(): void {
    this.counts.set(this.replicaId, (this.counts.get(this.replicaId) ?? 0) + 1);
  }

  merge(other: GCounter): GCounter {
    const merged = new GCounter(this.replicaId);
    const allIds = new Set([...this.counts.keys(), ...other.counts.keys()]);
    for (const id of allIds) {
      const a = this.counts.get(id) ?? 0;
      const b = other.counts.get(id) ?? 0;
      merged.counts.set(id, Math.max(a, b)); // take the max per replica
    }
    return merged;
  }

  value(): number {
    let total = 0;
    for (const count of this.counts.values()) total += count;
    return total;
  }
}
```

**Why it works:** For each replica ID, the counter is a grow-only value. The merge takes the max per replica, which is idempotent, commutative, and associative. The total is the sum, which is monotonic.

### LWW-Register (Last-Write-Wins Register)
A register that holds a single value. Each write includes a timestamp; on merge, the value with the latest timestamp wins.

```typescript
class LWWRegister<T> {
  private value: T | null = null;
  private timestamp: number = 0;
  private replicaId: string = '';

  set(value: T, timestamp: number, replicaId: string): void {
    if (timestamp > this.timestamp || (timestamp === this.timestamp && replicaId > this.replicaId)) {
      this.value = value;
      this.timestamp = timestamp;
      this.replicaId = replicaId;
    }
  }

  merge(other: LWWRegister<T>): LWWRegister<T> {
    const merged = new LWWRegister<T>();
    if (other.timestamp > this.timestamp || (other.timestamp === this.timestamp && other.replicaId > this.replicaId)) {
      merged.value = other.value;
      merged.timestamp = other.timestamp;
      merged.replicaId = other.replicaId;
    } else {
      merged.value = this.value;
      merged.timestamp = this.timestamp;
      merged.replicaId = this.replicaId;
    }
    return merged;
  }

  get(): T | null {
    return this.value;
  }
}
```

**Why it works:** Timestamps provide a total order. Tie-breaking by replica ID ensures determinism. **But:** LWW silently drops concurrent writes - the loser's write is lost. For collaborative editing, this is data loss.

### OR-Set (Observed-Remove Set)
A set that supports both add and remove. Each element is tagged with a unique ID when added. Remove marks the specific tags as removed.

```typescript
class ORSet<T> {
  private elements: Map<T, Set<string>> = new Map(); // element → set of unique tags
  private tombstones: Map<T, Set<string>> = new Map(); // element → removed tags

  add(element: T, tag: string): void {
    if (!this.elements.has(element)) this.elements.set(element, new Set());
    this.elements.get(element)!.add(tag);
  }

  remove(element: T): void {
    const tags = this.elements.get(element);
    if (tags) {
      if (!this.tombstones.has(element)) this.tombstones.set(element, new Set());

    // ...
  }

  has(element: T): boolean {
    const tags = this.elements.get(element);
    if (!tags) return false;
    const tombstoned = this.tombstones.get(element) ?? new Set();
    return [...tags].some((tag) => !tombstoned.has(tag));
  }
}
```

**Why it works:** Tags provide causal context. An element is present if it has at least one tag that has not been tombstoned. Concurrent add and remove: the add wins if it has a tag the remove did not see.

### Deeper Explanation: Semilattices In Practice

A state-based CRDT is a value in a join-semilattice with a monotone merge, and several familiar types fit the pattern cleanly:

| Type | State | Merge |
|---|---|---|
| G-Counter | `{ replica: count }` | pointwise max then sum on read |
| PN-Counter | two G-Counters | sums of increments minus decrements |
| G-Set | a set | union |
| 2P-Set | added set + removed set | union both; element present iff added-only |
| OR-Set | tags per element | union of tags; add wins over concurrent remove |
| LWW-Register | `{ value, timestamp, replica }` | keep the greater (deterministic tiebreak) |
| MV-Register | set of concurrent values | union (readers decide) |

The monotonicity requirement is the design constraint: state may only move "up" in the lattice, so anything that would require removing information (decrementing a counter, deleting without a tombstone) must be modelled with a companion structure.

### Extended Example: PN-Counter And OR-Set Merge

```ts
type PNCounter = { inc: Record<string, number>; dec: Record<string, number> };

export function counterMerge(a: PNCounter, b: PNCounter): PNCounter {
  const merge = (x: Record<string, number>, y: Record<string, number>) =>
    Object.fromEntries(
      [...new Set([...Object.keys(x), ...Object.keys(y)])].map((k) => [k, Math.max(x[k] ?? 0, y[k] ?? 0)]),
    );
  return { inc: merge(a.inc, b.inc), dec: merge(a.dec, b.dec) };
}

export const counterValue = (c: PNCounter) =>
  Object.values(c.inc).reduce((s, n) => s + n, 0) - Object.values(c.dec).reduce((s, n) => s + n, 0);

// OR-Set: each add carries a unique tag; remove deletes only the tags it observed
type ORSet<T> = { entries: Map<T, Set<string>>; tombstoned: Set<string> };

export function orSetMerge<T>(a: ORSet<T>, b: ORSet<T>): ORSet<T> {
  const entries = new Map<T, Set<string>>();
  for (const [key, tags] of [...a.entries, ...b.entries]) {
    const merged = new Set([...(entries.get(key) ?? []), ...tags]);
    for (const tag of b.tombstoned) merged.delete(tag);
    for (const tag of a.tombstoned) merged.delete(tag);
    if (merged.size) entries.set(key, merged);
  }
  return { entries, tombstoned: new Set([...a.tombstoned, ...b.tombstoned]) };
}
```

### Additional Pitfalls
- **Non-monotone state.** A plain integer counter that decrements is not a CRDT; concurrent operations lose updates.
- **Comparing states to decide sending order.** Merge is idempotent and commutative, so order never matters â€” but you must still send meaningful deltas.
- **Unbounded tombstones in remove-heavy workloads.** OR-Set tags accumulate; compact or use an LWW-element-set variant.
- **Per-element version vectors at scale.** A 10 000-row table with a vector per row is megabytes; consider per-field LWW where determinism allows.

### Real-World Deal-Breakers
- **Using LWW-Register for collaborative text** → data loss. Concurrent edits overwrite each other.
- **Using a G-Set when you need removals** → impossible. Use OR-Set.
- **Forgetting that state-based CRDTs transmit the full state** → for large documents, this is prohibitively expensive. Use delta-state.
- **Assuming the join is always set union** → for counters it's max-per-replica, for registers it's max-timestamp, for sets it's union of tags. Each CRDT has its own join.
