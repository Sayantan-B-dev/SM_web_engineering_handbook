### Installation
```bash
npm install @grafana/faro-web-sdk @grafana/faro-react @grafana/faro-web-tracing
```

### Basic Initialization
```typescript
import { initializeFaro, getWebInstrumentations, LogLevel } from '@grafana/faro-web-sdk';
import { TracingInstrumentation } from '@grafana/faro-web-tracing';
import { ReactIntegration } from '@grafana/faro-react';

initializeFaro({
  url: 'https://faro-collector.grafana.net/collect/xxx',
  app: {
    name: 'my-app',
    version: process.env.NEXT_PUBLIC_APP_VERSION,
    environment: process.env.NODE_ENV,
  },
  instrumentations: [
    ...getWebInstrumentations({
      captureConsole: true,
      captureConsoleDisabledLevels: [LogLevel.DEBUG],
    }),
    new TracingInstrumentation({
      instrumentationOptions: {
        propagateTraceHeaderCorsUrls: [
          /https:\/\/api\.example\.com\/.*/,
        ],
      },
    }),
    new ReactIntegration({
      router: createReactRouterV6DataOptions({
        routes: router.routes,
      }),
    }),
  ],
  beforeSend: (item) => {
    // PII filtering
    if (item.meta?.user?.email) item.meta.user.email = '[REDACTED]';
    return item;
  },
  paused: window.location.hostname === 'localhost',
});
```

### Critical Configuration Checklist
> "Check that you have these configured: `beforeSend` PII filtering (URLs and console output may contain tokens), `propagateTraceHeaderCorsUrls` (without this, browser traces never connect to backend spans), `paused on localhost`, `app.version` (filter errors by deploy), Error boundary (catches React errors)."

### Sourcemap Deobfuscation
Faro automatically deobfuscates stack traces if you upload sourcemaps to the Grafana Cloud Frontend Observability. Configure your build to upload sourcemaps on production builds.

### React Error Boundary
```tsx
import { FaroErrorBoundary } from '@grafana/faro-react';

<FaroErrorBoundary fallback={<ErrorPage />}>
  <App />
</FaroErrorBoundary>
```
Catches React rendering errors and reports them to Faro with component stack.

### Deeper Explanation: Faro Is The Frontend Half Of The Same Pipeline

Grafana Faro is a browser SDK plus a collector that turns RUM data into the same signals your backend already emits: logs to Loki, metrics to Prometheus, traces to Tempo. The strategic value is *correlation* â€” a frontend error and the API call it made share a trace id, so one Tempo query shows the whole journey instead of two disconnected views.

What it captures out of the box: web vitals, JS errors, console logs, unhandled rejections, and a custom event API. What you must decide: sampling rates (frontend volume is high), which URLs to trace (all of them is expensive), and the privacy boundary (never send PII, hash user ids).

### Extended Example: Faro Initialisation With Explicit Sampling

```ts
import { initializeFaro, getWebInstrumentations, LogLevel } from '@grafana/faro-web-sdk';
import { TracingInstrumentation } from '@grafana/faro-web-tracing';

initializeFaro({
  url: 'https://faro-collector.example.com/collect',
  app: { name: 'web-app', version: __APP_VERSION__, environment: env.MODE },
  instrumentations: [
    ...getWebInstrumentations({ captureConsole: false }),   // console logs are noise
    new TracingInstrumentation({
      instrumentationOptions: {
        propagateTraceHeaderCorsUrls: [/https:\/\/api\.example\.com\/.*/],
      },
    }),
  ],
  sessionTracking: { samplingRate: 0.1 },     // 10% of sessions
  beforeSend(item) {
    // strip tokens and personal data once, centrally
    return redactItem(item);
  },
  logLevel: LogLevel.WARN,
});

// one shared trace id now links browser â†’ edge â†’ API â†’ database
```

### Additional Pitfalls
- **Propagating trace headers to third parties.** Only allow CORS-propagated trace headers to domains you own.
- **100% session tracking.** Cost and noise explode; sample and keep errors at full fidelity.
- **Sending console logs by default.** Libraries log constantly and drown the signal.
- **Treating Faro as a replacement for an error monitor's workflow.** Assignments, releases, and ownership may still live elsewhere; pick one source of truth for triage.

### Real-World Deal-Breakers
- **No `beforeSend` PII filter** → user emails, tokens, and console output logged to Grafana Cloud.
- **No `propagateTraceHeaderCorsUrls`** → browser traces never connect to backend spans; you have two disconnected halves.
- **No `app.version`** → errors can't be filtered by deploy. "New errors appeared" but you don't know if a deploy caused them.
- **No `paused` on localhost** → local dev errors pollute production telemetry.
- **No sourcemap upload** → stack traces minified and useless.
- **No error boundary** → React rendering errors silently lost.
- **Telemetry blocking app** → if Faro's initialization fails, the app crashes. Wrap in try/catch.
