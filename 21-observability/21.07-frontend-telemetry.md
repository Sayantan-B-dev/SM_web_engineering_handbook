### Automatic Instrumentation
Most observability SDKs auto-instrument:
- Page loads and navigations
- Fetch/XHR requests
- Uncaught errors and unhandled rejections
- Console errors and warnings
- Web Vitals
- User interactions (clicks, form submissions)
- Resource timing

Manual instrumentation adds domain context: "user completed checkout", "payment failed", "user switched theme".

### Beacons (`navigator.sendBeacon`)
```typescript
window.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    // User leaving - send final telemetry with sendBeacon
    navigator.sendBeacon('/telemetry', JSON.stringify(finalMetrics));
  }
});
```
`sendBeacon` guarantees delivery even if the page is closing. `fetch` with `keepalive: true` works too.

### Batching and Resilience
Sending every event immediately is expensive (battery, network, cost). Batch events:
```typescript
const buffer: TelemetryEvent[] = [];

function track(event: TelemetryEvent) {
  buffer.push(event);
  if (buffer.length >= 20) flush();
}

async function flush() {
  if (buffer.length === 0) return;
  const payload = buffer.splice(0, buffer.length);
  try {
    await fetch('/telemetry', { method: 'POST', body: JSON.stringify(payload) });
  } catch {
    // Re-queue on failure (up to a limit)
    if (buffer.length < 1000) buffer.unshift(...payload);
  }
}
```

### Privacy-First Telemetry (GDPR/CCPA)
- **Anonymize IPs** - hash or truncate last octet.
- **Filter PII** - emails, tokens, credit cards in `beforeSend`.
- **Consent gating** - don't collect until user consents.
- **Data retention** - set a max retention window (e.g., 30 days).
- **Right to erasure** - support deleting a user's telemetry.

```typescript
beforeSend: (item) => {
  if (item.meta?.user?.email) item.meta.user.email = '[REDACTED]';
  if (item.meta?.session?.id) item.meta.session.id = hash(item.meta.session.id);
  if (item.type === 'log' && containsPII(item.payload)) return null; // drop
  return item;
}
```

### Deeper Explanation: Instrumentation Belongs In The Build, Not In Components

The failure mode of frontend telemetry is scattering `captureException` and `fetch('/collect')` through components until nobody owns the signal. The alternative is three layers:

1. **A transport layer** â€” one client that batches, retries, and flushes on page hide, so no component ever talks to the collector directly.
2. **Automatic instrumentation** â€” global `error`/`unhandledrejection` handlers, `PerformanceObserver` for vitals and long tasks, a patched `fetch` for API metrics, and route-change spans from the router.
3. **Explicit, schema-checked events** â€” named events with typed payloads (`checkout_started`, `search_performed`), ideally generated from one shared event map so client and dashboards cannot drift.

With those layers, adding a signal is a data change, not a codebase-wide edit â€” and the privacy review happens once, in the transport.

### Extended Example: One Transport, Automatic Signals, Typed Events

```ts
// telemetry/events.ts â€” single source of truth, checked at the call site
export type Events = {
  checkout_started: { items: number; valueCents: number };
  search_performed: { queryLength: number; results: number; latencyMs: number };
  feature_used: { name: 'export' | 'share' | 'invite' };
};

export function track<K extends keyof Events>(name: K, payload: Events[K]) {
  transport.enqueue({ kind: 'event', name, payload, ts: Date.now(), route: routeKey() });
}
```

```ts
// telemetry/auto.ts â€” wired once at the app entry
addEventListener('error', (e) => transport.enqueue({ kind: 'error', message: e.message, stack: e.error?.stack }));
addEventListener('unhandledrejection', (e) => transport.enqueue({ kind: 'error', message: String(e.reason) }));

new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.duration > 100) transport.enqueue({ kind: 'longtask', ms: Math.round(entry.duration) });
  }
}).observe({ type: 'longtask', buffered: true });
```

### Additional Pitfalls
- **Direct `fetch` calls to the collector from components.** No batching, no retry, and no single place to enforce privacy.
- **Untyped event names.** Typos silently create new metrics; a typed map turns them into compile errors.
- **Tracking on the critical path.** Telemetry must never delay the user interaction that triggered it.
- **No versioning of the event schema.** Dashboards break silently when a field is renamed.
- **Losing the last events of a session.** Flush on `visibilitychange` with `sendBeacon`, or the most interesting sessions report nothing.

### Real-World Deal-Breakers
- **No consent gating** → GDPR violation, fines up to 4% of global revenue.
- **No PII filtering** → user emails, tokens, and credit cards stored in observability stores.
- **No batching** → battery drain, network cost, telemetry rate limits.
- **No `beforeSend` hook** → no control over what leaves the browser.
- **No off switch** → if observability breaks the app, you can't disable it quickly.
- **No resilience** → telemetry endpoint down = app errors. Wrap in try/catch and drop telemetry.
