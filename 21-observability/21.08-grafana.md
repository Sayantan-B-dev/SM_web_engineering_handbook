### Deeper Explanation: Grafana Is A Query Layer, Not A Data Store

Grafana stores no telemetry; it queries sources (Prometheus/Mimir for metrics, Loki for logs, Tempo for traces) and renders them. That shapes how you work with it: the quality of a dashboard depends on the *labels* your metrics carry and the *queries* you can express, not on Grafana itself. Three sources, deliberately correlated by shared labels or trace ids, is the mature setup.

Two practices separate a useful Grafana instance from a wallpaper collection:

- **Provisions as code.** Dashboards and alerts in JSON/YAML in the repository means they are reviewable, diffable, and reproducible. Dashboard-by-clicking does not survive a migration.
- **Alerts with a runbook link.** Every alert should answer "what do I do now" in a URL, plus a link to the exact panel range that triggered it. Alert volume is a budget: few alerts, each actionable.

### Extended Example: Provisioned Dashboard Panel Plus Alert Rule

```json
{
  "type": "timeseries",
  "title": "Checkout error rate (p75 route)",
  "targets": [
    {
      "expr": "sum(rate(api_request_total{route=\"/api/checkout\", status=~\"5..\"}[5m])) / sum(rate(api_request_total{route=\"/api/checkout\"}[5m]))",
      "legendFormat": "5xx rate"
    }
  ],
  "thresholds": [{ "value": 0.02, "color": "red" }]
}
```

```yaml
# alert rule, provisioned with the stack
- alert: CheckoutErrorRateHigh
  expr: sum(rate(api_request_total{route="/api/checkout",status=~"5.."}[5m])) > 0.02
  for: 5m
  labels: { severity: page }
  annotations:
    summary: "Checkout is failing for more than 2% of requests"
    runbook_url: https://runbooks.example.com/checkout-errors
```

### Additional Pitfalls
- **Dashboards created only in the UI.** They cannot be code-reviewed and vanish with the instance.
- **Panel sprawl.** Twenty-panel dashboards mean everyone stares at the one panel that matters and misses the other nineteen.
- **Alerts on causes instead of symptoms.** Alert on user-visible failure (5xx rate, INP p75), not on CPU graphs.
- **No units or thresholds on panels.** An unlabelled 0.47 means nothing at 3am.
- **High-cardinality legends.** A legend with 200 series is a query mistake, not a dashboard problem.

### Real-World Deal-Breakers
- **No unified dashboards** → context switching between 5 tools slows incident response.
- **No alerting routing** → alerts go to a channel everyone mutes. Use on-call rotations.
- **No SLO tracking** → no basis for release gates or error budgets.
- **Too many dashboards** → nobody looks at them. Fewer, focused dashboards.
