### What Alloy Is
Grafana Alloy is Grafana's **distribution of the OpenTelemetry Collector** with additional capabilities: Prometheus scraping, Loki pushing, Pyroscope profiling, and native Grafana Cloud integration. It's the recommended way to send telemetry from your infrastructure to Grafana Cloud.

### Pipeline Architecture
```
Receivers → Processors → Exporters
  ↓            ↓              ↓
OTLP       Batch, PII      Loki, Tempo
Jaeger     Sampling        Mimir, Pyroscope
Zipkin     Enrichment      Datadog, OTLP
```

### Example Alloy Config
```alloy
// Receive OTLP from browser and backend
otelcol.receiver.otlp "default" {
  http {
    endpoint = "0.0.0.0:4318"
  }
  grpc {
    endpoint = "0.0.0.0:4317"
  }
  output {
    metrics = [otelcol.processor.batch.default.input]
    logs    = [otelcol.processor.batch.default.input]
    traces  = [otelcol.processor.batch.default.input]
  }
}

// Batch and process
otelcol.processor.batch "default" {
  timeout = "5s"
  output {
    metrics = [otelcol.exporter.otlphttp.grafana_cloud.input]
    logs    = [otelcol.exporter.otlphttp.grafana_cloud.input]
    traces  = [otelcol.exporter.otlphttp.grafana_cloud.input]
  }
}

// Export to Grafana Cloud
otelcol.exporter.otlphttp "grafana_cloud" {
  client {
    endpoint = "https://otlp-gateway-prod-us-east-0.grafana.net/otlp"
    auth     = otelcol.auth.basic.grafana_cloud.handler
  }
}
```

### Deeper Explanation: The Collector Is The Enforcement Point

Grafana Alloy (the successor to the Grafana Agent) is an OpenTelemetry-compatible collector whose real job is **policy**: it receives telemetry, drops what should never be stored, enriches what is missing, samples what is too expensive, and forwards the rest. Putting that logic in a collector instead of in application code means you can change retention, redaction, and routing without redeploying the app.

Typical pipeline stages:

| Stage | Purpose | Example |
|---|---|---|
| Receiver | Accept OTLP, Faro, Prometheus scrape | `otelcol.receiver.otlp` |
| Processor | Redact, enrich, filter, sample | drop `http.request.header.authorization` |
| Exporter | Send to Loki/Tempo/Mimir | fan-out to two backends |
| Relabel | Route by attribute | only keep 1% of `/health` spans |

For frontends, the collector is also the place to enforce a rate limit per origin, so one misbehaving release cannot flood the observability bill.

### Extended Example: Alloy Pipeline With Redaction And Tail Sampling

```alloy
otelcol.receiver.otlp "default" {
  http { endpoint = "0.0.0.0:4318" }
  output {
    metrics = [otelcol.processor.batch.default.input]
    logs    = [otelcol.processor.attributes.redact.input]
    traces  = [otelcol.processor.tail_sampling.errors.input]
  }
}

otelcol.processor.attributes.redact "default" {
  action {
    key    = "http.request.header.authorization"
    action = "delete"
  }
  output { logs = [otelcol.exporter.loki.default.input] }
}

otelcol.processor.tail_sampling.errors "default" {
  decision_wait = "10s"
  policy {
    name = "keep-errors-and-slow"
    type = "numeric_attribute"
    numeric_attribute { key = "http.status_code"; min_value = 500; max_value = 599 }
  }
  policy {
    name = "sample-the-rest"
    type = "probabilistic"
    probabilistic { sampling_percentage = 5 }
  }
  output { traces = [otelcol.exporter.otlp.tempo.input] }
}
```

### Additional Pitfalls
- **Redaction in the app instead of the collector.** Each new service forgets it; enforce centrally and treat the collector as a security boundary.
- **No per-origin rate limit.** A retry storm in the browser multiplies into a telemetry flood.
- **Dropping data you cannot get back.** Filter debug noise, never errors; sample high-volume success paths instead.
- **An unmonitored collector.** If it falls over, observability silently disappears â€” alert on its own metrics.
- **Config drift between environments.** Keep Alloy config in the repo and deploy it like code.

### Real-World Deal-Breakers
- **No PII scrubbing at the collector** → sensitive data leaves your network.
- **No batching** → network calls per event; costs explode.
- **No sampling at collector** → 100% of traces forwarded; storage costs surge.
- **No retry/backoff** → transient backend failures lose telemetry.
- **Sending telemetry directly from app** → no central control; changing backends requires redeploying every app.
