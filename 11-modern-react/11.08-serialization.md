### The RSC Payload
Server Components produce a **serialized UI tree** - the RSC payload - that's sent to the client. React must serialize props into this payload. Only serializable data can cross the Server → Client boundary.

### Complete Serializable Types List

| Type | Serializable? |
|------|--------------|
| `string`, `number`, `bigint`, `boolean` | ✅ |
| `null`, `undefined` | ✅ |
| Plain objects | ✅ |
| Arrays of serializable values | ✅ |
| **Server Actions** (`'use server'`) | ✅ (exception) |
| `Date` | ✅ |
| `Map`, `Set` | ✅ |
| `TypedArray`, `ArrayBuffer` | ✅ |
| Regular functions | ❌ |
| Closures | ❌ |
| Class instances | ❌ |
| `Symbol` | ❌ |
| `WeakMap`, `WeakSet` | ❌ |

### Class Instance Conversion
```jsx
// ❌ BAD - class instance
const url = new URL('https://example.com');
<ClientComponent link={url} />

// ✅ GOOD - converted to plain string
<ClientComponent link={url.toString()} />
```

### Server Actions as Functions
```jsx
// actions.ts
'use server';
export async function handleDelete(id) { ... }
```

```jsx
// Server Component
import { handleDelete } from './actions';
<ClientComponent onDelete={handleDelete} /> // ✅ Server Action is serializable
```

### Error Messages
- **Build time:** "Functions cannot be passed directly to Client Components because they're not serializable."
- **Runtime:** "Only plain objects can be passed to Client Components from Server Components. Classes or other objects with methods are not supported."
- **Silent data loss:** Some non-serializable values may become `undefined` without an error.

### Framework-Specific Behavior
- **Next.js:** Props must be serializable; `'use server'` functions are supported.
- **TanStack Start:** RSC payloads are "streams of data" - serialization still applies but the framework may handle more types.

### Real-World Deal-Breakers
- **Passing `new Intl.NumberFormat()`** → runtime error. Pass the formatted string or format on the client.
- **Passing a function from Server → Client (not a Server Action)** → error. Use `'use server'`.
- **Passing a `Symbol`** → error. Use a string ID instead.
- **Passing a `WeakMap`** → error. Use a regular object or serialize manually.
- **Assuming `Date` works everywhere** → some frameworks serialize to string; timezone may shift. Pass ISO strings for critical dates.
- **Silent data loss** → non-serializable values may become `undefined` without an error. Always check the RSC payload in DevTools.
