### Async Components
Server Components can be `async` and `await` directly in render - no hooks, no loading states, no client-side data fetching.

```jsx
async function ProductPage({ id }) {
  const product = await db.product.findUnique({
    where: { id },
    include: { reviews: true, related: true },
  });

  return (
    <article>
      <h1>{product.name}</h1>
      <p>{product.description}</p>
      <ReviewList reviews={product.reviews} />
      <RelatedProducts products={product.related} />
    </article>
  );
}
```

### Direct Backend Access
Server Components can directly access your database, file system, or any server-only APIs **without the security concerns or bundle bloat** that come with client-side code.

```jsx
async function AdminDashboard() {
  // Direct DB access - no API layer needed
  const stats = await db.stats.aggregate({ ... });

  // Read files
  const config = await fs.readFile('./config.json', 'utf-8');

  // Access server-only secrets
  const apiKey = process.env.INTERNAL_API_KEY; // never sent to client

  return <Dashboard stats={stats} />;
}
```

### Heavy Library Elimination
```jsx
// Server Component - markdown renderer never ships to client
import { compile } from '@mdx-js/mdx'; // heavy
import { highlight } from 'shiki';     // very heavy

async function Article({ source }) {
  const code = await compile(source);
  const highlighted = await highlight(code);
  return <div dangerouslySetInnerHTML={{ __html: highlighted }} />;
}
```
Without RSC, these libraries (~500KB+) would bloat the client bundle. With RSC, the client receives only the rendered HTML.

### RSC in Different Frameworks
- **Next.js App Router** - Server Components are the default. Add `'use client'` for interactive parts.
- **TanStack Start** - RSCs are "streams of data that you can fetch, cache, and render on your terms" - decoupled from a server-owned component tree.
- **Bundler-level** - RSC requires framework/bundler support. React 19's RSC APIs are stable but the underlying bundler APIs may change between minors.

### Real-World Deal-Breakers
- **Using `process.env.SECRET` in a Client Component** → secret leaked to browser. Only Server Components and Server Actions can safely access secrets.
- **RSC without Suspense boundaries** → the entire page blocks until every async component resolves. ALWAYS wrap slow async components in `<Suspense>`.
- **Assuming RSC works everywhere** → it requires framework support (Next.js, TanStack Start, etc.). Plain Vite + React doesn't support RSC out of the box.
- **Importing server-only code into client modules** → `server-only` package prevents this. Use it.
