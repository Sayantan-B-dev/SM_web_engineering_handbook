## 11.9 Server Actions

### Subtopic Tree
- Definition: server functions callable from client
- `'use server'` directive
- Form integration (`action` prop)
- Progressive enhancement
- `useActionState` / `useFormStatus`
- Optimistic updates (`useOptimistic`)
- Error handling
- Revalidation (`revalidatePath`, `revalidateTag`)
- Security (validation, authorization, rate limiting)
- Streaming responses

### What Server Actions Are
Functions that execute on the server but can be called from either Server Components or Client Components. They eliminate the need for manual API routes for mutations.

### Form Integration
```jsx
// Server Component
import { createPost } from './actions';

export default function NewPostPage() {
  return (
    <form action={createPost}>
      <input name="title" placeholder="Title" />
      <textarea name="body" placeholder="Body" />
      <button type="submit">Publish</button>
    </form>
  );
}
```

```jsx
// actions.ts
'use server';
import { revalidatePath } from 'next/cache';

export async function createPost(formData) {
  const title = formData.get('title');
  const body = formData.get('body');
  await db.post.create({ data: { title, body } });
  revalidatePath('/posts');
}
```

### Progressive Enhancement
Server Actions work **without JavaScript** when used as form actions. The form submits to the server, the action runs, and the page re-renders - all without client JS.

### Optimistic Updates
```jsx
'use client';
import { useOptimistic } from 'react';
import { addTodo } from './actions';

export function TodoList({ todos }) {
  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    todos,
    (state, newTodo) => [...state, { id: 'temp', text: newTodo, pending: true }],
  );

  async function handleSubmit(formData) {
    const text = formData.get('text');
    addOptimisticTodo(text);
    await addTodo(formData);
  }

  return (
    <>
      <ul>
        {optimisticTodos.map(t => (
          <li key={t.id} style={{ opacity: t.pending ? 0.5 : 1 }}>{t.text}</li>
        ))}
      </ul>
      <form action={handleSubmit}>
        <input name="text" />
        <button>Add</button>
      </form>
    </>
  );
}
```

### Revalidation
```jsx
'use server';
import { revalidatePath, revalidateTag } from 'next/cache';

export async function updatePost(id, data) {
  await db.post.update({ where: { id }, data });
  revalidatePath('/posts');       // revalidate by path
  revalidateTag('posts');          // or by cache tag
}
```

### Security Checklist
```jsx
'use server';
import { z } from 'zod';
import { rateLimit } from './rate-limit';

const Schema = z.object({ title: z.string().min(1).max(200) });

export async function createPost(formData) {
  // 1. Rate limiting
  const allowed = await rateLimit('create-post');
  if (!allowed) return { error: 'Too many requests' };

  // 2. Input validation
  const parsed = Schema.safeParse({ title: formData.get('title') });
  if (!parsed.success) return { error: parsed.error.flatten() };

  // 3. Authorization
  const user = await getCurrentUser();
  if (!user) return { error: 'Unauthorized' };

  // 4. Execute
  const post = await db.post.create({ data: { ...parsed.data, authorId: user.id } });

  // 5. Revalidate
  revalidatePath('/posts');

  // 6. Return serializable result
  return { post: { id: post.id, title: post.title } };
}
```

### Real-World Deal-Breakers
- **No validation** → Server Actions are public endpoints; anyone can call them with any payload.
- **No rate limiting** → brute-force or spam attacks.
- **No authorization** → any user can execute any action.
- **Returning non-serializable values** → same serialization rules apply as props.
- **Forgetting revalidation** → data mutates but UI doesn't update.
- **Assuming Server Actions are private** → they're HTTP endpoints. Treat them with Zero Trust.
- **Throwing errors without handling** → client sees a generic error; return structured results instead.
