## 11.5 Client Boundaries

### Subtopic Tree
- `'use client'` creates a client subtree
- Everything imported by a client module becomes client
- `children` prop as escape hatch (Server → Client → Server)
- Third-party library wrapping
- Client Component importing Server Component (NOT allowed directly)
- Client boundary and bundle size
- Detecting accidental client bundling
- `client-only` package

### How a Client Boundary Works
When a file marked with `'use client'` is imported from a Server Component, compatible bundlers treat the import as a boundary between server-run and client-run code. As descendants of this boundary, **modules are guaranteed to be bundled with and run on the client**.

```jsx
// ClientBoundary.tsx
'use client';
import { HeavyLib } from 'heavy-lib'; // ← becomes client code
import { useState } from 'react';

export default function ClientBoundary() {
  const [x] = useState(0);
  return <HeavyLib x={x} />; // HeavyLib ships to client
}
```

### Client Cannot Import Server Components Directly
```jsx
// ❌ NOT allowed - Client Component importing Server Component
'use client';
import ServerComponent from './ServerComponent'; // Build error

export default function Client() {
  return <ServerComponent />; // Can't do this
}
```

**But** you can pass Server Components as `children`:

```jsx
// ✅ Server Component passed as children
'use client';
export default function ClientWrapper({ children }) {
  const [open, setOpen] = useState(false);
  return <div>{open && children}</div>;
}
```

```jsx
// page.tsx - Server Component
import ClientWrapper from './ClientWrapper';
import ServerData from './ServerData';

export default function Page() {
  return (
    <ClientWrapper>
      <ServerData /> {/* Server Component as children */}
    </ClientWrapper>
  );
}
```

### Wrapping Third-Party Client Libraries
Third-party libraries that use hooks (e.g., carousel libraries, chart libraries) must be wrapped in a Client Component.

```jsx
// components/Carousel.tsx
'use client';
import { Carousel } from 'react-responsive-carousel'; // uses hooks

export default function CarouselWrapper(props) {
  return <Carousel {...props} />;
}
```

```jsx
// page.tsx - Server Component
import CarouselWrapper from './components/Carousel';

export default function Page() {
  return <CarouselWrapper items={items} />;
}
```

### Detecting Accidental Client Bundling
**Symptom:** Bundle exploded after adding one Client Component.

**Cause:** A Client Component imported a large library (e.g., a date library, a chart library) that became part of the client bundle. **Fix:** Move the heavy library usage to a Server Component, or lazy-load it.

### `client-only` Package
```jsx
// analytics.ts
import 'client-only'; // throws if imported from a Server Component

export function trackEvent(name) {
  window.gtag('event', name);
}
```

### Real-World Deal-Breakers
- **Client Component importing another Client Component** → `'use client'` has no effect. The directive is only meaningful at the Server → Client boundary.
- **Client Component importing a Server Component** → build error. Use `children` instead.
- **Entire app wrapped in one `'use client'`** → everything ships to client. Push boundaries to the leaves.
- **Third-party library with hooks used in Server Component** → build error. Wrap it in a Client Component.
- **No bundle analysis after adding Client Components** → silent bundle growth. Always check.
