### What a Server Boundary Is
The server boundary is the **module dependency line** marked by `'use client'`. Everything on one side is server code; everything on the other is client code.

```jsx
// Server side - no directive
import ClientThing from './ClientThing'; // ← boundary crossed here

async function ServerPage() {
  const data = await fetchData();
  return <ClientThing data={data} />; // ← serialization happens here
}
```

```jsx
// Client side - 'use client' marks the boundary
'use client';
export default function ClientThing({ data }) {
  return <div>{data.name}</div>;
}
```

### Serialization Rules (CRITICAL)
**Only serializable data can cross the Server → Client boundary.** React must serialize props into the RSC payload sent over the wire. Passing non-serializable values causes build or runtime errors.

**✅ Serializable:**
- Primitives: `string`, `number`, `bigint`, `boolean`, `null`, `undefined`
- Plain objects and arrays containing serializable values
- **Server Actions** (functions defined with `'use server'`) - the ONLY function type that can cross
- `Date`, `Map`, `Set`, `TypedArray`, `ArrayBuffer`

**❌ Non-Serializable:**
- Regular functions and closures
- Class instances (`new Intl.NumberFormat()`, `new URL()`, custom classes)
- `Symbol`, `WeakMap`, `WeakSet`

```jsx
// ❌ BAD - non-serializable props
<ClientCard
  onClick={() => console.log('clicked')}   // function
  formatter={new Intl.NumberFormat('en-US')} // class instance
  icon={Symbol('star')}                     // Symbol
/>

// ✅ GOOD - serializable props + Server Action
import { handleClick } from '@/app/actions'; // 'use server'

<ClientCard
  item={{ id: data.id, name: data.name }} // plain object
  tags={['featured', 'sale']}              // array of primitives
  onAction={handleClick}                    // Server Action (serializable)
/>
```

**Rule of thumb:** Check if `JSON.stringify(prop)` would succeed.

### Server Actions: The Exception
Functions marked with `'use server'` **CAN be passed to Client Components**. Your framework automatically creates a reference to the server function and passes that reference to the Client Component.

```jsx
// actions.ts
'use server';

export async function createPost(formData) {
  const post = await db.post.create({ data: { title: formData.get('title') } });
  revalidatePath('/posts');
}
```

```jsx
// ClientComponent.tsx
'use client';
import { createPost } from './actions';

export function NewPostForm() {
  return (
    <form action={createPost}>
      <input name="title" />
      <button type="submit">Create</button>
    </form>
  );
}
```

### Environment Poisoning Prevention
Use `server-only` and `client-only` packages to harden the boundary.

```jsx
// db.ts
import 'server-only'; // throws if imported from client code

export const db = new PrismaClient();
```

```jsx
// analytics.ts
import 'client-only'; // throws if imported from server code

export function track(event) {
  window.gtag('event', event);
}
```

### Provider Placement at Boundaries
Context providers use hooks → they must be Client Components. Place them at the top level, wrapping server content:

```jsx
// app/providers.tsx
'use client';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { useState } from 'react';

export function Providers({ children }) {
  const [client] = useState(() => new QueryClient());
  return <QueryClientProvider client={client}>{children}</QueryClientProvider>;
}
```

```jsx
// app/layout.tsx - Server Component
import { Providers } from './providers';

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

### Security at the Boundary (Zero Trust)
Follow a Zero Trust model: Server Components **must not access privileged data or server-only modules** unless explicitly authorized.

```jsx
// ❌ BAD - authorization check happens after data fetch
async function AdminPanel() {
  const data = await db.adminData(); // fetched before checking
  if (!isAdmin) return <AccessDenied />;
  return <Panel data={data} />;
}

// ✅ GOOD - authorization before data fetch
async function AdminPanel() {
  if (!await isAdmin()) return <AccessDenied />;
  const data = await db.adminData(); // only fetched if authorized
  return <Panel data={data} />;
}
```

Use React Taint APIs to prevent accidental exposure of private data to the client.

### Real-World Deal-Breakers
- **Passing a class instance** (`new URL()`) → runtime error at the boundary. Convert: `{ url: myUrl.toString() }`.
- **Defining event handlers in Server Components** → functions can't cross. Define handlers inside Client Components.
- **No `server-only` guard** → a server module accidentally imported by client code leaks secrets to the bundle.
- **Authorization after data fetch** → even if the UI hides data, the query ran. Check auth BEFORE fetching.
- **Provider in a Server Component** → build error. Providers use hooks → must be `'use client'`.
- **Passing Date objects as props** → technically serializable but can lose timezone info depending on the framework. Pass ISO strings for safety.
