### Where Suspense Fits in Modern React
In the RSC model Suspense is not just a loading spinner - it is the **unit of streaming and hydration**. Each boundary marks a point where the server can flush part of the page and where the client can hydrate independently.

```jsx
// Server Component - no 'use client' needed
<Suspense fallback={<FeedSkeleton />}>
  <Feed /> {/* async Server Component */}
</Suspense>
```

### Suspense + `use()`
React 19's `use()` unwraps a promise inside a Client Component. The promise must be created **outside** render (or handed over from a Server Component), otherwise a new promise is thrown on every render.

```jsx
'use client';
import { use } from 'react';

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise); // suspends until resolved
  return (
    <ul>
      {comments.map((c) => (
        <li key={c.id}>{c.text}</li>
      ))}
    </ul>
  );
}
```

### Suspense + Transitions
Wrapping the update in `startTransition` keeps the **current** UI on screen instead of flashing the fallback.

```jsx
const [query, setQuery] = useState('');
const [search, setSearch] = useState('');
const [isPending, startTransition] = useTransition();

<SearchInput
  value={query}
  onChange={(e) => {
    setQuery(e.target.value);                          // urgent: the input
    startTransition(() => setSearch(e.target.value));  // non-urgent: the results
  }}
/>

<Suspense fallback={<ResultsSkeleton />}>
  <Results query={search} />
</Suspense>
```

### Boundary Placement
- Boundary **close** to the slow content → small fallback, precise streaming.
- Boundary **too high** → the whole section flashes a spinner.
- `loading.tsx` in the App Router is just a `Suspense` boundary wrapped around the route segment.
- Each boundary hydrates on its own, so grouping unrelated slow sections under one boundary delays the fast ones.

### Real-World Deal-Breakers
- **Creating the promise inside render** → `use()` throws a fresh promise every render; create it in a parent or Server Component, or cache it.
- **No error boundary around the boundary** → a rejected promise propagates upward and can crash the route.
- **Fallback with a different height than the content** → layout shift (CLS) when the real content streams in; skeletons must match the final layout.
- **One Suspense around the entire page** → you trade streaming for a single page-wide spinner.
- **Assuming Suspense fetches data** → it only *reacts* to a thrown promise; the data source must itself be Suspense-aware.
