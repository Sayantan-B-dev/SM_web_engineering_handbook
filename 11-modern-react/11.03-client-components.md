## 11.3 Client Components

### Subtopic Tree
- `'use client'` directive
- Purpose: interactivity, state, effects, browser APIs
- Module dependency boundary (not render boundary)
- Transitive dependencies become client code
- Props must be serializable
- Cannot be async functions
- Event handlers live here
- Provider placement
- Third-party client libraries
- Leaf-pushing principle

### The `'use client'` Directive
Add `'use client'` at the top of a file to mark the module **and its transitive dependencies** as client code.

```jsx
'use client';

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

### What `'use client'` Actually Is
This is the source of ~80% of RSC confusion: **`'use client'` is a module dependency boundary, not a render boundary**. Two separate trees are in play:

| Tree | Boundary set by `'use client'`? |
|------|-------------------------------|
| Module dependency tree (imports) | ✅ YES - every transitive import becomes client code |
| Render tree (parent/child JSX) | ❌ NO - Server Components can render Client Components, and vice versa via `children` |

```jsx
// app/page.tsx - Server Component (default)
import ClientCounter from './ClientCounter'; // ✅ Server can import Client
import ServerChart from './ServerChart';     // ✅ Server can import Server

export default function Page() {
  return (
    <>
      <ServerChart />
      <ClientCounter />
    </>
  );
}
```

```jsx
// app/ClientCounter.tsx - Client Component
'use client';
import { useState } from 'react';

export default function ClientCounter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

A component can be imported into both server and client modules and ship to both - it has no inherent identity until it's imported somewhere.

### Leaf-Pushing Principle
**Mark the smallest possible leaf** - everything it imports becomes client code.

```jsx
// ❌ BAD - 'use client' on a large component makes everything client
'use client';
import { HeavyChart, HeavyTable, HeavyForm, HeavyEditor } from './heavy';
export default function Dashboard() {
  return <><HeavyChart /><HeavyTable /><HeavyForm /><HeavyEditor /></>;
}
// → ALL heavy components ship to client

// ✅ GOOD - leaf-pushing: only the interactive bit is client
export default function Dashboard() { // Server Component
  return (
    <>
      <HeavyChart />        {/* Server */}
      <HeavyTable />        {/* Server */}
      <InteractiveFilter /> {/* Client - 'use client' only on this */}
      <HeavyEditor />       {/* Server */}
    </>
  );
}
```

### Slot Pattern: Server Children Inside Client Parent
Use the `children` slot to put Server Components inside Client Components.

```jsx
// ClientComponent.tsx
'use client';
import { useState } from 'react';

export default function ClientWrapper({ children }) {
  const [open, setOpen] = useState(false);
  return (
    <div>
      <button onClick={() => setOpen(o => !o)}>Toggle</button>
      {open && children}
    </div>
  );
}
```

```jsx
// page.tsx - Server Component
import ClientWrapper from './ClientWrapper';
import ServerData from './ServerData'; // Server Component

export default function Page() {
  return (
    <ClientWrapper>
      <ServerData /> {/* Server Component passed as children to Client */}
    </ClientWrapper>
  );
}
```

### Client Component Constraints
- **Cannot be `async` functions** - `async` Client Components are invalid.
- **Props from Server must be serializable** - functions, class instances, Symbols will error.
- **Hooks, event handlers, browser APIs** - only allowed here.

### Real-World Deal-Breakers
- **`'use client'` on a parent** → the entire subtree (and all imports) becomes client code. Push it to the leaves.
- **Passing functions from Server → Client** → runtime error. Use Server Actions (`'use server'`) instead - they ARE serializable.
- **`async` Client Component** → invalid; Client Components cannot be async.
- **Importing a Client Component into another Client Component** → `'use client'` has no effect (it's already client). The directive is only meaningful at the Server → Client boundary.
- **Context providers in Server Components** → providers need `'use client'` because they use state. Wrap the app at the top level.
