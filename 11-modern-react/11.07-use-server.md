### What Server Actions Are
`'use server'` marks server-side functions that can be called from client-side code. When a Server Action is defined, your framework automatically creates a reference to the server function and passes that reference to the Client Component. When the client calls the function, the framework sends a network request to the server, executes the function, and returns the result.

### File-Level Directive
```jsx
// actions.ts
'use server';

export async function createPost(formData) {
  const title = formData.get('title');
  const post = await db.post.create({ data: { title } });
  revalidatePath('/posts');
  return post;
}

export async function deletePost(id) {
  await db.post.delete({ where: { id } });
  revalidatePath('/posts');
}
```

### Inline Directive
```jsx
// page.tsx - Server Component
export default function Page() {
  async function handleSubmit(formData) {
    'use server';
    const name = formData.get('name');
    await db.user.create({ data: { name } });
  }

  return (
    <form action={handleSubmit}>
      <input name="name" />
      <button type="submit">Create</button>
    </form>
  );
}
```

### Called from Client Components
```jsx
// ClientComponent.tsx
'use client';
import { createPost } from './actions';

export function NewPostForm() {
  return (
    <form action={createPost}>
      <input name="title" />
      <button type="submit">Create</button>
    </form>
  );
}
```

### `useActionState` (React 19)
```jsx
'use client';
import { useActionState } from 'react';
import { createPost } from './actions';

export function NewPostForm() {
  const [state, formAction, isPending] = useActionState(createPost, null);

  return (
    <form action={formAction}>
      <input name="title" />
      <button disabled={isPending}>
        {isPending ? 'Creating...' : 'Create'}
      </button>
      {state?.error && <p>{state.error}</p>}
    </form>
  );
}
```

### `useFormStatus` (React 19)
```jsx
'use client';
import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'Saving...' : 'Save'}</button>;
}
```

### Security: Validate Everything
Server Actions are **public HTTP endpoints**. Treat them with Zero Trust:

```jsx
'use server';
import { z } from 'zod';

const CreatePostSchema = z.object({
  title: z.string().min(1).max(200),
  body: z.string().min(1),
});

export async function createPost(formData) {
  // ✅ Validate input
  const result = CreatePostSchema.safeParse({
    title: formData.get('title'),
    body: formData.get('body'),
  });
  if (!result.success) return { error: result.error.flatten() };

  // ✅ Check authorization
  const user = await getCurrentUser();
  if (!user) return { error: 'Unauthorized' };

  // ✅ Execute
  const post = await db.post.create({ data: { ...result.data, authorId: user.id } });
  revalidatePath('/posts');
  return { post };
}
```

### Real-World Deal-Breakers
- **No input validation** → Server Actions are callable by anyone; validate every input.
- **No authorization check** → a logged-out user can call the action directly.
- **Passing Server Action as a prop from a Client Component** → allowed only if the action is imported from a `'use server'` module.
- **Defining Server Actions inside Client Components** → `'use server'` inside a Client Component marks a server function, but it must be async and defined at the top level of the function body.
- **Assuming Server Actions are private** → they're public endpoints. Anyone with the reference can call them.
- **Not handling errors** → a thrown error in a Server Action returns a generic 500; always return structured errors.
