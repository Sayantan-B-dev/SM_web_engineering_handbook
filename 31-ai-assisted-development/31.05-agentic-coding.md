### The Mental Model
Agentic coding changes the unit of work from "a line" to **a verified change**: you define the task, the constraints, and the acceptance signal, and let the agent iterate until the signal is green. What makes it work in a real repo is the same thing that makes CI work â€” a fast objective check.

```text
Task contract (what the agent needs)
  1. Scope:      which packages/files it may touch
  2. Behaviour:  the observable outcome, with examples
  3. Constraints: conventions, dependencies allowed, no new deps without asking
  4. Acceptance: the exact command proving success (test path, typecheck, build)
  5. Stop rule:  when to ask a human instead of guessing
```

```bash
# Parallel agents on isolated worktrees: same task family, no interference
git worktree add ../wt-a -b agent/a && git worktree add ../wt-b -b agent/b
# Each agent runs in its own worktree with its own verify command; a human merges the winner.
```

### Real-World Deal-Breakers
- **Acceptance criteria missing.** The agent optimises for "looks done", which is not "is done".
- **Two agents in one working tree.** They overwrite each other's edits; isolate branches or worktrees.
- **No convention brief.** Output diverges from house style and creates review churn.
- **Quality traded for throughput.** Counting merged PRs without defect rates hides the cost.
- **Context dumping.** Whole-file pastes of irrelevant code dilute attention; give the minimal relevant slice.
- **Skipping the human gate on destructive operations.** Migrations, dependency upgrades, and infra changes need review before running.
