## AI Developer Workflows

### Subtopic Tree
- Where AI fits in the daily loop: explore, write, test, review, debug, document
- Local assistants vs PR-bots vs CI checks
- Prompt and context libraries for a codebase (conventions, patterns)
- Guardrails: pre-commit checks, required CI, review rules
- Team norms: attribution, disclosure, review depth
- Measuring impact: cycle time, review comments, defect escape rate
- Learning loops: turning repeated prompts into tooling

### The Mental Model
AI-assisted development is a **workflow design** problem. The same model in a bad workflow produces noise; in a good workflow it removes toil. Three placements dominate:

| Placement | Effect | Guardrail |
|---|---|---|
| In the editor (completion, edits) | Faster authoring | Linters, types, tests running locally |
| In the PR (review, tests, docs) | Cheaper review, more coverage | Required CI, human approval, diff limits |
| In CI/ops (triage, summaries, dependency bumps) | Less repetitive work | Least privilege, human sign-off on changes |

And the loop that matters most: **turn repeated prompts into tooling**. If you paste the same context or ask for the same task weekly, that is a script, a template, or a codemod â€” not a prompt.

### Real-World Deal-Breakers
- **No convention file for prompts.** Agents guess your patterns and reviewers spend the savings on fixing style.
- **Review depth reduced without evidence.** If defect escape rate rises, the workflow is net-negative regardless of velocity.
- **AI output merged with no human approval.** Accountability does not transfer to a model.
- **No disclosure norms.** Teams should agree when AI involvement is mentioned (large diffs, generated tests).
- **Guarding the wrong thing.** Blocking AI usage entirely while allowing copy-paste from the same sources adds friction without safety.
- **Not measuring.** Cycle time, review iterations, and escaped defects tell you whether the workflow is helping.
