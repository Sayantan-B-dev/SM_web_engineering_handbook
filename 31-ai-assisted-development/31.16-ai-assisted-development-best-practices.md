### The PyTorch Playbook (May 2026)
PyTorch's playbook for AI coding includes:
- If a PR is big, make sure there is a **coherent order to engage** with the change and write down the "read order."
- Separate **cosmetic changes from semantic changes**.
- Well-encapsulated unreviewed code is a risk.

### Martin Fowler's Five Patterns
The practices that make human pair programming effective - onboarding, structured design discussion, shared standards - apply equally to working with AI coding assistants. Five patterns bring this collaborative scaffolding to AI-assisted development, shifting the experience from **correcting a tool** to **collaborating with a capable teammate**.

### KodeKloud's Copilot Adoption Guide
- Start small: try Copilot on low-risk tasks (boilerplate, tests, docs)
- Learn from suggestions: use prompts and edits to discover APIs and idioms
- Establish team norms: share examples and review AI output as a team to standardize usage
- Iterate and measure

### The Vibe Coding Prompt Cheat Sheet
- Be specific about languages and frameworks
- Supply example inputs and outputs
- Break large tasks into smaller steps
- Give agents one task at a time
- Define a persona
- Use and maintain a rules file
- Start simple and build on it
- Treat AI like a pool of junior developers, not a senior developer
- Revert and try again

### Deeper Explanation: The Practices That Survive Contact With Real Teams

Five habits separate teams that get durable gains from teams that get churn:

1. **Bounded tasks with acceptance criteria.** Scope, behaviour, constraint, and verify command stated before the agent starts.
2. **Small diffs and frequent commits.** Reviewable units, revertible history, and an audit trail.
3. **Types and tests as the contract.** Strong types give models instant feedback; tests give them (and you) an objective definition of done.
4. **A committed convention file.** House style, patterns, forbidden dependencies, and review expectations in the repo where every tool can read them.
5. **Human review proportional to risk.** Trivial changes can be fast-tracked; auth, payments, and migrations get real scrutiny.

Then measure: cycle time, review iterations per PR, and escaped defects. If velocity rises while escaped defects rise faster, the workflow is a net loss.

### Additional Pitfalls
- **Treating any of this as a one-off setup.** Conventions, prompts, and verifiers need maintenance as the codebase evolves.
- **Uniform review policy.** Every diff reviewed identically wastes effort in both directions.
- **No measurement.** Without baseline metrics, "AI made us faster" is a feeling.
- **Ignoring onboarding.** New engineers need to learn the workflow deliberately, or they inherit its worst habits.

### Real-World Deal-Breakers
- **No spec** → vague prompts produce vague code. Write specs before code.
- **Big tasks in one prompt** → break work into small, iterative chunks.
- **No rules file** → agents reinvent conventions every session. Maintain a rules file.
- **Treating AI like a senior developer** → it's a pool of junior developers. Review everything.
- **No security pass** → AI-generated code is not secure by default. Do a security pass.
- **No team norms** → every developer uses AI differently. Standardize.
