### Deeper Explanation: Task Scoping Beats Prompt Cleverness

Codex-style task agents (cloud or CLI) are strongest at **well-specified, verifiable, bounded** work: implement this function to these tests, fix this failing build, write this integration, port this module. The quality ceiling comes from the specification and the verifier, not from prompt poetry.

Two habits make them reliable:

- **Write the ticket you would give a new contributor**: scope, expected behaviour, examples, acceptance command, and what not to touch.
- **Keep a fast verify path**: a subset of tests that runs in seconds makes iteration productive; a 10-minute suite turns the loop into guesswork.

### Additional Pitfalls
- **Delegating ambiguity.** "Make the dashboard better" produces churn; define the change.
- **No sandbox.** Cloud task runners need least-privilege credentials and no production data.
- **Accepting the first passing run.** A test that passes because the agent weakened it is a regression, not a success â€” inspect diffs to test files closely.
- **Ignoring the parallel-work conflict.** Two task agents on overlapping files cause merges you have to untangle.

### Real-World Deal-Breakers
- **Assuming Codex is only for OpenAI models** → Codex is a harness that can run various models.
- **No enterprise governance** → Codex has strong governance controls, but they must be configured.
