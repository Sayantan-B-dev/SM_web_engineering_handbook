### The Three Levels of AI Autonomy

| Level | What it means | Human role | Example |
|-------|--------------|-----------|---------|
| **AI-Assisted** | Autocomplete, inline suggestions | Writes every line | GitHub Copilot inline |
| **Vibe Coding** | Natural-language prompts → AI generates → human runs/tweaks | Director, prompt-refiner | Cursor Composer, Bolt |
| **Agentic Coding** | Goal → agent plans, executes, tests, iterates autonomously | Reviewer, guardrail-setter | Claude Code, Devin |

A rough rule of thumb: if you're reading the AI's output one token at a time, it's assisted coding. If you're reviewing it turn by turn in a chat window, it's vibe coding. If the agent is off working while you do something else, it's agentic coding.

Harvard research found that AI coding agents increased code production by **30%** but **resolved zero additional issues**. Workers pushed 20% more commits and 23% more pull requests per month, but business value - measured by resolved issues - remained flat. Review times jumped by **49%**, increasing by an average of 3.45 days.

Plandek's Q4 2026 benchmarks found Cycle Time improved by **16%**, but Lead Time to Value (the true idea-to-production measure) improved by only **4%**. Token spend soared **10-13×**.

DX's research found AI adoption up **65%**, but PR throughput up only **7.76%** (median) - a modest 8% improvement despite massive tool adoption.

### The 94% / 6% Gap

### Deeper Explanation: Tools Differ By Where They Intervene

The landscape reduces to four intervention points, and their strengths follow from it: inline completion (keystroke latency, narrow context), chat/edits (file and multi-file scope, user-driven), agents (repo scope, loop with tools), and review/CI bots (PR scope, batch mode). Choosing well is matching the intervention point to the task:

- **Localised change with a clear intent** â†’ chat/edit mode with the file open.
- **Bounded task with an objective verifier** â†’ agent with tests as the acceptance signal.
- **Scale-wide work** (codemods, dependency migrations, docs) â†’ CI-side bots with reviewable diffs.

The trap is using an agent for a task that inline completion or a codemod would do better, faster, and cheaper.

### Additional Pitfalls
- **Tool maximalism.** Three assistants in one repo produce inconsistent style and duplicated setup.
- **Ignoring latency budgets.** A 20-second agent for a 2-line edit is a workflow regression.
- **No shared configuration.** Conventions, prompts, and ignore files should be committed for the whole team.
- **Measuring adoption instead of outcomes.** Usage dashboards say nothing about quality or cycle time.

### Real-World Deal-Breakers
- **Assuming more code = more value** → 30% more code, zero more issues resolved. Track business outcomes, not lines of code.
- **Ignoring the verification bottleneck** → AI generates faster, but human review is the constraint. Review times jumped 49%.
- **No governance** → 94% adoption, 6% governance. Security, compliance, and cost controls are missing.
- **Assuming the model is the differentiator** → all major tools run the same backing models. The workflow shell is what matters.
