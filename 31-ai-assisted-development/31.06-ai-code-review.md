### The Honest Assessment
> "The evidence it works is not settled: vendor benchmarks claim 44-82% bug-catch rates, but the only large peer-reviewed test (1,000 PRs) put the best system at **F1 ≈ 19%**, with most techniques scoring under 10% precision - i.e. most flagged issues are noise."

**Use it as a first-pass triage filter that lowers the cost of a human review, never as a merge gate that replaces one.**

### What Makes a Review "Agentic"
A single-pass LLM reviewer is a linear pipeline: ingest diff → evaluate against rules → emit comments. An **agentic** reviewer receives a goal, decomposes it, and runs an Observe→Think→Act loop where step N depends on results from steps 1…N−1, calling tools and revising its plan as it goes.

**Four axes separate the two:**
1. **Retrieval beyond the diff** - Greptile builds a dependency graph of files and functions; Qodo's Context Engine indexes four layers (rules, codebase, PR history, business requirements).
2. **Multi-agent fan-out** - parallel agents each assess one dimension (logic, security, regressions) and an aggregator dedupes and ranks.
3. **Tool calling** - the agent can call tools to verify, not just comment.
4. **Follow-up fix PRs** - the agent can open a PR to fix what it found.

### Deeper Explanation: Review-Bots Add Coverage, Not Judgement

AI review works best where humans are inconsistent: catching missing tests, forgotten error handling, obvious security patterns, naming and consistency drift, and documentation gaps. It is weakest exactly where human review is strongest: architecture, product intent, and whether the change should exist at all.

The workflow that keeps it useful:

- **Batch of small checks, each with a rationale**, not one giant "here are 40 concerns" comment.
- **Severity labels** so humans can triage (blocker/major/minor/nit).
- **A human gate remains** â€” bots do not approve, and their comments are advisory.
- **Feedback loops**: mark comments as accepted/rejected; if the bot's precision is low, tighten its instructions or drop the check.

### Additional Pitfalls
- **Noise fatigue.** Twenty stylistic comments train reviewers to ignore all bot output.
- **Hallucinated issues.** Bots confidently flag non-problems; verify before acting.
- **Confidential context in prompts.** Reviewing code must respect the same data policy as writing it.
- **Bot approval as a merge gate.** Automated checks complement review; they cannot replace accountability.

### Real-World Deal-Breakers
- **Using AI review as a merge gate** → F1 ≈ 19%; most flagged issues are noise. Use it as triage, not a gate.
- **No human review** → AI review lowers the cost of human review but does not replace it.
- **Not tuning sensitivity** → AI review tools require thoughtful configuration. Tune sensitivity levels, disable unhelpful comment types, and establish clear opt-in/opt-out policies.
- **Starting with high-stakes PRs** → start with low-stakes lanes (style, docstrings, test coverage gaps).
- **No full codebase context** → AI review without codebase context regresses to the same ceiling. Pair the tool with full context.
