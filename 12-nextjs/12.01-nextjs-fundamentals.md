### What Next.js Is
Next.js is a **full-stack React framework** that provides routing, rendering strategies, data fetching, caching, and deployment tooling out of the box. Unlike plain React (a library), Next.js makes architectural decisions for you - Server Components by default, file-system routing, and automatic code splitting.

```bash
# Create a new Next.js app
npx create-next-app@latest my-app --typescript --tailwind --app
```

### App Router vs Pages Router

| Feature | Pages Router (legacy) | App Router (default) |
|---------|----------------------|---------------------|
| Directory | `pages/` | `app/` |
| Data fetching | `getServerSideProps`, `getStaticProps` | `async` components, `fetch` |
| Layouts | `_app.tsx`, `_document.tsx` | Nested `layout.tsx` |
| Server Components | ❌ | ✅ Default |
| Streaming | Limited | ✅ First-class |
| Server Actions | ❌ | ✅ |

### Automatic Optimizations (Zero Config)
Next.js enables these by default:
- **Server Components** - run on server, no JS to client
- **Code-splitting** - automatic by route segment
- **Prefetching** - links prefetched when in viewport
- **Prerendering** - Server and Client Components prerendered at build time
- **Caching** - data requests, rendered output, static assets

### Real-World Deal-Breakers
- **Mixing Pages Router and App Router without understanding boundaries** → confusing mental model; each has its own data-fetching patterns.
- **Assuming Next.js is "just React with routing"** → it's a full-stack framework; Server Components, caching, and streaming change how you think about data.
- **Using `pages/api` in a new App Router project** → use `app/api/route.ts` (Route Handlers) instead.
