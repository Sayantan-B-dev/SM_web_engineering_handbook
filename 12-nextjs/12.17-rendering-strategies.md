## 12.25 Rendering Strategies

### Subtopic Tree
- Static rendering (SSG) - build time
- Dynamic rendering (SSR) - request time
- ISR (Incremental Static Regeneration)
- Partial Prerendering (PPR)
- Cache Components (`use cache`)
- Client-side rendering (CSR)
- Choosing a strategy

### Comparison

| Strategy | When rendered | Use case |
|----------|--------------|----------|
| Static (SSG) | Build time | Blog, marketing |
| Dynamic (SSR) | Request time | Personalized, auth |
| ISR | Build + revalidate | E-commerce, news |
| PPR | Static shell + dynamic holes | Dashboards |
| CSR | In browser | Highly interactive |

### ISR Example
```tsx
// app/blog/[id]/page.tsx
export const revalidate = 60; // seconds

export async function generateStaticParams() {
  const posts = await getPosts();
  return posts.map(p => ({ id: p.id }));
}

export default async function Page({ params }) {
  const post = await getPost((await params).id);
  return <article>{post.content}</article>;
}
```
ISR updates static content without rebuilding the entire site, serves prerendered pages for most requests, and handles large content volumes without long build times.

### Real-World Deal-Breakers
- **`revalidate = 0`** → disables caching; every request re-renders.
- **ISR without `generateStaticParams`** → dynamic route not prerendered.
- **PPR without Cache Components** → not available; requires `cacheComponents: true`.
