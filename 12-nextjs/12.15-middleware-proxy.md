## 12.23 Middleware / Proxy

### Subtopic Tree
- `middleware.ts` → `proxy.ts` (Next.js 16)
- Request/response modification
- Redirects, rewrites, headers
- Auth checks
- Edge runtime limitations
- Matcher configuration

### Syntax
```tsx
// proxy.ts (Next.js 16+) / middleware.ts (deprecated)
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
  if (!request.cookies.get('session')) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  return NextResponse.next();
}

export const config = { matcher: '/dashboard/:path*' };
```
In Next.js 16, `middleware.ts` is renamed to `proxy.ts` and the exported function is renamed from `middleware` to `proxy`.

### Real-World Deal-Breakers
- **Heavy logic in proxy** → runs on every matched request; keep it light.
- **Fetch caching in proxy** → not supported; fetches inside proxy are uncached.
- **Streaming through proxy rewrites** → may buffer entire response; streaming can break.
