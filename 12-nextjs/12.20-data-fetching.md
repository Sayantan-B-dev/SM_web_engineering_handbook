## 12.28 Data Fetching

### Subtopic Tree
- `fetch` in Server Components
- `await` directly in component
- Request memoization (automatic)
- Data Cache (persistent)
- `cache: 'no-store'` (dynamic)
- `next: { revalidate }` (time-based)
- `next: { tags }` (tag-based)
- Parallel vs sequential fetching
- `Promise.all` for parallel

### Fetch in Server Components
```tsx
async function getData() {
  const res = await fetch('https://api.example.com/data');
  return res.json();
}

export default async function Page() {
  const data = await getData();
  return <div>{data.title}</div>;
}
```

### Caching Options
```tsx
// Default: cached (static)
await fetch('https://api.example.com/data');

// No cache (dynamic)
await fetch('https://api.example.com/data', { cache: 'no-store' });

// Time-based revalidation
await fetch('https://api.example.com/data', { next: { revalidate: 60 } });

// Tag-based revalidation
await fetch('https://api.example.com/data', { next: { tags: ['posts'] } });
```

### Real-World Deal-Breakers
- **Fetching in Client Components with `useEffect`** → can't access server data; use Server Components.
- **Sequential fetches** → use `Promise.all` for parallel.
- **`cache: 'no-store'` on every fetch** → no caching benefit.
