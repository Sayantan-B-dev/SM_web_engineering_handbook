## 12.29 Caching

### Subtopic Tree
- Request Memoization (per-request)
- Data Cache (persistent)
- Full Route Cache (HTML + RSC payload)
- Router Cache (client-side)
- Cache tags
- `revalidateTag`, `revalidatePath`
- `cacheLife` (Cache Components)

### Four Caching Layers

| Mechanism | What | Where | Duration |
|-----------|------|-------|----------|
| Request Memoization | Return values of functions | Server | Per-request |
| Data Cache | Data | Server | Persistent |
| Full Route Cache | HTML + RSC payload | Server | Persistent |
| Router Cache | RSC Payload | Client | Session/time |

Next.js caches as much as possible by default: routes are statically rendered and data requests are cached unless you opt out.

### Cache Tags
```tsx
// Set tag on fetch
const res = await fetch('https://api.example.com/posts', {
  next: { tags: ['posts'] },
});

// Invalidate by tag
import { revalidateTag } from 'next/cache';
revalidateTag('posts');

// Invalidate by path
import { revalidatePath } from 'next/cache';
revalidatePath('/blog');
```
On-demand revalidation explicitly invalidates cached content by calling `revalidateTag()` or `revalidatePath()`.

### Real-World Deal-Breakers
- **Assuming fetch cache is disabled by default** → it's cached unless `no-store`.
- **No revalidation after mutation** → stale UI.
- **`revalidatePath('/')` in a large app** → invalidates everything; use tags for granularity.
- **Cache Components without `use cache`** → opt-in; default is still dynamic.
