## 12.30 Revalidation

### Subtopic Tree
- Time-based (stale-while-revalidate)
- On-demand (`revalidateTag`, `revalidatePath`)
- `revalidate` route segment config
- `cacheLife` profiles
- Tag system architecture
- HTML + RSC payload consistency

### Time-Based Revalidation
```tsx
export const revalidate = 3600; // revalidate every hour
```

### On-Demand Revalidation
```tsx
'use server';
import { revalidatePath, revalidateTag } from 'next/cache';

export async function updatePost(id, data) {
  await db.post.update({ where: { id }, data });
  revalidatePath('/posts');
  revalidateTag('posts');
}
```
There are two types of revalidation: time-based uses stale-while-revalidate, and on-demand explicitly invalidates cached content.

### Real-World Deal-Breakers
- **Forgetting revalidation after mutation** → users see stale data.
- **Revalidating too broadly** → invalidates unrelated content.
- **Cross-deployment skew** → client and server on different deploys; use `deploymentId`.
